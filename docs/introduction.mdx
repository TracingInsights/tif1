# Welcome to tif1

`tif1` is a Python library for Formula 1 data analysis. It provides access to timing, telemetry, and weather data from TracingInsights (2018-current).

`tif1` is an alternative to `fastf1` with a compatible API. It loads data lazily, fetches multi-file loads in parallel over HTTP/2, and supports pandas and polars backends.

## Why tif1?

## Why tif1 over fastf1?

`fastf1` is an established library at the center of the F1 data community. `tif1` started as a personal project with a different approach in a few areas:

1. **Fetch only the necessary data.** `session.load()` is not necessary. One lap of telemetry for one driver needs three small files. They hold the driver list, the lap table, and the telemetry of that lap.
2. **No API rate limits.** fastf1 raises `RateLimitExceededError` after **500 uncached requests in one hour**. The jolpica-f1 API behind it documents the same limit for unauthenticated use. `tif1` reads static CDN files and keeps no request quota.
3. **Charts included.** 22 optional one-call `plot_*()` functions turn raw data into finished charts: `tif1.plot_top_speeds(...)`, `tif1.plot_driver_laptimes(...)`, and more.
4. **Public CDN access.** `tif1` needs no API key, cookie, or account. Any network that can reach jsDelivr, Hugging Face, or StaticDelivr can load the data.
5. **More data.** Mini-sector color codes, weather columns on every lap row, and acceleration channels in telemetry. The `fastf1` laps and telemetry do not include these columns.

## Key Features

- **Multi-CDN**: jsDelivr, Hugging Face buckets, and StaticDelivr with automatic fallback and SQLite caching
- **Complete**: Lap times, sectors, telemetry, tire compounds, weather, and race control messages
- **Historical**: Data from 2018-current
- **Reliable**: Automatic retry logic with circuit breaker and multi-CDN fallback
- **Async**: Parallel data fetching for multi-file loads
- **HTTP/2**: Uses niquests for multiplexed, connection-efficient network requests
- **Flexible**: Supports both pandas and polars backends
- **Type-Safe**: Type hints on the public API for IDE support
- **Jupyter-Ready**: `tif1.jupyter` adds HTML display for sessions, drivers, and laps in notebooks
- **Native Charts**: 22 one-call chart functions in `tif1.charts` for track maps, telemetry comparisons, and performance analysis

## Performance

`tif1` does not publish a timed comparison with `fastf1`. The benchmark suite in the repository measures `tif1` itself. One test sends 10 simulated requests of 0.1 s each. The parallel batch must finish more than 3x faster than the same requests in sequence. Results vary by machine and network. Run `uv run pytest tests/benchmarks/ -m benchmark` in a clone of the repository to measure them.

## Core Architecture

`tif1` uses an HTTP/2 networking stack with multi-CDN support and a multi-tier cache. This design decreases the time spent waiting for data.

```mermaid
graph TD
    User[User Script] --> Session[tif1 Session]
    Session --> MemCache[Memory LRU Cache]
    MemCache -- Miss --> SQLite[SQLite Persistent Cache]
    SQLite -- Miss --> CDN[CDN Manager]
    CDN --> JS[jsDelivr Primary]
    CDN --> HF[Hugging Face Fallback]
    CDN --> SD[StaticDelivr Backup]
    JS -- Data --> SQLite
    HF -- Data --> SQLite
    SD -- Data --> SQLite
    SQLite -- Data --> MemCache
    MemCache -- Data --> Session
```

## Data Available

- Lap times and sectors (S1, S2, S3). `LapTime` is a Timedelta on pandas and float seconds on polars. `LapTimeSeconds` is float seconds on both.
- Tire compounds and stint information
- Telemetry: speed, throttle, brake, RPM, gear, and DRS as a 0/1 flag
- Position data (X, Y, Z coordinates)
- Acceleration data (X, Y, Z axes)
- Weather data automatically included in laps
- Driver metadata with team colors and headshots
- Race control messages
