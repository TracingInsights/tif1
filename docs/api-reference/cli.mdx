# CLI Reference

The `tif1` CLI provides a command-line interface for exploring Formula 1 data from the terminal. It is built with [Typer](https://typer.tiangolo.com/) for argument parsing. It uses [Rich](https://rich.readthedocs.io/) for colorful terminal output with tables and progress indicators. The CLI requires no configuration.

## What is the tif1 CLI?

The tif1 CLI is a command-line tool. It gives access to Formula 1 data without writing Python code. It is designed for data analysts, F1 enthusiasts, and developers. It serves anyone who wants to explore F1 data from the terminal.

The CLI has exactly eight commands: `events`, `sessions`, `drivers`, `fastest`, `cache-info`, `cache-clear`, `version`, and `debug`.

**Key Features:**

- **Zero Configuration**: Works out of the box after installation
- **Rich Terminal Output**: Color-coded tables with Unicode borders
- **Automatic Caching**: SQLite cache speeds up repeated queries
- **Progress Indicators**: A progress bar while a session loads
- **Cross-Platform**: Works on Linux, macOS, and Windows
- **Scriptable**: Exit codes for scripts, and output without color codes when piped
- **Shared Configuration**: Reads the same environment variables and `.tif1rc` file as the Python API

## Overview

The CLI is designed for multiple use cases and user personas:

### Use Cases

1. **Quick Data Exploration**
   - View race calendars, session lists, driver lineups, and fastest laps
   - No Python code required - type a command and see the result
   - Explore names and data before writing analysis code

2. **Debugging & Development**
   - Check that a session loads
   - Troubleshoot issues with debug logging
   - Identify network issues and cache behavior

3. **Cache Management**
   - Show the cache location, file count, and size
   - Clear the cache to force fresh downloads

4. **Scripting & Automation**
   - Integrate F1 data into shell scripts and automation workflows
   - Build CI/CD jobs that depend on F1 data
   - Branch on exit codes

5. **Learning & Discovery**
   - Understand F1 data hierarchy (seasons → events → sessions → drivers)
   - Learn event naming conventions and session types
   - Discover what data is available before committing to analysis

6. **Performance Analysis**
   - Compare fastest laps across sessions and drivers
   - Track driver performance throughout a race weekend
   - Compare qualifying and race pace

7. **Data Validation**
   - Check driver participation in sessions
   - Check the lap count of a session with `debug`

### Who Should Use the CLI?

- **Data Analysts**: Quick data exploration and validation
- **F1 Enthusiasts**: Instant access to race data and statistics
- **Developers**: Testing and debugging data pipelines
- **DevOps Engineers**: Automation and monitoring scripts
- **Researchers**: Data collection for academic studies
- **Journalists**: Quick fact-checking and statistics lookup
- **Content Creators**: Gathering data for articles, videos, or social media

### Performance Characteristics

- **Fast Startup**: Commands import pandas and Rich only when they need them, so `tif1 version` returns at once
- **Cached Requests**: A cached session loads in under 1 second (local SQLite read)
- **First Request**: The time depends on the network. Data comes from jsDelivr, with Hugging Face and StaticDelivr as fallbacks.
- **Concurrent Safe**: Multiple CLI instances can run at the same time. The SQLite cache runs in WAL mode.

## Installation

The CLI is included with every tif1 installation. Typer and Rich are core dependencies of tif1, so no extra packages are necessary.

### Standard Installation

Install tif1 using pip (Python 3.11 or higher required):

```bash
pip install tif1
```

After installation, the `tif1` command is available in the terminal of that Python environment. The CLI and the Python API share the installation, the cache, and the configuration.

### Installation Methods

**1. System-Wide Installation** (requires admin/sudo):
```bash
# Linux/macOS
sudo pip install tif1

# Windows (run as Administrator)
pip install tif1
```

**2. User Installation** (recommended for non-admin users):
```bash
pip install --user tif1
```

**3. Virtual Environment** (recommended for development):
```bash
# Create virtual environment
python -m venv venv

# Activate virtual environment
# Linux/macOS:
source venv/bin/activate
# Windows:
venv\Scripts\activate

# Install tif1
pip install tif1
```

**4. Development Installation** (from source):
```bash
# Clone repository
git clone https://github.com/TracingInsights/tif1.git
cd tif1

# Install with uv (recommended)
uv sync --all-extras

# Or install with pip
pip install -e .
```

### Verify Installation

Confirm the CLI is installed correctly and check the version:

```bash
tif1 version
```

**Expected output:**
```text
tif1 version 0.11.1
```

If the command is not found, troubleshoot using these steps:

1. **Check Python Environment**:
   ```bash
   # Verify Python version (3.11+ required)
   python --version

   # Check if tif1 is installed
   pip show tif1
   ```

2. **Verify PATH Configuration**:
   ```bash
   # Linux/macOS - check if Python scripts directory is in PATH
   echo $PATH | grep -o "[^:]*python[^:]*"

   # Windows - check PATH
   echo %PATH%
   ```

3. **Locate tif1 Executable**:
   ```bash
   # Linux/macOS
   which tif1

   # Windows
   where tif1
   ```

4. **Common Issues**:
   - **Virtual environment not activated**: Run `source venv/bin/activate` (Linux/macOS) or `venv\Scripts\activate` (Windows)
   - **User installation PATH issue**: Add `~/.local/bin` (Linux/macOS) or `%APPDATA%\Python\Scripts` (Windows) to PATH
   - **Permission issues**: Use `pip install --user tif1` instead of system-wide installation

### Upgrading

To upgrade to the latest version:

```bash
# Upgrade to latest version
pip install --upgrade tif1

# Verify new version
tif1 version
```

### Uninstallation

To remove tif1:

```bash
# Uninstall tif1
pip uninstall tif1

# Optionally remove cache
rm -rf ~/.cache/tif1  # Linux
# or
rmdir /s "%LOCALAPPDATA%\Temp\tif1"  # Windows
```

## Getting Started

### First Commands

Walk through a complete workflow from discovering events to analyzing lap times:

**Step 1: Discover Available Events**

Start by listing all events in a season to see what data is available:

```bash
tif1 events 2025
```

This shows all events of 2025, testing included. Note the exact event names for the next commands.

**Step 2: Check Event Sessions**

Pick an event and see what sessions are available:

```bash
tif1 sessions 2025 "Monaco Grand Prix"
```

This displays all sessions (Practice 1-3, Qualifying, Race) for Monaco. Note that sprint weekends have different session structures.

**Step 3: View Participating Drivers**

See which drivers participated in a specific session:

```bash
tif1 drivers 2025 "Monaco Grand Prix" "Qualifying"
```

This loads the session data and displays all drivers with their teams and car numbers. The first run fetches data from the network. Later runs read the SQLite cache and are faster.

**Step 4: Analyze Lap Times**

View fastest lap times for all drivers:

```bash
tif1 fastest 2025 "Monaco Grand Prix" "Qualifying"
```

Or check a specific driver's fastest lap:

```bash
tif1 fastest 2025 "Monaco Grand Prix" "Qualifying" --driver VER
```

**Step 5: Manage Cache**

Check the cache size and location:

```bash
tif1 cache-info
```

Clear cache if needed:

```bash
tif1 cache-clear --yes
```

### Understanding the Data Hierarchy

F1 data in tif1 follows a clear hierarchy:

```text
Season (Year)
  └── Event (Grand Prix)
      └── Session (Practice, Qualifying, Race)
          └── Driver (3-letter code)
              └── Laps (individual lap data)
```

**Example Navigation:**
```bash
# Season level
tif1 events 2025

# Event level
tif1 sessions 2025 "Monaco Grand Prix"

# Session level
tif1 drivers 2025 "Monaco Grand Prix" "Qualifying"
tif1 fastest 2025 "Monaco Grand Prix" "Qualifying"

# Driver level
tif1 fastest 2025 "Monaco Grand Prix" "Qualifying" --driver VER
```

## Global Usage Pattern

```bash
tif1 [OPTIONS] COMMAND [ARGS]...
```

All commands follow a consistent, predictable pattern:

- **OPTIONS**: Options before the command are `--help`, `--install-completion`, and `--show-completion` only
- **COMMAND**: The action to perform (for example, `events`, `sessions`, `drivers`, `fastest`)
- **ARGS**: Positional arguments in a fixed order (year, event, session), then command options such as `--driver` or `--yes`

### Command Structure

Commands are organized hierarchically by data granularity:

1. **Season Level**: `events` - Lists all events in a season
2. **Event Level**: `sessions` - Lists all sessions in an event
3. **Session Level**: `drivers`, `fastest` - Analyzes data within a session
4. **Utility Commands**: `cache-info`, `cache-clear`, `version`, `debug` - Management and debugging

### Getting Help

Every command has built-in help documentation:

```bash
# General help - lists all commands
tif1 --help

# Command-specific help
tif1 events --help
tif1 fastest --help
tif1 cache-clear --help
```

The help output shows:
- Command description
- Arguments with their types and a `[required]` marker
- Options with their short forms

```text
 Usage: tif1 fastest [OPTIONS] {year} {event} {session}

 Show fastest laps.

╭─ Arguments ──────────────────────────────────────────────────────╮
│ *    year         <int>  Year (1950-current) [required]          │
│ *    event        <str>  Event name [required]                   │
│ *    session      <str>  Session name [required]                 │
╰──────────────────────────────────────────────────────────────────╯
╭─ Options ────────────────────────────────────────────────────────╮
│ --driver  -d      <str>  Specific driver                         │
│ --help                   Show this message and exit.             │
╰──────────────────────────────────────────────────────────────────╯
```

### Command Naming Conventions

- Commands use lowercase with hyphens for multi-word names (for example, `cache-info`, `cache-clear`)
- Arguments use natural language names (for example, `year`, `event`, `session`)
- Options use double dashes for long form (`--driver`) and single dash for short form (`-d`)

## Core Concepts

Understanding these core concepts helps with effective CLI use and helps avoid common pitfalls.

### Event Names

Event names are the official Grand Prix names as they appear in the FIA Formula 1 World Championship calendar. The CLI resolves a name like `tif1.get_event_by_name()`. It tries a case-insensitive exact name first, then the alias table ("Monza", "Silverstone"), then fuzzy matching. The alias table holds circuit, city, and country names. A fuzzy match needs a score of at least 70 and logs `Correcting user input '...' to '...'`. A name below that score fails with `EventNotFoundError`. The official name is the safest input.

**Standard Event Name Format:**

Most events follow the pattern: `"[Location] Grand Prix"`

Examples:
- "Monaco Grand Prix"
- "British Grand Prix"
- "Italian Grand Prix"
- "Japanese Grand Prix"
- "Australian Grand Prix"

**Special Event Names:**

Some events have unique naming conventions:

- "São Paulo Grand Prix" (note the special character ã)
- "United States Grand Prix" (not "US Grand Prix")
- "Emilia Romagna Grand Prix" (not "Imola Grand Prix")
- "Mexico City Grand Prix" (not "Mexican Grand Prix")
- "Las Vegas Grand Prix" (not "Vegas Grand Prix")
- "Saudi Arabian Grand Prix" (not "Saudi Grand Prix")

**Why Official Names Help:**

The `drivers`, `fastest`, and `debug` commands resolve the name through `tif1.get_session()`. The `sessions` command resolves it through `tif1.get_sessions()`. Variants resolve to the same event, but a typo can resolve to a different race without an error:

```bash
# These all resolve to the Monaco Grand Prix or the São Paulo Grand Prix
tif1 sessions 2025 "Monaco GP"
tif1 sessions 2025 "monaco grand prix"
tif1 sessions 2025 "Sao Paulo Grand Prix"

# Official names need no resolution step
tif1 sessions 2025 "Monaco Grand Prix"
tif1 sessions 2025 "São Paulo Grand Prix"
```

The table titles of `sessions`, `drivers`, and `fastest` repeat the name as typed, not the resolved name.

**Shell Quoting Rules:**

Always use quotes around event names with spaces. The shell interprets unquoted spaces as argument separators:

```bash
# ❌ WRONG - the shell passes "Monaco", "Grand", and "Prix" as separate arguments
tif1 sessions 2025 Monaco Grand Prix
# Error: Got unexpected extra argument(s) (Grand Prix)

# ✅ CORRECT - Quotes preserve the full name
tif1 sessions 2025 "Monaco Grand Prix"
```

**Finding Exact Event Names:**

Always use the `events` command to get the exact event names:

```bash
# List all events for a year
tif1 events 2025

# Find specific event (Linux/macOS)
tif1 events 2025 | grep -i monaco

# Find specific event (Windows PowerShell)
tif1 events 2025 | Select-String -Pattern "monaco" -CaseSensitive:$false
```

**Copy-Paste Workflow:**

The safest approach is to copy event names directly from the `events` output:

```bash
# Step 1: List events
tif1 events 2025

# Step 2: Copy exact name from output (e.g., "Monaco Grand Prix")

# Step 3: Paste into next command
tif1 sessions 2025 "Monaco Grand Prix"
```

### Session Names

Session names identify specific track sessions within an event. They are case-insensitive, and the abbreviations `FP1`, `FP2`, `FP3`, `Q`, `S`, `SS`, `SQ`, and `R` also work. Session names do not use fuzzy matching.

**Standard Weekend Format:**

Traditional race weekends have 5 sessions:

1. "Practice 1"
2. "Practice 2"
3. "Practice 3"
4. "Qualifying"
5. "Race"

**Sprint Weekend Format:**

Sprint weekends from 2024 have a different structure:

1. "Practice 1"
2. "Sprint Qualifying"
3. "Sprint"
4. "Qualifying"
5. "Race"

Earlier sprint weekends differ. The 2023 weekends have "Sprint Shootout" in place of "Sprint Qualifying". The 2021 and 2022 weekends have "Practice 1", "Qualifying", "Practice 2", "Sprint", and "Race".

**Session Name Variations:**

- Practice sessions: "Practice 1", "Practice 2", "Practice 3" (note the space)
- Qualifying: "Qualifying" or "Q" (not "Quali")
- Sprint qualifying: "Sprint Qualifying" (two words)
- Sprint race: "Sprint" (not "Sprint Race")
- Main race: "Race" (not "Grand Prix" or "Main Race")

**Common Mistakes:**

```bash
# ❌ WRONG (ValueError: Session '...' does not exist for 2025 Monaco Grand Prix.)
tif1 drivers 2025 "Monaco Grand Prix" "Quali"            # Use "Qualifying" or "Q"
tif1 drivers 2025 "Monaco Grand Prix" "Sprint Race"      # Use "Sprint" (sprint weekends only)
tif1 drivers 2025 "Monaco Grand Prix" "P1"               # Use "Practice 1" or "FP1"

# ✅ CORRECT
tif1 drivers 2025 "Monaco Grand Prix" "Practice 1"
tif1 drivers 2025 "Monaco Grand Prix" "FP1"
tif1 drivers 2025 "Monaco Grand Prix" "practice 1"
tif1 drivers 2025 "Monaco Grand Prix" "Qualifying"
```

**Discovering Available Sessions:**

Always use the `sessions` command to see what sessions are available for an event:

```bash
# Check available sessions
tif1 sessions 2025 "Monaco Grand Prix"

# Output shows exact session names to use
```

**Sprint Weekend Detection:**

To check if an event is a sprint weekend:

```bash
# List sessions
tif1 sessions 2025 "São Paulo Grand Prix"

# A sprint weekend lists a "Sprint" session
```

### Data Loading & Caching

The CLI implements caching to optimize performance and reduce network requests.

**Cache Architecture:**

```text
User Request
    ↓
Cache Check (SQLite)
    ↓
├─ Cache Hit → Return Data
└─ Cache Miss → Fetch from CDN → Parse JSON → Cache → Return Data
```

**First Request (Cache Miss):**

When data is requested for the first time:

1. **Cache Lookup**: CLI checks local SQLite cache
2. **Network Fetch**: Data is downloaded from the CDN (jsDelivr primary; Hugging Face and StaticDelivr fallbacks)
3. **JSON Parsing**: Raw JSON is parsed into structured data
4. **DataFrame Creation**: Data is converted to pandas/polars DataFrame
5. **Cache Write**: The payloads and the built lap table are stored in the cache
6. **Return**: Data is displayed to user

The time of a first request depends on the network and on the CDN.

**Subsequent Requests (Cache Hit):**

When the same data is requested again:

1. **Cache Lookup**: CLI checks local SQLite cache
2. **Cache Read**: Data is loaded from disk
3. **Deserialization**: Cached data is reconstructed
4. **Return**: Data is displayed to user

A cached `tif1 fastest` run finishes in under a second.

**Performance Benefit:**

```bash
# First run (cache miss): the time depends on the network
time tif1 fastest 2025 "Monaco Grand Prix" "Qualifying"

# Second run (cache hit): under a second
time tif1 fastest 2025 "Monaco Grand Prix" "Qualifying"
```

**Cache Location:**

Cache location is platform-specific:

| Platform | Default Location | Override Environment Variable |
|----------|------------------|------------------------------|
| **Linux** | `~/.cache/tif1` (`~/.tif1` if `~/.cache` does not exist) | `$TIF1_CACHE_DIR` |
| **macOS** | `~/Library/Caches/tif1` | `$TIF1_CACHE_DIR` |
| **Windows** | `%LOCALAPPDATA%\Temp\tif1` | `%TIF1_CACHE_DIR%` |

**Custom Cache Location:**

Override the default cache location:

```bash
# Set custom cache directory
export TIF1_CACHE_DIR="/path/to/custom/cache"

# Verify new location
tif1 cache-info
```

**Cache Persistence:**

- Cache persists across CLI runs
- Cache survives system reboots
- Cache is shared across all CLI commands
- Cache is shared with the Python API: both use `tif1.get_cache()` and the same directory

**Cache Invalidation:**

Cached session data does not expire. Two kinds of entries expire:

- The live schedule of the current season. tif1 downloads it again after `schedule_ttl_hours` (default 6).
- The record of a file that no CDN has. It expires after `missing_payloads_ttl_days` (default 7).

To force fresh data:

```bash
# Clear entire cache
tif1 cache-clear --yes

# Or delete cache directory manually
rm -rf ~/.cache/tif1  # Linux
```

**Cache Size Management:**

Monitor cache growth:

```bash
# Check cache size
tif1 cache-info
```

**Cache Behavior:**

- Each session is cached independently
- Different data types (laps, telemetry) are cached separately
- Cache keys include year, event, session, and data type
- Cache is SQLite-based (ACID compliant, crash-safe)

**Disabling Cache:**

For testing or debugging, disable caching. With `TIF1_ENABLE_CACHE=false`, the data commands do not read or write the SQLite cache.

```bash
# Disable cache for single command
TIF1_ENABLE_CACHE=false tif1 fastest 2025 "Monaco Grand Prix" "Qualifying"

# Disable cache globally
export TIF1_ENABLE_CACHE=false
tif1 fastest 2025 "Monaco Grand Prix" "Qualifying"
```

### Output Formatting

The CLI uses the Rich library for colorful terminal output with structured formatting.

**Table Components:**

1. **Title**: The arguments as typed (event name, year, and session)
2. **Headers**: Column names
3. **Borders**: Unicode box-drawing characters
4. **Data Rows**: Color-coded values
5. **Summary**: `events` and `drivers` print a `Total:` line

**Color Scheme:**

- **Cyan**: Row numbers, driver codes in `drivers`, positions in `fastest`, progress text
- **Green**: Event, session, and team names, success messages, the single-driver lap time
- **Yellow**: Driver codes in `fastest`, the `Cache clear cancelled` message
- **Magenta**: Lap times in `fastest`, car numbers in `drivers`
- **Red**: The `No valid laps for <code>` message
- **Bold**: Labels such as `Total:` and `Cache location:`

**Table Example:**

```text
  Fastest Laps - Monaco Grand Prix 2025 -
                 Qualifying
┏━━━━━┳━━━━━━━━┳━━━━━━━━━━━━━━━━━┳━━━━━━━━━┓
┃ Pos ┃ Driver ┃ Team            ┃ Time    ┃
┡━━━━━╇━━━━━━━━╇━━━━━━━━━━━━━━━━━╇━━━━━━━━━┩
│ 1   │ NOR    │ McLaren         │ 69.954s │
│ 2   │ LEC    │ Ferrari         │ 70.063s │
│ 3   │ PIA    │ McLaren         │ 70.129s │
└─────┴────────┴─────────────────┴─────────┘
```

Rich wraps a table title that is wider than the table.

**Progress Indicators:**

The `drivers`, `fastest`, and `debug` commands show a progress bar while the session loads:

```text
Loading session... ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 100% 0:00:00
```

**Terminal Compatibility:**

- **Unicode Support**: Uses Unicode box-drawing characters
- **Color Support**: Automatically detects terminal color capabilities
- **Width Adaptation**: Tables adapt to terminal width

**Piping Behavior:**

When output is piped, Rich drops the color codes and keeps the box-drawing characters. The progress bar prints once, as the first line.

```bash
# Pipe to file
tif1 fastest 2025 "Monaco Grand Prix" "Qualifying" > results.txt

# Pipe to grep
tif1 fastest 2025 "Monaco Grand Prix" "Qualifying" | grep "VER"

# Pipe to less
tif1 fastest 2025 "Monaco Grand Prix" "Qualifying" | less
```

**Plain Text Extraction:**

Data rows contain the `│` character. Header rows use `┃`, so a filter on `│` keeps only the data rows:

```bash
# Driver codes, one per line
tif1 drivers 2025 "Monaco Grand Prix" "Race" | awk '/│/ {print $2}'

# Driver code and team, comma-separated
tif1 drivers 2025 "Monaco Grand Prix" "Race" | \
```

## Error Handling & Troubleshooting

When a command fails, Typer prints a Rich traceback. The last line names the exception and its message. The exit code is `1`.

### Common Error Messages

**1. Unknown Event Name**

```bash
$ tif1 sessions 2025 "Not A Grand Prix"
EventNotFoundError: No event matching 'Not A Grand Prix' in 2025
```

**Cause**: The name resembles no event of the season (fuzzy score below 70). A typo such as "Monacco" still resolves, with a `Correcting user input` warning.
**Solution**: Use `tif1 events 2025` to find the exact event name.

**2. Event Not on the Calendar**

```bash
$ tif1 drivers 2025 "Sochi" "Race"
EventNotInSeasonError: 'Sochi' refers to the Russian Grand Prix, which is not on the 2025 calendar
```

**Cause**: The name is an alias of an event that is not in that season.
**Solution**: Use `tif1 events 2025` to see the events of the season.

**3. Session Not Found**

```bash
$ tif1 drivers 2025 "Monaco Grand Prix" "Sprint"
ValueError: Session 'Sprint' does not exist for 2025 Monaco Grand Prix.
Available sessions: Practice 1, Practice 2, Practice 3, Qualifying, Race
```

**Cause**: The event does not have that session.
**Solution**: Use `tif1 sessions 2025 "Monaco Grand Prix"` to find exact session names.

**4. Driver Not Found**

```bash
$ tif1 fastest 2025 "Monaco Grand Prix" "Race" --driver ABC
DriverNotFoundError: Driver 'ABC' not found in session
```

**Cause**: Invalid driver code, wrong case, or driver did not participate.
**Solution**: Use `tif1 drivers 2025 "Monaco Grand Prix" "Race"` to see available drivers.

**5. Network Failure**

The message has the form `Network request failed: url='<url>'`. It ends with `status=<code>` when the server sent a response.

**Cause**: Slow network connection or CDN unavailable.
**Solution**:
- Check internet connection
- Increase timeout: `TIF1_TIMEOUT=60 tif1 fastest ...`
- Try again later

**6. Data Not Available**

```bash
$ tif1 drivers 2026 "Abu Dhabi Grand Prix" "Race"
DataNotFoundError: Data not found: year=2026, event='Abu Dhabi Grand Prix', session='Race'
```

**Cause**: The session has not taken place yet, or its data is not published. tif1 raises `DataNotFoundError` only when every CDN returns 404.
**Solution**: Check if event has taken place and data is available.

**7. Usage Errors**

Missing or invalid arguments exit with code `2`. Typer prints the usage line and the error, for example `Missing argument 'year'.` or `Invalid value for 'year': 'abc' is not a valid int.`

### `cache-info` - Display Cache Statistics

Show information about the tif1 cache: location, file count, and size.

**Syntax:**
```bash
tif1 cache-info
```

**Arguments:**
None

**Description:**

The `cache-info` command provides a summary of the local tif1 cache. The cache stores downloaded F1 data to speed up subsequent requests. This is useful for monitoring cache growth, troubleshooting storage issues, and understanding cache behavior.

**Output Format:**

The command displays:
- **Cache location**: Full filesystem path to the cache directory
- **Cache files**: Number of `cache.sqlite*` files. If none exists, the command counts every file in the directory.
- **Total size**: Combined size of these files in megabytes (MB)

**Examples:**

```bash
# Check cache information
tif1 cache-info
```

**Sample Output (Linux):**
```text
Cache location: /home/user/.cache/tif1
Cache files: 3
Total size: 245.67 MB
```

**Sample Output (Windows):**
```text
Cache location: C:\Users\user\AppData\Local\Temp\tif1
Cache files: 3
Total size: 512.34 MB
```

**Sample Output (macOS):**
```text
Cache location: /Users/user/Library/Caches/tif1
Cache files: 3
Total size: 128.45 MB
```

**Use Cases:**
- **Monitor cache growth**: Check how much disk space the cache is using
- **Troubleshoot performance**: Verify cache is being used
- **Storage management**: Identify if cache needs clearing
- **Debugging**: Confirm cache location for manual inspection
- **Documentation**: Record cache paths for team documentation

**Cache Location by Platform:**

| Platform | Default Cache Location |
|----------|------------------------|
| **Linux/other POSIX** | `~/.cache/tif1` (or `~/.tif1` if `~/.cache` doesn't exist) |
| **macOS** | `~/Library/Caches/tif1` |
| **Windows** | `%LOCALAPPDATA%\Temp\tif1` |

**Cache Structure:**

The cache directory contains:
- `cache.sqlite`: Main SQLite database file
- `cache.sqlite-wal`: Write-Ahead Log file (WAL mode)
- `cache.sqlite-shm`: Shared memory file (WAL mode)

The WAL and SHM files exist while a process has the database open. The `cache-info` command opens it too, so it usually counts 3 files.

**Understanding Cache Size:**

Cache size grows based on:
- **Number of sessions loaded**: Each session adds lap data, telemetry, etc.
- **Data types requested**: Telemetry data is larger than lap times
- **Historical data**: Older seasons accumulate over time

**Custom Cache Location:**

The default cache location can be overridden using the `TIF1_CACHE_DIR` environment variable:

```bash
# Set custom cache location
export TIF1_CACHE_DIR="/path/to/custom/cache"
tif1 cache-info
```

**Troubleshooting:**

If cache size seems incorrect:
1. Check for multiple cache locations (environment variable override)
2. Verify disk space availability
3. Check file permissions on cache directory
4. Consider clearing cache if corrupted: `tif1 cache-clear`

**Related Commands:**
- `tif1 cache-clear`: Clear all cached data
- Environment variable `TIF1_CACHE_DIR`: Override cache location
- Environment variable `TIF1_ENABLE_CACHE`: Stop the data commands from using the cache

### `cache-clear` - Clear Cache Database

`--ergast` clears only the Ergast tier (the Stats repository files and the Jolpica answers) and keeps the timing and telemetry payloads.

Delete all cached data to force fresh data fetches.

**Syntax:**
```bash
tif1 cache-clear [OPTIONS]
```

**Options:**

| Option | Short | Type | Description |
|--------|-------|------|-------------|
| `--yes` | `-y` | Flag | Skip confirmation prompt and clear immediately |

**Description:**

The `cache-clear` command removes all cached Formula 1 data from the local cache database. This is useful when:

- **Forcing fresh data**: Suspect cached data is stale or corrupted
- **Troubleshooting**: Debugging cache-related issues
- **Testing**: Measuring cold-start performance
- **Data updates**: Ensuring the latest data comes from the CDN

**Important**: Clearing the cache means all subsequent data requests need a network fetch. These requests are slower until the cache is rebuilt.

**Interactive Mode** (default):

By default, the command asks for confirmation before clearing:

```bash
tif1 cache-clear
```

**Sample Output:**
```text
Are you sure you want to clear the cache? [y/N]: y
Cache cleared successfully!
```

If the answer is 'n' or Enter is pressed (default is No):

```text
Are you sure you want to clear the cache? [y/N]: n
Cache clear cancelled
```

**Non-Interactive Mode** (`--yes` flag):

Skip the confirmation prompt for scripting or automation:

```bash
tif1 cache-clear --yes
```

**Sample Output:**
```text
Cache cleared successfully!
```

**Short Form:**

```bash
tif1 cache-clear -y
```

**Use Cases:**

1. **Force Data Refresh**:
   ```bash
   # Clear cache to get latest data
   tif1 cache-clear -y
   # Reload session with fresh data
   tif1 fastest 2025 "Monaco Grand Prix" "Qualifying"
   ```

2. **Automated Scripts**:
   ```bash
   #!/bin/bash
   # Clear cache before daily analysis
   tif1 cache-clear --yes
   # Run analysis commands...
   ```

3. **Troubleshooting**:
   ```bash
   # If seeing errors or unexpected data
   tif1 cache-clear -y
   tif1 debug 2025 "Monaco Grand Prix" "Race"
   ```

**What Gets Cleared:**

The command deletes the rows of every cache table:
- Cached JSON payloads (drivers, laps, weather, messages, and the downloaded live schedule)
- Cached telemetry payloads
- Built lap and telemetry tables
- The records of files that no CDN has

**What Does not Get Cleared:**

- The cache directory and the `cache.sqlite` file. The file keeps its size, and SQLite reuses the free pages for new data. To get the disk space back, delete the cache directory.
- Configuration files (`.tif1rc`)
- The schedule files that ship with tif1

**Performance Impact:**

After clearing cache:
- **First data load**: Network fetch
- **Subsequent loads**: Under 1 second (cached)
- **Cache rebuild**: Automatic as commands are used

**Safety Notes:**

- **No data loss**: Only cached data is removed; original data remains on CDN
- **Reversible**: Cache rebuilds automatically as the CLI is used
- **No configuration changes**: Configuration settings remain intact
- **Safe to interrupt**: Can be cancelled with Ctrl+C before confirmation

**Exit Codes:**

- `0`: Cache cleared, or clear cancelled with an answer other than `y`
- `1`: Prompt interrupted with Ctrl+C or end of input (prints `Aborted.`), or an error during clearing

**Related Commands:**

- `tif1 cache-info`: Check cache size before clearing
- Environment variable `TIF1_CACHE_DIR`: Custom cache location

### `debug` - Debug Session Loading

**Arguments:**

| Argument | Type | Required | Description |
|----------|------|----------|-------------|
| `YEAR` | Integer | Yes | Season year (1950-current; timing and telemetry from 2018) |
| `EVENT` | String | Yes | Event name (use quotes for multi-word names) |
| `SESSION` | String | Yes | Session name (use quotes for multi-word names) |

**Description:**

The `debug` command calls `tif1.setup_logging(logging.DEBUG)` and loads the session. Then it prints the driver count and the lap count. This is useful for:

- **Troubleshooting**: Diagnose why data is not loading correctly
- **Network Issues**: Identify connection problems or timeouts
- **Cache Behavior**: Verify cache hits and cache writes

- CDN request URLs

**Debug Output Details:**

Each log line has the form `<date> <time> - <logger> - <level> - <message>`. The output includes:

- **Timestamps**: Date and time to the second
- **Logger names**: For example `tif1.cdn`, `tif1.cache`, `tif1.async_fetch`
- **URLs**: Full CDN URLs being fetched
- **Cache operations**: SQLite hits, frame-tier hits, and writes
- **Errors**: Full stack traces for failures

**Logging Levels:**

The `debug` command sets logging to DEBUG level, which shows:
- DEBUG: Detailed internal operations
- INFO: General information messages
- WARNING: Potential issues
- ERROR: Failures and exceptions

**Output Destination:**

Debug output goes to:
- **stdout**: The progress bar and the summary (`Session loaded successfully!`, driver and lap counts)
- **stderr**: All log lines

This allows separating debug info from actual data:

```bash
# Capture only debug logs
tif1 debug 2025 "Monaco Grand Prix" "Race" 2> debug.log

# Capture only output
tif1 debug 2025 "Monaco Grand Prix" "Race" 2>/dev/null
```

**Comparison with Normal Commands:**

| Aspect | Normal Command | Debug Command |
|--------|---------------|---------------|
| **Logging** | Warnings and errors only | All levels from DEBUG |
| **Output** | Tables | Log lines + summary |
| **Use Case** | Production use | Troubleshooting |

**Important Notes:**

- Output can be verbose (dozens of lines for a cold load)
- URLs and file paths appear in the log
- Not recommended for production scripts (use normal commands)

**Exit Codes:**

- `0`: Session loaded successfully
- `1`: Error loading session (network, data, cache issues)

**Related Commands:**

- `tif1 drivers`: Normal driver listing (no debug output)
- `tif1 fastest`: Normal fastest lap listing (no debug output)

## Tips & Best Practices

### General Tips

1. **Always use quotes for multi-word names**:
   ```bash
   # ✅ Correct
   tif1 sessions 2025 "Monaco Grand Prix"

   tif1 sessions 2025 Monaco Grand Prix
   ```

   ```bash
   tif1 ev<TAB>        # Completes to: tif1 events
   ```

   ```bash
   tif1 --help              # List all commands
   tif1 fastest --help      # Command-specific help
   ```

   ```bash
   # Always check exact event name
   tif1 events 2025
   # Then use exact name from output
   tif1 sessions 2025 "Monaco Grand Prix"
   ```

   ```bash
   tif1 fastest 2025 "Monaco Grand Prix" "Qualifying" -d VER  # Faster to type

   ```

## Environment Variables

The CLI respects the same environment variables as the Python API for consistent behavior across interfaces:

### Available Environment Variables

| Variable | Type | Default | Description |
|----------|------|---------|-------------|
| `TIF1_CACHE_DIR` | Path | Platform-specific | Override cache directory location |
| `TIF1_LIB` | String | `pandas` | Set default DataFrame library (`pandas` or `polars`) |
| `TIF1_ENABLE_CACHE` | Boolean | `true` | Enable/disable caching globally |
| `TIF1_TIMEOUT` | Integer | `30` | Network timeout in seconds |
| `TIF1_MAX_RETRIES` | Integer | `3` | Maximum retry attempts for failed requests |

Use the `debug` command for debug logs. See the [environment variables reference](/reference/environment-variables) for the full list.

### Configuration File

For persistent settings, tif1 reads a JSON file named `.tif1rc` in the home directory. The keys are the lowercase configuration names, such as `cache_dir` for `TIF1_CACHE_DIR`:

```json
{
  "cache_dir": "/home/user/tif1-cache",
  "lib": "pandas",
  "timeout": 30,
  "max_retries": 3
}
```

`TIF1_CONFIG_FILE` points tif1 to another file. A `.tif1rc` in the working directory is read only when `TIF1_TRUST_CWD_CONFIG=true`.

Shell profiles can also hold the variables:

**Linux/macOS (~/.bashrc or ~/.zshrc):**

```bash
# tif1 CLI Configuration
export TIF1_CACHE_DIR="$HOME/.cache/tif1"
export TIF1_LIB="pandas"
export TIF1_TIMEOUT=30
export TIF1_MAX_RETRIES=3
```

**Windows PowerShell ($PROFILE):**

```powershell
# tif1 CLI Configuration
$env:TIF1_CACHE_DIR = "$env:USERPROFILE\.cache\tif1"
$env:TIF1_LIB = "pandas"
$env:TIF1_TIMEOUT = 30
$env:TIF1_MAX_RETRIES = 3
```

### Environment Variable Precedence

When multiple configuration sources exist, precedence is:

1. **Environment variable** (highest priority), set for one command or exported in the shell
   ```bash
   TIF1_TIMEOUT=60 tif1 fastest 2025 "Monaco Grand Prix" "Qualifying"
   ```

2. **Configuration file** (`.tif1rc`, JSON)

3. **Default value** (lowest priority)

## Advanced Topics

### Performance Optimization

**1. Parallel Processing**

Process multiple sessions simultaneously:

```bash
# Using GNU parallel
parallel tif1 fastest 2025 "Monaco Grand Prix" {} ::: \
    "Practice 1" "Practice 2" "Practice 3" "Qualifying" "Race"

# Using bash background jobs
tif1 fastest 2025 "Monaco Grand Prix" "Practice 1" > p1.txt &
tif1 fastest 2025 "Monaco Grand Prix" "Practice 2" > p2.txt &
tif1 fastest 2025 "Monaco Grand Prix" "Practice 3" > p3.txt &
wait
```

**2. Cache Warming**

Pre-populate cache for faster subsequent access:

```bash
#!/bin/bash
# warm_cache.sh - Pre-load common sessions

YEAR=2025
EVENTS=("Monaco Grand Prix" "British Grand Prix" "Italian Grand Prix")
SESSIONS=("Practice 1" "Practice 2" "Practice 3" "Qualifying" "Race")

for event in "${EVENTS[@]}"; do
    for session in "${SESSIONS[@]}"; do
        echo "Caching: $event - $session"
        tif1 fastest $YEAR "$event" "$session" > /dev/null 2>&1
    done
done

echo "Cache warming complete!"
tif1 cache-info
```

**3. Batch Processing**

Process multiple events efficiently:

```bash
#!/bin/bash
# batch_process.sh

YEAR=2025

# Get the Grand Prix names (testing excluded) from the Python API, one per line
python -c "import tif1; print('\n'.join(tif1.get_event_schedule($YEAR, include_testing=False)['EventName']))" |
while IFS= read -r event; do
    echo "Processing: $event"
    tif1 fastest $YEAR "$event" "Qualifying" > "results_${event// /_}.txt"
done
```

### Security Considerations

**1. Cache Security**

tif1 creates the cache directory with mode `0o700` (owner only). Check the permissions:

```bash
ls -ld ~/.cache/tif1
```

**2. Network Security**

All data requests use HTTPS:

```bash
# Verify CDN uses HTTPS
tif1 debug 2025 "Monaco Grand Prix" "Race" 2>&1 | grep "https://"
```

The HTTP session sets `trust_env = False`, so no request pays for environment lookups. The proxies are resolved once when the session is created. That covers the `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY` variables on every platform, and the system proxy setting on Windows. Set the variables before the first request.

**3. Input Validation**

Sanitize user input in scripts:

```bash
#!/bin/bash
# Validate year input
if ! [[ "$1" =~ ^[0-9]{4}$ ]]; then
    echo "Error: Invalid year format"
    exit 1
fi

tif1 events "$1"
```

## Frequently Asked Questions (FAQ)

### General Questions

**Q: Is the CLI free to use?**
A: Yes, tif1 CLI is completely free and open-source.

**Q: Do I need an API key?**
A: No, tif1 CLI does not require any API keys or authentication.

**Q: What data is available?**
A: Lap times, telemetry, weather and race control messages from 2018 onwards, and Ergast results, lap times and standings from 1950 onwards. The CLI shows schedules, drivers, fastest laps, classifications and standings.

**Q: Can I use this for commercial purposes?**
A: tif1 is released under the MIT License. Read the LICENSE file for the terms.

### Technical Questions

**Q: Why is the first command slow?**
A: The first request fetches data from the network and caches it. Subsequent requests are much faster.

**Q: How much disk space does the cache use?**
A: It depends on the sessions and the data types loaded. Check with `tif1 cache-info`.

**Q: Can I use this offline?**
A: Past-season schedules ship with tif1, so `events` and `sessions` work offline. Sessions in the cache load offline too.

**Q: Does the CLI support Python 2?**
A: No, Python 3.11 or higher is required (3.11 through 3.15 are supported).

**Q: Can I run multiple CLI instances simultaneously?**
A: Yes. The SQLite cache runs in WAL mode, so several processes can share it.

### Data Questions

**Q: Why is driver X missing from the results?**
A: The driver did not take part in that session, or has no timed lap (for example, a DNS).

**Q: Can I get telemetry data via CLI?**
A: No. The CLI shows lap times and driver info. Use the Python API for telemetry.

### Troubleshooting Questions

**Q: Command not found error?**
A: Ensure tif1 is installed and the Python Scripts directory is in the PATH.

**Q: Permission denied error?**
A: Check cache directory permissions or use a custom cache location.

**Q: Network timeout error?**
A: Increase timeout with `TIF1_TIMEOUT=60` or check the internet connection.

**Q: Cache corruption error?**
A: Clear cache with `tif1 cache-clear -y` and try again.
