## Overview

`tif1` implements a multi-tier caching architecture that reduces redundant network requests. The SQLite-backed `Cache` consists of:

1. **Parsed-object LRUs**: Decoded JSON payloads (128 items) and telemetry payloads (256 items); fixed size
2. **Blob LRUs**: Serialized JSON bytes (1024 items) and telemetry bytes (2048 items); sized by `memory_cache_max_items` and `memory_telemetry_cache_max_items`
3. **SQLite payload tables**: Durable `cache` and `telemetry_cache` tables that survive across processes
4. **SQLite frame tiers**: Materialized telemetry DataFrames in `telemetry_frames` (pandas) and `telemetry_frames_pl` (polars), and the processed laps DataFrame of a session in `laps_frames` / `laps_frames_pl`. Both tiers derive from the payload tables, and the loader rebuilds missing rows. SQLite's `PRAGMA user_version` versions the telemetry frame tables (`_FRAME_TIER_SCHEMA_VERSION`, now `1`). A cache file with an older version drops these two tables once
5. **Negative-verdict tier**: The `missing_payloads` table remembers payloads that every CDN reported missing, for `missing_payloads_ttl_days` (default 7 days)

The `cache` table also holds one TTL-scoped row per live season, `f1schedule/schedule_{year}.json`, written by `tif1.events` and re-fetched after `schedule_ttl_hours` (default 6).

Two more tiers live outside `Cache`: the per-session `SessionMemo` (`Session._memo`) and the process-global backend lap LRU (`get_backend_lap_cache`). Hot data comes from memory (microsecond latency). Cold data comes from disk (millisecond latency) instead of a network request (latency of a second or more). The cache is thread-safe and supports synchronous and asynchronous operations.

<Note>
  `tif1.Cache` (the exported name) is the FastF1-compatible helper class in `tif1.fastf1_compat`. `tif1.get_cache()` returns the SQLite-backed `tif1.cache.Cache` that this page documents.
</Note>

### Cache Architecture

The cache stores two primary types of data:

- **JSON Data**: Session metadata, lap data, driver information, weather data, and race control messages in a key-value table
- **Telemetry Data**: High-frequency sensor data (speed, throttle, brake, gear, RPM, DRS). Stored in the dedicated `telemetry_cache` table with a composite primary key on (year, gp, session, driver, lap)

With `enable_cache` on (the default), `Session.load()` caches all data that it fetches. The Cache API gives manual control.

## Getting the Cache Instance

### `get_cache()`

```python
def get_cache() -> Cache
```

Returns the global singleton `Cache` instance used throughout the library. This is the primary entry point for all cache operations.

The cache is initialized lazily on first access and configured based on environment variables and `.tif1rc` settings. The same instance is shared across all sessions and operations in the application.

**Returns:** `Cache` - The global cache singleton

**Thread Safety:** The cache instance is thread-safe and can be safely accessed from multiple threads.

**Example:**
```python
import tif1

# Get the cache instance
cache = tif1.get_cache()

# Check cache configuration
print(f"Cache directory: {cache.cache_dir}")
print(f"Database path: {cache.db_path}")
```

**Configuration:**
The cache behavior can be customized through environment variables. The `Cache` reads all of them except `TIF1_ENABLE_CACHE` when it is created (the first `get_cache()` call):
- `TIF1_CACHE_DIR`: Custom cache directory (default: OS-dependent; see the platform defaults in the configuration reference)
- `TIF1_ENABLE_CACHE`: Set to `"false"` so that sessions neither read nor write the cache
- `TIF1_MEMORY_CACHE_MAX_ITEMS` / `TIF1_MEMORY_TELEMETRY_CACHE_MAX_ITEMS`: Size of the JSON and telemetry blob LRUs (defaults `1024` and `2048`)
- `TIF1_MISSING_PAYLOADS_TTL_DAYS`: Lifetime of all-CDN-missing verdicts in days (default `7.0`)

## Cache Management Operations

### `clear()`

```python
def clear() -> None
```

Removes all cached data from every in-memory tier and from the SQLite `cache`, `telemetry_cache`, `telemetry_frames`, `telemetry_frames_pl`, `laps_frames`, `laps_frames_pl`, and `missing_payloads` tables. This operation is irreversible and forces all later data requests to fetch from the CDN.

**Use Cases:**
- Clearing corrupted cache data
- Freeing disk space
- Forcing a complete data refresh
- Troubleshooting data inconsistencies

**Performance Impact:** After the cache is cleared, the first load of any session is slower. All data must be fetched from the network again.

**Example:**
```python
import tif1

cache = tif1.get_cache()

# Clear all cached data
cache.clear()
print("Cache cleared successfully")

# Verify cache is empty (gp and session use the URL-encoded cache form)
has_data = cache.has_session_data(2024, "Monaco%20Grand%20Prix", "Race")
print(f"Has cached data: {has_data}")  # False
```

**Advanced Usage:**
```python
# Clear cache before a critical data refresh
cache.clear()

# Load fresh data
session = tif1.get_session(2024, "Monaco Grand Prix", "Race")
session.load(laps=True, telemetry=True, weather=True)
print("Fresh data loaded and cached")
```

### `invalidate()`

```python
def invalidate(scope: InvalidateScope = "all") -> None
```

Invalidates cached data by scope. This is the only selective invalidation API; prefer it over raw SQL against `cache.sqlite`.

**Parameters:**
- `scope` (`"all" | "memory" | "json" | "telemetry"`): The tier to drop
  - `"all"` - Every tier, memory and SQLite; equivalent to `clear()`
  - `"memory"` - Only the four in-memory LRU tiers and the in-memory verdict mirror; SQLite rows persist
  - `"json"` - The JSON payload tier: the `cache` table, `missing_payloads`, the derived `laps_frames` / `laps_frames_pl` rows, and the JSON LRUs
  - `"telemetry"` - The telemetry tier: `telemetry_cache`, `telemetry_frames`, `telemetry_frames_pl`, `laps_frames` / `laps_frames_pl`, `missing_payloads`, and the telemetry LRUs

Any other value raises `ValueError`. The method first joins pending background frame writers, so a late write cannot re-insert cleared rows.

**Example:**
```python
import tif1

cache = tif1.get_cache()

# Drop every telemetry payload and derived frame; JSON payloads stay cached
cache.invalidate("telemetry")

# Free memory without touching the SQLite file
cache.invalidate("memory")
```

### `has_session_data()`

```python
def has_session_data(year: int, gp: str, session: str) -> bool
```

Checks whether the cache contains any data for a specific session without actually loading it. The method URL-encodes `gp` and `session` first, then scans the JSON blob LRU for the `{year}/{gp}/{session}/` prefix and the SQLite `cache` and `telemetry_cache` tables. On a probe error it returns `True` to keep cache reads enabled.

**Parameters:**
- `year` (int): Season year (for example, `2024`, `2023`)
- `gp` (str): Grand Prix name, plain (`"Monaco Grand Prix"`) or URL-encoded as held in `session.gp` (`"Monaco%20Grand%20Prix"`)
- `session` (str): Session name, plain (`"Practice 1"`) or URL-encoded as held in `session.session` (`"Race"`, `"Qualifying"`, `"Practice%201"`, `"Sprint%20Qualifying"`)

<Note>
Only `has_session_data()` normalizes its arguments. The cache keys themselves use the URL-encoded names of the CDN paths, so `get()`, `get_telemetry()` and the batch readers need the encoded form (`session.gp`, `session.session`). A snake_case name such as `"Monaco_Grand_Prix"` matches nothing in either method.
</Note>

**Returns:** `bool` - `True` if any JSON or telemetry data exists for the session, `False` otherwise

**Use Cases:**
- Checking cache availability before loading
- Building cache status dashboards
- Implementing cache warming strategies
- Conditional data loading logic

**Example:**
```python
import tif1

cache = tif1.get_cache()

# Check if data is cached before loading
session = tif1.get_session(2024, "Monaco Grand Prix", "Race")

# session.gp and session.session hold the URL-encoded names that the cache uses
if cache.has_session_data(session.year, session.gp, session.session):
    print(f"✓ {session.year} {session.gp} {session.session} is cached")
    session.load()  # Fast load from cache
else:
    print(f"✗ {session.year} {session.gp} {session.session} not cached")
    session.load()  # Slower load from CDN
```

**Batch Checking:**
```python
# Check cache status for multiple sessions
sessions_to_check = [
    (2024, "Monaco%20Grand%20Prix", "Race"),
    (2024, "Monaco%20Grand%20Prix", "Qualifying"),
    (2024, "Canadian%20Grand%20Prix", "Race"),
]

for year, gp, session_type in sessions_to_check:
    cached = cache.has_session_data(year, gp, session_type)
    status = "✓ Cached" if cached else "✗ Not cached"
    print(f"{year} {gp} {session_type}: {status}")
```

### `close()`

```python
def close() -> None
```

Explicitly closes the SQLite database connection and releases associated resources. For the `get_cache()` singleton, an `atexit` handler runs it when the Python process exits. A private `Cache()` instance also closes when it is garbage-collected. Invoke it manually for fine-grained resource management.

**When to Use:**
- Releasing the SQLite handle of a separate `Cache()` instance after maintenance work
- Testing scenarios that build and discard throwaway `Cache()` instances

**Note:** `close()` sets the connection to `None` and clears every in-memory tier. There is no reconnect: every later read returns `None` and every later write is a no-op. Do not close the singleton from `get_cache()` before the process exits; the `atexit` handler closes it. For maintenance work, construct a separate `Cache(cache_dir)` instance and close that one.

**Example:**
```python
from tif1.cache import Cache

# A private instance on the configured directory; tif1.get_cache() stays open
cache = Cache()
print(f"Monaco cached: {cache.has_session_data(2024, 'Monaco%20Grand%20Prix', 'Race')}")

# Explicitly close the private instance when done
cache.close()
print("Cache connection closed")
```

**Private Instance Pattern:**
```python
from pathlib import Path

from tif1.cache import Cache

def inspect_cache(cache_dir: Path) -> bool:
    cache = Cache(cache_dir)  # separate instance; the singleton is untouched
    try:
        return cache.has_session_data(2024, "Monaco%20Grand%20Prix", "Race")
    finally:
        cache.close()  # Ensure cleanup of the private instance only
```

## General Cache Access (JSON Data)

These methods provide low-level access to the cache's key-value store for JSON-serializable data. Most users will not need these methods directly, as `Session.load()` handles caching automatically. However, they are useful for advanced use cases like custom data pipelines or cache inspection.

### `get()`

```python
def get(key: str) -> Any | None
```

Retrieves cached JSON-serializable data for a specific key. Checks the parsed-object LRU, then the blob LRU, then SQLite.

**Parameters:**
- `key` (str): Cache key in the format `"{year}/{gp}/{session}/{path}"` where `path` is the CDN payload path, for example:
  - `drivers.json` - Driver list and metadata
  - `session_laptimes.json` - Session lap times
  - `rcm.json` - Race control messages
  - `weather.json` - Weather conditions
  - `corners.json` - Circuit corner markers
  - `{driver}/laptimes.json` - Per-driver lap times
  - `{driver}/{lap}_tel.json` - Per-lap telemetry payload

**Returns:** `Any | None` - The cached data (typically a dict or list), or `None` if not found

**Example:**
```python
import tif1

cache = tif1.get_cache()

# Retrieve cached driver data: {"drivers": [{"driver": "VER", "fn": "Max", ...}]}
key = "2024/Monaco%20Grand%20Prix/Race/drivers.json"
payload = cache.get(key)

if payload:
    drivers = payload["drivers"]
    print(f"Found {len(drivers)} drivers in cache")
    for driver in drivers:
        print(f"  - {driver['driver']}: {driver['fn']} {driver['ln']}")
else:
    print("Driver data not cached")
```

**Advanced Usage - Cache Inspection:**
```python
# Inspect what is cached for a session
year, gp, session_type = 2024, "Monaco%20Grand%20Prix", "Race"
base_key = f"{year}/{gp}/{session_type}"

data_files = ["drivers.json", "session_laptimes.json", "weather.json", "rcm.json"]
for file in data_files:
    key = f"{base_key}/{file}"
    data = cache.get(key)
    status = "✓" if data else "✗"
    print(f"{status} {file}")
```

### `set()`

```python
def set(key: str, data: Any) -> None
```

Stores JSON-serializable data in the cache with the specified key. Updates the blob LRU and the persistent SQLite database, and drops any stale parsed-object entry.

**Parameters:**
- `key` (str): Cache key in the format `"{year}/{gp}/{session}/{path}"`
- `data` (Any): JSON-serializable data to cache (dict, list, str, int, float, bool, None)

**Serialization:** Data is serialized with `orjson` for performance. Ensure that the data contains only JSON-compatible types.

**Compression:** Serialized rows of 4096 bytes or more are compressed at the SQLite boundary with zstd level 1. Without a zstd binding, zlib level 3 is used. The in-memory LRU keeps the plain bytes.

**Example:**
```python
import tif1

cache = tif1.get_cache()

# Manually cache custom data
custom_data = {
    "drivers": ["VER", "HAM", "LEC"],
    "fastest_lap": 94.123,
    "conditions": "dry"
}

key = "2024/Monaco%20Grand%20Prix/Race/custom_analysis.json"
cache.set(key, custom_data)
print(f"Cached custom data at {key}")

# Retrieve it later
retrieved = cache.get(key)
print(f"Retrieved: {retrieved}")
```

**Bulk Caching:**
```python
# Cache multiple related datasets of your own.
# Use custom file names: a key such as ".../drivers.json" overwrites the real payload.
session_data = {
    "custom_stints.json": {"VER": [1, 2], "HAM": [1, 2, 3]},
    "custom_pit_laps.json": {"VER": [20], "HAM": [18, 45]},
    "custom_notes.json": {"conditions": "dry"},
}

base_key = "2024/Monaco%20Grand%20Prix/Race"
for filename, data in session_data.items():
    cache.set(f"{base_key}/{filename}", data)
    print(f"Cached {filename}")
```

### `set_raw()`

```python
def set_raw(key: str, blob: bytes | bytearray | memoryview) -> None
```

Stores an already-serialized JSON blob without re-encoding. The async fetch pipeline uses this when validation left the payload byte-identical to the HTTP body.

Blobs of 4 KB or larger are compressed with zstd level 1 at the SQLite boundary only. Legacy zlib rows stay readable via magic-byte detection. The in-memory LRU keeps the plain blob. Small rows stay plain TEXT, the legacy storage shape. Python 3.14+ uses the standard-library `compression.zstd` binding and 3.11-3.13 use the `zstandard` package; both write identical frames.

**Parameters:**
- `key` (str): Cache key in the format `"{year}/{gp}/{session}/{path}"`
- `blob` (bytes | bytearray | memoryview): UTF-8 JSON bytes

**Example:**
```python
import tif1

cache = tif1.get_cache()
cache.set_raw("2024/Monaco%20Grand%20Prix/Race/custom_drivers.json", b'{"drivers":["VER"]}')
```

## Telemetry Cache Access

Telemetry data (high-frequency sensor readings) lives in the dedicated `telemetry_cache` SQLite table, optimized for lap-by-lap queries. This separation improves performance for telemetry-heavy workloads and enables efficient batch operations.

### Telemetry Data Structure

Each telemetry entry is the raw CDN payload of a single lap: a dict of parallel lists with lowercase keys.
- **`time`** - Seconds from the start of the lap
- **`speed`** - Vehicle speed in km/h
- **`rpm`** - Engine revolutions per minute
- **`gear`** - Current gear (0-8, where 0 is neutral)
- **`throttle`** - Throttle position (0-100%)
- **`brake`** - Brake applied (0 or 1)
- **`drs`** - DRS flag (0=closed, 1=open)
- **`distance`**, **`rel_distance`** - Distance in meters and as a fraction of the lap
- **`acc_x`**, **`acc_y`**, **`acc_z`** - Accelerations
- **`x`**, **`y`**, **`z`** - 3D position coordinates
- **`DriverAhead`**, **`DistanceToDriverAhead`** - Car ahead and the gap to it
- **`dataKey`** - A string label of the lap (for example `"2024-Monaco Grand Prix-Race-ALB-1"`), not a list

`Telemetry` frames rename these keys (`Time`, `Speed`, `nGear`, ...). The raw payload keeps the lowercase names.

### `get_telemetry()`

```python
def get_telemetry(
    year: int,
    gp: str,
    session: str,
    driver: str,
    lap: int
) -> Any | None
```

Retrieves telemetry data for a specific driver's lap. Returns `None` if the telemetry is not cached.

**Parameters:**
- `year` (int): Season year (for example, `2024`)
- `gp` (str): URL-encoded Grand Prix name, as in `session.gp` (for example, `"Monaco%20Grand%20Prix"`)
- `session` (str): URL-encoded session name, as in `session.session` (for example, `"Race"`, `"Practice%201"`)
- `driver` (str): Three-letter driver code (for example, `"VER"`, `"HAM"`, `"LEC"`)
- `lap` (int): Lap number (1-indexed)

**Returns:** `Any | None` - Telemetry data structure (typically a dict with arrays), or `None` if not found

**Performance:** Single telemetry lookup is optimized with a composite index on (year, gp, session, driver, lap).

**Example:**
```python
import tif1

cache = tif1.get_cache()

# Get telemetry for Verstappen's lap 1
telemetry = cache.get_telemetry(
    year=2024,
    gp="Monaco%20Grand%20Prix",
    session="Race",
    driver="VER",
    lap=1
)

if telemetry:
    # Raw payload: parallel lists with lowercase keys
    print(f"Telemetry data points: {len(telemetry['time'])}")
    print(f"Max speed: {max(telemetry['speed'])} km/h")
    print(f"Max RPM: {max(telemetry['rpm'])}")
else:
    print("Telemetry not cached")
```

**Analyzing Cached Telemetry:**
```python
# Compare telemetry availability for multiple drivers
drivers = ["VER", "HAM", "LEC", "SAI"]
lap_num = 1

for driver in drivers:
    telem = cache.get_telemetry(2024, "Monaco%20Grand%20Prix", "Race", driver, lap_num)
    if telem:
        points = len(telem.get('time', []))
        print(f"{driver} lap {lap_num}: {points} data points cached")
    else:
        print(f"{driver} lap {lap_num}: not cached")
```

### `set_telemetry()`

```python
def set_telemetry(
    year: int,
    gp: str,
    session: str,
    driver: str,
    lap: int,
    data: Any
) -> None
```

Stores telemetry data for a specific driver's lap in the telemetry blob LRU and the `telemetry_cache` table.

**Parameters:**
- `year` (int): Season year
- `gp` (str): Grand Prix identifier
- `session` (str): Session type
- `driver` (str): Three-letter driver code
- `lap` (int): Lap number
- `data` (Any): Telemetry data structure to cache

**Serialization:** Data is serialized using `orjson` before storage.

**Compression:** Serialized rows of 4096 bytes or more are compressed at the SQLite boundary (zstd level 1), as for `set()`.

<Warning>
`set_telemetry()` overwrites the cached payload for that lap, and `tif1` later reads it as real telemetry. Write only complete payloads in the CDN format, or use a session identity that no real session uses.
</Warning>

**Example:**
```python
import tif1

cache = tif1.get_cache()

# A payload in the CDN format: parallel lists with lowercase keys
telemetry_data = {
    "time": [0.0, 0.1, 0.2, 0.3],
    "speed": [0, 50, 100, 150],
    "rpm": [8000, 10000, 12000, 11000],
    "throttle": [0, 50, 100, 100],
    "brake": [0, 0, 0, 0],
    "gear": [1, 2, 3, 4],
}

# A test identity, so no real lap is overwritten
cache.set_telemetry(
    year=2099,
    gp="Test%20Grand%20Prix",
    session="Race",
    driver="TST",
    lap=1,
    data=telemetry_data
)
print("Telemetry cached successfully")
```

### `get_telemetry_batch()`

```python
def get_telemetry_batch(
    year: int,
    gp: str,
    session: str,
    driver_laps: list[tuple[str, int]]
) -> dict[tuple[str, int], Any]
```

Retrieves multiple telemetry entries in a single optimized batch query. This is more efficient than calling `get_telemetry()` multiple times, as it uses a single SQL query with an `IN` clause.

**Parameters:**
- `year` (int): Season year
- `gp` (str): Grand Prix identifier
- `session` (str): Session type
- `driver_laps` (list[tuple[str, int]]): List of (driver_code, lap_number) tuples to fetch

**Returns:** `dict[tuple[str, int], Any]` - Dictionary mapping (driver, lap) tuples to telemetry data. Missing entries are not included in the result.

**Performance Benefits:**
- Single database query instead of N queries
- Reduced Python-SQLite round trips
- Optimized for bulk telemetry analysis
- Ideal for comparing multiple drivers/laps

**Example - Basic Batch Fetch:**
```python
import tif1

cache = tif1.get_cache()

# Fetch telemetry for multiple driver-lap combinations
driver_laps = [
    ("VER", 1),
    ("VER", 2),
    ("HAM", 1),
    ("HAM", 2),
    ("LEC", 1)
]

batch = cache.get_telemetry_batch(
    year=2024,
    gp="Monaco%20Grand%20Prix",
    session="Race",
    driver_laps=driver_laps
)

# Access individual entries
for (driver, lap), telemetry in batch.items():
    if telemetry:
        max_speed = max(telemetry['speed'])
        print(f"{driver} lap {lap}: max speed {max_speed} km/h")
```

**Example - Comparing Driver Performance:**
```python
# Compare first 5 laps for top 3 drivers
drivers = ["VER", "HAM", "LEC"]
laps = range(1, 6)

# Build request list
driver_laps = [(driver, lap) for driver in drivers for lap in laps]

# Fetch all telemetry in one query
batch = cache.get_telemetry_batch(2024, "Monaco%20Grand%20Prix", "Race", driver_laps)

# Analyze results
for driver in drivers:
    driver_data = [(lap, batch.get((driver, lap))) for lap in laps]
    cached_count = sum(1 for _, telem in driver_data if telem)
    print(f"{driver}: {cached_count}/{len(laps)} laps cached")
```

**Example - Fastest Lap Analysis:**
```python
# Find fastest lap from cached telemetry
drivers = ["VER", "HAM", "LEC", "SAI", "NOR"]
laps = range(1, 21)  # First 20 laps

driver_laps = [(d, l) for d in drivers for l in laps]
batch = cache.get_telemetry_batch(2024, "Monaco%20Grand%20Prix", "Race", driver_laps)

fastest = None
fastest_key = None

for (driver, lap), telemetry in batch.items():
    if telemetry and 'speed' in telemetry:
        max_speed = max(telemetry['speed'])
        if fastest is None or max_speed > fastest:
            fastest = max_speed
            fastest_key = (driver, lap)

if fastest_key:
    print(f"Fastest: {fastest_key[0]} lap {fastest_key[1]} - {fastest} km/h")
```

### `get_telemetry_frames_batch()`

```python
def get_telemetry_frames_batch(
    year: int,
    gp: str,
    session: str,
    driver_laps: list[tuple[str, int]],
    lib: Literal["pandas", "polars"] = "pandas",
) -> dict[tuple[str, int], Any]
```

Batch-reads materialized telemetry DataFrames from the frame tier. The tier stores pickled, compressed rows (lz4, with zstd as fallback) in `telemetry_frames` (pandas) or `telemetry_frames_pl` (polars). The method never returns rows from the other backend. Refs without a frame row, or with a corrupt row, are absent from the result. They fall through to the payload tier.

**Parameters:**
- `year`, `gp`, `session`: Session identity, as for `get_telemetry_batch()`
- `driver_laps` (list[tuple[str, int]]): `(driver, lap)` refs to read
- `lib` (`"pandas"` or `"polars"`): Backend whose frame table to read

**Returns:** `dict[tuple[str, int], Any]` - `(driver, lap)` to DataFrame; empty when the connection is closed or no frame codec is available

def set_telemetry_frames_batch(

### `get_laps_frame()` / `set_laps_frame()`

```python
def get_laps_frame(
    year: int,
    gp: str,
    session: str,
    lib: Literal["pandas", "polars"] = "pandas",
) -> Any
def set_laps_frame(
    year: int,
    gp: str,
    session: str,
    frame: Any,
    lib: Literal["pandas", "polars"] = "pandas",
) -> int
```

The laps frame tier: one processed laps DataFrame per `(year, gp, session)` and backend, stored in `laps_frames` (pandas) or `laps_frames_pl` (polars) with the same pickle-and-compress format as the telemetry frames. `get_laps_frame()` returns the DataFrame, or `None` on a miss, a corrupt row, or a row written by the other backend. `set_laps_frame()` returns `1` when the row was written and `0` when the tier is unavailable. `invalidate("json")`, `invalidate("telemetry")` and `clear()` drop these rows; the loader rebuilds them from the payloads.

---

## Negative-Verdict Tier

When every CDN returns a 4xx other than 408 or 429 for a payload, the loader records the key in the `missing_payloads` table. Later loads skip the network probe for that key until the verdict expires. The lifetime is `missing_payloads_ttl_days` (`TIF1_MISSING_PAYLOADS_TTL_DAYS`, default `7.0`). The verdicts load lazily from SQLite once per process.

### `is_known_missing()`

```python
def is_known_missing(key: str) -> bool
```

Returns `True` when `key` has an unexpired all-CDN-missing verdict. Keys use the JSON-tier format `"{year}/{gp}/{session}/{path}"`, also for telemetry paths. An expired verdict is discarded on read and returns `False`.

### `record_missing()`

```python
def record_missing(key: str) -> None
```

Records an all-CDN-missing verdict for `key` with the current timestamp, in memory and in SQLite. A later `set()` for the same key removes the verdict from memory and from SQLite.

### `discard_missing()`

```python
def discard_missing(key: str) -> None
```

Removes the verdict for `key` from memory and SQLite, so the next load probes the CDNs again.

**Example:**
```python
import tif1

cache = tif1.get_cache()
key = "2024/Monaco%20Grand%20Prix/Race/VER/99_tel.json"

if cache.is_known_missing(key):
    # Force a fresh CDN probe on the next load
    cache.discard_missing(key)
```

## Async Methods

The main read and write methods have async variants for use in async contexts. These methods enable high-performance async applications to interact with the cache without blocking the event loop.

### Async Method Overview

| Sync Method | Async Method | Description |
| :--- | :--- | :--- |
| `get(key)` | `get_async(key)` | Retrieve JSON data asynchronously |
| `set(key, data)` | `set_async(key, data)` | Store JSON data asynchronously |
| `get_telemetry(...)` | `get_telemetry_async(...)` | Retrieve single telemetry entry asynchronously |
| `set_telemetry(...)` | `set_telemetry_async(...)` | Store single telemetry entry asynchronously |
| `get_telemetry_batch(...)` | `get_telemetry_batch_async(...)` | Retrieve multiple telemetry entries asynchronously |

### Implementation Details

Async methods use `loop.run_in_executor(None, ...)` to run the synchronous SQLite operations in the default thread pool. This keeps the event loop free and preserves the thread safety of the sync methods.

### `get_async()`

```python
async def get_async(key: str) -> Any | None
```

Asynchronously retrieves cached JSON data for a specific key.

**Example:**
```python
import asyncio
import tif1

async def fetch_cached_drivers():
    cache = tif1.get_cache()
    key = "2024/Monaco%20Grand%20Prix/Race/drivers.json"
    payload = await cache.get_async(key)

    if payload:
        drivers = payload["drivers"]
        print(f"Found {len(drivers)} drivers")
        return drivers
    else:
        print("No cached driver data")
        return None

# Run the async function
asyncio.run(fetch_cached_drivers())
```

### `get_telemetry_batch_async()`

```python
async def get_telemetry_batch_async(
    year: int,
    gp: str,
    session: str,
    driver_laps: list[tuple[str, int]]
) -> dict[tuple[str, int], Any]
```

Asynchronously retrieves multiple telemetry entries in a single optimized batch query.

**Example - Parallel Telemetry Fetching:**
```python
import asyncio
import tif1

async def analyze_multiple_sessions():
    cache = tif1.get_cache()

    # Define multiple batch requests
    sessions = [
        (2024, "Monaco%20Grand%20Prix", "Race"),
        (2024, "Monaco%20Grand%20Prix", "Qualifying"),
        (2024, "Canadian%20Grand%20Prix", "Race")
    ]

    driver_laps = [("VER", 1), ("HAM", 1), ("LEC", 1)]

    # Fetch all batches concurrently
    tasks = [
        cache.get_telemetry_batch_async(year, gp, session, driver_laps)
        for year, gp, session in sessions
    ]

    results = await asyncio.gather(*tasks)

    # Process results
    for (year, gp, session), batch in zip(sessions, results):
        print(f"\n{year} {gp} {session}:")
        for (driver, lap), telemetry in batch.items():
            if telemetry:
                print(f"  {driver} lap {lap}: ✓ cached")

asyncio.run(analyze_multiple_sessions())
```

import asyncio
import tif1

async def build_telemetry_dataset():

    print(f"  Cached: {total_cached} entries")

asyncio.run(build_telemetry_dataset())

## Module-Level Cache API

Besides the `Cache` class, `tif1.cache` exposes the building blocks of the memory tiers.

### `LRUCache`

```python
def __init__(maxsize: int = 100, *, lock: threading.Lock | None = None)
```

The default `maxsize` is `MAX_CACHE_SIZE` (`100`) from `tif1.core_utils.constants`; the `Cache` tiers pass their own configured limits. Thread-safe bounded LRU cache. It is the single LRU implementation backing the `Cache` in-memory tiers and the process-global backend lap caches. Reads support a lock-free fast path (`get(key, ordered=False)`); writes refresh LRU order and evict oldest-first at `maxsize`.

**Methods:** `get(key, *, ordered=True)`, `set(key, value)`, `clear()`, `pop(key, default=None)`, plus `in`, `len()`, and iteration support.

### `get_backend_lap_cache`

```python
def get_backend_lap_cache(lib: Literal["pandas", "polars"]) -> LRUCache
```

Return the process-global lap cache for the given backend, keyed by `"{year}_{gp}_{session}_laps"`. One cache per backend; shared across sessions in the same process.

### `clear_lap_cache`

```python
def clear_lap_cache() -> None
```

Clear both process-global backend lap caches (pandas and polars).

### `Cache.get_entry` / `Cache.set_entry`

```python
def get_entry(kind: CacheKind, key: Any) -> Any | None
def set_entry(kind: CacheKind, key: Any, value: Any) -> None
```

Unified kind-based access to the memory tiers and SQLite. `CacheKind` is `"json"` (a `str` path key) or `"telemetry"` (a `(year, gp, session, driver, lap)` tuple key). `get()`/`set()` and `get_telemetry()`/`set_telemetry()` are thin wrappers over these. Any other kind raises `ValueError`. The kinds `"telemetry_payload"` and `"telemetry_df"` belong to `SessionMemo`, not to `Cache`.

### `SessionMemo`

Per-session memo tier held as `Session._memo`. It consolidates the session-scoped caches behind the same kind-based interface. It also owns the fastest-lap-reference memo, the persistent-cache probe result (`has_session_data`), and per-driver telemetry failure tracking. Not internally synchronized. The owning session's access patterns are single-threaded per event loop.

## Performance Considerations

### Cache Hit Rates

The cache is most effective when:
- Loading the same session multiple times
- Analyzing historical data that does not change
- Working with telemetry-heavy workloads
- Running batch analyses across multiple sessions

### Memory Management

Each in-memory LRU tier has a size limit to prevent excessive memory usage. The blob tiers default to 1024 JSON and 2048 telemetry items (`memory_cache_max_items`, `memory_telemetry_cache_max_items`). The parsed-object tiers are fixed at 128 and 256 items. A full tier evicts its least-recently-used entries (they remain in SQLite).

### Disk Space

The SQLite database grows as more data is cached. A session with full telemetry adds one `telemetry_cache` row per driver lap, plus the derived frame rows. Telemetry takes most of the file size.

**Disk Space Management:**
```python
import tif1

cache = tif1.get_cache()

# Check current cache size
size_mb = cache.db_path.stat().st_size / 1024 / 1024
print(f"Current cache size: {size_mb:.2f} MB")

# Clear the cache if it is too large
if size_mb > 1000:  # 1 GB threshold
    print("Cache exceeds 1 GB, clearing...")
    cache.clear()
```

### Optimization Tips

1. **Use Batch Operations**: `get_telemetry_batch()` is faster than multiple `get_telemetry()` calls
2. **Selective Loading**: Only load the data that is needed (for example, `session.load(laps=True, telemetry=False)`)
3. **Async for Concurrency**: Use the async methods to read the cache from async code without blocking the event loop
4. **Cache Warming**: Pre-load frequently accessed sessions during off-peak hours
5. **Selective Invalidation**: Use `cache.invalidate("telemetry")` to drop the telemetry payloads and derived frames while the JSON payloads stay cached

**Example - Cache Warming Script:**
```python
import tif1

def warm_cache(year: int, event_names: list[str]):
    """Pre-load the race sessions of the given events."""
    for event_name in event_names:
        try:
            session = tif1.get_session(year, event_name, 'Race')
            session.load(laps=True, telemetry=True, weather=True)
            print(f"✓ Cached {event_name} Race")
        except Exception as e:
            print(f"✗ Failed to cache {event_name}: {e}")

# Warm the cache for selected races. For a whole season pass the calendar:
# tif1.get_event_schedule(2024, include_testing=False)["EventName"]
warm_cache(2024, ["Monaco Grand Prix"])
```

### Use Case 2: Selective Cache Clearing

Prefer `cache.invalidate(scope)` over raw SQL. It clears the matching memory tiers and the derived SQLite rows together.

```python
import tif1

cache = tif1.get_cache()

# Refresh every telemetry payload and derived frame; JSON payloads stay cached
cache.invalidate("telemetry")

# Refresh every JSON payload (drivers, lap times, weather, race control)
cache.invalidate("json")
```

`invalidate()` has no per-session scope. A per-session purge needs raw SQL and must cover the derived tables too. Otherwise `telemetry_frames`, `telemetry_frames_pl`, `laps_frames`, `laps_frames_pl`, and `missing_payloads` keep stale rows for the session.

<Warning>
Run this only when no `Cache` writer is active in the process. The singleton batches writes and commits every `cache_commit_interval` operations, so a second connection can hit `database is locked` while a batch is open. Run the purge from a dedicated maintenance process after every tif1 process that writes to the cache has exited. Do not close the global singleton in a process that keeps using tif1. `close()` is final and disables caching for the rest of that process.
</Warning>

```python
import sqlite3
from pathlib import Path

import tif1

def clear_session_cache(year: int, gp: str, session: str):
    """Clear every table for one session (maintenance process, global cache not opened)."""
    # Resolve the file from the config: tif1.get_cache() would open a second writer
    db_path = Path(tif1.get_config().get("cache_dir")) / "cache.sqlite"
    conn = sqlite3.connect(db_path, timeout=10.0)
    cursor = conn.cursor()

    # JSON payloads and all-CDN-missing verdicts share the path-shaped key
    key_pattern = f"{year}/{gp}/{session}/%"
    cursor.execute("DELETE FROM cache WHERE key LIKE ?", (key_pattern,))
    json_deleted = cursor.rowcount
    cursor.execute("DELETE FROM missing_payloads WHERE key LIKE ?", (key_pattern,))

    # Telemetry payloads plus the derived pandas and polars frame rows
    telemetry_deleted = 0
    for table in (
        "telemetry_cache",
        "telemetry_frames",
        "telemetry_frames_pl",
        "laps_frames",
        "laps_frames_pl",
    ):
        cursor.execute(
            f"DELETE FROM {table} WHERE year = ? AND gp = ? AND session = ?",
            (year, gp, session),
        )
        telemetry_deleted += cursor.rowcount

    conn.commit()
    conn.close()

    print(f"Cleared {year} {gp} {session}:")
    print(f"  JSON entries: {json_deleted}")
    print(f"  Telemetry and frame rows: {telemetry_deleted}")

# Clear one session (the URL-encoded names; here the test identity written above)
try:
    clear_session_cache(2099, "Test%20Grand%20Prix", "Race")
except sqlite3.OperationalError as e:
    # Another connection holds an open write batch (this process or another one)
    print(f"Purge skipped ({e}): stop every tif1 process that writes to the cache first")
```

A process that already holds the singleton keeps the session in its LRU tiers. In that process, call `tif1.get_cache().invalidate("memory")` after the purge. `invalidate("memory")` also drops the in-memory mirror of the verdicts, and the next probe reloads them from SQLite. Call `cache.discard_missing(key)` to delete one verdict outright.

### Use Case 3: Cache Export/Import

Do not close the `get_cache()` singleton to copy the file: `close()` disables caching for the rest of the process. Run the copy from a separate process, or before the first `get_cache()` call, and resolve the path from the config. To restore a backup, copy it into a cache directory that no running tif1 process has open. Use a fresh directory, or the real one after every tif1 process exited. Then point `TIF1_CACHE_DIR` at it.

```python
import shutil
import tempfile
from pathlib import Path

import tif1

def cache_db_path() -> Path:
    """Resolve cache.sqlite without opening the global cache."""
    return Path(tif1.get_config().get("cache_dir")) / "cache.sqlite"

def export_cache(backup_path: Path):
    """Copy the cache database to a backup location (no tif1 session open)."""
    backup_path.parent.mkdir(parents=True, exist_ok=True)
    shutil.copy2(cache_db_path(), backup_path)
    print(f"Cache exported to {backup_path}")

def import_cache(backup_path: Path, cache_dir: Path):
    """Seed a cache directory from a backup (no tif1 process uses cache_dir)."""
    if not backup_path.exists():
        print(f"Backup not found: {backup_path}")
        return
    cache_dir.mkdir(parents=True, exist_ok=True)
    shutil.copy2(backup_path, cache_dir / "cache.sqlite")
    print(f"Cache imported into {cache_dir}")

work = Path(tempfile.mkdtemp())
backup = work / "tif1_cache_backup.sqlite"

# Export the cache
export_cache(backup)

# Seed a new cache directory (use it with TIF1_CACHE_DIR=/path/to/tif1-seeded)
import_cache(backup, work / "tif1-seeded")
```

The database runs in WAL mode, so a live writer may hold pending pages in `cache.sqlite-wal`. Copy the file only while no tif1 process uses the cache.

## Troubleshooting

### Cache Not Working

**Symptoms:** Data is fetched from CDN every time, even for previously loaded sessions.

**Solutions:**
1. Check if caching is enabled:
   ```python
   import tif1
   cache = tif1.get_cache()
   print(f"Enabled: {tif1.get_config().get('enable_cache')}")
   print(f"Cache dir: {cache.cache_dir}")
   ```

2. Verify cache directory is writable:
   ```python
   import os
   cache = tif1.get_cache()
   print(f"Writable: {os.access(cache.cache_dir, os.W_OK)}")
   ```

3. Check environment variables:
   ```bash
   echo $TIF1_ENABLE_CACHE
   echo $TIF1_CACHE_DIR
   ```

---

### Database Locked Errors

**Symptoms:** `sqlite3.OperationalError: database is locked`

**Causes:**
- Multiple processes accessing the cache simultaneously
- Long-running transactions
- Improper connection handling

**Solutions:**
1. Raise the SQLite busy timeout before the first `get_cache()` call:
   ```python
   import tif1
   tif1.get_config().set("sqlite_timeout", 60.0)  # or TIF1_SQLITE_TIMEOUT=60
   ```

2. Avoid concurrent writes from multiple processes
3. Give each writer process its own `TIF1_CACHE_DIR` for heavy parallel writes

### Cache Corruption

**Symptoms:** Errors when reading cached data, invalid JSON, or database integrity errors.

**Solutions:**
1. Clear and rebuild the cache:
   ```python
   import tif1
   cache = tif1.get_cache()
   cache.clear()
   print("Cache cleared - will rebuild on next load")
   ```

2. Stop every tif1 process, then delete the database file and its WAL files manually (Linux default path):
   ```bash
   rm ~/.cache/tif1/cache.sqlite ~/.cache/tif1/cache.sqlite-wal ~/.cache/tif1/cache.sqlite-shm
   ```

3. Verify database integrity:
   ```python
   import sqlite3
   import tif1

   cache = tif1.get_cache()
   conn = sqlite3.connect(cache.db_path)
   cursor = conn.cursor()
   cursor.execute("PRAGMA integrity_check")
   result = cursor.fetchone()[0]
   print(f"Integrity check: {result}")
   conn.close()
   ```

---

### High Memory Usage

**Symptoms:** Python process consuming excessive RAM.

**Causes:**
- Large in-memory LRU cache
- Loading many sessions with telemetry

**Solutions:**
1. Reduce the blob LRU sizes with `TIF1_MEMORY_CACHE_MAX_ITEMS` and `TIF1_MEMORY_TELEMETRY_CACHE_MAX_ITEMS` (or `config.set()` before the first `get_cache()` call)
2. Load data selectively:
   ```python
   import tif1

   # Load only the needed data
   session = tif1.get_session(2024, "Monaco Grand Prix", "Race")
   session.load(laps=True, telemetry=False)
   ```

3. Process data in batches:
   ```python
   import tif1

   # Process one session at a time
   for event_name in ["Monaco Grand Prix", "Canadian Grand Prix"]:
       session = tif1.get_session(2024, event_name, "Race")
       session.load(laps=True, telemetry=False)
       # ... process ...
       del session  # Drop the reference before the next session
   ```

### Slow Cache Performance

**Symptoms:** Cache reads are slower than expected.

**Solutions:**
1. Use batch operations for telemetry:
   ```python
   import tif1

   cache = tif1.get_cache()
   year, gp, session = 2025, "Bahrain%20Grand%20Prix", "Race"
   driver_laps = [("VER", lap) for lap in range(1, 11)]

   # Slow: multiple individual queries
   for driver, lap in driver_laps:
       telem = cache.get_telemetry(year, gp, session, driver, lap)

   # Fast: single batch query
   batch = cache.get_telemetry_batch(year, gp, session, driver_laps)
   ```

2. Optimize the database with `VACUUM`. Run it from a separate process while no tif1 process uses the cache:
   ```python
   import sqlite3
   from pathlib import Path

   import tif1

   # Resolve the file from the config: tif1.get_cache() would hold a second connection open
   db_path = Path(tif1.get_config().get("cache_dir")) / "cache.sqlite"
   conn = sqlite3.connect(db_path, timeout=10.0)
   try:
       conn.execute("VACUUM")
       print("Database optimized")
   except sqlite3.OperationalError as e:
       # Another connection holds an open write batch
       print(f"VACUUM skipped ({e}): stop every tif1 process that uses the cache first")
   finally:
       conn.close()
   ```

3. Check disk I/O performance:
   ```python
   import time
   import tif1

   cache = tif1.get_cache()

   # Benchmark cache read
   start = time.perf_counter()
   data = cache.get("2024/Monaco%20Grand%20Prix/Race/drivers.json")
   elapsed = time.perf_counter() - start

   print(f"Cache read took {elapsed*1000:.2f} ms")
   ```
