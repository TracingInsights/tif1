# FastF1 Compatibility Layer

The `fastf1_compat` module provides a compatibility layer for applications migrating from `fastf1` to `tif1`. This module maintains API compatibility while using tif1 performance optimizations, including async data fetching, HTTP/2 multiplexing, and caching strategies.

<Info>
  **For new projects**: Use the native tif1 API directly for the best experience. This compatibility layer is specifically designed to ease migration from existing fastf1 codebases with minimal code changes.
</Info>

<Note>
  **Performance benefit**: While maintaining API compatibility, tif1 delivers significant performance improvements:
  - **Faster cold starts** (first-time data loads) through lazy, file-level fetching
  - **Fast warm starts** (cached data) through the memory and SQLite cache tiers
  - **Async-first architecture** for parallel data fetching
  - **HTTP/2 multiplexing** for efficient network usage
  - **SQLite-backed caching** with in-memory LRU layer
</Note>

## Cache Management

The `Cache` class provides fastf1-compatible cache management with improved performance through a multi-layer caching strategy. tif1 uses a caching system that combines in-memory LRU caches with SQLite persistence. This structure gives faster data access than the fastf1 HTTP cache approach.

### Architecture Overview

tif1's caching system consists of three layers:

1. **In-Memory LRU Cache**: Lock-free reads for frequently accessed data (`memory_cache_max_items`, default 1024 items)
2. **Telemetry-Specific Cache**: Dedicated in-memory cache for telemetry data (`memory_telemetry_cache_max_items`, default 2048 items)
3. **SQLite Persistence**: WAL-mode SQLite database (`cache.sqlite`) for durable storage with optimized concurrency

Two smaller in-memory LRU tiers (128 and 256 items) keep parsed payloads, so repeated reads skip JSON parsing.

This multi-layer approach ensures that hot data is served from memory while maintaining persistence across sessions.

### `Cache.enable_cache`

```python
@classmethod
def enable_cache(
    cache_dir: str | Path | None = None,
    ignore_version: bool = True,
    force_renew: bool = False,
    use_requests_cache: bool = True
) -> tif1.cache.Cache
```

Enable caching with fastf1-compatible API. This method initializes tif1's caching system and configures the cache directory. After this call, tif1 caches all fetched data for faster access.

#### Parameters

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `cache_dir` | `str \| Path \| None` | `None` | Directory path for cache storage. If `None`, uses the configured cache directory (default: Windows `%LOCALAPPDATA%/Temp/tif1`; macOS `~/Library/Caches/tif1`; Linux/other POSIX `~/.cache/tif1` when `~/.cache` exists, otherwise `~/.tif1`) |
| `ignore_version` | `bool` | `True` | **Compatibility parameter** - Ignored by tif1. The built telemetry-frame tables carry a schema version, and tif1 rebuilds them when it changes |
| `force_renew` | `bool` | `False` | If `True`, clears all existing cache data after enabling. Use `Cache.clear_cache()` for more control |
| `use_requests_cache` | `bool` | `True` | **Compatibility parameter** - Ignored by tif1. tif1 uses SQLite-backed caching instead of requests-cache |

#### Returns

- **`tif1.cache.Cache`**: The configured global tif1 cache instance (the same object that `tif1.get_cache()` returns)

#### Behavior Details

When `enable_cache()` is called:

1. **Directory Creation**: Creates the cache directory if it does not exist, with restricted permissions (0o700 on Unix-like systems)
2. **SQLite Initialization**: Sets up the SQLite database with WAL (Write-Ahead Logging) mode for better concurrency
3. **Configuration Update**: Updates the global tif1 configuration to enable caching
4. **Instance Reset**: Closes any existing cache instance and creates a fresh one
5. **Optional Clear**: If `force_renew=True`, clears all cached data

#### Cache Directory Resolution

The cache directory is resolved in the following order of precedence:

1. Explicit `cache_dir` parameter
2. The directory of an earlier `enable_cache()` call in the same process
3. `TIF1_CACHE_DIR` environment variable
4. Configuration file setting (`~/.tif1rc`)
5. Platform-specific default:
   - **Windows**: `%LOCALAPPDATA%/Temp/tif1`
   - **macOS**: `~/Library/Caches/tif1`
   - **Linux/other POSIX**: `~/.cache/tif1` (or `~/.tif1` if `~/.cache` does not exist)

#### Examples

**Basic usage with default location:**
```python
import tif1

# Enable cache with platform-specific default directory
tif1.Cache.enable_cache()

# Now all data fetching will be cached
session = tif1.get_session(2024, "Monaco", "Q")
session.load()  # Data is fetched and cached
```

**Custom cache directory:**
```python
import tif1
from pathlib import Path

# Use a project-specific cache directory
cache_path = Path("./project_cache")
tif1.Cache.enable_cache(cache_dir=cache_path)

# Cache will be stored in ./project_cache/cache.sqlite
```

**Enable cache and clear existing data:**
```python
import tif1

# Start fresh - clear any existing cached data
tif1.Cache.enable_cache(cache_dir="./cache", force_renew=True)
```

**Environment variable configuration:**
```bash
# Set cache directory via environment variable
export TIF1_CACHE_DIR="/mnt/fast-ssd/f1-cache"
```

```python
import tif1

# In a new process, this uses /mnt/fast-ssd/f1-cache automatically
# (an earlier enable_cache("...") call in the same process takes precedence)
tif1.Cache.enable_cache()
```

#### Migration from fastf1

The call is the same, so migration needs few changes:

<CodeGroup>
```python fastf1
import fastf1
fastf1.Cache.enable_cache("./cache")
```

```python tif1
import tif1
tif1.Cache.enable_cache("./cache")
```
</CodeGroup>

Two defaults differ. In fastf1, `cache_dir` is required and `ignore_version` defaults to `False`. In tif1, `cache_dir` is optional and `ignore_version` defaults to `True` (it has no effect).

#### Performance Considerations

- **First call overhead**: Creating a new SQLite database and its tables takes about 10-50ms on a local disk
- **Subsequent calls**: Reusing an existing cache directory is nearly instant
- **Disk usage**: `cache.sqlite` grows with each loaded session. `Cache.get_cache_info()` returns the directory and its size in bytes

#### Thread Safety

`enable_cache()` closes the global cache instance and creates a new one. Call it once during application start-up, before other threads fetch data.

### `Cache.configure`

```python
@classmethod
def configure(
    cls,
    *,
    cache_dir: str | Path | None = None,
    force_renew: bool = False,
    ignore_version: bool = False,
    use_requests_cache: bool = True,
) -> None
```

The fastf1 `Cache.configure()` keywords, mapped onto `enable_cache()`. All arguments are keyword-only.

- `cache_dir`: The cache directory. tif1 creates it when it does not exist (fastf1 requires an existing directory). Without it, tif1 uses the configured directory
- `force_renew`: Clear the cache after enabling it
- `ignore_version`, `use_requests_cache`: Accepted for compatibility. tif1 keeps every payload in its SQLite tiers and has no separate HTTP cache

```python
import tif1

tif1.Cache.configure(cache_dir="./f1_cache")
print(tif1.Cache.get_cache_info()[0])  # .../f1_cache
```

### `Cache.clear_cache`

```python
@classmethod
def clear_cache(
    cache_dir: str | Path | None = None,
    deep: bool = False
) -> None
```

Clear cached data from the specified cache directory. This method removes all cached session data, lap times, telemetry, and other stored information. Use this method to force fresh data fetches or to troubleshoot cache-related issues.

#### Parameters

| Parameter | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `cache_dir` | `str \| Path \| None` | `None` | Optional cache directory path. If `None`, clears the currently active cache directory |
| `deep` | `bool` | `False` | If `True`, also removes legacy FastF1 HTTP cache database files (`fastf1_http_cache.sqlite*`) from `cache_dir`. Only applies when `cache_dir` is given |

#### Behavior Details

The clearing process works as follows:

1. **Active Cache Detection**: If `cache_dir` is `None`, uses the active cache instance (and creates it if needed)
2. **Directory Validation**: If `cache_dir` is given, verifies that it exists and is a directory
3. **SQLite Clearing**: Executes `DELETE` statements on all cache tables
4. **Memory Cache Flush**: Clears in-memory LRU caches
5. **Legacy Cleanup** (if `deep=True` and `cache_dir` is given): Removes FastF1 HTTP cache files for users migrating from fastf1

A `cache_dir` that is not the active directory gets a temporary cache instance, which is closed after the clear.

#### Cache Tables Cleared

- **`cache` table**: Fetched JSON payloads (lap times, drivers, race control messages, weather data), as text or compressed
- **`telemetry_cache` table**: Telemetry data indexed by (year, GP, session, driver, lap)
- **`telemetry_frames` and `telemetry_frames_pl` tables**: Built telemetry frames for the pandas and polars backends
- **`laps_frames` and `laps_frames_pl` tables**: Built laps tables for the pandas and polars backends
- **`missing_payloads` table**: Records of files that no CDN has
- **In-memory caches**: All four in-memory LRU tiers

#### Examples

**Clear the active cache:**
```python
import tif1

# Enable cache
tif1.Cache.enable_cache("./cache")

# ... use tif1 to fetch data ...

# Clear all cached data
tif1.Cache.clear_cache()

# Next data fetch will retrieve fresh data from CDN
```

**Clear a specific cache directory:**
```python
from pathlib import Path

import tif1

# Clear cache in a specific directory without activating it.
# A missing directory raises NotADirectoryError, so check it first.
old_cache = Path("./old_cache")
if old_cache.is_dir():
    tif1.Cache.clear_cache(cache_dir=old_cache)
```

**Deep clean (remove legacy FastF1 files):**
```python
import tif1

# Migrating from fastf1? Remove old HTTP cache files too
tif1.Cache.clear_cache(cache_dir="./cache", deep=True)
```

**Clear cache before important race weekend:**
```python
import tif1

# Ensure fresh data for the latest race
tif1.Cache.enable_cache()
tif1.Cache.clear_cache()

# Fetch latest data
session = tif1.get_session(2024, "Abu Dhabi", "R")
session.load()
```

#### Migration from fastf1

The signature is the same as in fastf1 (`cache_dir=None, deep=False`):

<CodeGroup>
```python fastf1
import fastf1
fastf1.Cache.clear_cache()
```

```python tif1
import tif1
tif1.Cache.clear_cache()
```
</CodeGroup>

#### Error Handling

- **`NotADirectoryError`**: Raised if the specified `cache_dir` does not exist or is not a directory
- **`OSError`** while a legacy file is removed: logged as a warning, not raised

#### Performance Impact

- **Clearing time**: Grows with the number of cached rows
- **Disk usage**: `DELETE` does not make `cache.sqlite` smaller. SQLite keeps the free pages for new data
- **Memory**: In-memory caches are cleared instantly

#### When to Clear Cache

Consider clearing the cache in these scenarios:

- **Data corruption**: When cached data is suspect or invalid
- **Schema changes**: After updating tif1 to a version with data format changes
- **Disk space**: When cache directory grows too large
- **Testing**: To ensure tests fetch fresh data
- **Season updates**: At the start of a new F1 season to remove old data

#### Thread Safety

`clear_cache()` holds the cache locks while it deletes the rows. Do not call it while other threads load data: a load in progress can write its rows again after the clear.

### Other `Cache` Methods

| Method | Behavior |
| :--- | :--- |
| `Cache.disabled(*, disable_http_cache=True, disable_func_cache=True)` | Context manager: caching is off inside the `with` block. The two keywords are the fastf1 cache stages. tif1 has one cache switch, which either keyword turns off. With both `False`, the block runs with caching unchanged. Blocks nest: caching comes back when the outermost block exits |
| `Cache.set_disabled(*, disable_http_cache=True, disable_func_cache=True)` | Sets the `enable_cache` option to `False`, with the same keywords. Calls nest. With both keywords `False`, nothing changes and no `set_enabled()` call is necessary |
| `Cache.set_enabled()` | Undoes one `set_disabled()` call. The last one restores the earlier `enable_cache` value |
| `Cache.offline_mode(enabled)` | Sets the `offline_mode` option. While it is on, `requests_get()` and `requests_post()` raise `NetworkError` |
| `Cache.ci_mode(enabled)` | Sets the `ci_mode` option |
| `Cache.get_cache_info()` | Returns `(cache_dir, size_in_bytes)` after `enable_cache()`, else `(None, None)` |
| `Cache.requests_get(url, **kwargs)` | HTTP GET through the shared tif1 session (default timeout: the `timeout` option) |
| `Cache.requests_post(url, data=None, **kwargs)` | HTTP POST through the shared tif1 session |
| `Cache.delete_response(url)` | Does nothing: tif1 has no FastF1-style HTTP response cache |

```python
import tif1

with tif1.Cache.disabled(disable_http_cache=False, disable_func_cache=True):
    print(tif1.get_config().get("enable_cache"))  # False
```

## Logging Functions

### `set_log_level`

```python
def set_log_level(level: str | int = logging.WARNING) -> None
```

Set the logging level for tif1 logger. `tif1.set_log_level` is `tif1.logger.set_log_level`. `tif1.fastf1_compat.set_log_level` is a separate wrapper that imports `tif1.logger` on its first call and passes `level` to it, so all three have the same effect.

**Parameters:**
- `level`: Python logging level (for example, `logging.DEBUG`, `logging.INFO`, `logging.WARNING`) or its name in any case (`"DEBUG"`, `"info"`). An unknown name raises `ValueError`

The `tif1` logger and its console handler both move to `level`.

**Example:**
```python
import logging
import tif1

# Enable debug logging
tif1.set_log_level(logging.DEBUG)

# Disable most logging
tif1.set_log_level(logging.ERROR)
```
**Migration from fastf1:**

<CodeGroup>
```python fastf1
import fastf1
import logging
fastf1.set_log_level(logging.DEBUG)
```

```python tif1
import tif1
import logging
tif1.set_log_level(logging.DEBUG)
```
</CodeGroup>

### `tif1.logger`

The fastf1 `fastf1.logger` module, with tif1 logger names. Every logger is `tif1` or a `tif1.<name>` child, never `fastf1`. Importing the module adds a console handler with the fastf1 line format to the `tif1` logger and sets that logger to `INFO`.

| Name | Behavior |
| :--- | :--- |
| `LoggingManager` | The fastf1 logging configuration class. `LoggingManager.set_level(level)` moves the console handler and the `tif1` logger. `LoggingManager.get_child(name)` returns `tif1.<name>`. `LoggingManager.debug` is `True` when the environment sets `TIF1_DEBUG=1` |
| `get_logger(name)` | Returns the logger `tif1.<name>` |
| `set_log_level(level)` | The function above |
| `soft_exceptions(descr_name, msg, logger)` | A decorator for data-loading functions. An exception in the wrapped function is logged (`msg` as a warning, the traceback at DEBUG level), and the call returns `None`. A `FastF1CriticalError` is always raised again. With `LoggingManager.debug`, nothing is caught |

```python
from tif1.logger import get_logger, soft_exceptions

logger = get_logger("my_analysis")  # The logger "tif1.my_analysis"


@soft_exceptions("weather summary", "Weather summary failed", logger)
def weather_summary(session):
    return session.weather["AirTemp"].mean()


print(logger.name)
print(weather_summary(None))  # Logs "Weather summary failed" and prints None
```

## `tif1.legacy`

### `inject_driver_ahead`

```python
def inject_driver_ahead(session) -> dict[str, Telemetry]
```

The fastf1 `fastf1.legacy.inject_driver_ahead()` function. It returns a dict keyed by driver number (the labels of `session.drivers`). Each value is the session-long `session.pos_data` telemetry of the driver. tif1 telemetry already carries `DriverAhead` and `DistanceToDriverAhead`, so the function only collects the frames. It reads the telemetry of every driver, which is slow on a cold cache. When no driver has telemetry, it raises `ValueError`, as fastf1 does.

```python
import tif1
from tif1.legacy import inject_driver_ahead

session = tif1.get_session(2025, "Bahrain Grand Prix", "Race")
by_driver = inject_driver_ahead(session)
print(by_driver["1"][["SessionTime", "DriverAhead", "DistanceToDriverAhead"]].head())
```

## Complete migration example

This complete example shows how to migrate a fastf1 script to tif1:

**Original fastf1 code:**
```python fastf1
import fastf1
import logging

# Setup
fastf1.Cache.enable_cache("./cache")
fastf1.set_log_level(logging.INFO)

# Load session
session = fastf1.get_session(2024, "Monaco", "Q")
session.load()

# Get the fastest lap of one driver
fastest = session.laps.pick_drivers("VER").pick_fastest()

# Get telemetry
tel = fastest.get_telemetry()
print(f"Max speed: {tel['Speed'].max()}")
```

**Migrated tif1 code (minimal changes):**
```python
import tif1
import logging

# Setup (same calls)
tif1.Cache.enable_cache("./cache")
tif1.set_log_level(logging.INFO)

# Load session (same calls)
session = tif1.get_session(2024, "Monaco", "Q")
session.load()

# Get the fastest lap of one driver (same calls)
fastest = session.laps.pick_drivers("VER").pick_fastest()

# Get telemetry (same calls)
tel = fastest.get_telemetry()
print(f"Max speed: {tel['Speed'].max()}")
```

## API Differences

While tif1 maintains API compatibility, there are some differences to be aware of:

### Supported Features

| Feature | fastf1 | tif1 | Notes |
| :--- | :--- | :--- | :--- |
| `Cache.enable_cache()` | ✅ | ✅ | Same call; `cache_dir` is optional in tif1 |
| `Cache.clear_cache()` | ✅ | ✅ | Same signature |
| `set_log_level()` | ✅ | ✅ | Same call |
| `get_session()` | ✅ | ✅ | Same call, with the fastf1 `identifier=`, `exact_match=`, and `backend=` keywords; tif1 adds `enable_cache`, `lib`, `ergast`, and `force_ergast` (a deprecated tif1 alias of `backend="ergast"`) |
| `Session.load()` | ✅ | ✅ | `laps`, `telemetry`, `weather`, `messages` flags. `livedata` raises `NotImplementedError` |
| `Session.laps` | ✅ | ✅ | Same call |
| `Session.get_driver()` | ✅ | ✅ | Same call; returns the `results` row of the driver. An unknown identifier raises `DriverNotFoundError`, a `ValueError` as in fastf1 |
| `Session.track_status`, `session_status`, `session_info` | ✅ | ✅ | Derived from race control messages and the schedule |
| `Cache.configure()`, `Cache.disabled(...)` | ✅ | ✅ | Same keywords |
| `fastf1.logger`, `fastf1.legacy`, `fastf1.mvapi` | ✅ | ✅ | `tif1.logger`, `tif1.legacy`, `tif1.mvapi` |
| `Driver.laps` | ✅ | ✅ | Same call |
| `Lap.get_telemetry()` | ✅ | ✅ | Same call |

### Ignored Parameters

Some fastf1 parameters are ignored in tif1 because they are handled automatically:

- `Cache.enable_cache(ignore_version)` and `Cache.configure(ignore_version=...)`: tif1 handles versioning automatically
- `Cache.enable_cache(use_requests_cache)` and `Cache.configure(use_requests_cache=...)`: tif1 uses SQLite cache

`Cache.enable_cache(force_renew=True)` is not ignored: it clears the cache after enabling it.

### Performance Improvements

tif1 provides significant performance improvements while maintaining API compatibility:

- **Async loading**: `session.laps_async()` for parallel data fetching
- **Ultra-cold start**: the `ultra_cold_start` option (on by default) for first-time loads
- **HTTP/2 multiplexing**: Faster parallel requests
- **Optimized caching**: SQLite-backed multi-layer cache

## Compatibility Checklist

When migrating from fastf1 to tif1:

- [ ] Replace `import fastf1` with `import tif1`
- [ ] Update `Cache.enable_cache()` calls (same call)
- [ ] Update `set_log_level()` calls (same call)
- [ ] Test that `get_session()` works with the year/GP/session combinations in use
- [ ] Verify DataFrame column names match (tif1 uses fastf1 naming conventions)
- [ ] Consider using async methods (`laps_async()`, `get_fastest_laps_tels_async()`) for better performance
- [ ] Update any custom caching logic (tif1 handles caching automatically)

## Ergast data

`tif1.ergast` is a drop-in for `fastf1.ergast`. `from tif1.ergast import Ergast` keeps the thirteen endpoint methods, their keyword arguments, the flattened column names, the response classes and the legacy `fetch_season`/`fetch_day`/`fetch_results` helpers. The data comes from the TracingInsights Stats repository first and from the Jolpica API only for what that repository cannot answer. The 500-requests-per-hour ceiling therefore stays out of the way for season-wide queries. `Session.results` carries the official classification (grid, points, status, race time, qualifying segments) and `get_session`, `get_event` and `get_event_schedule` accept fastf1's `backend=` keyword. Refer to [Ergast](/api-reference/ergast).

## Known Limitations

The following fastf1 features are not supported in tif1:

- **Live timing**: tif1 focuses on historical data. `session.load(livedata=...)` raises `NotImplementedError` for any value other than `None`
- **F1 account sign-in**: `set_auth_method()` and `F1AuthError` do not exist, because tif1 needs no account
- **Internal modules**: `fastf1.livetiming`, `fastf1.req`, `fastf1.api`, and `fastf1.internals` have no tif1 equivalent
- **Custom data sources**: the `cdns` setting can point at a mirror, but the mirror must use the same file layout as the TracingInsights repositories

When these features are needed, continue using fastf1 or open an issue on the tif1 GitHub repository.
