## Overview

The `http_session` module provides HTTP session management for tif1. It implements a thread-safe singleton pattern with connection pooling, a configurable DNS resolver list, and request counters. This infrastructure supports high-throughput parallel data fetching with low network overhead.

### Why HTTP Session Management Matters

Formula 1 session data is spread across many JSON files on CDN servers. A session load requests one file per payload:
- **A few requests** for the session tables (drivers, laps, weather, race control messages)
- **One request per driver lap** for telemetry, so a full race with telemetry can need more than 1000 requests

Without connection reuse, each request would pay for a new connection:
- **DNS resolution** of the CDN host name
- **TCP handshake**: one round trip
- **TLS handshake**: one or two round trips

The http_session module removes most of this overhead. It keeps one pooled session and reuses its open connections for later requests.

### Key Features

- **Thread-safe singleton pattern**: Single shared session across all threads and requests
- **Aggressive connection pooling**: Dynamically sized pools based on concurrency settings
- **HTTP/2 multiplexing**: Multiple requests over single connections (on by default, `http_multiplexed`)
- **HTTP/3 support**: QUIC, off by default (`http_disable_http3`)
- **Resolver list**: Configurable DNS resolvers, including DNS-over-HTTPS (DoH) entries (see [DoH support](#dns-over-https-doh-support))
- **Request counters**: Counts of the HTTP requests that tif1 sends through the shared session
- **Keep-alive headers**: Configurable `Keep-Alive` timeout and request limit values
- **Automatic resource cleanup**: Graceful shutdown on process exit
- **No environment settings**: `trust_env` is off, so the session does not read proxy variables (such as `HTTPS_PROXY`) or `.netrc` files

## Core API

### `get_session`

```python
def get_session() -> niquests.Session
```

Retrieve or create the shared HTTP session using a thread-safe singleton pattern. This function implements double-checked locking to ensure only one session instance exists across all threads while minimizing lock contention.

**Thread Safety:**
The function uses a module-level lock (`_session_lock`) to ensure thread-safe initialization. Once the session is created, subsequent calls return the cached instance without acquiring the lock. This keeps the common case free of lock contention.

**Session Lifecycle:**
1. First call creates the session with optimized settings
2. Subsequent calls return the cached instance
3. Session persists until process exit or explicit `close_session()` call
4. Automatic cleanup registered via `atexit` handler

**Returns:**
- `niquests.Session`: Shared session instance configured with:
  - Dynamic connection pooling based on concurrency settings
  - The first resolver from `http_resolvers` that builds a session
  - HTTP/2 multiplexing (if enabled)
  - HTTP/3 only when `http_disable_http3` is `False` (the default is `True`)
  - Keep-alive headers with configurable timeouts
  - Disabled `trust_env` for predictable behavior

**Implementation Details:**

The session is configured with:
- **HTTPAdapter** mounted on `https://` with custom pool settings
- **Connection pooling**: `pool_connections` and `pool_maxsize` dynamically calculated
- **Keep-alive headers**: `Connection: keep-alive` with timeout and max request limits
- **Resolver list**: Tries each entry of `http_resolvers` in order. It moves to the next entry only when session creation raises an error
- **Multiplexing**: HTTP/2 multiplexing enabled by default

**Performance Characteristics:**
- **First call**: Builds the session and mounts its adapter. DNS lookups and connections happen at the first request, not here
- **Subsequent calls**: Return the cached instance without a lock

**Example:**
```python
from tif1.http_session import get_session

# Get the shared session (creates on first call)
session = get_session()

# Make requests (connection pooling automatic)
url = "https://cdn.jsdelivr.net/gh/TracingInsights/2021@main/Belgian%20Grand%20Prix/Race/drivers.json"
response = session.get(url, timeout=30)
print(f"Status: {response.status_code}")  # 200

# Session is reused across all tif1 operations
# No need to close manually (automatic cleanup on exit)
```

**Advanced Usage:**
```python
from tif1.http_session import close_session, get_session
import tif1

# Set the pool sizes for the next session that tif1 builds
config = tif1.get_config()
config.set("pool_connections", 512)
config.set("pool_maxsize", 2048)
config.set("http_multiplexed", True)

# Close the shared session (if one exists), then build a new one with these settings
close_session()
session = get_session()

# Check session configuration
adapter = session.get_adapter("https://")
print(f"Pool connections: {adapter._pool_connections}")
print(f"Pool maxsize: {adapter._pool_maxsize}")
```

<Warning>
  This is an internal API. Most users do not need to interact with the HTTP session directly. The library handles all HTTP requests automatically through `Session.load()` and related methods.
</Warning>

<Note>
  Configuration changes only take effect when tif1 builds a session. To apply new settings, call `tif1.async_fetch.close_session()` and then `close_session()` from this module. The first call drops the reference that the async fetch layer keeps to the old session. The next `get_session()` call builds a new session.
</Note>

## Connection Statistics

### `get_connection_stats`

```python
def get_connection_stats() -> dict[str, Any]
```

Get current connection pool statistics for monitoring and debugging.

**Returns:**
- Dictionary with connection metrics:
  - `total_requests`: Number of payload requests that tif1 sent through the shared session
  - `connections_reused`: Number of those requests that used an open pooled connection
  - `connections_created`: Number of shared sessions created
  - `reuse_rate`: `connections_reused` as a percentage of `total_requests` (0-100)

<Note>
  tif1 counts a request as reused when niquests reports no connection or TLS handshake time for it. The first request on a new connection is not reused. Data served from the cache makes no request, so a session that loads from the cache leaves the request counters at 0. During `Session.load()`, tif1 fetches the session tables through a separate short-lived niquests session, and these counters do not include those requests.
</Note>

**Example:**
```python
from tif1.http_session import get_connection_stats

stats = get_connection_stats()
print(f"Total requests: {stats['total_requests']}")
print(f"Reuse rate: {stats['reuse_rate']:.1f}%")
```

### `reset_connection_stats`

```python
def reset_connection_stats() -> None
```

Reset connection statistics. Useful for testing or benchmarking.

**Example:**
```python
from tif1.http_session import reset_connection_stats

reset_connection_stats()
```

## Configuration

The HTTP session is configured via the global config object. Key settings:

| Config Key | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `http_multiplexed` | `bool` | `True` | Enable HTTP/2 multiplexing |
| `http_disable_http3` | `bool` | `True` | Disable HTTP/3 (QUIC); HTTP/2 over TCP is the default |
| `http_revocation_check` | `bool` | `True` | Check the certificate for revocation (OCSP) on the first connection; `False` skips it (120-240 ms per cold process), the chain is verified either way |
| `pool_connections` | `int` | Dynamic (min 256) | Number of connection pools (auto-sized based on concurrency) |
| `pool_maxsize` | `int` | Dynamic (min 512) | Maximum connections per pool (auto-sized to 4x pool_connections; a set value below 512 is raised to 512) |
| `keepalive_timeout` | `int` | `120` | Timeout value (seconds) sent in the `Keep-Alive` header |
| `keepalive_max_requests` | `int` | `10000` | Request limit sent in the `Keep-Alive` header |
| `http_resolvers` | `list[str]` | `["standard", "doh+cloudflare://", "doh+google://"]` | DNS resolvers to try in order when tif1 creates the session |

**Example:**
```python
import tif1

config = tif1.get_config()

# Disable HTTP/2 multiplexing (enabled by default)
config.set("http_multiplexed", False)

# Override automatic pool sizing
config.set("pool_connections", 512)
config.set("pool_maxsize", 2048)

# Configure DNS resolvers
config.set("http_resolvers", ["standard", "doh+cloudflare://"])
```

## DNS-over-HTTPS (DoH) Support

The `http_resolvers` list sets the DNS resolvers that tif1 passes to niquests. tif1 tries the entries in order only when it creates the shared session. It moves to the next entry only when session creation raises an error. A failed DNS lookup during a request does not switch the resolver.

**Default resolver order:**
1. Standard DNS (`"standard"`)
2. `doh+cloudflare://`
3. `doh+google://`

<Note>
  The resolver strings use niquests' `<scheme>+<provider>://` form. The older spelling `doh://cloudflare` is still accepted in `.tif1rc` and is translated to `doh+cloudflare://`. tif1 passes the chosen resolver to the pooled `HTTPAdapter` it mounts on `https://`, so HTTPS requests use it.
</Note>

**Custom resolvers:**
```python
import tif1

config = tif1.get_config()

# DoH resolvers in the niquests URL format
config.set("http_resolvers", ["doh+cloudflare://", "doh+google://"])

# Standard DNS only
config.set("http_resolvers", ["standard"])
```

## Connection Pooling

The HTTP session uses aggressive connection pooling for maximum performance:

- **Connection reuse**: Keeps connections alive for multiple requests
- **Pool sizing**: Dynamically sized based on concurrency settings
- **Keep-alive**: Configurable `Keep-Alive` header values
- **Thread-safe**: Single shared session across all threads

**Performance benefits:**
- Eliminates TCP handshake overhead
- Reduces TLS negotiation time
- Improves throughput for parallel requests
- Lowers latency for sequential requests

**Example monitoring:**
```python
import tif1
from tif1.http_session import get_connection_stats

# Load session data (2021 Belgian Grand Prix Race)
session = tif1.get_session(2021, "Belgian Grand Prix", "Race")
session.load()

# Check the request counters (all 0 when the session loads from the cache)
stats = get_connection_stats()
print(f"Requests: {stats['total_requests']}")
print(f"Reused: {stats['connections_reused']}")
print(f"Reuse rate: {stats['reuse_rate']:.1f}%")
```

## Advanced Configuration

### HTTP/2 Multiplexing

HTTP/2 multiplexing is enabled by default to send multiple requests over a single connection. Disable it when needed:

```python
import tif1

config = tif1.get_config()
config.set("http_multiplexed", False)
```

<Note>
  HTTP/2 multiplexing is enabled by default. Disable it only when a specific CDN configuration causes issues.
</Note>

### Custom pool sizing

Pool sizes are calculated from the concurrency settings. Override them only for specific requirements:

```python
import tif1

config = tif1.get_config()

# For high concurrency (e.g., loading full season data)
config.set("pool_connections", 512)
config.set("pool_maxsize", 2048)

# For low concurrency (e.g., single session analysis)
config.set("pool_connections", 64)
config.set("pool_maxsize", 512)  # values below 512 are raised to 512
```

<Note>
  The library automatically sizes connection pools based on `max_workers`, `max_concurrent_requests`, and `telemetry_prefetch_max_concurrent_requests` settings. Manual override is rarely needed.
</Note>

### Keep-Alive Tuning

These values only set the `Keep-Alive` request header. The server decides how long it keeps a connection open.

```python
import tif1

config = tif1.get_config()

# Longer keep-alive for stable connections
config.set("keepalive_timeout", 300)
config.set("keepalive_max_requests", 5000)

# Shorter keep-alive for unstable connections
config.set("keepalive_timeout", 30)
config.set("keepalive_max_requests", 100)
```

## Troubleshooting

### Connection pool exhaustion

Increase the pool size when connection pool warnings appear:

```python
import tif1

config = tif1.get_config()
config.set("pool_maxsize", 1024)
```

### DNS Resolution Failures

tif1 does not switch to DoH when a DNS lookup fails during a request. To use DoH, put a DoH entry first in `http_resolvers` and rebuild the shared session:

```python
import tif1
from tif1 import async_fetch, http_session

config = tif1.get_config()
config.set("http_resolvers", ["doh+cloudflare://", "doh+google://"])

# The resolver applies when tif1 builds a session
async_fetch.close_session()
http_session.close_session()
```

### Connection reuse issues

The counters show how many payload requests went to the network. They also show how many of them used an open connection (see [Connection Statistics](#connection-statistics)):

```python
from tif1.http_session import get_connection_stats

stats = get_connection_stats()
if stats["total_requests"] == 0:
    print("No network requests yet (data came from the cache)")
else:
    print(f"Network requests: {stats['total_requests']}")
    print(f"Reuse rate: {stats['reuse_rate']:.1f}%")
```

## Best Practices

1. **Do not create multiple sessions**: Use the shared session for all requests
2. **Monitor connection stats**: Track how many requests reach the network
3. **Tune pool size**: Match the pool size to the concurrency needs
4. **Use DoH when system DNS is unreliable**: Put a DoH entry first in `http_resolvers`
5. **Keep HTTP/2 multiplexing on**: It is the default. Disable it only when a CDN causes errors
6. **Let the library manage cleanup**: Session closes automatically on exit
