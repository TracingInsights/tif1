<Info>
  The `utils` module provides a suite of utility functions designed to simplify working with Formula 1 data. These functions handle common tasks such as time format conversions, lap-by-lap performance comparisons, and safe nested data access.
</Info>

## Overview

The `tif1.utils` module is a set of helpers for analysis code, compatible with `fastf1.utils`. It provides four primary categories of functionality:

1. **Time Conversion Functions**: Convert between various time representations (strings, floats, timedeltas, timestamps)
2. **Performance Analysis Functions**: Calculate lap-by-lap deltas and performance metrics
3. **Data Access Helpers**: Safely navigate nested data structures
4. **FastF1 Compatibility**: Maintain API compatibility with the FastF1 library

Session loading does not use these helpers: `tif1` builds its time columns with vectorized pandas or Polars code. Use the helpers on custom data, such as timing strings from a CSV file.

<Note>
  `recursive_dict_get` and `delta_time` return defaults (`{}`, `None` or an empty Series) instead of raising. `to_timedelta` and `to_datetime` raise the pandas error for input that pandas cannot parse.
</Note>

## Time Conversion Functions

Time conversion is a critical part of working with Formula 1 data. Timing information arrives in multiple formats. These formats include ISO strings from the API, numeric seconds from telemetry, and formatted strings from timing screens. The utilities module provides converters that handle all these formats.

### `to_timedelta`

```python
def to_timedelta(x: Any) -> pd.Timedelta
```

Converts various time representations to a standardized pandas Timedelta object. Use it for single lap, sector, or session time values in custom data.

#### Parameters

- **`x`** (`Any`): Time value in any of the following formats:
  - **`datetime.timedelta`**: Returned unchanged (passthrough)
  - **`str`**: Parsed as a time string with automatic format detection
    - Short format: `"1:23.456"` (minutes:seconds.milliseconds) → automatically prepended with `"00:"` to become `"00:01:23.456"`
    - Full format: `"00:01:23.456"` (hours:minutes:seconds.milliseconds)
    - ISO 8601 duration format: `"PT1M23.456S"`
  - **`int` or `float`**: Interpreted as seconds (for example, `83.456` → 1 minute 23.456 seconds)
  - **`numpy.float64`**: Interpreted as seconds (a subclass of `float`)
  - Any other pandas-compatible time format

<Warning>
  A `numpy.integer` or `numpy.float32` value is not an `int` or `float` subclass, so `pd.to_timedelta()` reads it as nanoseconds. For example, `to_timedelta(np.int64(90))` gives 90 ns. Convert the value with `int()` or `float()` first.
</Warning>

#### Returns

- **`pd.Timedelta`**: A pandas Timedelta object representing the time duration. A `datetime.timedelta` input is returned unchanged.

#### Behavior Details

The function implements automatic format detection:

1. **Passthrough for timedelta**: If the input is already a `datetime.timedelta`, it is returned immediately without conversion overhead
2. **String parsing with auto-formatting**: String inputs are analyzed for colon count:
   - If exactly one colon is found (for example, `"1:23.456"`), the function prepends `"00:"` to create a valid hours:minutes:seconds format
   - This allows users to input lap times naturally without typing leading zeros
3. **Numeric conversion**: Integer and float inputs are treated as seconds and converted using pandas' optimized `to_timedelta(x, unit="s")`
4. **Fallback to pandas**: Any other format is passed directly to `pd.to_timedelta()` for pandas' native parsing

#### Performance Characteristics

- **O(1) complexity** for all input types
- **Zero-copy** for timedelta passthrough
- **Scalars, not Series**: A pandas Series goes straight to `pd.to_timedelta()` without a unit, so numbers become nanoseconds
- **Errors**: Empty strings and `None` give `NaT`; an unparseable string such as `"garbage"` raises `ValueError` (pandas behavior)
- **Short strings in a Series**: A Series of `"m:ss.sss"` strings raises `ValueError`. Use `.apply(to_timedelta)` for such a Series, and `pd.to_timedelta(s, unit="s")` for a Series of seconds

#### Examples

**Basic conversions:**
```python
from tif1.utils import to_timedelta

# From lap time string (short format)
lap_time = to_timedelta("1:23.456")
print(lap_time)  # 0 days 00:01:23.456000
print(lap_time.total_seconds())  # 83.456

# From lap time string (full format)
lap_time_full = to_timedelta("00:01:23.456")
print(lap_time_full.total_seconds())  # 83.456

# From numeric seconds
lap_time_numeric = to_timedelta(83.456)
print(lap_time_numeric)  # 0 days 00:01:23.456000

# From integer seconds
lap_time_int = to_timedelta(90)
print(lap_time_int)  # 0 days 00:01:30

# From existing timedelta (passthrough)
import datetime
td = datetime.timedelta(minutes=1, seconds=23, milliseconds=456)
lap_time_td = to_timedelta(td)
print(lap_time_td)  # 0:01:23.456000 (the same datetime.timedelta object)
```

**Working with lap data:**
```python
import tif1

# Find fastest lap

print(f"Fastest lap: {fastest}")  # 0 days 00:01:09.876000

# Calculate gaps

print(f"Gaps: {[g.total_seconds() for g in gaps]}")  # [0.247, 0.0, 1.358]
```

```python
# 2    LEC  1:11.234 0 days 00:01:11.234000 0 days 00:00:01.358000
```

**Handling edge cases:**
```python

# Very small times (milliseconds)

print(milliseconds)  # 0 days 00:00:00.123000

print(negative)  # -1 days +23:59:54.500000
```

</Warning>

### `to_datetime`

```python
def to_datetime(x: Any) -> pd.Timestamp
```

Converts various datetime representations to a standardized pandas Timestamp object. Use it for single timestamps in custom data, such as event start times.

#### Parameters

- **`x`** (`Any`): Datetime value in any of the following formats:
  - **`str`**: ISO 8601 format (`"2025-05-25T14:00:00Z"`) or other common datetime strings
  - **`datetime.datetime`**: Python datetime objects
  - **`int` or `float`**: Nanoseconds since the epoch (pandas default), not Unix seconds. `to_datetime` has no `unit` argument; use `pd.to_datetime(x, unit="s")` for Unix seconds
  - **`pd.Timestamp`**: Pandas Timestamp (passthrough)
  - Any other pandas-compatible datetime format

#### Returns

- **`pd.Timestamp`**: A pandas Timestamp object representing the datetime

#### Behavior Details

This function is a thin wrapper around pandas' `pd.to_datetime()` function, providing:

1. **Automatic format detection**: Pandas detects ISO 8601, RFC 3339, and common datetime string formats
2. **Numeric input**: Numbers are read as nanoseconds since the epoch
3. **Timezone awareness**: Preserves timezone information when present in the input
4. **Output type**: A scalar input gives a pandas Timestamp (`NaT` for `None`). A list gives a `DatetimeIndex`

#### Performance Characteristics

- **O(1) complexity** for all input types
- **Delegates to pandas**: Uses pandas' optimized C-based datetime parsing
- **Timezone-aware**: Handles both naive and timezone-aware datetimes
- **Error handling**: An unparseable string raises `ValueError`; `None` gives `NaT`

#### Examples

**Basic conversions:**
```python
from tif1.utils import to_datetime

# From ISO 8601 string
dt1 = to_datetime("2025-05-25T14:00:00Z")
print(dt1)  # 2025-05-25 14:00:00+00:00

# From common datetime string
dt2 = to_datetime("2025-05-25 14:00:00")
print(dt2)  # 2025-05-25 14:00:00

# From datetime object
import datetime
dt3 = to_datetime(datetime.datetime(2025, 5, 25, 14, 0, 0))
print(dt3)  # 2025-05-25 14:00:00

# From a Unix timestamp in seconds: use pandas with unit="s".
# to_datetime(1748181600) reads the number as nanoseconds (1970-01-01 00:00:01.748181600).
import pandas as pd
dt4 = pd.to_datetime(1748181600, unit="s")
print(dt4)  # 2025-05-25 14:00:00
```

**Working with session data:**

</Note>

## Performance Analysis Functions

Performance analysis is central to Formula 1 data science. The utilities module provides functions to compare lap performance and calculate time deltas. These functions identify where drivers gain or lose time on track.

### `delta_time`

```python
def delta_time(
    reference_lap: Lap | pd.DataFrame,
    compare_lap: Lap | pd.DataFrame,
) -> tuple[pd.Series, pd.DataFrame, pd.DataFrame]
```

Estimates the time delta between two laps at each telemetry sample of the reference lap. The algorithm follows `fastf1.utils.delta_time`, without the distance scaling of recent FastF1 versions (see [FastF1 Compatibility](#fastf1-compatibility)). It shows where along the track one lap gains or loses time against the other.

#### Parameters

- **`reference_lap`** (`Lap` or telemetry DataFrame): The baseline lap
  - A `Lap` from `laps.pick_fastest()` or `driver.get_lap(n)`, or a telemetry frame with `Time` and `Distance`
  - Telemetry is fetched through `get_car_data()` (Polars frames are converted to pandas)

- **`compare_lap`** (`Lap` or telemetry DataFrame): The lap to compare against the reference
  - Accepts the same kinds of input as `reference_lap`

#### Returns

A tuple containing three elements:

1. **`delta`** (`pd.Series`, float64): Estimated time delta in seconds
   - **Index**: The index of the reference telemetry (one value per reference sample), not the distance
   - **Values**: Positive = the compare lap reached that point later (slower); negative = earlier (faster)
   - **Empty Series**: When either lap has fewer than two samples or no `Time`/`Distance` columns

2. **`reference_telemetry`** (`pd.DataFrame`): Telemetry of the reference lap
   - Contains all telemetry channels: `Time`, `Speed`, `RPM`, `nGear`, `Throttle`, `Brake`, `DRS`, `Distance`, etc.
   - Shares its index with `delta`; plot `delta` against `reference_telemetry["Distance"]`

3. **`compare_telemetry`** (`pd.DataFrame`): Telemetry of the comparison lap, unchanged
   - Same columns as the reference telemetry, but its own index and length (not resampled)

#### Algorithm Details

The delta time calculation follows these steps:

1. **Telemetry Retrieval**: Gets the telemetry of both laps with `get_car_data()` (adds `Distance` from `Speed` if it is missing)
2. **Time in Seconds**: Converts both `Time` channels to float seconds
3. **Distance Alignment**: Linearly interpolates (`np.interp`) the compare-lap time at each reference `Distance`
4. **Delta Calculation**: Subtracts the reference time from the interpolated compare time

The result shows:
- **Positive delta**: Compare lap is behind at that point (slower)
- **Negative delta**: Compare lap is ahead at that point (faster)
- **Zero delta**: Both laps are equal at that point

<Note>
  The delta is an estimate. `Distance` comes from integrated speed, so small errors add up along the lap. The last delta value can differ from the real lap time gap by a few tenths of a second. For the total gap, subtract the `LapTime` values.
</Note>

#### Performance Characteristics

- **Complexity**: O(n + m) linear interpolation over the n reference and m compare samples
- **Memory**: Requires the telemetry of both laps (several hundred samples per lap)
- **Interpolation**: Uses NumPy linear interpolation
- **Accuracy**: Limited by the telemetry sample rate (about 7-9 Hz) and the integrated `Distance` channel

#### Examples

**Basic delta time comparison:**
```python
import tif1
from tif1.utils import delta_time

# Load session and get driver data
session = tif1.get_session(2024, "Monaco Grand Prix", "Qualifying")

# Get fastest laps for two drivers (pick_fastest() returns a Lap)
ver = session.get_driver("VER")
ham = session.get_driver("HAM")

ver_fastest = ver.laps.pick_fastest()
ham_fastest = ham.laps.pick_fastest()

# Calculate delta
delta, ver_tel, ham_tel = delta_time(ver_fastest, ham_fastest)

# Analyze the delta (positive = HAM reached that point later than VER)
print(f"Largest VER lead on the lap: {delta.max():.3f}s")
print(f"Largest HAM lead on the lap: {-delta.min():.3f}s")

# The delta is an estimate: take the total gap from LapTime
gap = (ham_fastest["LapTime"] - ver_fastest["LapTime"]).total_seconds()
print(f"Lap time gap (LapTime): {gap:.3f}s")
print(f"Estimated gap at the line (delta): {delta.iloc[-1]:.3f}s")
```

**Identifying key performance differences:**
```python
import tif1
from tif1.utils import delta_time
import numpy as np

session = tif1.get_session(2024, "Monaco Grand Prix", "Qualifying")

# Get laps
ver = session.get_driver("VER")
ham = session.get_driver("HAM")
ver_fastest = ver.laps.pick_fastest()
ham_fastest = ham.laps.pick_fastest()

# Calculate delta
delta, ver_tel, ham_tel = delta_time(ver_fastest, ham_fastest)

# Time gained or lost between consecutive reference samples
step = delta.diff()
top_5_changes = step.abs().nlargest(5)

print("Top 5 locations with the biggest time changes:")
for idx in top_5_changes.index:
    distance = ver_tel.loc[idx, 'Distance']
    change = step.loc[idx]
    speed_ver = ver_tel.loc[idx, 'Speed']
    # ham_tel has its own index: interpolate its speed at the same distance
    speed_ham = np.interp(distance, ham_tel['Distance'], ham_tel['Speed'])

    # delta rises where HAM loses time and falls where HAM gains time
    gaining_driver = "VER" if change > 0 else "HAM"

    print(f"\nDistance: {distance:.0f}m")
    print(f"  {gaining_driver} gains {abs(change):.3f}s here")
    print(f"  VER speed: {speed_ver:.1f} km/h")
    print(f"  HAM speed: {speed_ham:.1f} km/h")
```

#### Interpretation Guidelines

When analyzing delta time plots:

- **Consistent positive delta**: Compare driver is consistently slower (setup or skill gap)
- **Consistent negative delta**: Compare driver is consistently faster
- **Oscillating delta**: Different driving styles or lines through corners
- **Sharp spikes**: Mistakes, traffic, or yellow flags
- **Gradual changes**: Tire degradation or fuel load differences
- **Sector-specific patterns**: Car strengths/weaknesses in different corner types

<Warning>

## Data Access Functions

Working with nested JSON data from Formula 1 APIs requires safe navigation through complex data structures. The utilities module provides helper functions to access nested dictionary values without raising exceptions.

### `recursive_dict_get`

```python
def recursive_dict_get(
    d: dict,
    *keys: str,
    default_none: bool = False
) -> Any
```

Safely accesses nested dictionary values using a sequence of keys. The function returns a default value if any key in the path does not exist. This function eliminates the need for multiple `try-except` blocks or chained `.get()` calls.

#### Parameters

- **`d`** (`dict`): The dictionary to traverse
  - Can be any nested dictionary structure
  - Typically JSON data from API responses

- **`*keys`** (`str`): Variable number of keys defining the path to traverse
  - Each key represents one level deeper in the nested structure
  - Keys are applied in order: `d[key1][key2][key3]...`
  - Can be any number of keys (0 to N)

- **`default_none`** (`bool`, optional): Controls the default return value
  - `False` (default): Returns empty dict `{}` when key path not found
  - `True`: Returns `None` when key path not found

#### Returns

- **`Any`**: The value at the specified key path, or the default value if not found
  - If all keys exist: Returns the value at the final key
  - If any key missing and `default_none=False`: Returns `{}`
  - If any key missing and `default_none=True`: Returns `None`

#### Behavior Details

The function traverses the dictionary iteratively:

1. **Start with root**: Begins with the input dictionary `d`
2. **Apply each key**: For each key in `*keys`, tries to access `d[key]`
3. **Handle missing keys**: If `KeyError` or `TypeError` occurs, returns the default value
4. **Return final value**: If all keys exist, returns the value at the final key

The function handles two types of errors:
- **`KeyError`**: Raised when a key does not exist in the dictionary
- **`TypeError`**: Raised when trying to index a non-dict value (for example, `None[key]`)

#### Performance Characteristics

- **Complexity**: O(n) where n is the number of keys
- **Memory**: O(1) - no additional data structures created
- **Safe for dicts**: Catches `KeyError` and `TypeError`; an out-of-range list index still raises `IndexError`
- **Efficient**: Short-circuits on first missing key

#### Examples

```python
    print("Key exists but value is empty dict")
```

#### Common Use Cases

1. **API response parsing**: Safely extract data from JSON responses without try-except blocks
2. **Configuration files**: Access nested configuration values with defaults
3. **Data validation**: Check for presence of required fields in nested structures
4. **ETL pipelines**: Extract data from complex nested sources
5. **Error handling**: Gracefully handle missing or malformed data
6. **Data exploration**: Probe unknown data structures without raising exceptions

#### Integration with tif1

`tif1` does not call `recursive_dict_get` internally. It is a `fastf1.utils`-compatible helper for parsing custom JSON in user code.

#### Best Practices

**When to use `default_none=False` (default):**
- When processing must continue even if data is missing
- When the code iterates over results (empty dict is safe to iterate)
- When `or` supplies fallback values
- When data structures are built incrementally

**When to use `default_none=True`:**
- When the code must distinguish between "missing" and "empty"
- For explicit `None` checks with `is None`
- When validating required fields
- When missing data must raise errors

<Note>
  The function returns the default value on the first missing key. It short-circuits and does not traverse the entire key path when an early key is missing.
</Note>

<Tip>
  For deeply nested structures with many optional fields, consider using `default_none=True` and checking for `None` explicitly. This makes the intent of the code clearer and helps distinguish missing data from empty values.
</Tip>

```python
    )
```

```python
    weather_data = recursive_dict_get(

    )

    drivers = recursive_dict_get(

    )
    metadata['driver_count'] = len(drivers) if isinstance(drivers, list) else 0

            lap_json, "driver", "team", default_none=True
        )

        # Extract lap timing
        lap_time_str = recursive_dict_get(
            lap_json, "timing", "lap_time", default_none=True
        )
        if lap_time_str:
            try:
                lap_data['LapTime'] = to_timedelta(lap_time_str)
                lap_data['LapTimeSeconds'] = lap_data['LapTime'].total_seconds()
            except ValueError:
                lap_data['LapTime'] = pd.NaT
                lap_data['LapTimeSeconds'] = None

        # Extract sector times
        for sector_num in [1, 2, 3]:
            sector_time_str = recursive_dict_get(
                lap_json, "timing", f"sector_{sector_num}", default_none=True
            )
            if sector_time_str:
                try:
                    lap_data[f'Sector{sector_num}Time'] = to_timedelta(sector_time_str)
                except ValueError:
                    lap_data[f'Sector{sector_num}Time'] = pd.NaT

        # Extract lap number
        lap_data['LapNumber'] = recursive_dict_get(
            lap_json, "lap_number", default_none=True
        )

        # Extract tyre info
        lap_data['Compound'] = recursive_dict_get(
            lap_json, "tyre", "compound", default_none=True
        )
        lap_data['TyreLife'] = recursive_dict_get(
            lap_json, "tyre", "life", default_none=True
        )

        # Extract position
        lap_data['Position'] = recursive_dict_get(
            lap_json, "position", default_none=True
        )

        # Extract track status
        lap_data['TrackStatus'] = recursive_dict_get(
            lap_json, "track_status", default_none=True
        )

        # Only add lap if we have minimum required data
        if lap_data.get('Driver') and lap_data.get('LapNumber'):
            processed_laps.append(lap_data)

    return pd.DataFrame(processed_laps)
```

## Performance Considerations and Best Practices

Understanding the performance characteristics of utility functions helps developers write efficient data analysis code.

### Time Conversion Performance

**`to_timedelta` and `to_datetime` optimization tips:**

1. **Vectorized operations**: When converting entire DataFrame columns, use pandas' native functions directly:
   ```python
   import pandas as pd
   from tif1.utils import to_timedelta

   df = pd.DataFrame({"LapTimeStr": ["1:10.123", "1:09.876", "1:11.234"]})

   # Slower: Apply to each element
   df['LapTime'] = df['LapTimeStr'].apply(to_timedelta)

   # Faster: Vectorized pandas operation ("m:ss.sss" strings need the "00:" prefix)
   df['LapTime'] = pd.to_timedelta("00:" + df['LapTimeStr'])
   ```

2. **Batch processing**: Convert data in batches rather than one-by-one:
   ```python
   time_list = ["00:01:10.123", "00:01:09.876", "00:01:11.234"]

   # Slower: Individual conversions
   times = [to_timedelta(t) for t in time_list]

   # Faster: Batch conversion (pandas needs the full "hh:mm:ss" form here)
   times = pd.to_timedelta(time_list)
   ```

3. **Type checking**: Avoid unnecessary conversions by checking types first:
   ```python
   # Check if already converted
   if not pd.api.types.is_timedelta64_dtype(df['LapTime']):
       df['LapTime'] = pd.to_timedelta(df['LapTime'])
   ```

### Delta Time Performance

**`delta_time` optimization strategies:**

1. **Cache telemetry data**: If comparing multiple laps, get the reference telemetry once and pass the frame:
   ```python
   import tif1
   from tif1.utils import delta_time

   session = tif1.get_session(2024, "Monaco Grand Prix", "Qualifying")
   reference_lap = session.laps.pick_driver("VER").pick_fastest()
   laps_to_compare = [session.laps.pick_driver(d).pick_fastest() for d in ("HAM", "LEC", "NOR")]

   # Telemetry frame of the reference lap (delta_time accepts a frame)
   reference_telemetry = reference_lap.get_car_data()

   # Compare against multiple laps
   for compare_lap in laps_to_compare:
       delta, _, comp_tel = delta_time(reference_telemetry, compare_lap)
       # Process delta...
   ```

2. **Limit telemetry channels**: When only specific channels are needed, filter after retrieval:
   ```python
   ref_lap, comp_lap = reference_lap, laps_to_compare[0]
   delta, ref_tel, comp_tel = delta_time(ref_lap, comp_lap)

   # Only keep needed columns
   ref_tel_minimal = ref_tel[['Distance', 'Speed', 'Time']]
   comp_tel_minimal = comp_tel[['Distance', 'Speed', 'Time']]
   ```

3. **Parallel processing**: For multiple comparisons, use parallel processing:
   ```python
   from concurrent.futures import ThreadPoolExecutor

   def compare_lap(compare_lap):
       return delta_time(reference_lap, compare_lap)

   with ThreadPoolExecutor(max_workers=4) as executor:
       results = list(executor.map(compare_lap, laps_to_compare))
   ```

### Nested Data Access Performance

**`recursive_dict_get` best practices:**

1. **Minimize depth**: Access data at the shallowest level possible:
   ```python
   # Less efficient: Multiple deep accesses
   name = recursive_dict_get(data, "a", "b", "c", "name")
   age = recursive_dict_get(data, "a", "b", "c", "age")

   # More efficient: Get parent once
   person = recursive_dict_get(data, "a", "b", "c")
   name = person.get("name")
   age = person.get("age")
   ```

2. **Cache intermediate results**: Store frequently accessed nested objects:
   ```python
   # Cache session info
   session_info = recursive_dict_get(data, "session", "info")

   # Access multiple fields from cached object
   name = session_info.get("name")
   year = session_info.get("year")
   type_ = session_info.get("type")
   ```

3. **Use default_none appropriately**: Choose the default that fits the use case:
   ```python
   # Use default_none=False for chaining
   drivers = recursive_dict_get(data, "session", "drivers") or []

   # Use default_none=True for explicit checks
   temperature = recursive_dict_get(data, "weather", "temp", default_none=True)
   if temperature is not None:
       process_temperature(temperature)
   ```

### Memory Management

**Tips for working with large datasets:**

1. **Process in chunks**: For very large lap datasets, process in chunks:
   ```python
   # Custom timing data with lap times as strings
   raw_laps = pd.DataFrame({"LapTime": ["1:10.123", "1:09.876", "1:11.234"] * 1000})

   chunk_size = 1000
   for i in range(0, len(raw_laps), chunk_size):
       chunk = raw_laps.iloc[i:i+chunk_size].copy()
       chunk['LapTime'] = chunk['LapTime'].apply(to_timedelta)
       # Process chunk...
   ```

2. **Delete unused data**: Free memory by deleting intermediate results:
   ```python
   delta, ref_tel, comp_tel = delta_time(ref_lap, comp_lap)

   # Process delta...

   # Free memory if telemetry not needed
   del ref_tel, comp_tel
   ```

3. **Use appropriate data types**: Convert to efficient types after processing:
   ```python
   # Convert timedelta to float32 if precision allows
   df['LapTimeSeconds'] = df['LapTime'].dt.total_seconds().astype('float32')
   ```

### Error Handling Best Practices

**Reliable error handling patterns:**

1. **Validate inputs before conversion**:
   ```python
   def safe_to_timedelta(value):
       """Safely convert to timedelta with validation."""
       if pd.isna(value):
           return pd.NaT
       try:
           return to_timedelta(value)
       except Exception as e:
           print(f"Warning: Could not convert {value}: {e}")
           return pd.NaT

   df['LapTime'] = df['LapTimeStr'].apply(safe_to_timedelta)
   ```

2. **Handle missing telemetry gracefully**:
   ```python
   def safe_delta_time(ref_lap, comp_lap):
       """Calculate delta with error handling."""
       try:
           return delta_time(ref_lap, comp_lap)
       except Exception as e:
           print(f"Warning: Could not calculate delta: {e}")
           return pd.Series(), pd.DataFrame(), pd.DataFrame()
   ```

3. **Validate nested data structure**:
   ```python
   def validate_and_extract(data, *keys):
       """Extract with validation."""
       result = recursive_dict_get(data, *keys, default_none=True)
       if result is None:
           raise ValueError(f"Required path {keys} not found in data")
       return result
   ```

## API Reference Summary

### Function Signatures

```python
# Time conversion
def to_timedelta(x: Any) -> pd.Timedelta

def to_datetime(x: Any) -> pd.Timestamp

# Performance analysis
def delta_time(
    reference_lap: Lap | pd.DataFrame,
    compare_lap: Lap | pd.DataFrame,
) -> tuple[pd.Series, pd.DataFrame, pd.DataFrame]

# Data access
def recursive_dict_get(
    d: dict,
    *keys: str,
    default_none: bool = False
) -> Any
```

### Return Types

| Function | Return Type | Description |
|----------|-------------|-------------|
| `to_timedelta` | `pd.Timedelta` | Pandas Timedelta object representing duration |
| `to_datetime` | `pd.Timestamp` | Pandas Timestamp object representing point in time |
| `delta_time` | `tuple[pd.Series, pd.DataFrame, pd.DataFrame]` | Estimated delta in seconds and the two telemetry DataFrames |
| `recursive_dict_get` | `Any` | Value at key path, or `{}` / `None` if not found |

### Common Exceptions

The following errors can occur:

- **`ValueError`**: Invalid input format that pandas cannot parse, or an object that `to_timedelta` cannot convert
- **`TypeError`**: An object that `to_datetime` cannot convert
- **`IndexError`**: An out-of-range list index in `recursive_dict_get`
- **No error from `delta_time`**: An object without telemetry gives an empty delta Series

## Integration with tif1 Ecosystem

### Use Inside tif1

The `tif1.utils` module is a compatibility layer for code ported from `fastf1.utils`. No other `tif1` module imports it:

- **Session loading** builds the time columns with vectorized pandas or Polars code, not with `to_timedelta` or `to_datetime`
- **Charts** such as `tif1.plot_lap_delta()` compute their own values and do not call `delta_time`
- **Payload parsing** reads JSON with `orjson` and does not use `recursive_dict_get`

Call the utilities directly in analysis code:

```python
import tif1
from tif1.utils import delta_time

session = tif1.get_session(2024, "Monaco Grand Prix", "Qualifying")
ref_lap = session.laps.pick_driver("VER").pick_fastest()
comp_lap = session.laps.pick_driver("LEC").pick_fastest()
delta, ref_tel, comp_tel = delta_time(ref_lap, comp_lap)
print(f"Samples: {len(delta)}, estimated gap at the line: {delta.iloc[-1]:.3f}s")
```

## FastF1 Compatibility

The four functions have the same names and arguments as in `fastf1.utils`. Some edge cases give different results (compared with FastF1 3.8):

### Compatible Functions

| tif1 Function | FastF1 Equivalent | Differences |
|---------------|-------------------|-------------|
| `to_timedelta` | `fastf1.utils.to_timedelta` | tif1 returns `pd.Timedelta` and reads numbers as seconds. FastF1 returns `datetime.timedelta`, and `None` for numbers or unparseable strings. tif1 raises `ValueError` for an unparseable string |
| `to_datetime` | `fastf1.utils.to_datetime` | tif1 returns `pd.Timestamp` (timezone-aware for a trailing `Z`) and raises for an unparseable string. FastF1 returns a naive `datetime.datetime`, or `None` |
| `delta_time` | `fastf1.utils.delta_time` | FastF1 uses `get_car_data(interpolate_edges=True)` and scales the compare lap distance to the reference lap length. tif1 does neither. FastF1 marks its function as deprecated |
| `recursive_dict_get` | `fastf1.utils.recursive_dict_get` | With `default_none=True`, FastF1 also returns `None` for a key that holds `{}`. tif1 returns the `{}` |

## Troubleshooting

### Common Issues and Solutions

**Issue: `to_timedelta` raises `ValueError` for a lap time string**

```python
# Problem: Unexpected format
time_str = "1.23.456"  # Wrong format (periods instead of colons)
result = to_timedelta(time_str)  # Raises ValueError

# Solution: Use correct format
time_str = "1:23.456"  # Correct format
result = to_timedelta(time_str)  # Works correctly
```

**Issue: `delta_time` returns empty Series**

```python
import tif1
from tif1.utils import delta_time

session = tif1.get_session(2024, "Monaco Grand Prix", "Qualifying")
ref_lap = session.laps.pick_driver("VER").pick_fastest()
lap = session.laps.pick_driver("LEC").pick_fastest()

# Problem: a lap with fewer than two telemetry samples gives an empty delta
# Solution: check the telemetry before the comparison
telemetry = lap.get_car_data()
if len(telemetry) >= 2:
    delta, _, _ = delta_time(ref_lap, lap)
    print(f"Delta samples: {len(delta)}")
else:
    print("No telemetry for this lap")
```

**Issue: `recursive_dict_get` returns empty dict unexpectedly**

```python
from tif1.utils import recursive_dict_get

data = {"session": {"info": {"name": "Monaco GP"}}}

# Problem: with the default, a missing path gives {}, which is not None
value = recursive_dict_get(data, "missing", "key")
if value is not None:  # True: value is {}
    print(f"Found: {value}")

# Solution: Use default_none=True for explicit checks
value = recursive_dict_get(data, "missing", "key", default_none=True)
if value is not None:  # False: value is None
    print(f"Found: {value}")
```

**Issue: Performance degradation with large datasets**

```python
import pandas as pd
from tif1.utils import to_timedelta

df = pd.DataFrame({"LapTimeStr": ["1:10.123", "1:09.876", "1:11.234"]})

# Problem: Applying to each element
df['LapTime'] = df['LapTimeStr'].apply(to_timedelta)  # Slow

# Solution: Use vectorized pandas operations ("m:ss.sss" strings need the "00:" prefix)
df['LapTime'] = pd.to_timedelta("00:" + df['LapTimeStr'])  # Fast
```
