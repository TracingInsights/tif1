## Overview

`tif1` implements a comprehensive, structured exception hierarchy designed to provide maximum clarity and debuggability when errors occur. Every exception in the library inherits from the base `TIF1Error` class and includes rich contextual information to help you understand exactly what went wrong and why.

The exception system is designed with several key principles:

- **Structured Context**: Every exception carries a `context` dictionary with relevant metadata (year, event, driver, URL, etc.)
- **Clear Hierarchy**: Exceptions are organized in a logical tree structure, allowing you to catch errors at the appropriate level of specificity
- **Actionable Messages**: Error messages are automatically constructed with relevant details to aid debugging
- **Type Safety**: All exceptions are properly typed for IDE autocomplete and type checking
- **Graceful Degradation**: The design encourages handling errors gracefully rather than crashing

This guide covers every exception type in detail, including when they're raised, what context they provide, and how to handle them effectively.

---

## Exception Hierarchy

The exception hierarchy is designed to allow you to catch errors at different levels of specificity. You can catch broad categories (like `TIF1Error` for any library error) or specific exceptions (like `DriverNotFoundError` for missing drivers).

```
TIF1Error (base exception for all tif1 errors)
│
├── DataNotFoundError (data unavailable in CDN/cache)
│   ├── DriverNotFoundError (specific driver not in session)
│   └── LapNotFoundError (specific lap not found for driver)
│
├── NetworkError (HTTP request failures after retries)
│
├── InvalidDataError (data validation/parsing failures)
│
├── CacheError (SQLite cache operation failures)
│
└── SessionNotLoadedError (accessing data before load())
```

### Catching Strategy

The hierarchy allows flexible error handling:

```python
import tif1

try:
    session = tif1.get_session(2024, "Monaco", "Race")
    driver = session.get_driver("VER")
    lap = driver.get_lap(1)
except tif1.DriverNotFoundError:
    # Handle specific driver not found
    pass
except tif1.DataNotFoundError:
    # Handle any data not found (including driver/lap)
    pass
except tif1.NetworkError:
    # Handle network issues
    pass
except tif1.TIF1Error:
    # Catch-all for any tif1 error
    pass
```

## Base Exception

### `TIF1Error`

The root exception class for all tif1 errors. Every exception in the library inherits from this class, making it easy to catch all tif1-specific errors with a single except clause.

**Signature:**
```python
class TIF1Error(Exception):
    def __init__(self, message: str, **context: Any) -> None
```

**Attributes:**
- `message` (str): Human-readable error message describing what went wrong
- `context` (dict[str, Any]): Dictionary containing structured contextual information about the error

**Key Features:**
- All context keyword arguments are automatically stored in the `context` dictionary
- The message is both stored as an attribute and passed to the base `Exception` class
- Subclasses can add their own context keys while preserving the base functionality

**When Raised:**
- Never raised directly; always use a more specific subclass
- Used as a catch-all when you want to handle any tif1 error

**Example - Basic Usage:**
```python
import tif1

try:
    session = tif1.get_session(2025, "Invalid GP", "Race")
except tif1.TIF1Error as e:
    print(f"Error occurred: {e.message}")
    print(f"Error type: {type(e).__name__}")
    print(f"Context data: {e.context}")

    # Output:
    # Error occurred: Data not found: year=2025, event='Invalid GP', session='Race'
    # Error type: DataNotFoundError
    # Context data: {'year': 2025, 'event': 'Invalid GP', 'session': 'Race'}
```

**Example - Logging with Context:**
```python
import logging
import tif1

logger = logging.getLogger(__name__)

try:
    session = tif1.get_session(2024, "Monaco", "Race")
    laps = session.laps
except tif1.TIF1Error as e:
    # Log with structured context for better debugging
    logger.error(
        f"Failed to load session: {e.message}",
        extra={
            "error_type": type(e).__name__,
            "error_context": e.context,
        }
    )
```


## Data Errors

### `DataNotFoundError`

Raised when requested F1 data is not available in the CDN or cache. This is one of the most common exceptions you'll encounter, typically occurring when requesting data for sessions that haven't happened yet, or for historical sessions where data was never collected.

**Signature:**
```python
class DataNotFoundError(TIF1Error):
    def __init__(
        self,
        year: int | None = None,
        event: str | None = None,
        session: str | None = None,
        **context: Any
    ) -> None
```

**Context Keys:**
- `year` (int | None): The requested year (e.g., 2024)
- `event` (str | None): The requested event/Grand Prix name (e.g., "Monaco Grand Prix")
- `session` (str | None): The requested session type (e.g., "Race", "Qualifying", "FP1")
- Additional context from `**context` kwargs

**When Raised:**
- HTTP 404 responses from the CDN (data file doesn't exist)
- Requesting future sessions that haven't occurred yet
- Requesting historical data that was never collected or published
- Requesting data for cancelled sessions (e.g., 2020 Australian GP)
- Invalid year/event/session combinations

**Common Scenarios:**

1. **Future Sessions**: Requesting data for races that haven't happened yet
2. **Historical Gaps**: Some older seasons have incomplete data coverage
3. **Cancelled Events**: Sessions that were scheduled but cancelled
4. **Invalid Combinations**: Requesting "Sprint" for a non-sprint weekend

**Example - Basic Handling:**
```python
import tif1

try:
    # Trying to get data for a future race
    session = tif1.get_session(2030, "Future GP", "Race")
    laps = session.laps
except tif1.DataNotFoundError as e:
    print(f"Data not available: {e.message}")
    print(f"Requested: Year {e.context['year']}, {e.context['event']}, {e.context['session']}")

    # Output:
    # Data not available: Data not found: year=2030, event='Future GP', session='Race'
    # Requested: Year 2030, Future GP, Race
```

**Example - Checking Data Availability:**

### `DriverNotFoundError`

Raised when attempting to access a driver that doesn't exist in the session. This is a subclass of `DataNotFoundError` and typically occurs due to typos in driver codes or requesting drivers who didn't participate in the session.

**Signature:**
```python
class DriverNotFoundError(DataNotFoundError):
    def __init__(self, driver: str, **context: Any) -> None
```

**Context Keys:**
- `driver` (str): The requested driver code (e.g., "VER", "HAM")
- `year` (int | None): Session year (if provided in context)
- `event` (str | None): Event name (if provided in context)
- `session` (str | None): Session name (if provided in context)

**When Raised:**
- Calling `session.get_driver("XXX")` with an invalid driver code
- Driver code typos (e.g., "VET" instead of "VER")
- Requesting a driver who didn't participate in that specific session
- Driver retired/withdrew before the session

**Common Causes:**

1. **Typos**: "HAM" vs "HAN", "VER" vs "VET"
2. **Wrong Session**: Driver participated in practice but not qualifying
3. **Historical Changes**: Driver codes changed between seasons
4. **Case Sensitivity**: Driver codes are case-sensitive

**Example - Basic Handling:**
```python
import tif1

session = tif1.get_session(2024, "Monaco", "Race")

try:
    driver = session.get_driver("XXX")  # Invalid driver code
except tif1.DriverNotFoundError as e:
    print(f"Driver not found: {e.message}")
    print(f"Requested driver: {e.context['driver']}")
    print(f"Available drivers: {session.drivers}")

    # Output:
    # Driver not found: Driver 'XXX' not found in session
    # Requested driver: XXX
    # Available drivers: ['VER', 'PER', 'LEC', 'SAI', ...]
```

--- ### `LapNotFoundError`

Raised when attempting to access a specific lap number that doesn't exist for a driver. This is a subclass of `DataNotFoundError` and typically occurs when requesting lap numbers beyond what the driver completed, or when requesting laps that were invalidated or deleted.

**Signature:**
```python
class LapNotFoundError(DataNotFoundError):
    def __init__(
        self,
        lap_number: int | None = None,
        driver: str | None = None,
        **context: Any
    ) -> None
```

**Context Keys:**
- `lap_number` (int | None): The requested lap number (e.g., 1, 50, 999)
- `driver` (str | None): The driver code for whom the lap was requested (e.g., "VER", "HAM")
- Additional context from `**context` kwargs

**When Raised:**
- Calling `driver.get_lap(N)` where N exceeds the driver's total lap count
- Requesting lap 0 or negative lap numbers
- Requesting laps that were deleted due to track limits violations
- Requesting laps from drivers who retired early in the session
- Accessing laps before the driver started (e.g., lap 1 when driver started from pit lane on lap 2)

**Common Scenarios:**

1. **Out of Range**: Requesting lap 60 when the driver only completed 45 laps
2. **Early Retirement**: Driver crashed on lap 10, requesting lap 20
3. **Invalid Laps**: Lap was deleted due to track limits or red flag
4. **Formation Laps**: Requesting lap 0 (formation lap) which may not be recorded

**Example - Basic Handling:**
```python
import tif1

session = tif1.get_session(2024, "Monaco", "Race")
driver = session.get_driver("VER")

try:
    lap = driver.get_lap(999)  # Way beyond race distance

    print(f"Requested lap: {e.context['lap_number']}")
    print(f"Driver: {e.context['driver']}")
```

## Network Errors

### `NetworkError`

Raised when HTTP network requests fail after all retry attempts and CDN fallback mechanisms have been exhausted. This exception indicates a persistent network connectivity issue, server unavailability, or infrastructure problem that prevents data retrieval.

The library implements sophisticated retry logic with exponential backoff and circuit breaker patterns before raising this exception, so when you see `NetworkError`, it typically means the problem is serious and persistent.

**Signature:**
```python
class NetworkError(TIF1Error):
    def __init__(
        self,
        url: str | None = None,
        status_code: int | None = None,
        **context: Any
    ) -> None
```

**Context Keys:**
- `url` (str | None): The full URL that failed (e.g., "https://cdn.jsdelivr.net/gh/TracingInsights/2024@main/...")
- `status_code` (int | None): HTTP status code if the server responded (e.g., 500, 502, 503, 504)
- Additional context from `**context` kwargs (may include retry count, timeout info, etc.)

**When Raised:**
- All retry attempts exhausted (typically 3-5 retries with exponential backoff)
- CDN fallback mechanisms failed
- HTTP 5xx server errors (500, 502, 503, 504) persisting after retries
- Connection timeouts exceeding configured thresholds
- DNS resolution failures
- SSL/TLS certificate validation errors
- Network connectivity issues (no internet connection)
- Firewall or proxy blocking requests

**Common Scenarios:**

1. **CDN Outage**: jsdelivr CDN experiencing downtime or degraded performance
2. **GitHub Issues**: Source repository unavailable or rate-limited
3. **Local Network**: No internet connection or restrictive firewall
4. **Server Errors**: Backend infrastructure experiencing issues
5. **Timeout**: Requests taking too long due to slow network or large files

**HTTP Status Codes:**

- **500 Internal Server Error**: CDN or origin server error
- **502 Bad Gateway**: CDN cannot reach origin server
- **503 Service Unavailable**: Server temporarily overloaded or down
- **504 Gateway Timeout**: CDN timeout waiting for origin server
- **None**: Connection failed before receiving response (timeout, DNS failure, etc.)

**Example - Basic Handling:**
```python
import tif1

try:
    session = tif1.get_session(2024, "Monaco", "Race")
    laps = session.laps
except tif1.NetworkError as e:
    print(f"Network error: {e.message}")
    print(f"Failed URL: {e.context.get('url')}")
    print(f"Status code: {e.context.get('status_code', 'No response')}")

    # Output:
    # Network error: Network request failed: url='https://...', status=503
    # Failed URL: https://cdn.jsdelivr.net/gh/TracingInsights/2024@main/...
    # Status code: 503
```

**Example - Retry with Exponential Backoff:**
```python
import tif1
import time

def load_session_with_retry(
    year: int,
    gp: str,
    session_name: str,
    max_retries: int = 3,
    base_delay: float = 2.0
):
    """Load session with custom retry logic."""
    for attempt in range(max_retries):
        try:
            session = tif1.get_session(year, gp, session_name)
            # Force data load to trigger network requests
            _ = session.laps
            return session
        except tif1.NetworkError as e:
            if attempt < max_retries - 1:
                delay = base_delay * (2 ** attempt)  # Exponential backoff
                print(f"Network error (attempt {attempt + 1}/{max_retries}): {e.message}")
                print(f"Retrying in {delay} seconds...")
                time.sleep(delay)
            else:
                print(f"Failed after {max_retries} attempts")
                print(f"Last error: {e.message}")
                print(f"URL: {e.context.get('url')}")
                print(f"Status: {e.context.get('status_code')}")
                raise

# Use with retry
session = load_session_with_retry(2024, "Monaco", "Race", max_retries=5)
```

## Data Validation Errors

### `InvalidDataError`

Raised when fetched data is invalid, corrupted, malformed, or fails validation checks. This exception indicates that while the network request succeeded and data was retrieved, the data itself doesn't meet the expected format, schema, or quality standards required by the library.

This is distinct from `DataNotFoundError` (data doesn't exist) and `NetworkError` (couldn't retrieve data) - `InvalidDataError` means the data was retrieved but is unusable.

**Signature:**
```python

    def __init__(self, reason: str | None = None, **context: Any) -> None
```

**Context Keys:**
- `reason` (str | None): Detailed description of why the data is invalid
- Additional context from `**context` kwargs (may include field names, expected vs actual values, etc.)

**When Raised:**
- JSON parsing failures (malformed JSON syntax)
- Missing required fields in data structures
- Data type mismatches (string where number expected)
- Invalid enum values (unknown session type, compound type, etc.)
- Corrupted or truncated data files
- Schema validation failures (pydantic validation errors)
- Inconsistent data (lap times without lap numbers, etc.)
- Data integrity violations (negative lap times, impossible speeds, etc.)
- Encoding issues (invalid UTF-8, etc.)

**Common Scenarios:**

1. **Malformed JSON**: CDN served corrupted or incomplete JSON
2. **Schema Changes**: Data structure changed but library not updated
3. **Missing Fields**: Required columns or fields absent from data
4. **Type Errors**: Data types don't match expected schema
5. **Validation Failures**: Data values outside acceptable ranges
6. **Encoding Issues**: Character encoding problems in text fields

## Cache Errors

### `CacheError`

Raised when cache operations fail, typically due to SQLite database errors, filesystem issues, or resource constraints. The library uses an SQLite-backed cache to store fetched data locally, and this exception indicates problems with that caching layer.

Cache errors are generally non-fatal for data retrieval (the library can fall back to fetching from CDN), but they may impact performance and offline capabilities.

**Signature:**
```python
class CacheError(TIF1Error):
    def __init__(self, message: str, **context: Any) -> None
```

**Context Keys:**
- Additional context from `**context` kwargs (may include cache path, operation type, SQLite error codes, etc.)

**When Raised:**
- SQLite database corruption or lock errors
- Insufficient disk space for cache operations
- Permission denied when accessing cache directory
- Cache database schema migration failures
- Concurrent access conflicts (multiple processes)
- Filesystem errors (read-only filesystem, etc.)
- Cache directory doesn't exist and can't be created
- Database connection failures
- Transaction rollback errors

**Common Scenarios:**

1. **Disk Full**: No space left on device for cache writes
2. **Permissions**: Cache directory not writable by current user
3. **Corruption**: SQLite database file corrupted
4. **Locks**: Database locked by another process
5. **Migration**: Cache schema version mismatch

## Session State Errors

### `SessionNotLoadedError`

Raised when attempting to access session data or attributes before the session has been properly loaded. This exception enforces the library's data loading contract, ensuring that users explicitly load data before accessing it.

The library uses lazy loading patterns for performance, meaning session objects can be created without immediately fetching all data. This exception occurs when you try to access data that requires an explicit load operation.

**Signature:**
```python
class SessionNotLoadedError(TIF1Error):
    def __init__(self, attribute: str | None = None) -> None
```

**Context Keys:**
- `attribute` (str | None): The specific attribute or property that was accessed before loading

**When Raised:**
- Accessing `session.laps` before calling `session.load(laps=True)`
- Accessing `session.telemetry` before loading telemetry data
- Accessing driver-specific data before session initialization completes
- Calling methods that require loaded data on an unloaded session
- Accessing internal data structures (e.g., `_laps_df`) before population

**Common Scenarios:**

1. **Forgot to Load**: Created session but didn't call load methods
2. **Partial Loading**: Loaded some data but not the specific data needed
3. **Lazy Loading**: Accessing properties that trigger lazy loading failures
4. **Internal Access**: Directly accessing private attributes before initialization

### Retry with Exponential Backoff Pattern

Implement sophisticated retry logic for transient network errors.

```python
import tif1
import time
from typing import Callable, TypeVar, Any

T = TypeVar('T')

def retry_with_backoff(
    func: Callable[[], T],
    max_retries: int = 3,
    base_delay: float = 1.0,
    max_delay: float = 60.0,
    exponential_base: float = 2.0,
    jitter: bool = True
) -> T:
    """
    Retry a function with exponential backoff.

    Args:
        func: Function to retry
        max_retries: Maximum number of retry attempts
        base_delay: Initial delay in seconds
        max_delay: Maximum delay between retries
        exponential_base: Base for exponential backoff calculation
        jitter: Add random jitter to prevent thundering herd

    Returns:
        Result of successful function call

    Raises:
        Last exception if all retries exhausted
    """
    import random

    last_exception = None

    for attempt in range(max_retries):
        try:
            return func()
        except tif1.NetworkError as e:
            last_exception = e

            if attempt < max_retries - 1:
                # Calculate delay with exponential backoff
                delay = min(base_delay * (exponential_base ** attempt), max_delay)

                # Add jitter to prevent thundering herd
                if jitter:
                    delay = delay * (0.5 + random.random() * 0.5)

                print(f"Network error (attempt {attempt + 1}/{max_retries}): {e.message}")
                print(f"Retrying in {delay:.2f} seconds...")
                time.sleep(delay)
            else:
                print(f"Failed after {max_retries} attempts")
                raise
        except tif1.DataNotFoundError:
            # Don't retry data not found errors
            print("Data not found - retrying won't help")
            raise
        except tif1.TIF1Error as e:
            # Don't retry other tif1 errors
            print(f"Non-retryable error: {type(e).__name__}")
            raise

    # Should never reach here, but satisfy type checker
    if last_exception:
        raise last_exception

# Usage

    session = tif1.get_session(2024, "Monaco", "Race")
    _ = session.laps  # Force load
    return session
```

### Circuit Breaker Pattern

Implement circuit breaker to prevent cascading failures.

```python
import tif1
import time
from enum import Enum
from typing import Callable, TypeVar, Any

T = TypeVar('T')

class CircuitState(Enum):
    CLOSED = "closed"  # Normal operation
    OPEN = "open"      # Failing, reject requests
    HALF_OPEN = "half_open"  # Testing if recovered

class CircuitBreaker:
    """Circuit breaker for tif1 operations."""

    def __init__(
        self,
        failure_threshold: int = 5,
        recovery_timeout: float = 60.0,
        expected_exception: type = tif1.NetworkError
    ):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.expected_exception = expected_exception

        self.failure_count = 0
        self.last_failure_time = None
        self.state = CircuitState.CLOSED

    def call(self, func: Callable[[], T]) -> T:
        """Execute function with circuit breaker protection."""
        if self.state == CircuitState.OPEN:
            if self._should_attempt_reset():
                self.state = CircuitState.HALF_OPEN
                print("Circuit breaker: Attempting recovery (HALF_OPEN)")
            else:
                time_remaining = self.recovery_timeout - (time.time() - self.last_failure_time)
                raise tif1.NetworkError(
                    message=f"Circuit breaker OPEN. Retry in {time_remaining:.0f}s",
                    circuit_breaker_state="open",
                    failure_count=self.failure_count
                )

        try:
            result = func()
            self._on_success()
            return result
        except self.expected_exception as e:
            self._on_failure()
            raise

    def _should_attempt_reset(self) -> bool:
        """Check if enough time has passed to attempt recovery."""
        return (
            self.last_failure_time is not None and
            time.time() - self.last_failure_time >= self.recovery_timeout
        )

    def _on_success(self):
        """Handle successful call."""
        if self.state == CircuitState.HALF_OPEN:
            print("Circuit breaker: Recovery successful (CLOSED)")
        self.failure_count = 0
        self.state = CircuitState.CLOSED

    def _on_failure(self):
        """Handle failed call."""
        self.failure_count += 1
        self.last_failure_time = time.time()

        if self.failure_count >= self.failure_threshold:
            self.state = CircuitState.OPEN
            print(f"Circuit breaker: OPEN after {self.failure_count} failures")
        elif self.state == CircuitState.HALF_OPEN:
            self.state = CircuitState.OPEN
            print("Circuit breaker: Recovery failed, back to OPEN")

# Usage
breaker = CircuitBreaker(failure_threshold=3, recovery_timeout=30.0)

def load_session_with_breaker(year: int, gp: str, session_name: str):
    """Load session with circuit breaker protection."""
    def load():
        session = tif1.get_session(year, gp, session_name)
        _ = session.laps
        return session

    try:
        return breaker.call(load)
    except tif1.NetworkError as e:
        if e.context.get('circuit_breaker_state') == 'open':
            print("Circuit breaker is open - service unavailable")
        raise

# Multiple calls will trigger circuit breaker if failing
for i in range(10):
    try:

        print(f"Call {i+1}: Success")
```

### Fallback Chain Pattern

Implement multiple fallback strategies in sequence.

```python
import tif1
from typing import List, Tuple, Callable, TypeVar, Optional

T = TypeVar('T')

class FallbackChain:
    """Execute strategies in sequence until one succeeds."""

    def __init__(self, strategies: List[Tuple[str, Callable[[], T]]]):
        """
        Initialize fallback chain.

        Args:
            strategies: List of (name, function) tuples to try in order
        """
        self.strategies = strategies
        self.errors = []

    def execute(self) -> Tuple[Optional[T], List[dict]]:
        """
        Execute strategies until one succeeds.

        Returns:
            Tuple of (result, errors) where result is None if all failed
        """
        for name, strategy in self.strategies:
            try:
                print(f"Trying strategy: {name}")
                result = strategy()
                print(f"✓ Strategy '{name}' succeeded")
                return result, self.errors
            except tif1.TIF1Error as e:
                error_info = {
                    "strategy": name,
                    "error_type": type(e).__name__,
                    "message": e.message,
                    "context": e.context
                }
                self.errors.append(error_info)
                print(f"✗ Strategy '{name}' failed: {e.message}")
                continue

        print("All strategies failed")
        return None, self.errors

# Usage example
def load_session_with_fallbacks(year: int, gp: str, session_name: str):
    """Load session with multiple fallback strategies."""

    # Strategy 1: Load with full data
    def load_full():
        session = tif1.get_session(year, gp, session_name)
        session.load(laps=True, telemetry=True, weather=True, messages=True)
        return session

    # Strategy 2: Load with laps only (faster)
    def load_laps_only():
        session = tif1.get_session(year, gp, session_name)
        session.load(laps=True)
        return session

    # Strategy 3: Try alternative session type
    def load_alternative():
        # Try qualifying if race fails
        alt_session = "Qualifying" if session_name == "Race" else "Race"
        session = tif1.get_session(year, gp, alt_session)
        session.load(laps=True)
        print(f"Loaded alternative session: {alt_session}")
        return session

    # Strategy 4: Try previous year
    def load_previous_year():
        session = tif1.get_session(year - 1, gp, session_name)
        session.load(laps=True)
        print(f"Loaded previous year: {year - 1}")
        return session

    chain = FallbackChain([
        ("Full data load", load_full),
        ("Laps only", load_laps_only),
        ("Alternative session", load_alternative),
        ("Previous year", load_previous_year),
    ])

    result, errors = chain.execute()

    if result is None:
        print("\nAll fallback strategies failed:")
        for error in errors:
            print(f"  - {error['strategy']}: {error['message']}")
        raise tif1.DataNotFoundError(
            year=year,
            event=gp,
            session=session_name,
            fallback_errors=errors
        )

    return result

# Use with fallbacks
```

```python
        )

        # Store in history
        self.error_history.append(analysis)

        return analysis

    def _assess_severity(self, error: tif1.TIF1Error) -> str:
        """Assess error severity."""
        if isinstance(error, tif1.DataNotFoundError):
            return "low"  # Expected for future/missing data
        elif isinstance(error, tif1.NetworkError):
            status = error.context.get('status_code')
            if status and status >= 500:
                return "high"  # Server errors are serious
            return "medium"
        elif isinstance(error, tif1.InvalidDataError):
            return "high"  # Data corruption is serious
        elif isinstance(error, tif1.CacheError):
            return "low"  # Cache errors are usually non-critical
        else:
            return "medium"

    def _is_retryable(self, error: tif1.TIF1Error) -> bool:
        """Determine if error is retryable."""
        if isinstance(error, tif1.NetworkError):
            status = error.context.get('status_code')
            # Retry on 5xx errors and timeouts
            return status is None or status >= 500
        elif isinstance(error, tif1.CacheError):
            return True  # Cache errors often transient
        else:
            return False  # Data not found, invalid data not retryable

    def _get_recommendations(self, error: tif1.TIF1Error) -> List[str]:
        """Generate actionable recommendations."""
        recommendations = []

        if isinstance(error, tif1.DataNotFoundError):
            recommendations.append("Verify the year/event/session combination is correct")
            recommendations.append("Check if the session has occurred yet")
            recommendations.append("Try an alternative session type")

        elif isinstance(error, tif1.DriverNotFoundError):
            recommendations.append(f"Check driver code spelling: '{error.context.get('driver')}'")
            recommendations.append("Use session.drivers to see available drivers")
            recommendations.append("Verify driver participated in this session")

        elif isinstance(error, tif1.LapNotFoundError):
            lap_num = error.context.get('lap_number')
            recommendations.append(f"Lap {lap_num} may exceed race distance")
            recommendations.append("Check if driver retired early")
            recommendations.append("Use len(driver.laps) to see total laps")

        elif isinstance(error, tif1.NetworkError):
            status = error.context.get('status_code')
            if status and status >= 500:
                recommendations.append("CDN or server experiencing issues")
                recommendations.append("Retry with exponential backoff")
                recommendations.append("Check tif1 status page for outages")
            else:
                recommendations.append("Check internet connection")
                recommendations.append("Verify firewall/proxy settings")
                recommendations.append("Try again in a few moments")

        elif isinstance(error, tif1.InvalidDataError):
            recommendations.append("Data may be corrupted or incomplete")
            recommendations.append("Clear cache and retry")
            recommendations.append("Report issue if problem persists")

        elif isinstance(error, tif1.CacheError):
            recommendations.append("Check disk space availability")
            recommendations.append("Verify cache directory permissions")
            recommendations.append("Try clearing cache")

        return recommendations

    def get_error_summary(self) -> Dict[str, Any]:
        """Get summary of all errors encountered."""
        if not self.error_history:
            return {"total_errors": 0}

        error_types = {}
        for error in self.error_history:
            error_type = error["error_type"]
            error_types[error_type] = error_types.get(error_type, 0) + 1

        return {
            "total_errors": len(self.error_history),
            "error_types": error_types,
            "high_severity_count": sum(
                1 for e in self.error_history if e["severity"] == "high"
            ),
            "retryable_count": sum(
                1 for e in self.error_history if e["retryable"]
            )
        }

# Usage

try:
    session = tif1.get_session(2024, "Monaco", "Race")
    driver = session.get_driver("VER")
    lap = driver.get_lap(1)
except tif1.TIF1Error as e:
    analysis = handler.handle_error(e, "Load Monaco Race data")

    print(f"\nError Analysis:")
    print(f"  Type: {analysis['error_type']}")
    print(f"  Severity: {analysis['severity']}")
    print(f"  Retryable: {analysis['retryable']}")
    print(f"\nRecommendations:")

        print(f"  - {rec}")
```

## Best Practices

Comprehensive guidelines for robust error handling in production applications using tif1.

### 1. Catch Specific Exceptions First

Always catch more specific exceptions before general ones. Python evaluates except clauses in order, so place specific handlers first.

**Why:** Specific exceptions allow targeted recovery strategies and better error messages.

```python
import tif1

# ✓ CORRECT: Specific to general
try:
    session = tif1.get_session(2024, "Monaco", "Race")
    driver = session.get_driver("VER")
except tif1.DriverNotFoundError as e:
    # Handle driver-specific error
    print(f"Driver not found: {e.context['driver']}")
except tif1.DataNotFoundError as e:
    # Handle general data not found
    print(f"Data not found: {e.message}")
except tif1.TIF1Error as e:
    # Handle any other tif1 error
    print(f"tif1 error: {e.message}")

# ✗ WRONG: General before specific
try:
    session = tif1.get_session(2024, "Monaco", "Race")
    driver = session.get_driver("VER")
except tif1.DataNotFoundError as e:
    # This catches DriverNotFoundError too!
    print(f"Data not found: {e.message}")
except tif1.DriverNotFoundError as e:
    # This will never be reached
    print(f"Driver not found: {e.context['driver']}")
```

### 4. Implement Retries for Network Errors

Network errors are often transient. Implement retry logic with exponential backoff.

**Why:** Temporary network issues shouldn't cause permanent failures.

```python
import tif1
import time
from typing import TypeVar, Callable

T = TypeVar('T')

def with_retry(
    func: Callable[[], T],
    max_retries: int = 3,
    base_delay: float = 1.0
) -> T:
    """Execute function with retry logic for network errors."""
    for attempt in range(max_retries):
        try:
            return func()
        except tif1.NetworkError as e:
            if attempt < max_retries - 1:
                delay = base_delay * (2 ** attempt)
                print(f"Network error, retrying in {delay}s...")
                time.sleep(delay)
            else:
                raise
        except tif1.TIF1Error:
            # Don't retry non-network errors
            raise

# Usage
session = with_retry(
    lambda: tif1.get_session(2024, "Monaco", "Race"),
    max_retries=5
)
```

### 11. Monitor and Alert on Errors

Implement monitoring for production applications.

**Why:** Proactive error detection prevents user impact.

```python
import tif1
import logging
from typing import Dict, Any
from datetime import datetime

class ErrorMonitor:
    """Monitor and track errors for alerting."""

    def __init__(self, alert_threshold: int = 10):
        self.alert_threshold = alert_threshold
        self.error_counts: Dict[str, int] = {}
        self.last_alert_time: Dict[str, datetime] = {}

    def record_error(self, error: tif1.TIF1Error) -> bool:
        """
        Record error and return True if alert threshold exceeded.

        Returns:
            True if alert should be sent
        """
        error_type = type(error).__name__
        self.error_counts[error_type] = self.error_counts.get(error_type, 0) + 1

        if self.error_counts[error_type] >= self.alert_threshold:
            # Check if we already alerted recently
            last_alert = self.last_alert_time.get(error_type)
            if not last_alert or (datetime.now() - last_alert).seconds > 300:
                self.last_alert_time[error_type] = datetime.now()
                return True

        return False

    def send_alert(self, error_type: str, count: int):
        """Send alert (implement with your alerting system)."""
        message = f"High error rate: {error_type} occurred {count} times"
        print(f"ALERT: {message}")
        # Integrate with PagerDuty, Slack, email, etc.

# Usage

for i in range(10):
```
