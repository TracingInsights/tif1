Beyond the core timing and telemetry API, `tif1` provides utility functions. They manage internal state, performance optimization, reliability layers, and system configuration. These utilities give fine-grained control over caching behavior, network resilience, logging verbosity, data processing pipelines, and more.

This guide is an exhaustive reference for all utility functions. It covers parameters, return values, edge cases, performance implications, thread safety, and real-world usage patterns. Use these utilities when debugging data loading issues, optimizing cache performance, or building production applications.

## Overview

The utilities in `tif1` are organized into several categories:

- **Logging**: Control diagnostic output verbosity
- **Configuration**: Manage global settings and preferences
- **Cache Management**: Control persistent and in-memory caching
- **Data Utilities**: Convert and manipulate time and data structures
- **Reliability & Networking**: Manage circuit breakers and CDN fallback
- **Memory Management**: Clear caches to free resources

All utilities are designed with performance in mind and are thread-safe where applicable.

## Logging

Logging is essential for debugging data loading issues, understanding cache behavior, and diagnosing network problems. The `tif1` library uses Python's standard `logging` module and provides a convenient setup function to control verbosity across all internal components.

### `setup_logging`

Configure the logging level for all `tif1` components.

```python
def setup_logging(level: int = logging.WARNING) -> None
```

This function configures the root logger and sets the level for the `tif1` logger hierarchy. It also suppresses noisy connection pool warnings from the underlying HTTP library.

**Parameters:**
- `level` (int): Standard logging level from Python's `logging` module. Defaults to `logging.WARNING`.

**Available Levels:**

| Level | Value | Description | Use Case |
| :--- | :--- | :--- | :--- |
| `logging.DEBUG` | 10 | Detailed diagnostic information including cache hits/misses, HTTP requests, data parsing steps | Development, debugging data loading issues |
| `logging.INFO` | 20 | General informational messages about major operations | Production monitoring, understanding data flow |
| `logging.WARNING` | 30 | Warning messages about potential issues (default) | Normal operation, alerts for degraded performance |
| `logging.ERROR` | 40 | Error messages for failures that don't stop execution | Production error tracking |
| `logging.CRITICAL` | 50 | Critical errors that may cause application failure | Severe production issues |

**Behavior:**
- Configures logging format: `%(asctime)s - %(name)s - %(levelname)s - %(message)s`
- Sets date format: `%Y-%m-%d %H:%M:%S`
- Applies to all `tif1.*` loggers (`tif1.core`, `tif1.cache`, `tif1.async_fetch`, `tif1.http_session`, `tif1.cdn`, `tif1.retry`, and others)
- Suppresses `urllib3_future.connectionpool` warnings (set to ERROR level)
- Thread-safe: Can be called from any thread

**Basic Example:**
```python
import tif1
import logging

# Enable debug logging to see everything
tif1.setup_logging(logging.DEBUG)

# Now all tif1 operations will log detailed diagnostic info
session = tif1.get_session(2021, "Belgian Grand Prix", "Race")
laps = session.laps
```

**Debug Output Example** (a warm cache; a cold load also logs the CDN requests):
```text
2026-10-14 18:40:49 - tif1.core - DEBUG - Session initialized: year=2021, gp=Belgian Grand Prix, session=Race, lib=pandas
2026-10-14 18:40:49 - tif1.cache - DEBUG - SQLite cache initialized at /home/user/.cache/tif1/cache.sqlite with WAL mode
2026-10-14 18:40:49 - tif1.core - INFO - Loading laps async (pandas): 2021_Belgian%20Grand%20Prix_Race_laps
2026-10-14 18:40:49 - asyncio - DEBUG - Using selector: EpollSelector
2026-10-14 18:40:49 - tif1.core - INFO - Laps frame tier hit: 2021/Belgian%20Grand%20Prix/Race
2026-10-14 18:40:49 - tif1.cache - DEBUG - Cache connection closed
```

**Selective Logging Example:**
```python
import logging

import tif1

# Only show warnings and errors
tif1.setup_logging(logging.WARNING)

# Or use INFO for production monitoring
tif1.setup_logging(logging.INFO)

# Disable all tif1 logging
tif1.setup_logging(logging.CRITICAL + 1)
```

**Advanced: Per-Module Logging:**
```python
import logging

import tif1

# Set global level
tif1.setup_logging(logging.INFO)

# But enable DEBUG for specific modules
logging.getLogger("tif1.cache").setLevel(logging.DEBUG)
logging.getLogger("tif1.async_fetch").setLevel(logging.DEBUG)

# Now only cache and HTTP fetch operations show debug output
```

**Performance Considerations:**
- DEBUG and INFO logging format and write a record for each cache lookup and fetch step
- WARNING and above log only problems, so they add almost no work
- Python logging is synchronous: each record is written in the thread that logs it

**Best Practices:**
1. Use DEBUG during development to understand data flow
2. Use INFO in production for operational visibility
3. Use WARNING (default) for minimal overhead
4. Disable logging in performance-critical tight loops
5. Consider using a logging handler that writes to files for production

## Configuration

The `tif1` configuration system provides a flexible way to customize library behavior through environment variables, configuration files, or programmatic API calls. Configuration is managed through a singleton `Config` object that loads settings from multiple sources with a defined precedence order.

### Configuration Loading Order

Settings are loaded in the following order (later sources override earlier ones):

1. **Built-in defaults**: Hardcoded sensible defaults
2. **Configuration file** (`~/.tif1rc`): JSON file in user's home directory
3. **Environment variables**: Prefixed with `TIF1_` (for example, `TIF1_LIB=polars`)
4. **Programmatic calls**: Using `config.set()` at runtime

### `get_config`

Returns the global configuration singleton instance.

```python
def get_config() -> Config
```

The `Config` object is a singleton, meaning all calls to `get_config()` return the same instance. This ensures configuration consistency across the entire application.

**Returns:**
- `Config`: Singleton configuration instance

**Thread Safety:**
- `get()` and `set()` are plain dictionary operations without a lock
- Set the configuration once at start-up, before worker threads start
- `save()` writes the file in place; it is not an atomic write

**Basic Example:**
```python
import tif1

config = tif1.get_config()

# Get current settings
print(f"DataFrame library: {config.get('lib')}")
print(f"Cache enabled: {config.get('enable_cache')}")
print(f"Request timeout: {config.get('timeout')}s")
print(f"Max retries: {config.get('max_retries')}")

# Update settings at runtime
config.set("lib", "polars")
config.set("timeout", 60)

# Persist changes to disk
config.save()  # Saves to ~/.tif1rc
```

### Config Methods

#### `get(key: str, default: Any = None) -> Any`

Retrieve a configuration value by key.

**Parameters:**
- `key` (str): Configuration key name
- `default` (Any, optional): Value to return if key does not exist. Defaults to `None`.

**Returns:**
- The configuration value, or `default` if key not found

**Example:**
```python
config = tif1.get_config()

# Get with default fallback
lib = config.get("lib", "pandas")
timeout = config.get("timeout", 30)
custom = config.get("my_custom_key", "default_value")

# Check if key exists
if config.get("ultra_cold_start") is not None:
    print("Ultra cold start is configured")
```

#### `set(key: str, value: Any) -> None`

Update a configuration value in memory.

**Parameters:**
- `key` (str): Configuration key name
- `value` (Any): New value to set

**Behavior:**
- Most settings take effect on the next operation that reads them
- Some components read their settings once, when they are created. The CDN manager reads `cdns` and `cdn_use_minification` when `tif1.cdn` is first imported; `get_cdn_manager().reload()` applies a change. The circuit breaker applies new values after `reset_circuit_breaker()`
- Changes are in-memory only until `save()` is called
- `set()` does no type conversion: pass the type that the key expects (for example, an `int` for `timeout`)
- Unknown keys are stored as-is

**Example:**
```python
config = tif1.get_config()

# Set DataFrame backend
config.set("lib", "polars")  # or "pandas"

# Configure caching
config.set("enable_cache", True)
config.set("cache_dir", "/custom/cache/path")

# Network settings
config.set("timeout", 60)
config.set("max_retries", 5)

# Performance tuning
config.set("ultra_cold_start", True)
config.set("validate_data", False)

# Circuit breaker settings
config.set("circuit_breaker_threshold", 10)
config.set("circuit_breaker_timeout", 120)
```

#### `save(path: Path | str | None = None) -> None`

Save current configuration to a JSON file.

**Parameters:**
- `path` (Path | str | None, optional): File path to save to. If `None`, saves to `~/.tif1rc`. Defaults to `None`.

**Behavior:**
- Does not create parent directories: the target directory must exist
- Writes the file in place (not an atomic write)
- Logs an error instead of raising an exception when the write fails
- Saves all current settings, including defaults
- File format is human-readable JSON

**Example:**
```python
config = tif1.get_config()

# Save to default location (~/.tif1rc)
config.save()

# Save to custom location (the directory must exist)
config.save("./project_tif1_config.json")

# Save to user's config directory
from pathlib import Path
config_dir = Path.home() / ".config" / "tif1"
config_dir.mkdir(parents=True, exist_ok=True)
config.save(config_dir / "config.json")
```

**Configuration File Format:**
```json
{
  "lib": "polars",
  "enable_cache": true,
  "cache_dir": "<platform-specific default>",
  "timeout": 60,
  "max_retries": 5,
  "validate_data": false,
  "ultra_cold_start": true,
  "circuit_breaker_threshold": 10,
  "circuit_breaker_timeout": 120,
  "cdns": [
    "https://cdn.jsdelivr.net/gh/TracingInsights",
    "https://huggingface.co/buckets/tracinginsights",
    "https://cdn.staticdelivr.com/gh/TracingInsights"
  ]
}
```

### Available Configuration Keys

Reference of all configuration options:

| Key | Type | Default | Description | Performance Impact |
| :--- | :--- | :--- | :--- | :--- |
| `lib` | `str` | `"pandas"` | DataFrame library: `"pandas"` or `"polars"` | Depends on the workload; pick the library of the analysis code |
| `enable_cache` | `bool` | `True` | Enable multi-layer caching system | Disabling eliminates cache overhead but requires re-fetching |
| `cache_dir` | `str` | OS-dependent | SQLite cache database location | SSD recommended for best performance |
| `timeout` | `int` | `30` | Network request timeout in seconds | Increase for slow connections |
| `max_retries` | `int` | `3` | Maximum retry attempts for failed requests | More retries = better reliability, slower failures |
| `validate_data` | `bool` | `False` | Enable Pydantic validation of JSON data | Enabling adds validation work to each payload |
| `ultra_cold_start` | `bool` | `True` | Cold-start fast path: an uncached session skips the cache read and validation | Faster first load; a cached session loads from the cache as usual |
| `circuit_breaker_threshold` | `int` | `5` | Failures before circuit breaker opens | Lower = faster failure detection |
| `circuit_breaker_timeout` | `int` | `60` | Circuit breaker reset timeout in seconds | Time to wait before retrying failed service |
| `cdns` | `list[str]` | `["https://cdn.jsdelivr.net/gh/TracingInsights", "https://huggingface.co/buckets/tracinginsights", "https://cdn.staticdelivr.com/gh/TracingInsights"]` | List of CDN base URLs, tried in order | Multiple CDNs improve reliability |
| `cdn_use_minification` | `bool` | `False` | Request `.min.json` files from custom mirrors (the default CDNs ignore it) | Only useful with a mirror that serves minified copies |

### Environment Variable Configuration

Most configuration keys can be set via environment variables using the `TIF1_` prefix:

```bash
# Set DataFrame library
export TIF1_LIB=polars

# Configure caching
export TIF1_ENABLE_CACHE=true
export TIF1_CACHE_DIR=/custom/cache/path

# Network settings
export TIF1_TIMEOUT=60
export TIF1_MAX_RETRIES=5

# Performance tuning
export TIF1_ULTRA_COLD_START=true
export TIF1_VALIDATE_DATA=false

# Circuit breaker
export TIF1_CIRCUIT_BREAKER_THRESHOLD=10
export TIF1_CIRCUIT_BREAKER_TIMEOUT=120
```

**Type Conversion:**
- Booleans: `"true"`, `"1"`, `"yes"`, `"on"` → `True`; `"false"`, `"0"`, `"no"`, `"off"` → `False`
- Integers: Parsed automatically
- Lists: Comma-separated values (for example, `"url1,url2,url3"`)

```python
import tif1

config = tif1.get_config()
```

#### Custom Cache Location
```python

import tempfile

# The cache reads cache_dir once, when it is created (first data load).

config.save()
```

### Configuration Best Practices

1. **Use environment variables for deployment**: Easier to configure across environments without code changes
2. **Save configuration after tuning**: Persist the optimized settings with `config.save()`
3. **Use polars when the analysis code uses polars**: Laps and telemetry then arrive as polars frames
4. **Keep validation off in production**: `validate_data` is off by default; turn it on to check untrusted data
5. **Increase timeout for slow networks**: Default 30s may not be enough on mobile/satellite connections
6. **Keep ultra-cold start on**: It makes the first load of an uncached session faster
7. **Configure the circuit breaker for each use case**: Lower threshold for fail-fast, higher for resilience
8. **Use multiple CDNs for reliability**: Configure fallback CDNs in production

## Cache Management

The `tif1` caching system is a performance component that reduces data loading times and network bandwidth usage. It implements a multi-layer caching strategy with both in-memory (LRU) and persistent (SQLite) storage.

### Cache Architecture

The cache system consists of three layers:

1. **In-memory LRU tiers of the `Cache` object**: Raw and parsed JSON and telemetry payloads
2. **SQLite persistent cache**: Disk-based storage for JSON responses, telemetry payloads and built DataFrames
3. **Process-global lap caches**: One LRU of lap DataFrames for pandas and one for polars (see `clear_lap_cache()`)

### `get_cache`

Returns the persistent SQLite cache singleton instance.

```python
def get_cache() -> Cache
```

The `Cache` object manages the SQLite database that stores fetched JSON data and telemetry. Like `Config`, it is a singleton ensuring consistent cache state across the application.

**Returns:**
- `Cache`: Singleton cache instance

**Thread Safety:**
- The Cache singleton is thread-safe
- Uses one SQLite connection (WAL mode) guarded by a lock
- Automatic transaction management with periodic commits
- Safe for use in multi-threaded applications

**Basic Example:**
```python
import tif1

cache = tif1.get_cache()

# Inspect cache location
print(f"Cache directory: {cache.cache_dir}")
print(f"Cache database: {cache.db_path}")  # <cache_dir>/cache.sqlite

# Check if specific session is cached.
# Cache keys use the URL-encoded names, as in session.gp and session.session.
session = tif1.get_session(2025, "Monaco Grand Prix", "Race")
has_data = cache.has_session_data(session.year, session.gp, session.session)
print(f"Monaco GP cached: {has_data}")

# cache.clear() deletes all cached data (see clear() below)
```

### Cache Methods

#### `get(key: str) -> Any | None`

Retrieve raw cached data by key.

**Parameters:**
- `key` (str): Cache key. Session files use `{year}/{gp}/{session}/{file}.json` with URL-encoded names, for example `2025/Monaco%20Grand%20Prix/Race/drivers.json`

**Returns:**
- Cached data (usually dict or list), or `None` if not found

**Behavior:**
- Checks in-memory cache first (O(1) lookup)
- Falls back to SQLite if not in memory (O(log n) lookup)
- Automatically deserializes JSON data
- Updates in-memory cache on SQLite hit

**Example:**
```python
cache = tif1.get_cache()

# Get the raw drivers payload ({"drivers": [...]}) of a session
drivers = cache.get("2025/Monaco%20Grand%20Prix/Race/drivers.json")
if drivers:
    print(f"Found {len(drivers['drivers'])} drivers in cache")
else:
    print("Drivers file not cached yet")
```

#### `set(key: str, data: Any) -> None`

Store data in cache.

**Parameters:**
- `key` (str): Cache key
- `data` (Any): Data to cache (must be JSON-serializable)

**Behavior:**
- Stores in both memory and SQLite
- Automatically serializes to JSON
- Commits to disk periodically (every `cache_commit_interval` writes, default 100) or on close
- Overwrites existing data for the same key

**Example:**
```python
cache = tif1.get_cache()

# Cache custom data
cache.set("custom/analysis/results.json", {
    "fastest_lap": "1:23.456",
    "driver": "VER",
    "session": "Q3"
})

# Retrieve it later
results = cache.get("custom/analysis/results.json")
```

#### `get_telemetry(year: int, gp: str, session: str, driver: str, lap: int) -> Any | None`

Get cached telemetry data for a specific lap.

**Parameters:**
- `year` (int): Season year
- `gp` (str): Grand Prix name, URL-encoded as in `session.gp` (for example, `"Belgian%20Grand%20Prix"`)
- `session` (str): Session name, URL-encoded as in `session.session` (for example, `"Race"`, `"Practice%201"`)
- `driver` (str): Driver code (for example, "VER", "HAM")
- `lap` (int): Lap number

**Returns:**
- Raw telemetry payload (a dict of channel lists such as `time`, `speed`, `rpm`), or `None` if not cached

**Behavior:**
- Keys entries on the tuple `(year, gp, session, driver, lap)`
- Checks memory cache first for ultra-fast access
- Falls back to SQLite for persistent storage
- Returns the raw payload dict (not a DataFrame)

**Example:**
```python
cache = tif1.get_cache()

# Check if specific lap telemetry is cached
tel = cache.get_telemetry(2021, "Belgian%20Grand%20Prix", "Race", "VER", 1)
if tel:
    print(f"Cached telemetry has {len(tel['time'])} samples")
else:
    print("Telemetry not cached; tif1 fetches it from the CDN on first use")
```

#### `set_telemetry(year: int, gp: str, session: str, driver: str, lap: int, data: Any) -> None`

Store telemetry data in cache.

**Parameters:**
- `year` (int): Season year
- `gp` (str): Grand Prix name, URL-encoded as in `session.gp`
- `session` (str): Session name, URL-encoded as in `session.session`
- `driver` (str): Driver code
- `lap` (int): Lap number
- `data` (Any): Telemetry data to cache

**Behavior:**
- Stores in both memory and SQLite
- Compresses payloads of 4 KB or more in SQLite (zstd, or zlib without zstd)
- Automatically commits periodically
- Enables fast subsequent access

**Example:**
```python
cache = tif1.get_cache()

# Manually cache telemetry (tif1 does this automatically for real laps).
# Use a key that no real session uses, so real telemetry is not replaced.
telemetry_data = {
    "time": [0.0, 0.1, 0.2],
    "speed": [0, 50, 100],
    "throttle": [0, 50, 100]
}
cache.set_telemetry(2099, "Example%20Grand%20Prix", "Race", "TST", 1, telemetry_data)
print(cache.get_telemetry(2099, "Example%20Grand%20Prix", "Race", "TST", 1)["speed"])
```

#### `get_telemetry_batch(year: int, gp: str, session: str, driver_laps: list[tuple[str, int]]) -> dict[tuple[str, int], Any]`

Get multiple laps of telemetry in a single operation.

**Parameters:**
- `year` (int): Season year
- `gp` (str): Grand Prix name, URL-encoded as in `session.gp`
- `session` (str): Session name, URL-encoded as in `session.session`
- `driver_laps` (list[tuple[str, int]]): `(driver_code, lap_number)` pairs; one batch can mix drivers

**Returns:**
- Dict mapping `(driver_code, lap_number)` to telemetry data (only includes cached laps)

**Performance:**
- Single SQLite query for all laps (much faster than individual queries)
- Optimized for bulk operations
- Returns only cached laps (missing laps are omitted)

**Example:**
```python
cache = tif1.get_cache()

# Get telemetry for multiple laps at once
laps_to_fetch = [("VER", 1), ("VER", 2), ("HAM", 1), ("HAM", 2)]
cached_telemetry = cache.get_telemetry_batch(
    2021, "Belgian%20Grand%20Prix", "Race", laps_to_fetch
)

print(f"Found {len(cached_telemetry)} of {len(laps_to_fetch)} laps in cache")

# Process cached laps
for (driver, lap_num), tel_data in cached_telemetry.items():
    print(f"{driver} lap {lap_num}: {len(tel_data['time'])} samples")
```

#### `has_session_data(year: int, gp: str, session: str) -> bool`

Check if cache contains data for a specific session.

**Parameters:**
- `year` (int): Season year
- `gp` (str): Grand Prix name, URL-encoded as in `session.gp` (the plain name also works)
- `session` (str): Session name, URL-encoded as in `session.session` (the plain name also works)

**Returns:**
- `True` if session data exists in cache, `False` otherwise

**Behavior:**
- Returns `True` when any cached JSON file or telemetry entry belongs to the session
- Fast operation (a memory scan, then at most two SQLite queries)
- Returns `True` when the probe itself fails, so that loads still try the cache
- Useful for pre-flight checks before loading

**Example:**
```python
from urllib.parse import quote

cache = tif1.get_cache()
gp = quote("Monaco Grand Prix")  # "Monaco%20Grand%20Prix"

# Check multiple sessions
sessions = ["Practice 1", "Practice 2", "Practice 3", "Qualifying", "Race"]
for session_name in sessions:
    cached = cache.has_session_data(2025, gp, quote(session_name))
    status = "✓ cached" if cached else "✗ not cached"
    print(f"{session_name}: {status}")

# Conditional loading
if not cache.has_session_data(2025, gp, "Race"):
    print("Data not cached; the next load fetches it from the CDN")
```

#### `clear() -> None`

Remove all entries from both memory and SQLite cache.

**Behavior:**
- Clears in-memory LRU cache
- Deletes all rows from SQLite tables
- Does not vacuum the database: the file keeps its size until SQLite reuses the free pages
- Thread-safe operation

**Example:**
```python
cache = tif1.get_cache()

# Clear all cached data
cache.clear()
print("All cache data cleared")

# Verify cache is empty
print(cache.has_session_data(2025, "Monaco%20Grand%20Prix", "Race"))  # False
```

**Use Cases:**
- Free disk space
- Force re-fetch of all data
- Clear corrupted cache entries
- Reset after configuration changes

#### `close() -> None`

Close the SQLite database connection and flush pending writes.

**Behavior:**
- Commits any pending transactions
- Closes database connection
- Releases file locks
- `tif1` registers an `atexit` hook that closes the global cache, so an explicit call is not necessary

<Note>
  Closing the global cache also releases it: the next `get_cache()` call opens a new, working instance, and later loads use it. The closed object itself stays closed: its reads miss and its writes are dropped. Call `get_cache()` again instead of keeping the old reference.
</Note>

**Example:**
```python
import tif1

cache = tif1.get_cache()
cache.close()  # commits pending writes and closes the connection

# get_cache() now opens a new instance
new_cache = tif1.get_cache()
print(new_cache is cache)  # False
```

### Cache Size Management

The cache grows over time as more sessions are loaded. Here is how to manage cache size:

**Check Cache Size:**
```python
import tif1
from pathlib import Path

cache = tif1.get_cache()

# The database is cache.sqlite plus its -wal and -shm files
size_bytes = sum(path.stat().st_size for path in Path(cache.cache_dir).glob("cache.sqlite*"))
print(f"Cache size: {size_bytes / (1024 * 1024):.2f} MB")
```

**Cache Cleanup Strategies:**

```python
import tif1

cache = tif1.get_cache()

# Strategy 1: Clear everything (the database file keeps its size)
cache.clear()
```

Strategy 2 is to delete the database files. First stop all Python processes that use `tif1`. Then delete `cache.sqlite`, `cache.sqlite-wal` and `cache.sqlite-shm` in the cache directory. A process that has the database open continues to write to the deleted file.

### Async Cache Operations

The cache also supports async operations for use in async applications:

```python
import asyncio
import tif1

async def fetch_cached_data():
    cache = tif1.get_cache()

    # Async get
    data = await cache.get_async("2025/Monaco%20Grand%20Prix/Race/drivers.json")

    # Async set
    await cache.set_async("custom/key", {"data": "value"})

    # Async telemetry get
    tel = await cache.get_telemetry_async(
        2021, "Belgian%20Grand%20Prix", "Race", "VER", 1
    )

    # Async batch telemetry: (driver, lap) pairs
    batch = await cache.get_telemetry_batch_async(
        2021, "Belgian%20Grand%20Prix", "Race", [("VER", 1), ("VER", 2), ("VER", 3)]
    )

    return data

# Run async code
asyncio.run(fetch_cached_data())
```

### Cache Best Practices

1. **Let the cache warm up**: First load is slow, subsequent loads are fast
2. **Do not clear cache unnecessarily**: The cache improves performance on repeated loads
3. **Monitor cache size**: Set up periodic cleanup if disk space is limited
4. **Use batch operations**: `get_telemetry_batch()` is much faster than individual calls
5. **Do not keep a closed cache object**: `tif1` closes the cache at exit. After `close()`, call `get_cache()` again
6. **Check what is cached**: `has_session_data()` tells whether any file of a session is in the cache
7. **Use SSD for cache**: Faster than HDD for SQLite operations
8. **Consider cache location**: Put cache on fast local storage, not network drives

## Data Utilities

The data utilities provide convenient functions for converting between different time formats and safely navigating nested data structures. These are particularly useful when working with lap times, timestamps, and JSON responses.

### `to_timedelta`

Convert various time formats to pandas `Timedelta` objects.

```python
def to_timedelta(x: str | float | int | timedelta) -> pd.Timedelta
```

This function provides a unified interface for converting lap times, sector times, and other duration values into pandas `Timedelta` objects. The converted values support consistent time arithmetic and comparison.

**Parameters:**
- `x` (str | float | int | timedelta): Time value to convert

**Supported Input Formats:**

| Input Type | Format | Example | Result |
| :--- | :--- | :--- | :--- |
| String (MM:SS.mmm) | `"M:SS.mmm"` | `"1:23.456"` | 1 min 23.456 sec |
| String (HH:MM:SS.mmm) | `"HH:MM:SS.mmm"` | `"00:01:23.456"` | 1 min 23.456 sec |
| Float (seconds) | Decimal seconds | `83.456` | 83.456 seconds |
| Integer (seconds) | Whole seconds | `83` | 83 seconds |
| Timedelta | Passthrough | `pd.Timedelta(seconds=83.456)` | Unchanged |

**Behavior:**
- Automatically adds leading `"00:"` to `"M:SS.mmm"` format
- Handles negative numbers (for example, `-1.234` for a delta). A negative string needs the full `"-00:00:01.234"` form
- Keeps nanosecond precision
- Returns pandas `Timedelta` for consistent arithmetic

**Basic Examples:**
```python

import pandas as pd

# From lap time string (M:SS.mmm format)
lap_time = to_timedelta("1:23.456")
print(lap_time)  # 0 days 00:01:23.456000

# From full time string (HH:MM:SS.mmm format)
full_time = to_timedelta("00:01:23.456")
print(full_time)  # 0 days 00:01:23.456000

# From seconds (float)
from_seconds = to_timedelta(83.456)
print(from_seconds)  # 0 days 00:01:23.456000

# From seconds (int)
from_int = to_timedelta(83)
print(from_int)  # 0 days 00:01:23

# Passthrough timedelta
td = pd.Timedelta(seconds=83.456)
result = to_timedelta(td)
assert result == td
```

**Time Arithmetic:**
```python

lap2 = to_timedelta("1:24.123")

print(f"Lap 2 was {delta.total_seconds():.3f}s slower")  # 0.667s slower

# Sum sector times

sector3 = to_timedelta("0:23.789")

# Calculate average lap time
```


### `recursive_dict_get`

Safely navigate nested dictionaries without raising `KeyError`.

```python

```

This function provides safe access to deeply nested dictionary values. It returns a default value instead of raising exceptions when keys do not exist.

**Parameters:**
- `d` (dict): Dictionary to navigate
- `*keys` (str): Keys to traverse in order
- `default_none` (bool, optional): If `True`, return `None` for missing keys; if `False`, return `{}`. Defaults to `False`.

**Returns:**
- The value at the nested key path, or default value if any key is missing

**Basic Examples:**

```python
            "humidity": 65
        }
    }
}

# Successful navigation

print(name)  # "Monaco Grand Prix"

year = recursive_dict_get(data, "session", "info", "year")
print(year)  # 2025

# Missing key with default_none=False (returns {})

print(type(missing))  # <class 'dict'>

# Missing key with default_none=True (returns None)
```


### `delta_time`

Calculate delta time between two laps (FastF1 compatibility function).

```python
def delta_time(reference_lap: Lap, compare_lap: Lap) -> tuple[pd.Series, pd.DataFrame, pd.DataFrame]
```

This function follows FastF1's `delta_time`, without the distance scaling of recent FastF1 versions. It interpolates the comparison lap's time onto the reference lap's distance axis.

**Parameters:**
- `reference_lap` (Lap): Reference lap (for example, from `laps.pick_fastest()` or `Driver.get_lap()`), or a telemetry frame with `Time` and `Distance`
- `compare_lap` (Lap): Lap to compare against the reference (same kinds as `reference_lap`)

**Returns:**
- Tuple of `(delta_series, ref_telemetry, comp_telemetry)`
  - `delta_series`: Float seconds at each reference telemetry point. A positive value means that the comparison lap is slower at that point. The series is empty when either lap has fewer than two samples
  - `ref_telemetry`: Reference lap telemetry (pandas, also on the polars backend)
  - `comp_telemetry`: Comparison lap telemetry

**Example:**
```python
import tif1

# pick_driver() and pick_fastest() are pandas Laps methods: ask for pandas
# even when the configuration selects polars
session = tif1.get_session(2021, "Belgian Grand Prix", "Qualifying", lib="pandas")
laps = session.laps

# Get fastest laps for two drivers
ver_fastest = laps.pick_driver("VER").pick_fastest()
ham_fastest = laps.pick_driver("HAM").pick_fastest()

# Calculate delta (positive = HAM slower than VER at that point)
delta, ref_tel, comp_tel = tif1.utils.delta_time(ver_fastest, ham_fastest)

# Analyze where time was gained/lost
print(f"Largest HAM deficit: {delta.max():.3f}s")
print(f"Largest HAM advantage: {-delta.min():.3f}s")
```

**Note:** The delta is an estimate from interpolated telemetry, so it can differ slightly from the official lap time gap.

## Reliability & Networking

The `tif1` library implements reliability patterns to handle network failures, CDN outages, and transient errors gracefully. The circuit breaker pattern prevents cascading failures, while the CDN manager provides automatic fallback to alternative data sources.

### Circuit Breaker Pattern

The circuit breaker is a critical reliability component. It stops the application from repeatedly trying operations that are likely to fail. It acts like an electrical circuit breaker, "opening" after too many failures to prevent cascading issues.

**Circuit Breaker States:**

1. **Closed** (Normal): All requests are allowed through
2. **Open** (Failing): Requests are blocked immediately without attempting
3. **Half-Open** (Testing): Requests are allowed again. A success closes the breaker and a failure opens it again

**State Transitions:**
```text
Closed --[threshold failures]--> Open
Open --[timeout elapsed]--> Half-Open
Half-Open --[success]--> Closed
Half-Open --[failure]--> Open
```

### `get_circuit_breaker`

Returns the global circuit breaker instance used for CDN payload requests.

```python
def get_circuit_breaker() -> CircuitBreaker
```

The circuit breaker is a singleton that tracks failures across all network operations in the application.

**Returns:**
- `CircuitBreaker`: Global circuit breaker instance

**Thread Safety:**
- Fully thread-safe with atomic state transitions
- Uses reentrant locks for nested calls
- Safe for concurrent use across multiple threads

**Basic Example:**
```python
from tif1.retry import get_circuit_breaker

cb = get_circuit_breaker()

# Inspect current state
print(f"State: {cb.state}")  # "closed", "open", or "half-open"
print(f"Failure count: {cb.failures}")
print(f"Threshold: {cb.threshold}")
print(f"Timeout: {cb.timeout}s")

# Check if last failure time is set
if cb.last_failure_time:
    print(f"Last failure: {cb.last_failure_time}")
```

### CircuitBreaker Properties

#### `state: str`

Current circuit breaker state (read-only).

**Possible Values:**
- `"closed"`: Normal operation, all requests allowed
- `"open"`: Too many failures, requests blocked
- `"half-open"`: Testing recovery, limited requests allowed

**Example:**
```python
cb = get_circuit_breaker()

if cb.state == "open":
    print("Circuit breaker is open - service unavailable")
elif cb.state == "half-open":
    print("Circuit breaker testing recovery")
else:
    print("Circuit breaker closed - normal operation")
```

#### `failures: int`

Current failure count.

**Example:**
```python

```

#### `threshold: int`

Number of failures before circuit opens.

**Default:** 5 (configurable via `circuit_breaker_threshold` config)

#### `timeout: int`

Seconds to wait before transitioning from open to half-open.

**Default:** 60 (configurable via `circuit_breaker_timeout` config)

#### `last_failure_time: datetime | None`

Timestamp of the most recent failure.

**Example:**

#### `record_success() -> None`

**Behavior:**
- Resets failure counter to 0, unless the circuit is open
- Transitions from half-open to closed
- Thread-safe atomic operation

**Example** (`fetch_data()` stands for the application's own network call):


#### `record_failure() -> None`

Record a failed operation (increments failure count).

**Behavior:**
- Atomically increments failure counter
- Updates last failure timestamp
- Opens circuit if threshold reached
- Thread-safe operation

**Example:**

**Returns:**
- Tuple of `(should_proceed, current_state)`

**Example:**

#### Production Error Handling
```python
import tif1
from tif1.retry import get_circuit_breaker, reset_circuit_breaker
from tif1.cdn import get_cdn_manager
from tif1.exceptions import NetworkError, DataNotFoundError
import logging
import time

# Configure logging
tif1.setup_logging(logging.INFO)

def robust_session_loader(year, gp, session_type, max_attempts=3):
    """Production-grade session loader with comprehensive error handling."""
    cb = get_circuit_breaker()
    cdn = get_cdn_manager()

    for attempt in range(max_attempts):
        try:
            # Check circuit breaker
            if cb.state == "open":
                logging.warning(f"Circuit breaker open, waiting {cb.timeout}s...")
                time.sleep(cb.timeout)
                reset_circuit_breaker()

            # Attempt to load session
            logging.info(f"Loading session (attempt {attempt + 1}/{max_attempts})...")
            session = tif1.get_session(year, gp, session_type)
            laps = session.laps

            logging.info(f"Successfully loaded {len(laps)} laps")
            return session

        except DataNotFoundError as e:
            # Data genuinely doesn't exist - don't retry
            logging.error(f"Data not found: {e.message}")
            raise

        except NetworkError as e:
            logging.error(f"Network error: {e.message}")
            logging.info(f"Circuit breaker: {cb.state}, failures: {cb.failures}")
            logging.info(f"CDN sources: {len(cdn.get_sources())} available")

            if attempt < max_attempts - 1:
                wait_time = 2 ** attempt  # Exponential backoff
                logging.info(f"Retrying in {wait_time}s...")
                time.sleep(wait_time)
            else:
                logging.error("Max attempts reached, giving up")
                raise

    raise RuntimeError("Failed to load session after all attempts")

# Use in production
try:
    session = robust_session_loader(2021, "Belgian Grand Prix", "Race")
except Exception as e:
    logging.critical(f"Fatal error: {e}")
    # Alert monitoring system, etc.
```

### Reliability Best Practices

1. **Monitor circuit breaker state**: Check state before critical operations
2. **Respect circuit breaker**: Do not bypass it when open
3. **Reset after network changes**: Call `reset_circuit_breaker()` when switching networks
4. **Configure thresholds appropriately**: Lower for fail-fast, higher for resilience
5. **Use multiple CDNs**: Configure fallback CDNs for production
6. **Log failures**: Track patterns to identify systemic issues
7. **Implement exponential backoff**: Do not retry immediately after failures
8. **Handle DataNotFoundError separately**: Do not retry when data genuinely does not exist

### Example 4: Handle Network Issues

Reliable error handling with circuit breaker awareness.

```python
import tif1
from tif1.retry import get_circuit_breaker, reset_circuit_breaker
from tif1.cdn import get_cdn_manager
from tif1.exceptions import NetworkError, DataNotFoundError
import time
import logging

# Configure logging
tif1.setup_logging(logging.INFO)

def load_with_resilience(year, gp, session_type, max_retries=3):
    """Load session with comprehensive error handling and retry logic."""
    cb = get_circuit_breaker()
    cdn = get_cdn_manager()

    print(f"Loading {year} {gp} {session_type}...")
    print(f"Circuit breaker: {cb.state}, failures: {cb.failures}/{cb.threshold}")
    print(f"Available CDNs: {len(cdn.get_sources())}")

    for attempt in range(max_retries):
        try:
            # Check circuit breaker state
            if cb.state == "open":
                wait_time = cb.timeout
                print(f"\n⚠ Circuit breaker is OPEN")
                print(f"  Waiting {wait_time}s before retry...")
                time.sleep(wait_time)
                reset_circuit_breaker()
                print(f"  Circuit breaker reset")

            # Attempt to load
            print(f"\nAttempt {attempt + 1}/{max_retries}...")
            start_time = time.time()

            session = tif1.get_session(year, gp, session_type)
            laps = session.laps

            load_time = time.time() - start_time
            print(f"✓ Success! Loaded {len(laps)} laps in {load_time:.2f}s")

            return session

        except DataNotFoundError as e:
            # Data doesn't exist - don't retry
            print(f"\n✗ Data not found: {e.message}")
            print(f"  This session may not have data available")
            raise

        except NetworkError as e:
            print(f"\n✗ Network error: {e.message}")
            print(f"  Status code: {e.context.get('status_code')}")
            print(f"  Circuit breaker: {cb.state}")
            print(f"  Failures: {cb.failures}/{cb.threshold}")

            # Check CDN health
            available_cdns = cdn.get_sources()
            print(f"  Available CDNs: {len(available_cdns)}")

            if attempt < max_retries - 1:
                # Exponential backoff
                wait_time = 2 ** attempt
                print(f"  Retrying in {wait_time}s...")
                time.sleep(wait_time)
            else:
                print(f"\n✗ Failed after {max_retries} attempts")
                print(f"  Circuit breaker state: {cb.state}")
                print(f"  Consider:")
                print(f"    - Checking network connection")
                print(f"    - Increasing timeout (current: {tif1.get_config().get('timeout')}s)")
                print(f"    - Trying again later")
                raise

        except Exception as e:
            print(f"\n✗ Unexpected error: {type(e).__name__}: {e}")
            raise

    raise RuntimeError("Failed to load session")

# Example usage
try:
    session = load_with_resilience(2021, "Belgian Grand Prix", "Race")
    print(f"\nSession loaded successfully!")
    print(f"Drivers: {sorted(set(session.laps['Driver']))}")
except Exception as e:
    print(f"\nFatal error: {e}")
```

### Example 7: Memory-Efficient Batch Processing

Process multiple sessions while managing memory usage.

```python
import tif1
from tif1.cache import clear_lap_cache
import psutil
import os

def get_memory_mb():
    """Get current process memory usage in MB."""
    process = psutil.Process(os.getpid())
    return process.memory_info().rss / 1024 / 1024

def batch_process_season(year, cache_clear_interval=5):
    """Process entire season with memory management."""
    print(f"Batch Processing Season {year}")
    print("="*60)

    # Get all race weekends (pre-season testing has no race)
    events = tif1.get_event_schedule(year, include_testing=False)
    print(f"Found {len(events)} events\n")

    results = []
    initial_memory = get_memory_mb()

    for i, event_name in enumerate(events["EventName"], 1):
        print(f"[{i}/{len(events)}] Processing {event_name}...")

        try:
            # Load session (pick_fastest() is a pandas Laps method, so ask for
            # pandas even when the saved configuration selects polars)
            session = tif1.get_session(year, event_name, "Race", lib="pandas")
            laps = session.laps

            # Analyze (pick_fastest() returns one lap as a Series)
            fastest = laps.pick_fastest()
            fastest_time = fastest['LapTime']
            fastest_driver = fastest['Driver']

            result = {
                "event": event_name,
                "fastest_driver": fastest_driver,
                "fastest_time": str(fastest_time),
                "total_laps": len(laps)
            }
            results.append(result)

            current_memory = get_memory_mb()
            memory_increase = current_memory - initial_memory

            print(f"  Fastest: {fastest_driver} - {fastest_time}")
            print(f"  Memory: {current_memory:.1f} MB (+{memory_increase:.1f} MB)")

            # Clear cache periodically
            if i % cache_clear_interval == 0:
                clear_lap_cache()
                after_clear = get_memory_mb()
                freed = current_memory - after_clear
                print(f"  Cleared cache: freed {freed:.1f} MB")

        except Exception as e:
            print(f"  ✗ Error: {e}")
            results.append({
                "event": event_name,
                "error": str(e)
            })

        print()

    # Summary
    print("="*60)
    print("Batch Processing Complete")
    print(f"Processed: {len(results)} events")
    print(f"Final memory: {get_memory_mb():.1f} MB")
    print(f"Peak increase: {get_memory_mb() - initial_memory:.1f} MB")

    return results
```

## Best Practices

Guidelines for using `tif1` utilities effectively in different scenarios.

### Development Best Practices

1. **Enable Debug Logging During Development**
   ```python
   import tif1
   import logging

   # Enable detailed logging
   tif1.setup_logging(logging.DEBUG)
   ```
   - Helps understand data flow and identify issues
   - Shows cache hits/misses for optimization
   - Reveals network request patterns
   - Displays parsing and validation steps

2. **Use Pandas for Easier Debugging**
   ```python
   config = tif1.get_config()
   config.set("lib", "pandas")
   ```
   - More familiar API for most developers
   - `Laps` methods such as `pick_driver()` and `pick_fastest()` are available
   - Easier to inspect intermediate results

3. **Keep Validation Enabled**
   ```python
   config.set("validate_data", True)
   ```
   - Catches data quality issues early
   - Provides clear error messages
   - Helps identify API changes
   - The validation overhead is acceptable in development

4. **Use Shorter Timeouts**
   ```python
   config.set("timeout", 10)
   ```
   - Fail fast during development
   - Do not wait for slow connections
   - Iterate quickly on code changes

5. **Clear Cache When Testing**
   ```python
   cache = tif1.get_cache()
   cache.clear()
   ```
   - Ensures that tests run with fresh data
   - Forces new downloads from the CDN
   - Catches cache-related bugs

### Production Best Practices

1. **Use Polars When the Analysis Code Uses Polars**
   ```python
   config = tif1.get_config()
   config.set("lib", "polars")
   config.save()
   ```
   - Laps and telemetry arrive as polars frames
   - No conversion step in polars pipelines
   - The `Laps` helper methods (`pick_*`) need the pandas backend

2. **Keep Validation Off in Production**
   ```python
   config.set("validate_data", False)  # the default
   ```
   - Skips the validation work on each payload
   - Reduces CPU usage
   - Only disable if data quality is trusted
   - Keep enabled if data source is unreliable

3. **Increase Timeout for Reliability**
   ```python
   config.set("timeout", 60)
   config.set("max_retries", 5)
   ```
   - Handle slow networks gracefully
   - Accommodate mobile/satellite connections
   - Reduce failure rate
   - Balance with user experience

4. **Configure Circuit Breaker Appropriately**
   ```python
   config.set("circuit_breaker_threshold", 10)
   config.set("circuit_breaker_timeout", 120)
   ```
   - Higher threshold for production resilience
   - Longer timeout for recovery
   - Prevents cascading failures
   - Monitor circuit breaker state

5. **Use Multiple CDNs**
   ```python
   from tif1.cdn import get_cdn_manager

   config.set("cdns", [
       "https://cdn.jsdelivr.net/gh/TracingInsights",
       "https://huggingface.co/buckets/tracinginsights",
       "https://cdn.staticdelivr.com/gh/TracingInsights",
       "https://mirror.example.com/TracingInsights",  # a custom mirror
   ])

   config.save()
   ```

   - Automatic fallback on CDN failure
   - Improved reliability
   - Geographic redundancy
   - Load distribution

6. **Set Up Proper Logging**

   - Monitor operational health

   - Audit data access

### Performance Optimization

   ```python
       session.load(laps=True, telemetry=False)
   except ValueError as e:
       # Unknown event or session name - fix the request, do not retry
       print(f"Invalid request: {e}")
   except DataNotFoundError:
       # Data doesn't exist - don't retry
       print("Session data not available")
   except NetworkError:
       # Network issue - can retry
       print("Network error, retrying...")
   ```
   - Do not retry `ValueError` (unknown names) or DataNotFoundError
   - Retry NetworkError with backoff
   - Handle each error type appropriately

3. **Implement Exponential Backoff**
   ```python
   import time

   from tif1.exceptions import NetworkError

   year, gp, session_type = 2021, "Belgian Grand Prix", "Race"
   max_retries = 3

   for attempt in range(max_retries):
       try:
           session = tif1.get_session(year, gp, session_type)
           break
       except NetworkError:
           if attempt < max_retries - 1:
               wait_time = 2 ** attempt
               time.sleep(wait_time)
   ```
   - Do not retry immediately
   - Give service time to recover
   - Reduce load on failing service
   - Increase wait time exponentially
