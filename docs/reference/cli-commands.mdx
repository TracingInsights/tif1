The `tif1` CLI provides quick access to F1 data without writing Python code. It is a thin wrapper around the Python API. The data commands load data through `tif1.get_events()`, `tif1.get_sessions()`, or `tif1.get_session()` and print a table.

## Installation

The CLI is included with tif1. Verify the installation:

```bash
tif1 version
```

## Usage

```bash
tif1 [OPTIONS] COMMAND [ARGS]...
```

The CLI has no global options other than the standard ones below. Behaviour such as the DataFrame backend or caching is controlled through [environment variables](#environment-variables) or a `.tif1rc` file.

| Option | Description |
| :--- | :--- |
| `--help` | Show help for the CLI or for one command and exit |
| `--install-completion` | Install shell completion for the current shell |
| `--show-completion` | Print the completion script instead of installing it |

Every command accepts `--help`, for example `tif1 fastest --help`.

Times are lap times in seconds. Rich wraps a table title that is wider than the table.

**Options:**

| Option | Description |
| :--- | :--- |
| `--driver`, `-d CODE` | Show only this driver's fastest lap (three-letter code, for example `VER`). The code is case-sensitive; an unknown code exits with `DriverNotFoundError`. |

A lap counts when its `LapTime` is set. A driver without any timed lap is left out of the table; with `--driver` the command prints `No valid laps for CODE` instead of a time.

### results

Show the classification of a session: the official Ergast results merged into `session.results` (grid, status, points, race time or qualifying segments).

```bash
tif1 results YEAR EVENT SESSION [--no-ergast]
```

**Options:**

| Option | Description |
| :--- | :--- |
| `--no-ergast` | Print the lap-derived classification without the Ergast merge |

```bash
tif1 results 2024 "Bahrain Grand Prix" Race
tif1 results 2010 "Abu Dhabi Grand Prix" Qualifying
```

### standings

Show the drivers' (default) or constructors' championship standings after a round. Without `ROUND`, the standings after the last completed round (the final standings of a past season).

```bash
tif1 standings YEAR [ROUND] [--constructors]
```

**Options:**

| Option | Description |
| :--- | :--- |
| `--constructors`, `-c` | Constructors' standings instead of drivers' |

```bash
tif1 standings 2024 10
tif1 standings 2023 --constructors
```

### cache-info

Show where the cache lives and how large it is.

```bash
tif1 cache-info
```

```text
Cache location: /home/user/.cache/tif1
Cache files: 3
Total size: 184.52 MB
```

The size counts the SQLite database and its WAL/SHM files. If no `cache.sqlite*` file exists yet, it counts every file in the cache directory. Set `TIF1_CACHE_DIR` to move the cache.

### cache-clear

Delete all cached data. The command asks for confirmation unless `--yes` is given.

```bash
tif1 cache-clear [--yes] [--ergast]
```

**Options:**

| Option | Description |
| :--- | :--- |
| `--yes`, `-y` | Skip the confirmation prompt (for scripts) |
| `--ergast` | Clear only the Ergast tier (Stats repository files and Jolpica answers) |

```text
Are you sure you want to clear the cache? [y/N]: y
Cache cleared successfully!
```

Any answer other than `y` prints `Cache clear cancelled`. The command deletes the rows of every cache table. The `cache.sqlite` file keeps its size, and SQLite reuses the free pages for new data.

### version

Print the installed tif1 version.

```bash
tif1 version
```

```text
tif1 version 0.11.1
```

### debug

Load a session with debug logging enabled and print a short summary. Use it to see which CDN sources and cache tiers a load touches.

```bash
tif1 debug YEAR EVENT SESSION
```

Output of `tif1 debug 2025 "Monaco Grand Prix" Race` with a warm cache:

```text
2026-10-14 18:29:47 - tif1.core - DEBUG - Session initialized: year=2025, gp=Monaco Grand Prix, session=Race, lib=pandas
2026-10-14 18:29:47 - tif1.cache - DEBUG - SQLite cache initialized at /home/user/.cache/tif1/cache.sqlite with WAL mode
Loading session with debug logging... ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 100% 0:00:00
Session loaded successfully!
2026-10-14 18:29:47 - tif1.cache - DEBUG - Cache hit (SQLite): 2025/Monaco%20Grand%20Prix/Race/drivers.json
2026-10-14 18:29:47 - tif1.core - INFO - Loading laps async (pandas): 2025_Monaco%20Grand%20Prix_Race_laps
2026-10-14 18:29:47 - asyncio - DEBUG - Using selector: EpollSelector
2026-10-14 18:29:47 - tif1.core - INFO - Laps frame tier hit: 2025/Monaco%20Grand%20Prix/Race
Drivers: 20
```

The command calls `tif1.setup_logging(logging.DEBUG)`. The timestamped log lines go to stderr, and the summary goes to stdout. Drivers and laps load lazily, so `Session loaded successfully!` appears before the fetch and cache log lines. On a cold cache, the log also shows the `Trying CDN: jsDelivr - <url>` request lines.

## Environment Variables

The CLI reads the same configuration as the Python API. The most useful variables are:

```bash
# Use the polars backend for the fastest-lap table
export TIF1_LIB=polars
tif1 fastest 2025 "Monaco Grand Prix" Race

# Disable the on-disk cache
export TIF1_ENABLE_CACHE=false
tif1 drivers 2025 "Monaco Grand Prix" Race

# Use another cache directory
export TIF1_CACHE_DIR="$HOME/tif1-cache"
tif1 cache-info
```

For debug logs, use the `debug` command.

See the [environment variables reference](/reference/environment-variables) for the full list.

## Shell Completion

Typer generates completion scripts for bash, zsh, fish, and PowerShell.

```bash
# Install completion for the current shell, then restart the shell
tif1 --install-completion

# Or print the script to inspect it
tif1 --show-completion
```

## Piping and Scripting

Commands print formatted tables, not machine-readable output. For scripting, grep the table or use the Python API directly.

```bash
# Check that a session exists before running a longer job
if tif1 sessions 2025 "Monaco Grand Prix" | grep -q "Race"; then
  tif1 fastest 2025 "Monaco Grand Prix" Race
fi

# Machine-readable data: use Python
python -c "import tif1; print(tif1.get_session(2025, 'Monaco', 'Race').laps.to_csv())" > laps.csv
```

## Exit Codes

| Exit Code | Meaning |
| :--- | :--- |
| `0` | Success |
| `1` | A `tif1` error (for example data not found, network failure) or any other exception; the traceback is printed |
| `2` | Usage error: missing or invalid arguments |

```bash
tif1 drivers 2025 "Monaco Grand Prix" Sprint
echo $?  # 1 (ValueError: Session 'Sprint' does not exist for 2025 Monaco Grand Prix.)

tif1 events
echo $?  # 2 (Missing argument 'year'.)
```

A misspelled event name does not fail. Event names are fuzzy-matched, so `tif1 sessions 2025 "Monacco"` logs `Correcting user input 'Monacco' to 'Monaco Grand Prix'` on stderr. It then exits `0` with the sessions of that event. Circuit, city, and country aliases resolve directly.

A name that resembles no event, such as `"Paris"`, exits `1` with `EventNotFoundError` in `sessions`, `drivers`, `fastest`, and `debug`. An alias of an event that is not on the calendar exits `1` with `EventNotInSeasonError`.
