This guide explains how to set up a development environment and how to submit changes to `tif1`.

## Development Setup

### Prerequisites
- **Python 3.11+** (CI tests 3.11 through 3.15)
- **[uv](https://github.com/astral-sh/uv)** (Recommended for dependency management)

### Installation
<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/TracingInsights/tif1.git
    cd tif1
    ```
  </Step>
  <Step title="Install dependencies">
    Use `uv` to create a virtual environment and install all development extras.
    ```bash
    uv sync --all-extras
    ```
  </Step>
  <Step title="Install git hooks with prek">
    Enable the lint and format checks before every commit and push.
    ```bash
    uv run prek install
    ```
  </Step>
</Steps>

## Testing Workflow

The test suite uses `pytest`, with `xdist` for parallel execution.

### Running Tests
<CodeGroup>
```bash All Tests
uv run pytest tests/ -v
```

```bash Unit Only
uv run pytest tests/unit/ -v
```

```bash Integration
uv run pytest -o addopts='' tests/ -v -n 0 -m integration
```

```bash Benchmarks
uv run pytest -o addopts='' tests/benchmarks/ -v -m benchmark --benchmark-only --no-cov -n 0
```
</CodeGroup>

An autouse fixture blocks real network sockets. A test that must reach the network needs the `integration`, `compliance_online`, or `benchmark` marker. Tests under `tests/integration/` are exempt.

### Code Coverage
Run the tests with coverage reporting. CI fails when the total coverage is below 80%.
```bash
uv run pytest -o addopts='' tests/ -v -n auto --dist=loadfile --cov=src/tif1 --cov-report=html
```

## Code Quality

Make sure that the code passes all quality checks before a pull request is submitted.

- **Linting & Formatting:** The project uses `ruff`.
  ```bash
  uv run ruff check src/ tests/
  uv run ruff format src/ tests/
  ```
- **Type Checking:** The project uses `ty`.
  ```bash
  uv run ty check src/tif1
  ```
- **prek:** Run the git hook checks (ruff, ruff format, and file checks) on all files. CI runs the same command.
  ```bash
  uv run prek run --all-files
  ```

## Documentation

The documentation is built with **Mintlify**.

### Local Development
To preview the documentation locally:
1. Install the Mintlify CLI: `npm i -g mint`
2. Run the dev server in the `docs` directory: `mint dev`

### Guidelines
- Use **Google-style** docstrings for all public functions.
- Update `docs/docs.json` when a new page is added.
- Follow the house style in `docs/style-ste100.md`. Check a page with `python3 tools/ste_check.py docs/<page>.mdx`.
- Use Mintlify components (`<Steps>`, `<Card>`, `<CodeGroup>`) to structure the pages.

## Pull Request Process

1. **Create a branch:** `git checkout -b feat/your-awesome-feature`
2. **Implement & Test:** Make sure that the coverage does not drop.
3. **Commit:** Use [Conventional Commits](https://www.conventionalcommits.org/), for example `feat:`, `fix:`, `docs:`, `perf:`.
4. **Push & Open PR:** Describe the changes and the reason for them.

<Tip>
  Check **CHANGELOG.md** and add a summary of the changes there as well.
</Tip>
