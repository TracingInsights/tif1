`tif1` provides data in a structured format consistent with `fastf1`. This page lists every column in the main DataFrames.

<Note>
  `tif1` uses the fastf1 column names, which are mostly **PascalCase**, for example `LapTime` and `Speed`. A few source columns keep lower-case names: `index`, `drv`, `team`, `ms1` to `ms3`, and the telemetry column `nGear`.
</Note>

<Info>
  This page documents the DataFrame columns that tif1 provides. tif1 builds these DataFrames from raw JSON files in the TracingInsights data repos. The repos store the data under short abbreviated keys: `s1`, `vi1`, `wWS`. Every raw field is documented in the [Data Reference](/reference/data-reference).
</Info>

## ⏱️ Lap Data (`session.laps`)

The `laps` DataFrame contains one row for every lap completed by every driver in the session. The dtype of a column depends on the backend. On pandas, time columns are `timedelta64[ns]`. On polars, the same columns are `Duration("ns")`.

<Note>
  Compare pandas time columns with `pd.Timedelta`, or use `LapTimeSeconds`, which is a float on both backends. `laps[laps["LapTime"] < 90]` raises `TypeError` on pandas. On polars, `pl.col("LapTime") < 90` compares nanoseconds and selects no lap.
</Note>

### Core Timing
| Column | pandas dtype | polars dtype | Unit | Description |
| :--- | :--- | :--- | :--- | :--- |
| `index` | `int64` | not present | - | Row index from the source data, kept as a leading column. `to_csv(index=False)` still writes it. |
| `LapNumber` | `float64` | `Int64` | - | Which lap this is (starts at 1). |
| `LapTime` | `timedelta64[ns]` | `Duration("ns")` | - | The total time to complete the lap. |
| `LapTimeSeconds` | `float64` | `Float64` | Seconds | The lap time as a float on both backends. |
| `Time` | `timedelta64[ns]` | `Duration("ns")` | - | Session time when the lap ended. |
| `LapStartTime` | `timedelta64[ns]` | `Duration("ns")` | - | Session time when the lap started. |
| `LapStartDate` | `datetime64[ns]` | `Datetime("ns")` | - | Absolute calendar timestamp when the lap started. |
| `WeatherTime` | `timedelta64[ns]` | `Duration("ns")` | - | Session time of the weather sample that the source data matched to the lap. The match is not always the right one: refer to Per-Lap Weather. |

### Per-Lap Weather
Every lap carries one weather sample that the source data matched to the lap. `WeatherTime` gives the session time of that sample. These columns are misaligned in the source data. In the 2025 Bahrain race, 435 of the 1,128 laps carry a sample other than the one that the fastf1 rule picks. To relate weather to laps, use `laps.get_weather_data()`. It picks the sample of each lap from `session.weather` with the fastf1 rule. The rule takes the first sample within the lap, else the last one before the lap ended.

| Column | pandas dtype | polars dtype | Unit | Description |
| :--- | :--- | :--- | :--- | :--- |
| `AirTemp` | `float64` | `Float64` | °C | Ambient air temperature. |
| `TrackTemp` | `float64` | `Float64` | °C | Asphalt surface temperature. |
| `Humidity` | `float64` | `Float64` | % | Relative humidity. |
| `Pressure` | `float64` | `Float64` | mbar | Atmospheric pressure. |
| `Rainfall` | `bool` | `Boolean` | - | `True` if it was raining. |
| `WindDirection` | `Int64` | `Int64` | ° | Compass bearing (0-359). |
| `WindSpeed` | `float64` | `Float64` | m/s | Wind speed. |

## 🎯 Telemetry Data (`lap.telemetry`)

Samples recorded throughout a lap, about 0.13 s apart in the 2024 Monaco Race data. `Time` is lap-relative and starts at 0 at the lap start. The telemetry of several laps (`laps.telemetry`) counts `Time` from the start of the first lap, and `session.car_data[n]` holds the session time in `Time`, as fastf1 does. `SessionTime` and `Date` give the session time and the wall-clock date of each sample. The columns follow the fastf1 order, then the tif1 extras.

### Car Metrics
| Column | pandas dtype | polars dtype | Unit | Description |
| :--- | :--- | :--- | :--- | :--- |
| `Date` | `datetime64[ns]` | `Datetime("ns")` | - | Wall-clock date of the sample: `LapStartDate + Time`. |
| `SessionTime` | `timedelta64[ns]` | `Duration("ns")` | - | Session time of the sample: `LapStartTime + Time`. |
| `Time` | `timedelta64[ns]` | `Duration("ns")` | - | Time from the start of the lap (of the first lap for several laps; the session time in `session.car_data`). |
| `Speed` | `float64` | `Float64` | km/h | Current speed of the car. |
| `RPM` | `float64` | `Float64` | RPM | Engine revolutions per minute. |
| `nGear` | `Int64` | `Int64` | - | Current gear (1-8, 0 for Neutral). |
| `Throttle` | `float64` | `Float64` | % | Throttle pedal position (0-100). Some samples hold values above 100. |
| `Brake` | `bool` | `Boolean` | - | `True` while the brake pedal is pressed. |
| `DRS` | `Int64` | `Int64` | - | DRS flag: `0` = closed, `1` = open. The source data maps the raw FastF1 values `10`, `12`, and `14` to `1`. The column never holds a value of 10 or more. |
| `Source`, `Status` | `object` | `Categorical` | - | `Source` is `"merged"`, and `"interpolation"` on the edge samples that `interpolate_edges` adds and the gaps that `fill_missing()` fills. `Status` is always `"OnTrack"`. |

### Spatial Data
| Column | pandas dtype | polars dtype | Unit | Description |
| :--- | :--- | :--- | :--- | :--- |
| `Distance` | `float64` | `Float64` | Meters | Distance driven since the start of the lap. |
| `RelativeDistance`| `float64` | `Float64` | - | Normalized distance (0.0 to 1.0). |
| `X`, `Y`, `Z` | `float64` | `Float64` | 1/10 m | 3D coordinates of the car on the track. The path length through `X` and `Y` is about 10 times `Distance`. |

### Driver Ahead
| Column | pandas dtype | polars dtype | Unit | Description |
| :--- | :--- | :--- | :--- | :--- |
| `DriverAhead` | `str` or `object` | `String` | - | Car number of the driver directly ahead, as a string (`"44"`). A missing value when nobody is ahead: `NaN` or `None` on pandas, `null` on polars. |
| `DistanceToDriverAhead` | `float64` | `Float64` | Meters | Gap to the car ahead. `NaN` (pandas) or `null` (polars) when nobody is ahead. |

### Lap Identity
| Column | pandas dtype | polars dtype | Description |
| :--- | :--- | :--- | :--- |
| `Driver` | `object` | `String` | 3-letter driver identifier of the lap. |
| `LapNumber` | `Int64` | `Int64` | Lap number of the sample. |

### Acceleration (G-Forces)
These are mathematically derived and smoothed from position and speed data. All three columns are `float64` (pandas) or `Float64` (polars) in m/s².

| Column | Direction | Computation Formula |
| :--- | :--- | :--- |
| `AccelerationX` | Longitudinal | `ax = gradient(v_ms) / gradient(time)` |
| `AccelerationY` | Lateral | `ay = v² × Curvature` |
| `AccelerationZ` | Vertical | `az = v² × Vertical_Curvature` |

<Note>
  Longitudinal acceleration is smoothed with a 3-point moving average. Lateral and Vertical are smoothed with a 9-point moving average to reduce noise.
</Note>

## 🚩 Race Control (`session.race_control_messages`)

Official messages issued during the session.

| Column | pandas dtype | polars dtype | Description |
| :--- | :--- | :--- | :--- |
| `Time` | `datetime64[ns]` | `Datetime` | UTC timestamp of the message, without a time zone. |
| `Category` | `object` | `String` | Message type (`Flag`, `Drs`, `SafetyCar`, `CarEvent`, `Other`). |
| `Message` | `object` | `String` | Human-readable description. |
| `Status` | `object` | `String` | Message state, for example `ENABLED`, `DISABLED`, `DEPLOYED`, `IN THIS LAP`. |
| `Flag` | `object` | `String` | Type of flag (`GREEN`, `YELLOW`, `DOUBLE YELLOW`, `BLUE`, `RED`, `CLEAR`, `CHEQUERED`, `BLACK AND WHITE`). Missing for a message without a flag. |
| `Scope` | `object` | `String` | Impact area (`Track`, `Sector`, `Driver`). Missing when the message has no scope. |
| `Sector` | `float64` | `Float64` | The affected marshal sector. The number of marshal sectors depends on the circuit. `NaN` (pandas) or `null` (polars) when the scope is not a sector. |
| `RacingNumber` | `object` | `String` | Car number of the affected driver, if applicable. |
| `Lap` | `int64` | `Int64` | Lap number the message refers to. A message without a lap holds `0` on pandas and `null` on polars. |

## 🏁 Session Results (`session.results`)

One row per driver, in classification order. On pandas, `session.results` is a `SessionResults` frame indexed by driver number. On polars, it is a `PolarsSessionResults` frame with `DriverNumber` as a column. Race, Sprint, and Qualifying sessions take the official Ergast classification: grid, points, status, and times.

<Note>
  Without an official classification (practice, the sprint qualifying formats, or `ergast=False`), tif1 classifies the session from the laps, as fastf1 does. Sprint Qualifying, Sprint Shootout, and Qualifying with `ergast=False` take the best accurate lap of each segment into `Q1` to `Q3` and rank by `Q3`, then `Q2`, then `Q1`. Other sessions keep the order that `drivers.json` lists when that is already a classification. Otherwise tif1 rebuilds it. Races and sprints rank by laps completed, then by position on the last lap. Practice ranks by the best lap that is not deleted. Post-session penalties are not visible in lap data. A rebuilt order can differ from the official result by a place or two. `session.drivers` and `session.drivers_df` share this order.
</Note>

| Column | dtype | Description |
| :--- | :--- | :--- |
| `DriverNumber` | `str` | The car number as a string. |
| `Abbreviation` | `str` | 3-letter driver identifier. |
| `TeamName` | `str` | Team name. |
| `TeamColor` | `str` | Hex color without a leading `#` (e.g., `FF8000`). |
| `FirstName`, `LastName`, `FullName` | `str` | Driver names. |
| `HeadshotUrl` | `str` | Link to the driver headshot. |
| `Position` | `float64` | Classification position, `1.0` for the winner. NaN when tif1 cannot set a classification order: `drivers.json` is in car-number order and the session has no laps payload. |
| `ClassifiedPosition` | `str` | `Position` as text (`"1"`), or the Ergast code (`"R"`, `"D"`, ...). `"N"` for a driver out in Q1 outside 107% when tif1 classifies a qualifying session from the laps. Empty when the position is unknown. |
| `GridPosition` | `float64` | Grid position from the Ergast classification. NaN (polars: null) outside races and sprints, and with `ergast=False`. |
| `Status` | `str` | Races and sprints: the official status, for example `"Finished"`, `"Retired"`, `"Disqualified"`. With `ergast=False`: `"Finished"`, `"+1 Lap"`, ... or `"Did not start"` from the lap count. Practice and qualifying: `"Finished"`. `None` without a laps payload. |
| `Points` | `float64` | Points from the Ergast classification. NaN (polars: null) outside races and sprints, and with `ergast=False`. |
| `Laps` | `float64` | Laps completed. NaN for qualifying with Ergast results. |
| `BroadcastName`, `DriverId`, `TeamId`, `CountryCode`, `Q1` to `Q3`, `Time` | mixed | The other fastf1 columns. `Time` is the total race time, and in practice the best lap that is not deleted, as in fastf1. Practice and the sprint qualifying formats take `DriverId` and `TeamId` from the Ergast race results. tif1 extras such as `TimeGap` follow them. Refer to the [Core API](/api-reference/core). |
