`tif1` keeps the fastf1 API shape for sessions, laps, and telemetry. This guide shows the similarities and the key differences.

## Comparison at a Glance

| Feature | fastf1 | tif1 |
| :--- | :--- | :--- |
| **Data Source** | Ergast + F1 Live Timing | TracingInsights (CDN) |
| **Loading Speed** | Baseline | **Parallel async loading** (3x+ vs sequential, benchmark-validated) |
| **Lib** | Pandas only | **Pandas + Polars** |
| **Caching** | File-based Pickle | **SQLite + Memory LRU** |
| **HTTP Version** | HTTP/1.1 | **HTTP/2** |

## Migration Steps

<Steps>
  <Step title="Update Imports">
    Change `import fastf1` to `import tif1`.
    ```python
    import tif1 as ff1 # Alias to keep existing code working
    ```
  </Step>
  <Step title="Update get_session Calls">
    Full GP names are the clearest. Circuit, city, and country names such as `"Monaco"` or `"Spa"` also resolve to the event of that season. Session names are case-insensitive, so `"Race"`, `"race"`, and `"R"` all work. `session.load()` is optional because `tif1` loads data lazily.
    <CodeGroup>
    ```python tif1 (Lazy)
    session = tif1.get_session(2025, "Monaco Grand Prix", "Race")
    laps = session.laps # Fetches automatically
    ```
    ```python fastf1 (Explicit)
    session = fastf1.get_session(2025, "Monaco", "R")
    session.load()
    laps = session.laps
    ```
    </CodeGroup>
  </Step>
  <Step title="Check Filters">
    The `pick_` methods work unchanged. `pick_driver` accepts a 3-letter code or a driver number. `Session` adds direct accessors.

    | fastf1 | tif1 |
    | :--- | :--- |
    | `laps.pick_fastest()` | `laps.pick_fastest()` or `session.get_fastest_laps(by_driver=False)` |
    | `laps.pick_driver('VER')` | `laps.pick_driver('VER')`, `laps.pick_driver(1)`, or `session.get_driver('VER').laps` |
  </Step>
</Steps>

## Key API Differences

### 1. Lazy Loading
tif1 uses lazy loading by default. A `session.load()` call is not necessary.

<CodeGroup>
```python fastf1
import fastf1

session = fastf1.get_session(2025, "Monaco", "R")
session.load()
laps = session.laps
```
```python tif1
import tif1

session = tif1.get_session(2025, "Monaco Grand Prix", "Race")
laps = session.laps  # Automatically fetches on first access
```
</CodeGroup>

### 2. Property Access
In `fastf1`, telemetry is a method. In `tif1`, `lap.telemetry` is a property, and `lap.get_telemetry()` also works.

<CodeGroup>
```python fastf1
telemetry = lap.get_telemetry()
```
```python tif1
telemetry = lap.telemetry
```
</CodeGroup>

### 3. Driver Information
`session.drivers` holds driver numbers as strings in finishing order, as in fastf1. `session.drivers_df` adds the codes, teams, and colors in one DataFrame.

```python
import tif1

session = tif1.get_session(2025, "Monaco Grand Prix", "Race")
print(session.drivers[:3])  # ['4', '16', '81']: NOR, LEC, PIA

drivers_df = session.drivers_df
print(drivers_df[["Driver", "Team", "DriverNumber", "TeamColor"]])
```

### 4. Enriched Data
tif1 automatically enriches data:

- Weather data is included in every lap
- Telemetry includes DriverAhead and DistanceToDriverAhead
- LapTimeSeconds is provided as a numeric helper alongside LapTime

### 5. Telemetry Differences
Some telemetry columns differ from fastf1:

- `DRS` is a 0/1 flag. fastf1 keeps the raw values, where 10, 12, and 14 mean open.
- `Time` is lap-relative and starts at zero on every lap. There is no `SessionTime` or `Date` column.
- `DriverAhead` holds driver numbers. `DistanceToDriverAhead` is in meters and is NaN when nobody is ahead.

`tif1.utils.delta_time(ref_lap, comp_lap)` uses the fastf1 algorithm. It returns `(delta, ref_tel, comp_tel)`. A positive delta means the comparison lap is slower at that point. The delta is an estimate from the distance samples, so it can differ from the real lap time gap.

```python
import tif1
from tif1.utils import delta_time

session = tif1.get_session(2025, "Monaco Grand Prix", "Race")
ref = session.laps.pick_driver("VER").pick_fastest()
comp = session.laps.pick_driver("LEC").pick_fastest()

delta, ref_tel, comp_tel = delta_time(ref, comp)
print(f"Estimated delta at the line: {delta.iloc[-1]:+.3f}s (positive = LEC slower)")
print(f"Real lap time gap: {comp['LapTimeSeconds'] - ref['LapTimeSeconds']:+.3f}s")
```

### 6. Async Optimization
For maximum performance, adopt the async pattern:

```python
import asyncio
import tif1

async def main():
    session = tif1.get_session(2025, "Monaco Grand Prix", "Race")
    return await session.laps_async()  # Parallel fetch for the initial load

laps = asyncio.run(main())
```

## Feature Parity

<CardGroup cols={2}>
  <Card title="Archive Only" icon="box-archive">
    `tif1` focuses on historical data (2018-current). It does not support Live Timing.
  </Card>
  <Card title="Track Maps" icon="map">
    `session.get_circuit_info()` returns the corners and the rotation. Marshal lights and marshal sectors are empty. Six track-map charts, such as `plot_track_speed_map` and `plot_gear_shifts`, draw the layout.
  </Card>
  <Card title="Weather Data" icon="cloud">
    `session.weather` holds the raw samples. Every lap row also carries the weather columns (`AirTemp`, `TrackTemp`, `Rainfall`, ...).
  </Card>
  <Card title="Categorical Optimization" icon="database">
    `tif1` optimizes memory by default using categoricals, which may behave slightly differently in some Pandas operations.
  </Card>
</CardGroup>
