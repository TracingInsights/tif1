This document explains how data moves through tif1, from the first CDN request to the final DataFrame delivery. It covers caching mechanisms, network protocols, data transformations, and performance optimizations. These details help with performance tuning, troubleshooting, and data loading decisions.

tif1 treats performance as its core principle. The multi-tier caching system, HTTP/2 multiplexing, and async parallel fetching all minimize latency and maximize throughput. Each section explains what happens, why it happens, and how to use these systems.

## System Architecture Overview

The tif1 architecture follows three core principles:

1. **Performance First**: Every component is optimized for speed, from HTTP/2 multiplexing to orjson parsing to categorical data types.
2. **Resilience**: Multi-tier caching, circuit breakers, and retry logic ensure reliability even under adverse network conditions.
3. **Transparency**: Logging and monitoring show what happens at each stage.

### Component Responsibilities

**Session Object (`core.py`)**
- Entry point for all data access
- Manages lazy loading of laps, telemetry, weather, and race control data
- Coordinates between cache layers and CDN fetching
- Handles backend selection (pandas vs polars)

**Memory LRU Cache (`cache.py`)**
- In-memory `LRUCache` built on `collections.OrderedDict`
- Stores raw JSON bytes plus a parsed-object front tier (not DataFrames)
- DataFrames live in the per-session `SessionMemo` and the backend lap LRU (`get_backend_lap_cache`)
- Default capacity: 1024 JSON payloads (`TIF1_MEMORY_CACHE_MAX_ITEMS`) and 2048 telemetry payloads (`TIF1_MEMORY_TELEMETRY_CACHE_MAX_ITEMS`)
- Eviction policy: Least Recently Used (LRU)
- Lifetime: Process duration only

**SQLite Persistent Cache (`cache.py`)**
- Disk-based cache using SQLite database
- Location: OS-dependent tif1 cache directory (configurable via `TIF1_CACHE_DIR`); see the platform defaults in the configuration reference
- Stores JSON payloads (compressed when 4096 bytes or larger) and pickled telemetry frames
- Tables: `cache`, `telemetry_cache`, `telemetry_frames`, `telemetry_frames_pl`, `missing_payloads`
- No expiry: entries persist until `clear()` or `invalidate()`
- Only negative "missing on every CDN" verdicts expire, after 7 days
- Thread-safe: one shared connection guarded by a lock, WAL journal mode

**CDN Manager (`cdn.py`)**
- Manages multiple CDN sources with automatic fallback
- Primary: jsDelivr CDN (`cdn.jsdelivr.net/gh/TracingInsights/{year}@main`)
- Fallback: Hugging Face buckets (`huggingface.co/buckets/tracinginsights/{year}/resolve`)
- Backup: StaticDelivr CDN (`cdn.staticdelivr.com/gh/TracingInsights/{year}/main`)
- Tracks failure counts per CDN source
- Automatically disables failing sources after 3 consecutive failures
- A 404 from one CDN falls through to the next, because mirrors can be stale
- A 403 from one CDN falls through the same way. jsDelivr answers 403 ("Package size exceeded the configured limit of 50 MB") for a file its edge has not cached yet. A 403 says nothing about the mirror's health, so it does not count towards disabling it
- tif1 raises `DataNotFoundError` when every CDN returns a 4xx client error (404 included)
- Requests for files missing everywhere never burn the retry/backoff budget
- 5xx and transport errors keep the retryable `NetworkError`
- Handles URL encoding and path construction
- Never uses `raw.githubusercontent.com` (strict rate limits)

**Async HTTP Fetcher (`async_fetch.py`)**
- Parallel HTTP requests using `niquests` (HTTP/2 support)
- Connection pooling and keep-alive
- Automatic retry with exponential backoff
- Timeout management (default: 30s per request)
- Progress tracking for batch operations

**Circuit Breaker (`retry.py`)**
- Prevents cascading failures during network issues
- States: `"closed"` (normal), `"open"` (failing), `"half-open"` (testing recovery)
- Failure threshold: 5 consecutive failures
- Recovery timeout: 60 seconds
- Automatic state transitions

**JSON Parser (`orjson`)**
- High-performance JSON parsing (2-3x faster than stdlib `json`)
- Direct bytes-to-Python object conversion
- Handles large payloads efficiently (100MB+ telemetry files)
- Strict validation mode enabled

**Schema Validator (`validation.py`)**
- Pydantic-based validation of JSON structure (off by default; turn it on with the `validate_data`, `validate_lap_times`, and `validate_telemetry` config keys)
- Ensures data integrity before DataFrame construction
- Type coercion and default value handling
- Detailed error messages for debugging

**DataFrame Constructor (`core.py` / `core_utils`)**
- Converts the columnar JSON payloads (one list per field) to pandas/polars DataFrames
- Renames the short upstream keys (`time`, `s1`, `sesT`, `wAT`, ...) to FastF1 names
- Example: `s1` becomes `Sector1Time`, and `wAT` becomes `AirTemp`
- Column order follows FastF1, plus the tif1 columns at the end
- pandas laps keep a `RangeIndex` (no `LapNumber` index)

**Data Enrichment (`core.py`)**
- Adds the computed `LapTimeSeconds` column (float seconds on both backends)
- Keeps the per-lap weather fields of the payload as `WeatherTime`, `AirTemp`, ..., `WindSpeed`
- Takes `Stint`, `IsPersonalBest`, `Driver`, `Team`, and `DriverNumber` from the payload as delivered

**Type Optimizer (`core_utils/helpers.py`)**
- Applies the dtype contract of each backend (see [Column types by backend](/concepts/backends#column-types-by-backend))
- pandas: converts time columns to `timedelta64[ns]` and `Driver`, `Team`, `Compound`, `TrackStatus` to `category`
- polars: keeps time columns as `Float64` seconds and text columns as `String`
- Replaces sentinel strings such as `"None"` with missing values; numeric columns stay 64-bit (no `float32` downcast)

## Complete Data Loading Pipeline

The data loading pipeline consists of eight distinct stages. Each stage has specific responsibilities and performance characteristics. These details help with code optimization and troubleshooting.

### Stage 1: Request Initiation

When code accesses data through a Session object, tif1 initiates the loading pipeline. This stage involves property access, lazy evaluation, and request routing.

```python
import tif1

# Create session (no data loaded yet)
session = tif1.get_session(2025, "Monaco Grand Prix", "Race")

# Access laps property - triggers loading pipeline
laps = session.laps  # Returns pandas/polars DataFrame

# Access specific driver data
verstappen = session.get_driver("VER")
verstappen_laps = verstappen.laps  # Filtered view, no additional loading

# Access telemetry (separate loading pipeline). pandas shown; on polars,
# get_fastest_lap() returns a plain DataFrame, so call verstappen.get_fastest_lap_tel()
fastest_lap = verstappen.get_fastest_lap()
telemetry = fastest_lap.get_telemetry()  # Triggers telemetry loading
```

**What Happens Internally:**

1. Property access runs the `Session.laps` property
2. Session checks if data is already loaded (`self._laps is not None`)
3. If not loaded, the property builds the laps table (there is no public loader method to call)
4. The loader builds the backend lap LRU key `f"{year}_{gp}_{session}_laps"` and the payload key `f"{year}/{gp}/{session}/session_laptimes.json"`
5. Passes control to cache layer

**Performance Characteristics:**
- Property access overhead: < 0.1ms
- Cache key construction: < 0.01ms
- No network I/O at this stage

**Configuration Options:**

```python
# Control what data gets loaded: get_session() only selects the session;
# session.load() picks the tables
session = tif1.get_session(2025, "Monaco", "Race")
session.load(
    laps=True,        # Load lap data
    telemetry=False,  # Skip telemetry (faster)
    weather=True,     # Load weather data
    messages=False    # Skip race control messages
)

# Choose backend
session = tif1.get_session(2025, "Monaco", "Race", lib="polars")  # Use polars
session = tif1.get_session(2025, "Monaco", "Race", lib="pandas")  # Use pandas (default)
```

### Stage 2: Multi-Tier Cache Lookup

tif1 implements a two-tier caching system that reduces load times for frequently accessed data. This section explains the cache behavior needed for performance optimization.

#### Tier 1: Memory LRU Cache (L1 Cache)

The memory cache is the fastest tier, holding raw JSON payloads and their parsed objects in RAM.

**Technical Specifications:**
- Implementation: `LRUCache` built on `collections.OrderedDict` (`cache.py`)
- Storage: In-process memory (heap)
- Data format: orjson bytes, plus a parsed-dict front tier that skips re-parsing on repeat hits
- DataFrames: held only by the per-session `SessionMemo`, the backend lap LRU, and the SQLite frame tier
- Capacity: 1024 JSON payloads (`TIF1_MEMORY_CACHE_MAX_ITEMS`), 2048 telemetry payloads (`TIF1_MEMORY_TELEMETRY_CACHE_MAX_ITEMS`)
- Eviction: Least Recently Used (LRU) algorithm, maintained through writes only
- Access time: < 1ms (typically 0.1-0.5ms)
- Thread safety: `LRUCache.set` takes a lock; hot-path reads are lock-free
- Persistence: None (cleared on process exit)

**Cache Key Structure:**
```python
# gp and session are URL-encoded, as in session.gp and session.session
year, gp, session, driver, lap = 2025, "Monaco%20Grand%20Prix", "Race", "VER", 10

# JSON tier: "{year}/{gp}/{session}/{path}" (payload_loader.PayloadLoader.cache_key)
key = f"{year}/{gp}/{session}/session_laptimes.json"
# Other paths: drivers.json, rcm.json, weather.json, corners.json,
#              f"{driver}/laptimes.json", f"{driver}/{lap}_tel.json"

# Telemetry tier: tuple key
key = (year, gp, session, driver, lap)

# Backend lap LRU (get_backend_lap_cache): assembled lap DataFrames
key = f"{year}_{gp}_{session}_laps"
```

**Memory Usage Estimation:**
```python
# Typical JSON payload sizes (2025 Bahrain Grand Prix race):
# - session_laptimes.json (20 drivers, 1128 laps): ~340 KB
# - {driver}/{lap}_tel.json (one lap, 700-800 samples): ~150 KB
# - weather.json (158 samples): ~7 KB
# - rcm.json (91 messages): ~13 KB

# The telemetry payloads dominate: 2048 cached laps x ~150 KB ≈ 300 MB
# Lap and session tables stay small (well under 100 MB for 1024 payloads)
```

**Cache Hit Rate Optimization:**
```python
# Good: Reuse session objects
session = tif1.get_session(2025, "Monaco", "Race")
for analysis in range(10):
    laps = session.laps  # Cache hit after first access
    # ... analysis code

# Bad: Create new sessions repeatedly
for analysis in range(10):
    session = tif1.get_session(2025, "Monaco", "Race")
    laps = session.laps  # Cache miss every time (different object)
```

#### Tier 2: SQLite Persistent Cache (L2 Cache)

The SQLite cache provides persistent storage that survives process restarts.

**Technical Specifications:**
- Implementation: `sqlite3` with one shared connection (`check_same_thread=False`)
- Storage: Disk-based database file (`cache.sqlite`)
- Location: OS-dependent tif1 cache directory (configurable via `TIF1_CACHE_DIR`); see the platform defaults in the configuration reference
- Data format: Compressed JSON (zstd level 1; legacy zlib rows stay readable). Python 3.14+ uses the standard-library `compression.zstd` binding, 3.11-3.13 use the `zstandard` package; both write identical frames
- Capacity: Unlimited (constrained by disk space)
- Access time: 10-50ms (depends on disk I/O)
- Thread safety: every SQLite call runs under `Cache._sqlite_lock`
- Write batching: writes commit every `cache_commit_interval` (default 100) operations
- Pragmas: `journal_mode=WAL`, `synchronous=NORMAL`, 64 MB page cache
- Persistence: Permanent (until `clear()` or `invalidate()`; nothing expires)

**Database Schema:**
```sql
-- Session JSON payloads, keyed "{year}/{gp}/{session}/{path}".
-- `data` holds plain JSON text, or a compressed blob for rows >= 4096 bytes.
CREATE TABLE IF NOT EXISTS cache (key TEXT PRIMARY KEY, data TEXT);

-- Per-lap telemetry payloads (same encoding as `cache.data`).
CREATE TABLE IF NOT EXISTS telemetry_cache (
    year INTEGER, gp TEXT, session TEXT, driver TEXT, lap INTEGER,
    data TEXT,
    PRIMARY KEY (year, gp, session, driver, lap)
);

-- Materialized telemetry DataFrames (pickle protocol 5, lz4-compressed).
-- `telemetry_frames` holds pandas frames; `telemetry_frames_pl` holds polars frames.
CREATE TABLE IF NOT EXISTS telemetry_frames (
    year INTEGER, gp TEXT, session TEXT, driver TEXT, lap INTEGER,
    frame BLOB,
    PRIMARY KEY (year, gp, session, driver, lap)
);
CREATE TABLE IF NOT EXISTS telemetry_frames_pl (
    year INTEGER, gp TEXT, session TEXT, driver TEXT, lap INTEGER,
    frame BLOB,
    PRIMARY KEY (year, gp, session, driver, lap)
);

-- Negative tier: payloads that returned 4xx on every CDN.
CREATE TABLE IF NOT EXISTS missing_payloads (key TEXT PRIMARY KEY, recorded_at REAL);
```

The primary keys are the only indexes; there are no secondary indexes.

**Compression Strategy:**
```python
import orjson

# Python 3.14+ ships zstd in the standard library (PEP 784); older
# interpreters use the `zstandard` package. Same libzstd, same frames.
try:
    from compression import zstd
except ImportError:
    import zstandard as zstd

# A payload in the upstream layout (one list per field)
data = {"lap": list(range(1, 58)), "time": [95.0 + i / 10 for i in range(57)]}

# Serialization (write to cache)
json_bytes = orjson.dumps(data)
if len(json_bytes) >= 4096:
    stored = zstd.compress(json_bytes, 1)  # compressed BLOB row
else:
    stored = json_bytes.decode("utf-8")   # small rows stay plain TEXT
# Typical compression ratio: ~4:1 (better than zlib-3, ~4.5x faster)
# zlib level 3 is the fallback only when no zstd binding imports.

# Deserialization (read from cache)
json_bytes = zstd.decompress(stored) if isinstance(stored, bytes) else stored
data = orjson.loads(json_bytes)
```

Materialized telemetry DataFrames (the frame tier) use lz4 instead. The tier is
write-once/read-many, and lz4 halves both compress and decompress time.
zstd is the fallback when lz4 is unavailable, for example on Python 3.15 where
lz4 publishes no wheels yet. Each row carries its codec's magic prefix, so
both kinds of row stay readable regardless of which codec wrote them.

**Expiry:**

Cached payloads and frames never expire. Session data is immutable once published, so a
cached row stays valid until `cache.clear()` or `cache.invalidate(scope)` removes it.

The only time-to-live applies to the negative tier. When every CDN returns a 4xx for a
path, tif1 records the key in `missing_payloads`. Later lookups skip the network for that
key until the verdict is older than `TIF1_MISSING_PAYLOADS_TTL_DAYS` (default 7.0). A
successful write for the same key drops the verdict immediately.

```python
# Negative-tier TTL (the only TTL in the cache)
# Configurable via TIF1_MISSING_PAYLOADS_TTL_DAYS (default: 7.0 days)
import time
cutoff = time.time() - 7.0 * 86400
# Verdicts with recorded_at <= cutoff are ignored on load
```

#### Cache Lookup Flow

```python
def get_data(key):
    """Simplified cache lookup logic."""

    # Step 1: Check memory cache (L1)
    if key in memory_cache:
        logger.debug(f"Memory cache hit: {key}")
        return memory_cache[key]

    logger.debug(f"Memory cache miss: {key}")

    # Step 2: Check SQLite cache (L2)
    sqlite_data = sqlite_cache.get(key)
    if sqlite_data is not None:
        logger.debug(f"SQLite cache hit: {key}")

        # Decompress (if a compressed row) and parse JSON with orjson
        json_bytes = decode_sqlite_value(sqlite_data)
        data = orjson.loads(json_bytes)

        # Promote to memory cache (L1): raw bytes plus parsed object
        memory_cache[key] = json_bytes
        parsed_cache[key] = data

        return data

    logger.debug(f"SQLite cache miss: {key}")

    # Step 3: Fetch from CDN (cache miss)
    data = fetch_from_cdn(key)

    # Step 4: Save to both cache tiers (memory first, then SQLite)
    json_bytes = orjson.dumps(data)
    memory_cache[key] = json_bytes
    sqlite_cache.set(key, encode_sqlite_value(json_bytes))

    return data
```

**Performance Comparison:**

| Scenario | Memory Cache | SQLite Cache | CDN Fetch |
|----------|--------------|--------------|-----------|
| Access Time | < 1ms | 10-50ms | 2-5s |
| Throughput | 1000+ req/s | 50-100 req/s | 0.2-0.5 req/s |
| Persistence | No | Yes | N/A |
| Capacity | Limited (RAM) | Unlimited (disk) | N/A |
| Thread Safety | Yes (lock-free reads, locked writes) | Yes (shared connection + lock) | N/A |

**Cache Warming Strategies:**

```python
import logging

import tif1

logger = logging.getLogger(__name__)

# Strategy 1: Pre-warm on application startup
def warm_cache_for_season(year):
    """Load all race data for a season into cache."""
    events = tif1.get_event_schedule(year, include_testing=False)["EventName"]
    for event in events:
        for session_type in ["Practice 1", "Practice 2", "Practice 3", "Qualifying", "Race"]:
            try:
                session = tif1.get_session(year, event, session_type)
                _ = session.laps  # Trigger load
                logger.info(f"Cached: {year} {event} {session_type}")
            except (tif1.DataNotFoundError, ValueError):
                # ValueError: the event has no such session (sprint weekends have no FP2/FP3)
                continue

# Strategy 2: Background cache warming
import threading

def warm_cache_background(year):
    """Warm cache in background thread."""
    thread = threading.Thread(target=warm_cache_for_season, args=(year,))
    thread.daemon = True
    thread.start()

# Strategy 3: Selective warming (only races)
def warm_cache_races_only(year):
    """Load only race sessions (fastest to load)."""
    events = tif1.get_event_schedule(year, include_testing=False)["EventName"]
    for event in events:
        session = tif1.get_session(year, event, "Race")
        _ = session.laps
```

### Stage 3: CDN Fetching with Fallback Strategy

When both cache tiers miss, tif1 fetches data from the CDN. The fetch uses a multi-source strategy with automatic fallback.

#### CDN Architecture

**Primary Source: jsDelivr CDN**
- URL Pattern: `https://cdn.jsdelivr.net/gh/TracingInsights/{year}@main/{path}`
- Global CDN with edge locations worldwide
- Automatic caching and compression
- No rate limits for reasonable usage
- HTTPS with HTTP/2 support
- Average latency: 50-200ms (depending on location)
- Uptime: 99.9%+

**Fallback Source: Hugging Face Buckets**
- URL Pattern: `https://huggingface.co/buckets/tracinginsights/{year}/resolve/{path}`
- Mirrors the TracingInsights GitHub data repos with the same layout (no branch segment)
- Pre-warmed CDN edge locations in the US and EU
- Used when jsDelivr fails or is unavailable

**Backup Source: StaticDelivr CDN**
- URL Pattern: `https://cdn.staticdelivr.com/gh/TracingInsights/{year}/main/{path}`
- Global CDN with edge locations worldwide
- Automatic caching and compression
- No rate limits for reasonable usage
- HTTPS with HTTP/2 support
- Average latency: 50-200ms (depending on location)
- Used when both jsDelivr and Hugging Face fail or are unavailable

**Forbidden Source: raw.githubusercontent.com**
- Never used due to strict rate limits
- When all three sources fail, tif1 raises `NetworkError` (or `DataNotFoundError` when every source returned a 4xx) instead of trying it

#### URL Construction

```python

# The fallbacks use the same path after their own prefix:
# https://huggingface.co/buckets/tracinginsights/2025/resolve/Monaco%20Grand%20Prix/Race/...
# https://cdn.staticdelivr.com/gh/TracingInsights/2025/main/Monaco%20Grand%20Prix/Race/...
```

#### Fallback Logic

```python
async def fetch_with_fallback(url_path):
    """Fetch data with automatic CDN fallback."""

    # Attempt 1: jsDelivr CDN (primary)
    try:
        jsdelivr_url = f"https://cdn.jsdelivr.net/gh/TracingInsights/{year}@main/{url_path}"
        response = await http_client.get(jsdelivr_url, timeout=30)
        if response.status_code == 200:
            logger.info(f"jsDelivr success: {url_path}")
            return response.content
        logger.warning(f"jsDelivr returned {response.status_code}")
    except Exception as e:
        logger.warning(f"jsDelivr failed: {e}")

    # Attempt 2: Hugging Face bucket (fallback)
    try:
        hf_url = f"https://huggingface.co/buckets/tracinginsights/{year}/resolve/{url_path}"
        response = await http_client.get(hf_url, timeout=30)
        if response.status_code == 200:
            logger.info(f"Hugging Face success: {url_path}")
            return response.content
        logger.warning(f"Hugging Face returned {response.status_code}")
    except Exception as e:
        logger.warning(f"Hugging Face failed: {e}")

    # Attempt 3: StaticDelivr CDN (last-resort backup)
    try:
        staticdelivr_url = f"https://cdn.staticdelivr.com/gh/TracingInsights/{year}/main/{url_path}"
        response = await http_client.get(staticdelivr_url, timeout=30)
        if response.status_code == 200:
            logger.info(f"StaticDelivr success: {url_path}")
            return response.content
        logger.warning(f"StaticDelivr returned {response.status_code}")
    except Exception as e:
        logger.warning(f"StaticDelivr failed: {e}")

    # All sources failed (NetworkError takes the URL and extra context keys)
    raise tif1.NetworkError(url=url_path, attempts=3)
```

#### Circuit Breaker Pattern

tif1 implements a circuit breaker to prevent cascading failures during network issues.

**Circuit Breaker States:**

1. **`"closed"` (Normal Operation)**
   - All requests pass through
   - Failures are counted
   - Threshold: 5 consecutive failures (`circuit_breaker_threshold`)

2. **`"open"` (Failing)**
   - Requests fail immediately, without a network call
   - Prevents overload of the failing service
   - Duration: 60 seconds (`circuit_breaker_timeout`)

3. **`"half-open"` (Testing Recovery)**
   - The next request is allowed through
   - Success → transition to `"closed"`
   - Failure → transition back to `"open"`

The block below is a simplified, single-threaded copy of `tif1.retry.CircuitBreaker`. The real class adds a lock and uses `time.monotonic()`. Read the live instance with `tif1.get_circuit_breaker()`.

```python
import time

from tif1.exceptions import CircuitBreakerOpenError


class CircuitBreaker:
    """Circuit breaker for network requests (simplified)."""

    def __init__(self, threshold=5, timeout=60):
        self.threshold = threshold  # Failures before the breaker opens
        self.timeout = timeout  # Seconds the breaker stays open
        self.failures = 0
        self.opened_at = None
        self.state = "closed"

    def call(self, func, *args, **kwargs):
        """Execute function with circuit breaker protection."""

        # Check if circuit is open
        if self.state == "open":
            if time.monotonic() - self.opened_at > self.timeout:
                self.state = "half-open"
            else:
                # CircuitBreakerOpenError is a NetworkError subclass
                raise CircuitBreakerOpenError

        # Attempt request
        try:
            result = func(*args, **kwargs)
        except Exception:
            # Failure - increment count
            self.failures += 1
            self.opened_at = time.monotonic()
            if self.failures >= self.threshold:
                self.state = "open"
            raise

        # Success - close the breaker and reset the failure count
        self.state = "closed"
        self.failures = 0
        return result
```

#### Retry Strategy

Each CDN source gets its own retry loop (`tif1.retry.retry_with_backoff`, wrapped around the circuit breaker). Only `NetworkError` is retried; a 404 moves on to the next source at once. The block below is a simplified copy:

```python
import logging
import random
import time

from tif1 import NetworkError

logger = logging.getLogger(__name__)


def fetch_with_retry(fetch_from_url, url, max_retries=3, backoff_factor=2.0):
    """Exponential backoff with jitter (sync, per CDN source)."""
    # max_retries: TIF1_MAX_RETRIES; backoff_factor: TIF1_RETRY_BACKOFF_FACTOR
    for attempt in range(max_retries):
        try:
            return fetch_from_url(url)  # Goes through the circuit breaker
        except NetworkError as e:
            if attempt == max_retries - 1:
                raise  # Final attempt failed: try_sources moves on to the next CDN

            # 1s, 2s, 4s ... multiplied by a random factor between 0.5 and 1.5
            backoff = backoff_factor ** attempt
            backoff *= 0.5 + random.random()  # TIF1_RETRY_JITTER=false turns this off

            logger.warning(f"Retry {attempt + 1}/{max_retries} after {backoff:.2f}s: {e}")
            time.sleep(backoff)
```

### Stage 4: Async Parallel Fetching

tif1 fetches data for multiple drivers in parallel with asyncio and HTTP/2. This parallel fetching is one of the most important tif1 performance optimizations.

#### Sequential vs Parallel Fetching

**Sequential Fetching (Traditional Approach):**
```python
# Sequential fetching - SLOW
drivers = ["VER", "HAM", "LEC", "NOR", "PIA", ...]  # 20 drivers
lap_data = []

for driver in drivers:
    url = construct_url(driver)
    response = requests.get(url)  # Blocking call
    data = response.json()
    lap_data.append(data)

# Time: 20 drivers × 500ms = 10 seconds
```

**Parallel Fetching (tif1 Approach):**

`async_fetch.py` runs the blocking requests of the shared `niquests.Session` in a thread pool. An `asyncio.Semaphore` caps the number of requests in flight (`max_concurrent_requests`). The block below is a simplified copy:

```python
# Parallel fetching - FAST
import asyncio

from tif1.http_session import get_session as get_http_session


async def fetch_all_drivers(drivers, max_concurrent=20):
    """Fetch data for all drivers in parallel."""
    http = get_http_session()  # Shared niquests.Session (pooled, multiplexed)
    loop = asyncio.get_running_loop()
    semaphore = asyncio.Semaphore(max_concurrent)

    async def fetch_driver(driver):
        url = construct_url(driver)
        async with semaphore:
            response = await loop.run_in_executor(None, http.get, url)
        response.raise_for_status()
        return response.json()

    # Execute all tasks concurrently
    tasks = [fetch_driver(driver) for driver in drivers]
    return await asyncio.gather(*tasks, return_exceptions=True)

# Time: max(500ms across all drivers) ≈ 500-800ms
# Speedup: 10-15x faster
```

#### HTTP/2 Multiplexing

tif1 uses the `niquests` library. `niquests` supports HTTP/2 and multiplexes requests over a single TCP connection.

**HTTP/1.1 Limitations:**
- One request per TCP connection
- Multiple connections required for parallelism (typically 6-8 max)
- High overhead: TCP handshake + TLS handshake per connection
- Head-of-line blocking

**HTTP/2 Advantages:**
- Multiple requests over single TCP connection
- Binary framing for efficiency
- Header compression (HPACK)
- Server push capability (not used by tif1)
- Stream prioritization

```python
# HTTP/2 connection reuse with niquests
import niquests

with niquests.Session(multiplexed=True) as http:
    # One connection per host; HTTP/2 is negotiated when the server offers it
    responses = [http.get(construct_url(driver)) for driver in drivers]

    # multiplexed=True returns lazy responses: the requests share the
    # connection, and gather() waits for all of them
    http.gather()
```

tif1 builds this session once per process in `tif1.http_session` (`TIF1_HTTP_MULTIPLEXED`, default `true`).

**Performance Comparison:**

| Metric | HTTP/1.1 | HTTP/2 |
|--------|----------|--------|
| Connections | 6-8 | 1 |
| Handshake Overhead | High | Low |
| Request Latency | 500-800ms | 300-500ms |
| Throughput (20 drivers) | 3-4s | 0.5-0.8s |
| Memory Usage | Higher | Lower |

### Stage 5: High-Performance JSON Parsing

After the CDN fetch, tif1 parses JSON with `orjson`. This library parses 2-3x faster than the standard Python `json` module.

#### Why orjson?

**Performance Comparison:**

| Library | Parse Time (10MB) | Serialize Time | Memory Usage |
|---------|-------------------|----------------|--------------|
| `json` (stdlib) | 450ms | 380ms | High |
| `ujson` | 280ms | 220ms | Medium |
| `orjson` | 150ms | 120ms | Low |

**Key Features:**
- Written in Rust for maximum performance
- Direct bytes-to-Python object conversion (no intermediate string)
- Efficient handling of large payloads (100MB+ telemetry files)
- Strict validation mode
- Native support for datetime, UUID, and other types

#### Parsing Pipeline

```python
import orjson

async def parse_json_response(response_bytes):
    """Parse JSON response with validation."""

    # Step 1: Parse JSON bytes to Python dict
    try:
        data = orjson.loads(response_bytes)
    except orjson.JSONDecodeError as e:
        raise tif1.InvalidDataError(
            f"Failed to parse JSON: {e}",  # The first argument is the reason
            raw_data=response_bytes[:1000]  # First 1KB for debugging
        )

    # Step 2: Validate structure
    if not isinstance(data, dict):
        raise tif1.InvalidDataError(
            f"Expected dict, got {type(data).__name__}",
            data_type=type(data).__name__
        )

    # Step 3: Check required fields (a laptimes payload has one list per field)
    required_fields = ["lap", "time"]
    missing_fields = [f for f in required_fields if f not in data]
    if missing_fields:
        raise tif1.InvalidDataError(
            f"Missing required fields: {missing_fields}",
            missing=missing_fields,
            available=list(data.keys())
        )

    return data
```

#### Parsing Performance Optimization

**Lazy Parsing for Large Files:**

tif1 payloads are small (one telemetry file per lap, about 150 KB), so tif1 parses each one whole with orjson. To read a large JSON file made outside tif1, stream it with the third-party `ijson` package:

```python
# For very large JSON files made outside tif1 (100MB+), consider streaming
import ijson  # Iterative JSON parser (pip install ijson)

def parse_large_telemetry(file_path):
    """Stream parse a large JSON array of telemetry records."""
    with open(file_path, 'rb') as f:
        # Parse the top-level array incrementally
        telemetry_points = ijson.items(f, 'item')

        # Process in chunks
        chunk_size = 10000
        chunk = []

        for point in telemetry_points:
            chunk.append(point)

            if len(chunk) >= chunk_size:
                yield chunk
                chunk = []

        if chunk:
            yield chunk
```

#### Error Recovery

```python
def parse_with_recovery(response_bytes):
    """Parse JSON with error recovery."""

    try:
        # Attempt normal parsing
        return orjson.loads(response_bytes)

    except orjson.JSONDecodeError as e:
        # Try to identify and fix common issues

        # Issue 1: Trailing commas
        if "trailing comma" in str(e).lower():
            logger.warning("Attempting to fix trailing commas")
            fixed = response_bytes.replace(b',]', b']').replace(b',}', b'}')
            return orjson.loads(fixed)

        # Issue 2: Incomplete JSON (truncated response)
        if "unexpected end" in str(e).lower():
            logger.error("JSON appears truncated - re-fetching")
            # NetworkError takes url and status_code; extra keywords go to e.context
            raise tif1.NetworkError(reason="Incomplete response received")

        # Issue 3: Invalid UTF-8
        if "utf" in str(e).lower():
            logger.warning("Attempting UTF-8 error recovery")
            text = response_bytes.decode('utf-8', errors='replace')
            return orjson.loads(text.encode('utf-8'))

        # Unrecoverable error
        raise tif1.InvalidDataError(
            f"JSON parsing failed: {e}",
            error=str(e),
            position=e.pos if hasattr(e, 'pos') else None
        )
```

#### Type Optimization

tif1 applies a fixed dtype contract per backend. It does not downcast: numeric columns stay 64-bit.

**Pandas Type Optimization** (simplified from `_apply_laps_dtypes`):
```python
import pandas as pd


def apply_laps_dtypes_pandas(df):
    """Apply the pandas dtype contract to a renamed laps DataFrame (simplified)."""

    # "None" strings from the payload become missing values first
    df = df.replace("None", None)

    # Time columns: float seconds -> timedelta64[ns]
    for col in ["LapTime", "Time", "Sector1Time", "Sector2Time", "Sector3Time",
                "PitInTime", "PitOutTime", "LapStartTime", "WeatherTime"]:
        if col in df.columns:
            df[col] = pd.to_timedelta(pd.to_numeric(df[col], errors="coerce"), unit="s")
    df["LapTimeSeconds"] = df["LapTime"].dt.total_seconds()

    # Counters and speeds: float64 (FastF1 convention, NaN for missing)
    for col in ["LapNumber", "Stint", "TyreLife", "Position", "SpeedI1", "SpeedST"]:
        if col in df.columns:
            df[col] = pd.to_numeric(df[col], errors="coerce").astype("float64")

    # Flags: bool, and nullable boolean for Deleted
    for col in ["IsPersonalBest", "FreshTyre", "IsAccurate"]:
        if col in df.columns:
            df[col] = df[col].fillna(False).astype(bool)
    if "Deleted" in df.columns:
        df["Deleted"] = df["Deleted"].astype("boolean")

    # Low-cardinality text: category
    for col in ["Driver", "Team", "Compound", "TrackStatus"]:
        if col in df.columns:
            df[col] = df[col].astype("category")

    return df
```

```python
import logging

import pandas as pd
import tif1

logger = logging.getLogger(__name__)


def validate_dataframe(df):
    """Validate a pandas laps DataFrame (structure and content)."""

    # Check required columns
    required_columns = ["LapNumber", "Driver", "LapTime"]
    missing_columns = [col for col in required_columns if col not in df.columns]

    # Check data ranges
    if (df["LapNumber"] < 1).any() or (df["LapNumber"] > 100).any():
        raise tif1.InvalidDataError("LapNumber out of valid range (1-100)")

    if (df["Position"] < 1).any() or (df["Position"] > 22).any():  # NaN passes both checks
        raise tif1.InvalidDataError("Position out of valid range (1-22)")

    # Check for duplicates
    duplicates = df.duplicated(subset=["Driver", "LapNumber"])
    if duplicates.any():
        dup_count = duplicates.sum()
        raise tif1.InvalidDataError(
            f"Found {dup_count} duplicate lap entries",
            duplicate_count=dup_count
        )

    # Check data consistency
    # Lap time should approximately equal sum of sectors (timedeltas on pandas)
    sector_sum = df["Sector1Time"] + df["Sector2Time"] + df["Sector3Time"]
    inconsistent = (df["LapTime"] - sector_sum).abs() > pd.Timedelta(seconds=0.5)
    if inconsistent.any():
        logger.warning(f"Found {inconsistent.sum()} laps with inconsistent sector times")

    return df
```

### Stage 7: Data Enrichment and Augmentation

After the dtype step, tif1 adds one computed column to the laps: `LapTimeSeconds`. The other analysis columns arrive with the payload. Examples are the per-lap weather columns, `Stint`, `IsPersonalBest`, and the telemetry channels `RelativeDistance`, `DriverAhead`, `DistanceToDriverAhead`, and `AccelerationX/Y/Z`.

The functions in this stage are recipes for extra columns that tif1 does not add. They run on the pandas backend: pass `session.laps` or a telemetry frame such as `session.get_fastest_lap_tel()`. On pandas, `LapTime` and the sector times are timedeltas, so the recipes use `LapTimeSeconds` for arithmetic with plain numbers.

#### Lap Data Enrichment

**Computed Time Columns:**
```python
def enrich_lap_times(df):
    """Add computed time columns (pandas laps)."""

    lap_s = df["LapTimeSeconds"]  # Float seconds; LapTime is a timedelta

    # Sector percentages (timedelta / timedelta gives a float)
    df["Sector1Percent"] = (df["Sector1Time"] / df["LapTime"]) * 100
    df["Sector2Percent"] = (df["Sector2Time"] / df["LapTime"]) * 100
    df["Sector3Percent"] = (df["Sector3Time"] / df["LapTime"]) * 100

    # Delta to personal best (seconds)
    personal_best = df.groupby("Driver", observed=True)["LapTimeSeconds"].transform("min")
    df["DeltaToPersonalBest"] = lap_s - personal_best

    # Delta to session best (seconds)
    df["DeltaToSessionBest"] = lap_s - lap_s.min()

    # Cumulative time (seconds)
    df["CumulativeTime"] = df.groupby("Driver", observed=True)["LapTimeSeconds"].cumsum()

    return df
```

**Position and Strategy Analysis:**
```python
def enrich_position_data(df):
    """Add position-related computed columns (run enrich_lap_times first)."""

    # Position changes
    by_driver = df.groupby("Driver", observed=True)["Position"]
    df["PositionChange"] = by_driver.diff()
    df["StartPosition"] = by_driver.transform("first")
    df["CurrentPositionChange"] = df["StartPosition"] - df["Position"]

    # Gaps in seconds (requires sorting by position within each lap)
    df = df.sort_values(["LapNumber", "Position"])
    df["GapToLeader"] = df.groupby("LapNumber")["CumulativeTime"].transform(
        lambda x: x - x.iloc[0]
    )
    df["GapToAhead"] = df.groupby("LapNumber")["CumulativeTime"].diff()

    return df
```

**Tyre Strategy Enrichment:**
```python
def enrich_tyre_data(df):
    """Add tyre strategy computed columns (Stint comes from the payload)."""

    by_stint = df.groupby(["Driver", "Stint"], observed=True)

    # Stint length so far
    df["StintLength"] = by_stint.cumcount() + 1

    # Compound history
    df["PreviousCompound"] = df.groupby("Driver", observed=True)["Compound"].shift()

    # Pit stop detection: the first lap of a new stint
    df["IsPitLap"] = df.groupby("Driver", observed=True)["Stint"].diff() == 1

    # Laps since pit
    df["LapsSincePit"] = by_stint.cumcount()

    return df
```

**Performance Flags:**
```python
def enrich_performance_flags(df):
    """Add performance-related boolean flags (LapTimeSeconds based)."""

    lap_s = df["LapTimeSeconds"]
    by_driver = df.groupby("Driver", observed=True)["LapTimeSeconds"]

    # Fastest lap of each driver (IsPersonalBest from the payload marks every
    # lap that was a personal best when it was set)
    df["IsDriverBest"] = lap_s == by_driver.transform("min")

    # Session best lap
    df["IsSessionBest"] = lap_s == lap_s.min()

    # Top 3 lap
    df["IsTop3Lap"] = lap_s <= lap_s.nsmallest(3).max()

    # Outlier detection (lap time > 3 std dev from the driver mean)
    mean_time = by_driver.transform("mean")
    std_time = by_driver.transform("std")
    df["IsOutlier"] = (lap_s - mean_time).abs() > (3 * std_time)

    # Consistent lap (within 0.5s of personal average)
    df["IsConsistent"] = (lap_s - mean_time).abs() < 0.5

    return df
```

#### Weather Data Integration

`session.laps` already carries the weather sample of each lap (`WeatherTime`, `AirTemp`, ..., `WindSpeed`). To attach the nearest sample of `session.weather` to a time column, use `pd.merge_asof`. Both `LapStartTime` and the weather `Time` are timedeltas from the session start on pandas:

```python
import pandas as pd


def merge_weather_data(lap_df, weather_df):
    """Attach the nearest weather sample to each lap start (pandas)."""

    # merge_asof needs sorted keys without missing values
    laps_sorted = pd.DataFrame(lap_df).dropna(subset=["LapStartTime"]).sort_values("LapStartTime")

    merged = pd.merge_asof(
        laps_sorted,
        weather_df.sort_values("Time"),
        left_on="LapStartTime",
        right_on="Time",
        direction="nearest",
        suffixes=("", "_weather"),  # AirTemp_weather, TrackTemp_weather, ...
    )

    # Add weather-related computed columns
    merged["TrackTempChange"] = merged.groupby("Driver", observed=True)["TrackTemp"].diff()
    merged["AirTempChange"] = merged.groupby("Driver", observed=True)["AirTemp"].diff()

    # Weather condition categories (Rainfall is a boolean)
    merged["WeatherCondition"] = "Dry"
    merged.loc[merged["Rainfall"], "WeatherCondition"] = "Wet"
    merged.loc[merged["TrackTemp"] < 20, "WeatherCondition"] = "Cold"
    merged.loc[merged["TrackTemp"] > 50, "WeatherCondition"] = "Hot"

    return merged
```

#### Telemetry Enrichment

**Acceleration Calculation:**
```python
def enrich_telemetry_acceleration(tel_df):
    """Calculate acceleration from speed data (pandas telemetry)."""

    # Time is a timedelta from the lap start on pandas (float seconds on polars)
    tel_df["TimeDelta"] = tel_df["Time"].dt.total_seconds().diff()

    # Speed delta, converted from km/h to m/s
    tel_df["SpeedDelta"] = tel_df["Speed"].diff() / 3.6

    # Longitudinal acceleration (m/s²) = (v2 - v1) / dt
    tel_df["Acceleration"] = tel_df["SpeedDelta"] / tel_df["TimeDelta"]

    # G-force (1g = 9.81 m/s²). tif1 also ships smoothed channels in m/s²:
    # AccelerationX (longitudinal), AccelerationY (lateral), AccelerationZ (vertical)
    tel_df["AccelerationG"] = tel_df["Acceleration"] / 9.81
    tel_df["LateralG"] = tel_df["AccelerationY"] / 9.81

    return tel_df
```

```python
def add_driver_ahead_code(tel_df, lap_df):

    lap_number = tel_df["LapNumber"].iloc[0]
    driver = tel_df["Driver"].iloc[0]
    lap_rows = lap_df[lap_df["LapNumber"] == lap_number]

    position = lap_rows.loc[lap_rows["Driver"] == driver, "Position"].iloc[0]

    return tel_df
```

**Corner Detection:**
```python
def detect_corners(tel_df, speed_threshold=200):
    """Detect corners from speed and lateral G (run enrich_telemetry_acceleration first)."""

    # Corner = low speed + high lateral acceleration
    tel_df["IsCorner"] = (
        (tel_df["Speed"] < speed_threshold) &
        (tel_df["LateralG"].abs() > 1.5)
    )

    # Corner number (sequential numbering, a new corner starts on each False -> True step)
    corner_start = tel_df["IsCorner"] & ~tel_df["IsCorner"].shift(fill_value=False)
    tel_df["CornerNumber"] = corner_start.cumsum().astype("float64")

    # Only keep corner number where IsCorner=True
    tel_df.loc[~tel_df["IsCorner"], "CornerNumber"] = float("nan")

    return tel_df
```

`session.get_circuit_info().corners` lists the official corner numbers and their distances, which give a more reliable corner map than speed thresholds.

### Stage 8: Cache Storage and Finalization

The final stage saves processed data to both cache tiers and returns the DataFrame to the user.

#### Cache Storage Strategy

**Dual-Tier Write (memory first, then SQLite):**
```python
def save_to_cache(key, data):
    """Save a JSON payload to both cache tiers (mirrors Cache._store_json_blob)."""

    blob = orjson.dumps(data)

    # Step 1: Memory tier first (fast, < 1ms); stores the raw bytes
    memory_cache.set(key, blob)

    # Step 2: SQLite tier under the shared lock; compressed when >= 4096 bytes
    try:
        with sqlite_lock:
            conn.execute(
                "INSERT OR REPLACE INTO cache VALUES (?, ?)",
                (key, encode_sqlite_value(blob)),
            )
            pending_writes += 1
            if pending_writes >= 100:  # cache_commit_interval
                conn.commit()
    except sqlite3.Error:
        logger.debug(f"Cache write skipped: {key}")  # degrade to a cache miss later

    return data
```

A failed SQLite write is logged at DEBUG level and skipped; it never raises.

**Serialization for SQLite (payload tiers):**

The payload tiers store the CDN JSON, not DataFrames. DataFrames are rebuilt from the
payload on read, or served from the frame tier when one is materialized.

```python
import orjson
import zlib

COMPRESS_MIN_BYTES = 4096

def encode_sqlite_value(blob: bytes) -> bytes | str:
    """Encode an orjson payload for the `cache`/`telemetry_cache` tables."""
    if len(blob) >= COMPRESS_MIN_BYTES:
        if zstd_compress is not None:
            return zstd_compress(blob)          # zstd level 1 (preferred)
        return zlib.compress(blob, 3)           # fallback: no zstd binding importable
    return blob.decode("utf-8")                 # small rows stay plain TEXT
```

**Deserialization from SQLite (payload tiers):**
```python
ZSTD_MAGIC = b"\x28\xb5\x2f\xfd"

def decode_sqlite_value(stored: bytes | str) -> bytes | str:
    """Invert encode_sqlite_value; both zstd and legacy zlib rows stay readable."""
    if isinstance(stored, bytes):
        if stored[:4] == ZSTD_MAGIC:
            return zstd_decompress(stored)
        return zlib.decompress(stored)          # legacy zlib row
    return stored                               # plain TEXT row

data = orjson.loads(decode_sqlite_value(stored))
```

A corrupt compressed row raises `ValueError` inside the cache, which the read path logs
and turns into a cache miss.

**Serialization for SQLite (frame tier):**
```python
import pickle
from lz4 import frame as lz4_frame

def encode_frame(df) -> bytes:
    """Encode a materialized telemetry DataFrame for `telemetry_frames`."""
    blob = pickle.dumps(df, protocol=5)
    return lz4_frame.compress(blob, compression_level=0)  # zstd-1 when lz4 is missing
```

#### Cache Eviction Policies

**LRU Eviction (Memory Cache):**
```python
from collections import OrderedDict

class LRUCache:
    """LRU cache with size limit."""

    def __init__(self, max_size=1024):
        self.cache = OrderedDict()
        self.max_size = max_size

    def get(self, key):
        """Get item from cache."""
        if key not in self.cache:
            return None

        # Move to end (most recently used)
        self.cache.move_to_end(key)
        return self.cache[key]

    def set(self, key, value):
        """Set item in cache."""
        if key in self.cache:
            # Update existing item
            self.cache.move_to_end(key)
        else:
            # Add new item
            if len(self.cache) >= self.max_size:
                # Evict least recently used
                evicted_key, evicted_value = self.cache.popitem(last=False)
                logger.debug(f"Evicted from cache: {evicted_key}")

        self.cache[key] = value

    def clear(self):
        """Clear all items."""
        self.cache.clear()
```

**No Eviction (SQLite Cache):**

The SQLite tier has no time-based eviction and never runs `VACUUM`. Rows stay until a
caller removes them by scope:

```python
cache = tif1.get_cache()
cache.invalidate("json")        # DELETE FROM cache (+ missing_payloads)
cache.invalidate("telemetry")   # DELETE FROM telemetry_cache, telemetry_frames, telemetry_frames_pl (+ missing_payloads)
cache.clear()                   # Every table
```

The negative tier is the one exception: `missing_payloads` verdicts older than
`TIF1_MISSING_PAYLOADS_TTL_DAYS` (default 7.0) are filtered out on load.

- Size: ~0.46 MB (pandas) or ~0.35 MB (polars) for the full race (1128 laps)
- Cached: the JSON payload (memory and SQLite tiers) and the built frame (backend lap LRU)
- Ready: For immediate analysis

### Data Type Comparison: Pandas vs Polars

tif1 applies a dtype contract per backend after construction. The table lists the types of the main `laps` columns, as loaded for the 2025 Bahrain Grand Prix race.

| Column | pandas | polars |
| :--- | :--- | :--- |
| `LapTime`, `Sector1Time` to `Sector3Time`, `PitInTime`, `PitOutTime`, `LapStartTime`, `Time` | `timedelta64[ns]` | `Float64` (seconds) |
| `LapTimeSeconds` | `float64` | `Float64` |
| `LapNumber`, `Stint`, `TyreLife`, `Position` | `float64` | `Int64` |
| `Driver`, `Team`, `Compound`, `TrackStatus` | `category` | `String` |
| `IsPersonalBest`, `FreshTyre`, `IsAccurate`, `FastF1Generated`, `Rainfall` | `bool` | `Boolean` |
| `Deleted` | `boolean` (nullable) | `Boolean` |
| `LapStartDate` | `datetime64[ns]` | `String` (ISO 8601) |
| `WindDirection` | `Int64` (nullable) | `Int64` |
| `index` | `int64` (FastF1 compatibility column) | not present |

**Key Differences:**
- Time columns: pandas converts the upstream float seconds to `timedelta64[ns]`; polars keeps the float. `LapTimeSeconds` is a float on both backends.
- String columns: pandas uses `category`; polars uses `String`. Set `TIF1_POLARS_LAP_CATEGORICAL=true` to get `Categorical` on polars.
- Missing values: polars uses `null` for every type; pandas uses `NaN`, `NaT`, or `<NA>`, depending on the column type.
- Integer columns with no missing values are `Int64` on polars and `float64` on pandas (FastF1 convention).

See [Column types by backend](/concepts/backends#column-types-by-backend) for the weather, race control, and telemetry tables.

## Advanced Performance Optimizations

tif1 implements many performance optimizations throughout the data pipeline. This section explains them for faster code and better architectural decisions.

### 1. HTTP/2 Multiplexing and Connection Reuse

#### HTTP Protocol Evolution

**HTTP/1.0 (Legacy):**
- One request per TCP connection
- Connection closed after each request
- High overhead: TCP handshake (3-way) + TLS handshake (2-3 round trips)
- Total overhead: ~200-300ms per request

**HTTP/1.1 (Traditional):**
- Connection keep-alive (reuse connection)
- Pipelining (limited browser support)
- Head-of-line blocking (requests must complete in order)
- Typical browser limit: 6-8 concurrent connections per domain

**HTTP/2 (tif1):**
- Binary framing protocol (vs text-based HTTP/1.1)
- Multiplexing: Multiple requests over single connection
- Header compression (HPACK algorithm)
- Server push (not used by tif1)
- Stream prioritization
- No head-of-line blocking at HTTP layer

#### Performance Impact

```python
# Scenario: Fetch lap data for 20 drivers

# HTTP/1.1 (6 concurrent connections)
# Round 1: 6 requests × 500ms = 500ms
# Round 2: 6 requests × 500ms = 500ms
# Round 3: 6 requests × 500ms = 500ms
# Round 4: 2 requests × 500ms = 500ms
# Total: 2000ms

# HTTP/2 (single connection, unlimited multiplexing)
# All 20 requests in parallel over 1 connection
# Total: 500ms (limited by slowest request)

# Speedup: 4x faster
```

#### Implementation in tif1

`tif1.http_session.get_session()` returns the process-wide session. It is built once, with the settings below:

### 2. Lazy Loading and On-Demand Data Fetching

Lazy loading fetches data only when the code needs it. This reduces unnecessary network I/O and memory usage.

#### Implementation

The block below is a simplified view of `tif1.core.Session`. The attribute names match the real class; the `_build_*` helpers stand for the property bodies.

```python
class Session:
    """Session with lazy loading (simplified)."""

    def __init__(self, year, gp, session):
        self.year = year
        self.gp = gp            # URL-encoded event name
        self.session = session  # URL-encoded session name

        # Data not loaded yet
        self._laps = None
        self._weather = None
        self._race_control_messages = None
        self._car_data = None  # Telemetry of every lap

    @property
    def laps(self):
        """Lazy load lap data."""
        if self._laps is None:
            self._laps = self._build_laps()
        return self._laps

    @property
    def weather(self):
        """Lazy load weather data."""
        if self._weather is None:
            self._weather = self._build_weather()
        return self._weather

    # Same pattern for race_control_messages and car_data.
    # Lap telemetry loads per lap on first access (lap.telemetry).
```

#### Performance Benefits


### 5. Async Parallel Fetching

Async fetching is one of the most important tif1 performance optimizations.

#### Sequential vs Parallel Comparison

```python
import time
import asyncio

# Sequential fetching
def fetch_sequential(drivers):
    results = []
    start = time.time()

    for driver in drivers:
        result = fetch_driver_sync(driver)  # 500ms each
        results.append(result)

    duration = time.time() - start
    print(f"Sequential: {duration:.2f}s for {len(drivers)} drivers")
    return results

# Parallel fetching
async def fetch_parallel(drivers):
    start = time.time()

    tasks = [fetch_driver_async(driver) for driver in drivers]
    results = await asyncio.gather(*tasks)

    duration = time.time() - start
    print(f"Parallel: {duration:.2f}s for {len(drivers)} drivers")
    return results

# Test with 20 drivers
drivers = ["VER", "HAM", "LEC", ...] # 20 drivers

# Sequential: 10.00s for 20 drivers (20 × 500ms)
fetch_sequential(drivers)

# Parallel: 0.58s for 20 drivers (max of all requests)
asyncio.run(fetch_parallel(drivers))

# Speedup: 17.2x faster
```

#### Concurrency Control

```python
import asyncio
from asyncio import Semaphore

async def fetch_with_limit(drivers, max_concurrent=10):
    """Fetch with concurrency limit."""

    semaphore = Semaphore(max_concurrent)

    async def fetch_limited(driver):
        async with semaphore:
            return await fetch_driver(driver)

    tasks = [fetch_limited(driver) for driver in drivers]
    results = await asyncio.gather(*tasks)

    return results

# Limit to 10 concurrent requests
# Prevents overwhelming the CDN (tif1 itself uses max_concurrent_requests, default 22)
results = asyncio.run(fetch_with_limit(drivers, max_concurrent=10))
```

## Comprehensive Error Handling

tif1 implements an error handling system with a hierarchical exception structure, detailed error context, and recovery strategies.

### Exception Hierarchy

`src/tif1/exceptions.py` defines nine exception classes. Every one is exported from `tif1`. Eight of them form the `TIF1Error` hierarchy:

```text
TIF1Error (base exception)
├── NetworkError
├── DataNotFoundError
│   ├── DriverNotFoundError
│   └── LapNotFoundError
├── InvalidDataError
├── CacheError
└── SessionNotLoadedError
```

The ninth, `EventNotInSeasonError`, is a `ValueError` subclass, not a `TIF1Error`. `get_session()` and `get_event_by_name()` raise it when a circuit or country alias names an event that is not on that season's calendar. An example is `"Suzuka"` in 2021.

Every exception carries `message` (the formatted text) and `context` (a dict of keyword arguments passed at raise time). The constructors accept extra `**context` keys, so handlers should read `e.context.get(...)` rather than rely on attributes.

| Exception | Context keys set by the constructor |
|-----------|-------------------------------------|
| `NetworkError` | `url`, `status_code` |
| `DataNotFoundError` | `year`, `event`, `session` |
| `DriverNotFoundError` | `driver` |
| `LapNotFoundError` | `lap_number`, `driver` |
| `InvalidDataError` | `reason` |
| `SessionNotLoadedError` | `attribute` |
| `CacheError` | none (never raised by `tif1.cache`; see below) |

### Network Errors

`NetworkError` is raised when every CDN source fails or when `offline_mode` is on and the cache misses. The CDN fallback loop in `cdn.py` logs each failed source at `WARNING` before raising.

```python
import time

import tif1

try:
    laps = session.laps
except tif1.NetworkError as e:
    print(f"Network error: {e.message}")
    print(f"URL: {e.context.get('url')}")
    print(f"Status: {e.context.get('status_code')}")

    # Simple retry with backoff; tif1 already retried each CDN per TIF1_MAX_RETRIES
    for attempt in range(3):
        try:
            time.sleep(2**attempt)
            laps = session.laps
            break
        except tif1.NetworkError:
            if attempt == 2:
                raise
```

Timeouts and connection failures surface as `NetworkError` too; raise `TIF1_TIMEOUT` or `TIF1_MAX_RETRIES` through the environment or `tif1.get_config().set(...)` when a slow link needs more headroom.

### Data Not Found Errors

`DataNotFoundError` means every CDN returned a 4xx for the payload, or the negative-verdict tier already knows it is missing.

```python
import tif1

session = tif1.get_session(2025, "Bahrain Grand Prix", "Race")
try:
    lap = session.get_driver("VER").get_lap(999)
except tif1.DataNotFoundError as e:  # LapNotFoundError is a subclass
    print(f"Data not found: {e.message}")
    print(e.context)  # {'lap_number': 999, 'driver': 'VER', 'year': 2025, 'event': ..., 'session': 'Race'}
```

An unknown event name does not raise `DataNotFoundError`. tif1 resolves the name with fuzzy matching, so `"Nonexistent Grand Prix"` loads the Japanese Grand Prix. Check `session.event["EventName"]` after the call.

`DriverNotFoundError` and `LapNotFoundError` are subclasses, so one `except tif1.DataNotFoundError` handler covers all three.

```python
try:
    driver = session.get_driver("ZZZ")
except tif1.DriverNotFoundError as e:
    print(f"Requested: {e.context['driver']}")
    print(f"Available: {session.drivers_df['Driver'].tolist()}")  # session.drivers holds numbers

try:

    print(f"Lap {e.context['lap_number']} not found for {e.context['driver']}")
```

### Invalid Data Errors

`InvalidDataError` is raised when a payload fails pydantic validation in `validation.py` or cannot be parsed. Validation failures always raise; there is no fallback to unvalidated data.

```python

except tif1.InvalidDataError as e:
    print(f"Invalid data: {e.context.get('reason')}")
    print(e.context)  # any extra keys the raiser attached
```

### Session Not Loaded Errors

`SessionNotLoadedError` is defined and exported for FastF1-style code paths. tif1 sessions load lazily on attribute access, so the current code never raises it.

### Cache Errors

The cache never raises on read or write failures. `tif1.CacheError` exists in the
hierarchy as a direct `TIF1Error` subclass with no subclasses of its own. `cache.py` does
not raise it. tif1 logs a failed SQLite read, a corrupt compressed row, or a failed write.
Each case degrades to a cache miss, so the loader fetches from the CDN instead.

#### Diagnosing cache problems

```python
import logging
import os

# Surface cache warnings ("Cache read error for ...", "SQLite cache unavailable: ...")
logging.getLogger("tif1.cache").setLevel(logging.WARNING)

laps = session.laps  # Works even when the cache is unavailable; it fetches instead

# Recover from a damaged database: wipe every tier and reload
cache = tif1.get_cache()
cache.clear()
laps = session.laps

# Last resort: disable the cache for this process
os.environ["TIF1_ENABLE_CACHE"] = "false"
```

If SQLite cannot open `cache.sqlite` at startup, tif1 logs `SQLite cache unavailable`
and runs with the in-memory tiers only.

### Error Recovery Strategies

#### Automatic Retry with Exponential Backoff

```python
import time
from functools import wraps

def retry_with_backoff(max_retries=3, base_delay=1.0):
    """Decorator for automatic retry with exponential backoff."""

    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(max_retries):
                try:
                    return func(*args, **kwargs)
                except tif1.NetworkError as e:
                    if attempt == max_retries - 1:
                        raise

                    delay = base_delay * (2 ** attempt)
                    jitter = random.uniform(0, 0.1 * delay)
                    total_delay = delay + jitter

                    logger.warning(
                        f"Attempt {attempt + 1}/{max_retries} failed: {e}. "
                        f"Retrying in {total_delay:.2f}s"
                    )
                    time.sleep(total_delay)

            return None
        return wrapper
    return decorator

# Usage
@retry_with_backoff(max_retries=3, base_delay=1.0)
def load_session_data():
    session = tif1.get_session(2025, "Monaco", "Race")
    return session.laps
```

#### Fallback to Alternative Data Source

```python
import logging

import pandas as pd
import tif1

logger = logging.getLogger(__name__)


def load_with_fallback(year, event, session_type):
    """Load data with fallback to alternative sources."""

    # Try primary source (tif1)
    try:
        session = tif1.get_session(year, event, session_type)
        return session.laps
    except tif1.DataNotFoundError:
        logger.warning("Primary source failed, trying fallback")

        return pd.read_csv(file_path)
    except FileNotFoundError:
        logger.error("Fallback source also failed")

    # No data available (the constructor builds the message from these keys)
    raise tif1.DataNotFoundError(year=year, event=event, session=session_type)
```

#### Graceful Degradation

```python
def load_with_degradation(year, event, session_type):
    """Load data with graceful degradation."""

    session = tif1.get_session(year, event, session_type)

    # Try to load all data
    data = {}

    # Laps (critical)
    try:
        data["laps"] = session.laps
    except Exception as e:
        logger.error(f"Failed to load laps: {e}")
        raise  # Laps are critical, don't continue

    # Weather (optional). A weather payload that cannot be converted gives
    # an empty DataFrame and a logged warning, not an exception
    try:
        data["weather"] = session.weather
    except Exception as e:
        logger.warning(f"Failed to load weather: {e}")
        data["weather"] = None  # Continue without weather

    # Telemetry (optional): the fastest lap only; session.car_data loads every lap
    try:
        data["telemetry"] = session.get_fastest_lap_tel()
    except Exception as e:
        logger.warning(f"Failed to load telemetry: {e}")
        data["telemetry"] = None  # Continue without telemetry

    return data
```

```python
    """Decorator to time operations."""

    def decorator(func):
```

```python
import time


class RequestTracker:
    """Track HTTP requests."""

    def __init__(self):
        self.requests = []

    def record_request(self, url, method, status_code, duration, size):
        """Record HTTP request."""
        self.requests.append({
            "timestamp": time.time(),
            "url": url,
            "method": method,
            "status_code": status_code,
            "duration": duration,
            "size": size,
        })

    def get_summary(self):
        """Get request summary."""
        if not self.requests:
            return {}

        total_requests = len(self.requests)
        successful_requests = sum(1 for r in self.requests if 200 <= r["status_code"] < 300)
        total_duration = sum(r["duration"] for r in self.requests)
        total_size = sum(r["size"] for r in self.requests)

        return {
            "total_requests": total_requests,
            "successful_requests": successful_requests,
            "success_rate": successful_requests / total_requests,
            "total_duration": total_duration,
            "avg_duration": total_duration / total_requests,
            "total_size_mb": total_size / 1024 / 1024,
            "avg_size_kb": total_size / total_requests / 1024,
        }

    def get_slowest_requests(self, n=5):
        """Get slowest requests."""
        sorted_requests = sorted(self.requests, key=lambda r: r["duration"], reverse=True)
        return sorted_requests[:n]
```

## Data Flow Patterns and Scenarios

Common data flow patterns help with code optimization for different use cases.

### Pattern 1: Cold Start (First Load)

**Scenario:** First time loading data, no cache available.

```text
User Request
    ↓
Memory Cache Miss (< 1ms)
    ↓
SQLite Cache Miss (2ms)
    ↓
Circuit Breaker Check (< 1ms)
    ↓
CDN URL Construction (< 1ms)
    ↓
Async HTTP Fetch - jsDelivr (500-800ms)
    │
    ├─ Driver 1: 523ms
    ├─ Driver 2: 534ms
    ├─ Driver 3: 512ms
    └─ ... (parallel)
    ↓
JSON Parsing - orjson (100ms)
    ↓
Schema Validation (off by default)
    ↓
DataFrame Construction (81ms)
    ↓
Column Renaming (8ms)
    ↓
Type Optimization (25ms)
    ↓
LapTimeSeconds Column (< 5ms)
    ↓
SQLite Cache Save (50ms)
    ↓
Memory Cache Save (< 1ms)
    ↓
Return DataFrame
```

**Total Time:** ~2.5-3.0 seconds
**Network I/O:** ~500-800ms (parallel)
**CPU Processing:** ~220ms
**Cache Operations:** ~52ms
**Overhead:** ~5ms

**Optimization Tips:**
- Pre-warm cache during application startup
- Use async loading for non-blocking operation
- Consider loading only required data (laps vs telemetry)

### Pattern 2: Warm Start (SQLite Cache Hit)

**Scenario:** Data exists in SQLite cache, but not in memory.

```text
User Request
    ↓
Memory Cache Miss (< 1ms)
    ↓
SQLite Cache Hit (30ms)
    │
    ├─ Database query (5ms)
    ├─ Decompress data (15ms)
    └─ Deserialize JSON (10ms)
    ↓
DataFrame Reconstruction (5ms)
    ↓
Memory Cache Save (< 1ms)
    ↓
Return DataFrame
```

**Total Time:** ~30-50ms
**Network I/O:** 0ms (no network)
**CPU Processing:** ~30ms
**Cache Operations:** ~35ms

**Speedup vs Cold Start:** ~93x faster (30ms vs 2800ms)

**Optimization Tips:**
- Keep SQLite cache on SSD for faster access
- Keep the cache directory between runs; cached payloads never expire
- Compare warm and cold load times (the cache keeps no hit counters)

### Pattern 3: Hot Start (Memory Cache Hit)

**Scenario:** Data exists in memory cache.

```text
User Request
    ↓
Memory Cache Hit (< 1ms)
    ↓
Return DataFrame
```

**Total Time:** < 1ms
**Network I/O:** 0ms
**CPU Processing:** < 1ms
**Cache Operations:** < 1ms

**Speedup vs Cold Start:** ~2800x faster (< 1ms vs 2800ms)
**Speedup vs Warm Start:** ~30x faster (< 1ms vs 30ms)

**Optimization Tips:**
- Reuse session objects to maximize memory cache hits
- Increase the memory cache size when RAM is available
- Keep frequently accessed data in memory

### Pattern 4: Partial Cache Hit

**Scenario:** Some drivers cached, others need fetching.

```text
User Request (20 drivers)
    ↓
Memory Cache Check
    │
    ├─ 15 drivers: Cache Hit (< 1ms each)
    └─ 5 drivers: Cache Miss
        ↓
        SQLite Cache Check
        │
        ├─ 3 drivers: Cache Hit (30ms each)
        └─ 2 drivers: Cache Miss
            ↓
            CDN Fetch (500ms parallel)
            ↓
            Process & Cache (200ms)
```

**Total Time:** ~700ms
**Breakdown:**
- 15 drivers from memory: < 1ms
- 3 drivers from SQLite: ~90ms
- 2 drivers from CDN: ~700ms

**Optimization Tips:**
- Batch fetch missing drivers
- Pre-warm cache for commonly accessed drivers
- Use selective loading (only load needed drivers)

### Pattern 5: Network Failure with Retry

**Scenario:** jsDelivr times out, so tif1 retries it with backoff and then falls back to Hugging Face. The timings assume the default settings (`timeout` 30 s, `max_retries` 3, `retry_backoff_factor` 2.0, jitter on).

```text
User Request
    ↓
Memory Cache Miss
    ↓
SQLite Cache Miss
    ↓
jsDelivr - Attempt 1
    ↓
FAILURE (timeout after 30s, NetworkError)
    ↓
Exponential Backoff (~1s, randomized 0.5-1.5s)
    ↓
jsDelivr - Attempt 2
    ↓
FAILURE (timeout after 30s)
    ↓
Exponential Backoff (~2s, randomized 1-3s)
    ↓
jsDelivr - Attempt 3
    ↓
FAILURE (timeout after 30s): jsDelivr is marked failed
    ↓
Hugging Face - Attempt 1
    ↓
SUCCESS (500ms)
    ↓
Process & Cache
    ↓
Return DataFrame
```

**Total Time:** ~94 seconds (with failures)
**Breakdown:**
- jsDelivr: 3 tries × 30s (timeouts) + ~3s of backoff
- Hugging Face: 500ms (success)
- Processing: well under 1s

A 404 does not trigger this loop. tif1 moves to the next CDN at once, and raises `DataNotFoundError` when every CDN returns 404.

**Optimization Tips:**
- Reduce `timeout` (`TIF1_TIMEOUT`) or `max_retries` (`TIF1_MAX_RETRIES`) for faster failure detection
- After 3 failed fetches, tif1 skips a CDN source
- After 5 consecutive failures, the circuit breaker fails fast for 60 seconds

```python
class AdaptiveTimeout:

        # Adjust timeout based on recent performance
        if self.recent_durations:
            avg_duration = sum(self.recent_durations) / len(self.recent_durations)
            # Set timeout to 3x average duration (with min/max bounds)
            self.timeout = max(10, min(60, avg_duration * 3))

    def get_timeout(self):
        """Get current timeout."""
        return self.timeout

# Usage
import niquests

adaptive_timeout = AdaptiveTimeout()
url = "https://cdn.jsdelivr.net/gh/TracingInsights/2025@main/Monaco%20Grand%20Prix/Race/drivers.json"

# Make request with adaptive timeout
timeout = adaptive_timeout.get_timeout()
response = niquests.get(url, timeout=timeout)

# Record duration
adaptive_timeout.record_request(response.elapsed.total_seconds())

# Apply it to tif1 (the timeout setting takes whole seconds)
tif1.get_config().set("timeout", int(adaptive_timeout.get_timeout()))
```

### Strategy 8: Lazy Evaluation with Polars

Use Polars lazy evaluation for complex pipelines.

```python
import polars as pl

# Eager evaluation (executes immediately)
laps = session.laps
result = (
    laps
    .filter(pl.col("Compound") == "SOFT")
    .group_by("Driver")
    .agg(pl.col("LapTime").mean())
    .sort("LapTime")
)

# Lazy evaluation (optimizes entire pipeline)
laps_lazy = session.laps.lazy()  # Convert to lazy frame
result = (
    laps_lazy
    .filter(pl.col("Compound") == "SOFT")
    .group_by("Driver")
    .agg(pl.col("LapTime").mean())
    .sort("LapTime")
    .collect()  # Execute optimized plan
)

# Polars optimizes:
# - Predicate pushdown (filter early)
# - Projection pushdown (select only needed columns)
# - Common subexpression elimination
# - Parallel execution

# Speedup: 2-3x faster for complex pipelines
```

### Strategy 9: Compression for Cache Storage

Optimize cache storage with compression.

The codec and level are fixed; there is no compression-level setting.

```python
# Payload tiers (cache, telemetry_cache):
#   rows >= 4096 bytes -> zstd level 1 (zlib level 3 only when no zstd binding imports)
#   smaller rows       -> plain TEXT, no compression
#
# Frame tier (telemetry_frames, telemetry_frames_pl):
#   pickle protocol 5 -> lz4 (zstd level 1 when lz4 is unavailable)
#
# zstd-1 was chosen over zlib because it compresses ~4.5x faster at a
# slightly better ratio and decompresses ~2x faster on telemetry JSON.

# The one lever: install a fast binding so the preferred codec is active
#   Python 3.14+ : compression.zstd ships in the standard library
#   Python 3.11-3.13: pip install zstandard
#   Frame tier   : pip install lz4
```

### Strategy 10: Monitoring-Driven Optimization

Use monitoring data to identify bottlenecks.

```python
class PerformanceProfiler:
    """Profile performance to identify bottlenecks."""

    def __init__(self):
        self.timings = {}

    def time_section(self, name):
        """Context manager to time code sections."""
        import contextlib
        import time

        @contextlib.contextmanager
        def timer():
            start = time.time()
            yield
            duration = time.time() - start

            if name not in self.timings:
                self.timings[name] = []
            self.timings[name].append(duration)

        return timer()

    def get_report(self):
        """Get performance report."""
        report = {}
        for name, durations in self.timings.items():
            report[name] = {
                "count": len(durations),
                "total": sum(durations),
                "mean": sum(durations) / len(durations),
                "min": min(durations),
                "max": max(durations),
            }
        return report

    def print_report(self):
        """Print formatted report."""
        report = self.get_report()

        print("Performance Profile:")
        print("-" * 60)

        # Sort by total time (descending)
        sorted_sections = sorted(
            report.items(),
            key=lambda x: x[1]["total"],
            reverse=True
        )

        for name, stats in sorted_sections:
            print(f"{name}:")
            print(f"  Count: {stats['count']}")
            print(f"  Total: {stats['total'] * 1000:.2f}ms")
            print(f"  Mean: {stats['mean'] * 1000:.2f}ms")
            print(f"  Min: {stats['min'] * 1000:.2f}ms")
            print(f"  Max: {stats['max'] * 1000:.2f}ms")
            print()

# Usage
def analyze_laps(laps):
    return laps["LapTimeSeconds"].describe()  # Stands in for the real analysis

profiler = PerformanceProfiler()

with profiler.time_section("Load session"):
    session = tif1.get_session(2025, "Monaco", "Race")

with profiler.time_section("Load laps"):
    laps = session.laps

with profiler.time_section("Analysis"):
    result = analyze_laps(laps)

profiler.print_report()
# Identifies which section is slowest
```

## Comprehensive Summary

The tif1 data flow architecture targets maximum performance, reliability, and developer experience. This section summarizes the key concepts and gives actionable recommendations.

### Architecture Principles

**1. Performance First**
- Every component optimized for speed
- Multi-tier caching reduces latency by 2800x
- HTTP/2 multiplexing enables parallel fetching
- orjson provides 3x faster JSON parsing
- Categorical types reduce memory by 90%
- Polars backend offers 4x faster operations

**2. Resilience and Reliability**
- Circuit breaker prevents cascading failures
- Automatic retry with exponential backoff
- Multi-source CDN fallback (jsDelivr → Hugging Face → StaticDelivr)
- Comprehensive error handling with detailed context
- Graceful degradation for non-critical data

**3. Developer Experience**
- Lazy loading minimizes unnecessary work
- Intuitive API with sensible defaults
- Detailed logging and monitoring capabilities
- Detailed error messages with recovery suggestions
- Flexible backend selection (pandas/polars)

### Performance Characteristics

**Load Time Comparison:**

| Scenario | Time | Speedup vs Cold |
|----------|------|-----------------|
| Cold start (no cache) | 2.8s | 1x (baseline) |
| Warm start (SQLite cache) | 30ms | 93x faster |
| Hot start (memory cache) | < 1ms | 2800x faster |

**Memory Usage:**

| Data Type | Unoptimized | Optimized | Savings |
|-----------|-------------|-----------|---------|
| Lap data (1500 laps) | 15 MB | 4 MB | 73% |
| Telemetry (15k samples) | 45 MB | 18 MB | 60% |
| Weather (150 samples) | 0.8 MB | 0.3 MB | 63% |

**Backend Comparison:**

| Operation | Pandas | Polars | Speedup |
|-----------|--------|--------|---------|
| Load from JSON | 86ms | 20ms | 4.3x |
| Filter | 2.5ms | 0.8ms | 3.1x |
| Groupby | 12ms | 3ms | 4.0x |
| Memory usage | 7 MB | 3.5 MB | 50% less |

### Key Optimizations

**1. Multi-Tier Caching**
- L1 (Memory): < 1ms access, 1024 items
- L2 (SQLite): 30ms access, unlimited capacity
- Automatic promotion from L2 to L1
- No expiry: cached payloads persist until cleared

**2. Async Parallel Fetching**
- HTTP/2 multiplexing over single connection
- 20 drivers fetched in 500ms (vs 10s sequential)
- 17x speedup for multi-driver operations
- Automatic error handling and retry

**3. Type Optimization**
- Categorical encoding for string columns (pandas)
- Time columns as `timedelta64[ns]` (pandas) or `Float64` seconds (polars)
- Boolean flags as `bool`/`Boolean`; numeric columns stay 64-bit
- The pandas laps frame shrinks by about a third (718 KB to 462 KB for a full race)

**4. Data Enrichment**
- One computed column (`LapTimeSeconds`); per-lap weather comes with the payload
- Telemetry channels such as `RelativeDistance`, `DriverAhead`, and `AccelerationX/Y/Z` come with the payload
- The Stage 7 recipes add more columns in a few milliseconds
