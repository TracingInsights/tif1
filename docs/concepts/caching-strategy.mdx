## Overview

`tif1` downloads each payload once and serves later reads from local tiers. The tiers are:

1. **Session memo** - per-`Session` dictionaries that hold the payloads and frames of the current session.
2. **In-memory LRU tiers** - bounded process-wide caches in front of SQLite.
3. **SQLite frame tiers** - persistent, pre-built laps and telemetry DataFrames.
4. **SQLite payload tables** - persistent JSON and telemetry payloads in `cache.sqlite`.
5. **Negative-verdict tier** - payload paths that every CDN reported as missing.
6. **CDN fetch** - jsDelivr first, then Hugging Face buckets, then StaticDelivr.

A load stops at the first hit:

- `session.laps` checks the backend lap LRU, then the laps frame tier, then the payloads.
- A telemetry load checks the session memo, then the telemetry frame tier, then the payloads.
- A single lap (`lap.get_telemetry()`) reads its driver's frame-tier row and memoizes every lap of that driver. Later laps of the same driver are memo hits.
- A load served from the memo and the frame tiers never starts an event loop. The async fetch pipeline runs only for laps the tiers do not hold.
- A payload read checks the session memo, the LRU tiers, and the SQLite payload tables, in that order. On a miss, the fetch path checks the negative-verdict tier and then the CDN.

A fresh network result is written back to the memo, the LRU tiers, and SQLite. Every tier lives in `src/tif1/cache.py`.

<Note>
Positive cache entries never expire. The data behind a finished session does not change, so `tif1` keeps it until `clear()` or `invalidate()` removes it.
</Note>

## Tiers

### Session memo

Each `Session` owns one `SessionMemo`. The memo stores three kinds of data:

| Kind | Key | Holds |
|------|-----|-------|
| `"json"` | payload path | Payload dicts fetched during the session |
| `"telemetry_payload"` | `(driver, lap)` | Raw telemetry payload dicts |
| `"telemetry_df"` | `(driver, lap)` | Materialized telemetry DataFrames |

The memo also records the persistent-cache probe result and per-driver telemetry failure counts. It is not shared between sessions and is released with the session object.

### In-memory LRU tiers

The SQLite `Cache` object fronts its database with four `LRUCache` instances. `LRUCache` is an `OrderedDict`-based bounded LRU.

| Tier | Holds | Max items | Source of the limit |
|------|-------|-----------|---------------------|
| JSON blob LRU | Serialized payload bytes by path key | 1024 | `memory_cache_max_items` |
| Telemetry blob LRU | Serialized telemetry bytes by `(year, gp, session, driver, lap)` | 2048 | `memory_telemetry_cache_max_items` |
| Parsed JSON LRU | Parsed payload objects | 128 | fixed (`_PARSED_CACHE_MAX_ITEMS`) |
| Parsed telemetry LRU | Parsed telemetry objects | 256 | fixed (`_PARSED_TELEMETRY_CACHE_MAX_ITEMS`) |

Reads on the hot path do not take a lock. A hit in a parsed tier skips the orjson parse completely.

### SQLite payload tables

The database file is `cache.sqlite` inside the cache directory. Two tables hold payloads:

```sql
CREATE TABLE cache (key TEXT PRIMARY KEY, data TEXT);

CREATE TABLE telemetry_cache (
    year INTEGER, gp TEXT, session TEXT, driver TEXT, lap INTEGER,
    data TEXT,
    PRIMARY KEY (year, gp, session, driver, lap)
);
```

JSON-tier keys have the form `"{year}/{gp}/{session}/{path}"`. The payload paths are:

| Path | Content |
|------|---------|
| `drivers.json` | Driver list for the session |
| `session_laptimes.json` | Lap times for all drivers |
| `rcm.json` | Race control messages |
| `weather.json` | Weather samples |
| `corners.json` | Circuit corner markers |
| `{driver}/laptimes.json` | Lap times for one driver |
| `{driver}/{lap}_tel.json` | Telemetry for one lap |

Telemetry payloads (`{driver}/{lap}_tel.json`) are routed to `telemetry_cache`. Their key is the tuple `(year, gp, session, driver, lap)`. All other payloads go to the `cache` table.

### SQLite frame tiers

The frame tiers store assembled DataFrames so a warm load skips JSON parsing and frame construction. Each backend has its own tables with the same columns:

```sql
CREATE TABLE telemetry_frames_drv (
    year INTEGER, gp TEXT, session TEXT, driver TEXT,
    laps TEXT,      -- JSON list of the lap numbers stored in the row
    frame BLOB,     -- typed-columnar blob with every lap of the driver (lz4)
    PRIMARY KEY (year, gp, session, driver)
);
-- telemetry_frames holds one row per lap: pandas frames written by earlier
-- releases, and frames with a column outside the telemetry dtype contract.
CREATE TABLE telemetry_frames (
    year INTEGER, gp TEXT, session TEXT, driver TEXT, lap INTEGER,
    frame BLOB,
    PRIMARY KEY (year, gp, session, driver, lap)
);
-- telemetry_frames_pl has the same shape and holds polars frames written by
-- earlier releases, or by drivers whose laps have different schemas.

CREATE TABLE telemetry_frames_pl_ipc (
    year INTEGER, gp TEXT, session TEXT, driver TEXT,
    laps TEXT,      -- JSON list of [lap, row count] in storage order
    frame BLOB,     -- Arrow IPC file (lz4) with every lap of the driver
    PRIMARY KEY (year, gp, session, driver)
);

CREATE TABLE laps_frames (
    year INTEGER, gp TEXT, session TEXT,
    frame BLOB,
    PRIMARY KEY (year, gp, session)
);
-- laps_frames_pl has the same shape and holds polars frames.
```

`session.laps` reads the processed laps table from the laps frame table of its backend (`Cache.get_laps_frame()`) on a warm cache. After a build from the payload tier, it writes the table there (`Cache.set_laps_frame()`).

`Session.fetch_all_laps_telemetry()` assembles the telemetry frames and then hands the bulk write to a background daemon thread. `register_frame_writer()` starts that thread. `Cache.close()`, `invalidate()`, `clear()`, and the atexit handler join it, so the connection never closes under a live writer.

The payload tables stay the source of truth. A frame row that fails to load becomes a tier miss and the loader falls back to the payload tier.

The telemetry frame tables are versioned through SQLite `PRAGMA user_version` (`_FRAME_TIER_SCHEMA_VERSION`). When the stored version is older, `tif1` drops both telemetry frame tables once. Later loads rebuild the frames from the payload tier. The laps frame tables are not versioned.

### Negative-verdict tier

On the async fetch path, a 4xx answer from every CDN marks the payload as missing. A 408 or 429 does not count. `tif1` records the key in `missing_payloads`:

```sql
CREATE TABLE missing_payloads (key TEXT PRIMARY KEY, recorded_at REAL);
```

Later async fetches consult `is_known_missing()` after a cache miss and raise `DataNotFoundError` without a request. A verdict expires after `missing_payloads_ttl_days` (default `7.0`). A successful write for the same key discards the verdict.

### Live schedule row

`tif1.events` stores the raw `schedule_{year}.json` of a live season in the `json` tier under `f1schedule/schedule_{year}.json`, together with its fetch time. The row is re-fetched from the `theOehrly/f1schedule` repository once it is older than `schedule_ttl_hours` (default `6.0`); a failed refresh keeps serving the stale row. Session payloads never expire; this row and the negative verdicts are the two TTL-scoped entries.

### Backend lap LRU

Parsed lap tables are kept in one process-global `LRUCache` per backend (`pandas` and `polars`). The limit is `MAX_CACHE_SIZE = 100` sessions per backend and the key is `"{year}_{gp}_{session}_laps"`.

```python
from tif1.cache import clear_lap_cache, get_backend_lap_cache

print(len(get_backend_lap_cache("pandas")))
clear_lap_cache()  # empties both backend lap caches
```

## Storage format and compression

### Payload rows

Payload rows hold orjson-encoded bytes. A row of 4096 bytes or more (`_SQLITE_COMPRESS_MIN_BYTES`) is compressed with zstd at level 1 (`_ZSTD_LEVEL`). Smaller rows are stored as plain `TEXT`. Legacy zlib rows stay readable because zstd frames carry a 4-byte magic prefix.

The zstd binding depends on the interpreter:

- Python 3.14 and later use the standard-library `compression.zstd` module (PEP 784).
- Python 3.11 to 3.13 use the `zstandard` package.

Both bind the same libzstd and emit identical single-frame blobs. A cache written under one binding reads under the other.

zstd-1 compresses about 4.5x faster and decompresses about 2x faster than the previous zlib-3 codec. It also stores 23.4% of the original size against 26.2% for zlib-3. These figures were measured on 1452 telemetry payloads from the 2026 Monaco race.

### Frame rows

Pandas telemetry frames are stored per driver in `telemetry_frames_drv`. The row holds a typed-columnar encoding of every lap of the driver. The laps are grouped by block layout. Each group stores one array per block over all of its rows, a dictionary for the string columns, and a small header. The header lists the column names, the lap numbers, the row count of each lap, and the block layout. The reader builds each lap frame from views into the group arrays, without the DataFrame constructor and without a copy. A driver's merged telemetry (`Laps.telemetry`) is a slice of the same arrays. A partial write merges with the laps already stored for the driver. A frame with a column outside the telemetry dtype contract is pickled into the per-lap `telemetry_frames` table instead.

Rows written by earlier releases sit in `telemetry_frames` as per-lap pickles or per-lap typed-columnar blobs. The reader still serves them. When a load serves 32 or more laps of a session from these rows, a background thread rewrites them as driver rows. The per-lap rows are then deleted. The reader tells the formats apart by a magic prefix. Laps frame rows hold a pickle (protocol 5).

The blob is compressed with lz4 frame at level 0. When `lz4` is not installed, the writer falls back to zstd-1. Python 3.15 has no `lz4` wheels yet, so the frame tier uses zstd there. The reader detects the codec from the magic prefix, so lz4 and zstd rows coexist in one table. The reader decompresses lz4 rows through pyarrow's codec, which releases the GIL. A batch read decompresses in a thread pool. Each chunk is decoded while the others are still in flight. Without pyarrow's lz4 support, the reader uses the serial `lz4` codec.

Polars telemetry frames are stored per driver in `telemetry_frames_pl_ipc` as one Arrow IPC file with lz4 inside the stream. A lap is a slice of the driver frame; the row's `laps` column lists the lap numbers and row counts in storage order. A partial write merges with the laps already stored for the driver. A batch read reads the IPC files in a thread pool and converts them to polars in one step. The laps are slices at a global offset.

On the 1452-frame 2026 Monaco race set, a fresh process reads the pandas driver rows in 57 ms against 179 ms for per-lap rows. The polars driver rows read in 53 ms against 87 ms. The frame tier is write-once and read-many, so read speed wins over ratio.

## Cache location and configuration

### Default directory

| Platform | Default cache directory |
|----------|-------------------------|
| Linux and other POSIX | `~/.cache/tif1` when `~/.cache` exists, otherwise `~/.tif1` |
| macOS | `~/Library/Caches/tif1` |
| Windows | `%LOCALAPPDATA%/Temp/tif1` |

`tif1` creates the directory and sets its mode to `0o700` (owner access only). The frame tier unpickles blobs from this directory, so the restricted mode is part of the security model.

### Configuration keys

Configuration is read through `tif1.get_config().get(key)` and changed with `.set(key, value)`. The `Config` object has no attribute-style access and `tif1.Config` is not exported.

| Key | Environment variable | Default | Effect |
|-----|----------------------|---------|--------|
| `cache_dir` | `TIF1_CACHE_DIR` | platform default | Directory that holds `cache.sqlite` |
| `enable_cache` | `TIF1_ENABLE_CACHE` | `true` | Default for `get_session(enable_cache=...)` |
| `offline_mode` | `TIF1_OFFLINE_MODE` | `false` | Serve payloads from the cache only; a miss raises `NetworkError` |
| `ci_mode` | `TIF1_CI_MODE` | `false` | Skip persistent cache reads and writes for payload fetches |
| `cache_commit_interval` | `TIF1_CACHE_COMMIT_INTERVAL` | `100` | Writes per SQLite commit |
| `sqlite_timeout` | `TIF1_SQLITE_TIMEOUT` | `30.0` | SQLite busy timeout in seconds |
| `memory_cache_max_items` | `TIF1_MEMORY_CACHE_MAX_ITEMS` | `1024` | JSON blob LRU size |
| `memory_telemetry_cache_max_items` | `TIF1_MEMORY_TELEMETRY_CACHE_MAX_ITEMS` | `2048` | Telemetry blob LRU size |
| `missing_payloads_ttl_days` | `TIF1_MISSING_PAYLOADS_TTL_DAYS` | `7.0` | Lifetime of a negative verdict |
| `schedule_ttl_hours` | `TIF1_SCHEDULE_TTL_HOURS` | `6.0` | Age at which a live season's schedule is re-fetched |

Boolean environment variables accept `1`, `true`, `yes`, and `on`.

```python
import tif1

config = tif1.get_config()
config.set("cache_dir", "./tif1-cache")  # relative paths resolve against the working directory
config.set("memory_telemetry_cache_max_items", 4096)
print(config.get("cache_dir"))
print(config.get("cache_commit_interval"))
```

<Warning>
Change `cache_dir` before the first call to `tif1.get_cache()` or `tif1.get_session()`. The SQLite `Cache` reads the directory once when it is created.
</Warning>

### The `.tif1rc` file

`.tif1rc` is a JSON object. `tif1` reads `~/.tif1rc` by default. A `.tif1rc` in the current directory is read only when `TIF1_TRUST_CWD_CONFIG=true`. `TIF1_CONFIG_FILE` points at an explicit file instead. Environment variables override file values.

```json
{
  "cache_dir": "/data/tif1-cache",
  "cache_commit_interval": 200,
  "missing_payloads_ttl_days": 14
}
```

## Managing the cache from Python

### The SQLite cache object

`tif1.get_cache()` returns the process-wide `tif1.cache.Cache` instance.

```python
import tif1

cache = tif1.get_cache()
print(cache.cache_dir)
print(cache.db_path)

# has_session_data() accepts the readable or the URL-encoded event and session names
session = tif1.get_session(2024, "Monaco", "Race")
session.load(laps=True, telemetry=False)
print(cache.has_session_data(session.year, session.gp, session.session))  # True
```

| Method | Purpose |
|--------|---------|
| `get(key)` / `set(key, data)` / `set_raw(key, blob)` | JSON tier by string key |
| `get_async(key)` / `set_async(key, data)` | Async wrappers over `get` and `set` |
| `get_telemetry(year, gp, session, driver, lap)` / `set_telemetry(...)` | Telemetry tier; `_async` variants exist |
| `get_telemetry_batch(year, gp, session, driver_laps)` | Batch read of telemetry payloads; `_async` variant exists |
| `get_telemetry_frames_batch(..., lib=)` / `set_telemetry_frames_batch(..., lib=)` | Telemetry frame tier for `"pandas"` or `"polars"` |
| `get_laps_frame(year, gp, session, lib=)` / `set_laps_frame(year, gp, session, frame, lib=)` | Laps frame tier for `"pandas"` or `"polars"` |
| `get_entry(kind, key)` / `set_entry(kind, key, value)` | Kind-based interface; `kind` is `"json"` or `"telemetry"` |
| `invalidate(scope)` | Drop one tier group (see below) |
| `is_known_missing(key)` / `record_missing(key)` / `discard_missing(key)` | Negative-verdict tier |
| `has_session_data(year, gp, session)` | True when any payload for the session is cached; `gp` and `session` can be readable or URL-encoded |
| `clear()` | Delete every row and empty every memory tier |
| `close()` | Flush pending writes and close the connection |

### Invalidation scopes

```python
import tif1

cache = tif1.get_cache()
cache.invalidate("memory")     # empty the LRU tiers, keep SQLite
cache.invalidate("json")       # drop the cache table, both laps frame tables and the JSON memory tiers
cache.invalidate("telemetry")  # drop telemetry_cache, all four frame tables and the telemetry memory tiers
cache.invalidate("all")        # same as cache.clear()
```

Every scope except `"memory"` also deletes the negative verdicts. Both laps frame tables go with either payload scope because the laps table is derived from payloads of both tiers. Each scope first joins a pending frame writer, so a background write cannot re-insert rows after the wipe.

### The FastF1-compatible `tif1.Cache`

`tif1.Cache` is not the SQLite class. It is the FastF1-compatible facade from `src/tif1/fastf1_compat.py` and exposes class methods only:

| Class method | Effect |
|--------------|--------|
| `enable_cache(cache_dir=None, ignore_version=True, force_renew=False, use_requests_cache=True)` | Set `cache_dir`, set `enable_cache=True`, rebuild the global cache; `force_renew` clears it; the other two flags are accepted for FastF1 compatibility and ignored |
| `clear_cache(cache_dir=None, deep=False)` | Clear the active cache or the one in `cache_dir`; `deep` removes legacy FastF1 HTTP cache files |
| `disabled()` | Context manager that disables caching inside the block |
| `set_disabled()` / `set_enabled()` | Nested disable and restore of `enable_cache` |
| `offline_mode(enabled)` | Set the `offline_mode` config key |
| `ci_mode(enabled)` | Set the `ci_mode` config key |
| `get_cache_info()` | `(directory, size_in_bytes)` for the directory set by `enable_cache` |

```python
import tif1

tif1.Cache.enable_cache("./tif1-cache")

with tif1.Cache.disabled():
    session = tif1.get_session(2024, "Monaco", "Race")
    session.load(laps=True, telemetry=False)
```

The methods delegate to `tif1.get_config()` and `tif1.get_cache()`. Code that already targets FastF1 can keep its cache calls unchanged.

### Command line

```bash
tif1 cache-info          # directory, file count and total size of the cache.sqlite* files
tif1 cache-clear --yes   # Cache.clear() without the confirmation prompt
```

## Disabling the cache

Pass `enable_cache=False` to `get_session()` to bypass every persistent tier for one session. Nothing is written for that session.

```python
import tif1

session = tif1.get_session(2024, "Monaco", "Race", enable_cache=False)
session.load(laps=True, telemetry=False)
```

Set `TIF1_ENABLE_CACHE=false` or `tif1.get_config().set("enable_cache", False)` to change the default for every new session.

`offline_mode=True` keeps cache reads enabled and skips the network for payload fetches. A miss raises `NetworkError`. `ci_mode=True` skips persistent cache reads and writes for payload fetches.

<Warning>
The first access that needs two or more of `drivers.json`, `weather.json`, and `rcm.json` prefetches them in one batch, for example `session.load()`. That batch does not check `offline_mode` or `ci_mode`, so it can still use the network and write to the cache. The laps frame tier also ignores `ci_mode`.
</Warning>

## Behaviour notes

<AccordionGroup>
  <Accordion title="Concurrency model">
    One `sqlite3` connection is opened with `check_same_thread=False` and guarded by `Cache._sqlite_lock`. Writes are batched and committed every `cache_commit_interval` operations (default 100) and again on `close()`. The connection sets `journal_mode=WAL`, `synchronous=NORMAL`, and `cache_size=-64000` (a 64 MB page cache). Memory-tier reads do not take a lock.
  </Accordion>
  <Accordion title="Cold sessions skip cache reads">
    On first use, a session probes `has_session_data()`. A session with no cached rows skips cache reads for the rest of its life. It still writes everything it fetches. The next `Session` object for the same event finds a warm cache.
  </Accordion>
  <Accordion title="close() is final">
    `close()` flushes pending writes, closes the connection, and sets `conn` to `None`. The object does not reconnect. Later `get` calls return `None` and later `set` calls do nothing. The atexit handler closes the global cache and resets `get_cache()`, so a later `get_cache()` call creates a new instance.
  </Accordion>
  <Accordion title="Corrupt rows become misses">
    A row that fails to decompress, parse, or unpickle is logged and treated as a miss. The row is not deleted. The next successful write for the same key replaces it.
  </Accordion>
  <Accordion title="No TTL on positive entries">
    Payload rows, frame rows, and memory entries never expire. Only the negative-verdict tier (`missing_payloads_ttl_days`) and the live schedule row (`schedule_ttl_hours`) are TTL-scoped. Use `invalidate()` or `clear()` to remove data.
  </Accordion>
  <Accordion title="Directory permissions">
    The cache directory is forced to mode `0o700`. Keep the directory private: the frame tier unpickles blobs from it and trusts their origin.
  </Accordion>
  <Accordion title="Python 3.14 and 3.15 codecs">
    Python 3.14 and later compress payload rows with the standard-library `compression.zstd` module. Python 3.15 has no `lz4` wheels yet, so frame rows are zstd-1 there. Payload rows read under every binding, so one cache directory can be shared between interpreter versions. Frame rows are the exception. An interpreter without `lz4` treats lz4 rows from another interpreter as misses. It then rebuilds the frames from the payload tier.
  </Accordion>
</AccordionGroup>
