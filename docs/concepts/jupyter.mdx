`tif1` provides small HTML cards for its core objects in Jupyter Notebooks, JupyterLab, and other environments that run a Jupyter kernel. The cards show the context of an object without repeated print statements.

## Overview

The integration lives in the `tif1.jupyter` module. `import tif1` alone does not load it. When `tif1.jupyter` is imported inside a Jupyter kernel, it attaches an HTML representation to `Session`, `Driver`, and `Lap`. Any import counts, for example `import tif1.jupyter` or `from tif1.jupyter import display_dataframe_summary`. A cell that then evaluates one of these objects shows a short HTML table instead of the plain text representation.

### Key Benefits

- **One import**: `import tif1.jupyter` in a notebook turns the cards on
- **Kernel detection**: `tif1` checks for a Jupyter kernel (`IPKernelApp`). Plain Python and terminal IPython skip the setup
- **Light footprint**: The HTML is a few lines of inline CSS and does not slow data processing
- **Backend independent**: The cards and the DataFrame summary work with pandas and polars sessions

## Rich HTML Displays

`enable_jupyter_display()` attaches a `_repr_html_()` method to `Session`, `Driver`, and `Lap`. IPython uses this protocol to render HTML output. Importing `tif1.jupyter` in a Jupyter kernel calls `enable_jupyter_display()` once.

### Session Display

When a cell displays a `Session` object, `tif1` renders a table with these rows:

- **Year**: The season year of the session
- **Grand Prix**: The readable event name, for example `Monaco Grand Prix`
- **Session**: The session name, for example `Race` or `Practice 1`
- **Library**: The backend in use (`pandas` or `polars`)
- **Drivers**: The number of drivers, or `Not loaded` before the driver list loads

```python
import tif1
import tif1.jupyter  # turns on the HTML cards in a Jupyter kernel

# Load a race session
session = tif1.get_session(2025, "Monaco Grand Prix", "Race")

# Evaluate the session object to see the card
session
```


The session card shows the identity of the session and its backend without inspection of each attribute.

<Tip>
  The card is built each time the object is displayed. After `session.load()`, the **Drivers** row shows the number of drivers instead of `Not loaded`.
</Tip>

### Driver Display

The `Driver` card shows these rows:

- **Driver**: The three-letter driver code (such as VER, HAM, LEC), in the card title
- **Session**: The year, event name, and session name
- **Laps loaded**: `Yes` when the laps of the driver are in memory, otherwise `No`

For the full name, team, and car number, read the fields of the `Driver` object: `driver["FullName"]`, `driver["TeamName"]`, and `driver["DriverNumber"]`.

```python
# Get a specific driver from the session
verstappen = session.get_driver("VER")

# Display rich driver information
verstappen
```

This display is useful for work with multiple drivers. It shows which drivers have their laps loaded.

```python
# Compare multiple drivers side by side
hamilton = session.get_driver("HAM")
leclerc = session.get_driver("LEC")

# Display all three drivers in sequence
display(verstappen, hamilton, leclerc)
```


### Lap Display

The card of a `Lap` object shows these rows:

- **Lap**: The lap number, in the card title
- **Driver**: The three-letter code of the driver who completed the lap
- **Session**: The year, event name, and session name
- **Telemetry loaded**: `Yes` when the telemetry of the lap is in memory, otherwise `No`

The lap time, sector times, and compound are fields of the `Lap` object, for example `lap["LapTime"]` and `lap["Compound"]`.

```python
# Get the fastest lap of a driver as a Lap object
fastest_lap = verstappen.laps.pick_fastest()

# Display the lap card
fastest_lap
```

`Driver.get_fastest_lap()` returns a one-row DataFrame, so a notebook shows it as a table, not as a lap card. Use `driver.laps.pick_fastest()` or `driver.get_lap(n)` to get a `Lap` object.

The lap card helps to keep track of the laps under analysis, for example in a comparison of qualifying laps.

```python
# Compare multiple laps
lap_10 = verstappen.get_lap(10)
lap_20 = verstappen.get_lap(20)
lap_30 = verstappen.get_lap(30)

# Display lap progression
display(lap_10, lap_20, lap_30)
```

## DataFrame Summaries

Beyond object displays, `tif1` provides a utility function that summarizes the size of a DataFrame. This function is useful with large datasets that contain thousands of laps or telemetry points.

### The `display_dataframe_summary()` Function

This function returns an HTML string with one line:

- **Shape**: Number of rows and columns
- **Memory**: The memory size of the DataFrame in MB

The function returns the HTML; it does not display it. Wrap the result in `IPython.display.HTML` to render it:

```python
import tif1
from IPython.display import HTML, display
from tif1.jupyter import display_dataframe_summary

# Load session with lap data
session = tif1.get_session(2024, "Bahrain Grand Prix", "Race")
session.load(laps=True, telemetry=False)

# Display a summary of the laps DataFrame
display(HTML(display_dataframe_summary(session.laps)))
# DataFrame Summary: 1,129 rows × 46 columns | Memory: 0.44 MB
```

<Info>
  The `display_dataframe_summary()` function accepts pandas and polars DataFrames. On polars, the memory figure comes from `estimated_size()`.
</Info>

### Comparing DataFrames

Use this function to compare the size of different DataFrames:

```python
# Compare lap data vs telemetry data
verstappen = session.get_driver("VER")
display(HTML(display_dataframe_summary(session.laps)))
display(HTML(display_dataframe_summary(verstappen.get_fastest_lap_tel())))
```

This comparison is useful for optimizing memory usage and for understanding the scale of the data.

## Advanced Usage

### Manual Display Control

Importing `tif1.jupyter` in a Jupyter kernel enables the cards once. Manual control of this behavior is available.

#### Enabling Displays

Call `enable_jupyter_display()` to attach the cards again, for example after a reload of `tif1`. The function does nothing outside a Jupyter kernel and logs `Not in Jupyter environment, skipping display setup` at `INFO` level:

```python
from tif1.jupyter import enable_jupyter_display

# Manually activate rich HTML displays
enable_jupyter_display()
```

This function attaches the `_repr_html_()` methods to `Session`, `Driver`, and `Lap`.

#### Plain Text Output

`tif1.jupyter` has no function that turns the cards off. To see the plain text representation of one object, use `print(obj)` or `repr(obj)`.

### Custom Display Functions

For custom visualizations, `tif1.jupyter` exposes the functions that build the HTML. Each one returns an HTML string:

```python
from IPython.display import HTML, display
from tif1.jupyter import display_driver_info, display_lap_info, display_session_info

# Generate HTML strings for custom rendering
session_html = display_session_info(session)
driver_html = display_driver_info(verstappen)
lap_html = display_lap_info(verstappen.get_lap(10))

# Use these in custom widgets or dashboards
display(HTML(session_html))
```

## Visual Themes and Styling

The HTML cards from `tif1` use inline CSS only, so they look the same in every notebook front end.

### Colors

The colors are fixed. The notebook theme does not change them:

- **Backgrounds**: Each card type has a light background (gray for sessions, blue for drivers, yellow for laps)
- **Borders**: A light gray border with rounded corners; the DataFrame summary has a green left border
- **Text**: The cards do not set a text color, so the notebook theme sets it

<Warning>
  In a dark notebook theme, light theme text on the light card background can be hard to read. Use a light theme, or read the same values from the object fields.
</Warning>

### Layout

Each card is a plain HTML table with `width: 100%`, so it follows the width of the output area.

## Performance Considerations

The Jupyter integration is lightweight. Rich displays do not slow down the data analysis workflow.

### Lazy Rendering

HTML representations are generated on-demand only when an object is displayed. This means:

- **No overhead for non-displayed objects**: Creating thousands of `Lap` objects does not trigger HTML generation
- **Fast cell execution**: Displaying an object adds negligible time to cell execution
- **Memory efficient**: HTML strings are not stored; they are generated fresh each time

### Large DataFrames

`display_dataframe_summary()` reads only the shape and the memory size of a frame that is already in memory. On pandas, `memory_usage(deep=True)` scans the text columns, so it takes longer on frames with millions of rows. On polars, `estimated_size()` is fast.

```python
# One telemetry frame with the fastest lap of every driver
fastest_tels = session.get_fastest_laps_tels()
display(HTML(display_dataframe_summary(fastest_tels)))
```

### Optimization Tips

For maximum performance with large datasets:

1. **Load only the necessary data**: Use selective loading with `session.load(laps=True, telemetry=False)`
2. **Filter early**: Apply DataFrame filters before displaying to reduce rendering time
3. **Use Polars backend**: For very large datasets, Polars provides faster operations
4. **Batch displays**: When comparing many objects, use `display()` with multiple arguments rather than evaluating each separately

## Integration with Other Tools

### Pandas Styling

`tif1` DataFrames are standard Pandas or Polars objects, so they work with other visualization tools:

```python
# Use pandas styling on tif1 DataFrames (Styler needs jinja2: pip install jinja2).
# LapTime is a timedelta; color scales need the float LapTimeSeconds column
session.laps.head(10).style.background_gradient(subset=["LapTimeSeconds"])

# Highlight fastest laps
session.laps.style.highlight_min(subset=["LapTimeSeconds"], color="lightgreen")

# Custom formatting for lap times
session.laps.style.format({"LapTimeSeconds": "{:.3f}s"})
```

### Plotly and Matplotlib

Rich displays work alongside plotting libraries and combine data inspection with visualization:

```python
import matplotlib.pyplot as plt

# Display session info
display(session)

# Then plot lap times (LapTimeSeconds is float; LapTime is a timedelta)
plt.figure(figsize=(12, 6))
plt.plot(verstappen.laps["LapNumber"], verstappen.laps["LapTimeSeconds"])
plt.title("Verstappen Lap Times")
plt.xlabel("Lap Number")
plt.ylabel("Lap Time (s)")
plt.show()
```

### IPyWidgets

Create interactive dashboards combining `tif1` displays with widgets:

```python
from IPython.display import HTML, display
from ipywidgets import Dropdown, interact
from tif1.jupyter import display_dataframe_summary

def show_driver(driver_code):
    driver = session.get_driver(driver_code)
    display(driver)
    display(HTML(display_dataframe_summary(driver.laps)))

    # Show fastest lap
    fastest = driver.laps.pick_fastest()
    display(fastest)

# Driver codes in classification order
driver_codes = session.drivers_df["Driver"].tolist()
interact(show_driver, driver_code=Dropdown(options=driver_codes))
```

### Voilà Dashboards

The rich displays from `tif1` work in Voilà dashboards and support shareable F1 data applications:

```python
# In a notebook that becomes a Voilà dashboard
import tif1
import tif1.jupyter
from IPython.display import display
from ipywidgets import Dropdown, IntSlider, interact
from tif1.exceptions import LapNotFoundError

session = tif1.get_session(2024, "Monaco Grand Prix", "Race")
session.load(laps=True, telemetry=False)

@interact(
    driver=Dropdown(options=session.drivers_df["Driver"].tolist()),
    # LapNumber is float64 on pandas; IntSlider needs an int
    lap_number=IntSlider(min=1, max=int(session.laps["LapNumber"].max()), value=1),
)
def explore_lap(driver, lap_number):
    driver_obj = session.get_driver(driver)
    try:
        display(driver_obj.get_lap(lap_number))
    except LapNotFoundError:
        print(f"{driver} has no lap {lap_number}")
```

## Supported Environments

The Jupyter integration needs a Jupyter kernel (`IPKernelApp`). These environments run one:

### Jupyter Notebook (Classic)

The original Jupyter Notebook interface supports all `tif1` rich displays. Install Jupyter and start a notebook:

```bash
pip install jupyter
jupyter notebook
```

### JupyterLab

JupyterLab is the newer interface. It provides better layout and theming support:

```bash
pip install jupyterlab
jupyter lab
```

### VS Code Notebooks

The built-in notebook support in Visual Studio Code works with `tif1`. Open an `.ipynb` file in VS Code, and the rich displays render automatically.

### Google Colab

Google Colaboratory supports the Jupyter integration of `tif1`. Install `tif1` in a Colab cell:

```python
!pip install tif1
import tif1
```

### Kaggle Notebooks

The Kaggle notebook environment supports all `tif1` features. It enables easy sharing of F1 data analysis with the community.

### Databricks Notebooks

For enterprise users, `tif1` works in Databricks notebooks. Databricks notebooks combine F1 data with big data processing capabilities.

### IPython Terminal

Terminal IPython does not run a Jupyter kernel. `tif1` skips the setup there, and objects show their plain text representation.

## Troubleshooting

### Displays Not Showing

If rich HTML displays do not appear:

1. **Verify IPython environment**: Run `get_ipython()` in a cell. If it raises an error, no IPython environment is active.

2. **Check the import**: `import tif1` does not load the integration. Run `import tif1.jupyter` in the notebook.

3. **Restart kernel**: Sometimes a kernel restart resolves display issues. Go to Kernel → Restart.

4. **Manual enable**: Enable the displays explicitly:
   ```python
   from tif1.jupyter import enable_jupyter_display
   enable_jupyter_display()
   ```

### Plain Text Instead of HTML

If plain text representations appear instead of rich HTML:

- **Terminal IPython**: The cards need a Jupyter kernel. Terminal IPython shows plain text.
- **Output capture**: When output is captured with `%%capture`, HTML does not render. Remove the magic command.
- **Print statements**: Using `print(session)` bypasses HTML rendering. Evaluate `session` directly instead.

### Styling Issues

If displays look broken or poorly formatted:

- **Browser compatibility**: Use a modern browser (Chrome, Firefox, Safari, Edge)
- **Custom CSS**: Check whether custom notebook CSS interferes with the `tif1` styles
- **Dark themes**: The card backgrounds are always light; switch to a light theme for better contrast

### Performance Issues

If displays are slow to render:

- **Large DataFrames**: Use `display_dataframe_summary()` instead of displaying the entire DataFrame
- **Many objects**: Avoid displaying hundreds of objects in a single cell
- **Memory constraints**: Close unused notebooks to free up browser memory

## Best Practices

### Efficient Data Exploration

When exploring F1 data in Jupyter, follow these patterns:

```python
import tif1
from IPython.display import HTML, display
from tif1.jupyter import display_dataframe_summary  # also turns on the cards

# 1. Load session and inspect metadata first
session = tif1.get_session(2024, "Monaco Grand Prix", "Race")
display(session)  # Quick overview without loading data

# 2. Load only the required data
session.load(laps=True, telemetry=False)

# 3. Check the size of the data
display(HTML(display_dataframe_summary(session.laps)))

# 4. Explore specific drivers
verstappen = session.get_driver("VER")
display(verstappen)  # Driver card

# 5. Analyze specific laps
fastest = verstappen.laps.pick_fastest()
display(fastest)  # Lap card
```

### Combining Displays with Analysis

Put displays between analysis steps to build a narrative:

```python
# Show session context
display(session)

# Analyze lap time distribution
import matplotlib.pyplot as plt
plt.hist(session.laps['LapTime'].dt.total_seconds(), bins=50)
plt.title('Lap Time Distribution')
plt.show()

# Focus on a specific driver
verstappen = session.get_driver("VER")
display(verstappen)

# Compare their fastest lap
fastest = verstappen.laps.pick_fastest()
display(fastest)
```

### Documentation and Sharing

When creating notebooks to share with others:

1. **Use displays for context**: Rich displays help readers understand the data in the notebook
2. **Add markdown explanations**: Combine displays with markdown cells that explain the analysis
3. **Show data summaries**: Use `display_dataframe_summary()` to show readers the size of the data
4. **Include driver/lap displays**: Show the drivers and laps under analysis to help readers follow the notebook

## Real-World Examples

### Example 1: Race Strategy Analysis

```python
import tif1
import tif1.jupyter
from IPython.display import display

# Load race session
session = tif1.get_session(2024, "Monaco Grand Prix", "Race")
session.load(laps=True, telemetry=False)

# Show session overview
display(session)

# Analyze three drivers
for driver_code in ["VER", "LEC", "HAM"]:
    driver = session.get_driver(driver_code)
    display(driver)

    # Show their fastest lap
    fastest = driver.laps.pick_fastest()
    display(fastest)

    # Analyze stint strategy
    stints = driver.laps.groupby("Stint")["LapNumber"].count()
    print(f"{driver_code} stint lengths: {stints.tolist()}")
```

### Example 2: Qualifying Comparison

```python
# Load qualifying session
quali = tif1.get_session(2024, "British Grand Prix", "Qualifying")
quali.load(laps=True, telemetry=False)

# Split the laps into Q1, Q2, and Q3 (QualifyingSession column)
q1, q2, q3 = quali.laps.split_qualifying_sessions()

# Compare Q3 performances
q3_drivers = ["VER", "NOR", "HAM", "LEC"]

for driver_code in q3_drivers:
    driver = quali.get_driver(driver_code)
    display(driver)

    # Get fastest Q3 lap
    q3_laps = q3[q3["Driver"] == driver_code].dropna(subset=["LapTime"])
    if not q3_laps.empty:
        fastest_idx = q3_laps["LapTime"].idxmin()
        fastest_lap = driver.get_lap(int(q3_laps.loc[fastest_idx, "LapNumber"]))
        display(fastest_lap)
```

### Example 3: Detailed Telemetry Analysis

```python
import tif1
from IPython.display import HTML, display
from tif1.jupyter import display_dataframe_summary

# Load session laps; telemetry is fetched per lap on demand
session = tif1.get_session(2024, "Belgian Grand Prix", "Race")
session.load(laps=True, telemetry=False)

# Focus on a specific driver
verstappen = session.get_driver("VER")
display(verstappen)

# Get their fastest lap
fastest = verstappen.laps.pick_fastest()
display(fastest)

# Show telemetry data summary
telemetry = fastest.get_telemetry()
display(HTML(display_dataframe_summary(telemetry)))

# Plot speed trace
import matplotlib.pyplot as plt
plt.figure(figsize=(14, 6))
plt.plot(telemetry["Distance"], telemetry["Speed"])
plt.title(f"{verstappen['Abbreviation']} - Fastest Lap Speed Trace")
plt.xlabel('Distance (m)')
plt.ylabel('Speed (km/h)')
plt.grid(True, alpha=0.3)
plt.show()
```

### Example 4: Interactive Driver Comparison

```python
import pandas as pd
from ipywidgets import Dropdown, IntSlider, interact
from tif1.exceptions import LapNotFoundError

# Load session
session = tif1.get_session(2024, "Italian Grand Prix", "Race")
session.load(laps=True, telemetry=False)

# Get available drivers (codes, in classification order)
drivers = session.drivers_df["Driver"].tolist()

@interact(
    driver1=Dropdown(options=drivers, description='Driver 1'),
    driver2=Dropdown(options=drivers, description='Driver 2'),
    lap_num=IntSlider(min=1, max=53, value=1, description='Lap')
)
def compare_laps(driver1, driver2, lap_num):
    # Show both drivers
    d1 = session.get_driver(driver1)
    d2 = session.get_driver(driver2)

    display(d1)
    display(d2)

    # Compare specific lap
    try:
        lap1 = d1.get_lap(lap_num)
        lap2 = d2.get_lap(lap_num)

        display(lap1)
        display(lap2)

        # Calculate time difference (LapTimeSeconds is NaN for a lap without a time)
        if pd.notna(lap1["LapTimeSeconds"]) and pd.notna(lap2["LapTimeSeconds"]):
            diff = lap1["LapTimeSeconds"] - lap2["LapTimeSeconds"]
            print(f"\nTime difference: {abs(diff):.3f}s ({driver1 if diff < 0 else driver2} faster)")
    except LapNotFoundError:
        print(f"Lap {lap_num} not available for one or both drivers")
```
