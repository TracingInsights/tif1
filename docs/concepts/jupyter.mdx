`tif1` provides rich HTML representations for its core objects in Jupyter Notebooks, JupyterLab, and other IPython-based environments. These displays remove the need for repeated print statements and manual data inspection during interactive exploration.

## Overview

The Jupyter integration detects an IPython environment automatically and enhances the display of key objects with formatted HTML tables. A cell that evaluates a `Session`, `Driver`, or `Lap` object shows an information-dense HTML table. The table replaces the plain text representation.

### Key Benefits

- **Zero Configuration**: Works without setup in Jupyter Notebooks, JupyterLab, Google Colab, and VS Code notebooks
- **Automatic Detection**: No manual setup is required; `tif1` detects the IPython environment automatically
- **Theme Adaptive**: Displays adapt to both light and dark notebook themes
- **Performance Optimized**: HTML rendering is lightweight and does not slow data processing
- **Backend Agnostic**: Works with both Pandas and Polars DataFrames

## Rich HTML Displays

The core objects in `tif1` implement the `_repr_html_()` protocol. IPython uses this protocol to render rich HTML output. The HTML output is more informative than the standard string representation.

### Session Display

When a cell displays a `Session` object, `tif1` renders a summary table that shows:

- **Year**: The season year of the session
- **Event Name**: The full name of the Grand Prix or testing event
- **Session Type**: The type of session (Practice 1, Practice 2, Practice 3, Qualifying, Sprint, Sprint Qualifying, or Race)
- **Data Library**: The backend in use (Pandas or Polars)
- **Drivers Count**: The number of drivers in the session (if lap data has been loaded)
- **Load Status**: Visual indicators showing which data components have been fetched

```python
import tif1

# Load a race session
session = tif1.get_session(2025, "Monaco Grand Prix", "Race")

# Simply evaluate the session object to see the rich display
session
```


The session display gives an overview of the available data. The overview shows the state of the session object without inspection of each individual attribute.

<Tip>
  The session display updates dynamically to show the loaded data. When a call to `session.load(laps=True, telemetry=True)` finishes, the display shows that lap and telemetry data are available.
</Tip>

### Driver Display

The `Driver` object display focuses on driver-specific information and data availability:

- **Driver Code**: The three-letter FIA driver code (such as VER, HAM, LEC)
- **Full Name**: The complete name of the driver (if available in the session data)
- **Team**: The constructor or team that the driver raced for
- **Car Number**: The permanent race number assigned to the driver
- **Lap Data Status**: Whether lap data has been fetched for this driver
- **Lap Count**: Total number of laps completed by the driver in the session

```python
# Get a specific driver from the session
verstappen = session.get_driver("VER")

# Display rich driver information
verstappen
```

This display is useful for work with multiple drivers. It shows which drivers have data loaded and gives the basic session statistics for each driver.

```python
# Compare multiple drivers side by side
hamilton = session.get_driver("HAM")
leclerc = session.get_driver("LEC")

# Display all three drivers in sequence
display(verstappen, hamilton, leclerc)
```


### Lap Display

Individual `Lap` objects provide detailed information about a specific lap, including:

- **Lap Number**: The sequential lap number in the session
- **Driver**: The three-letter code of the driver who completed the lap
- **Lap Time**: The total lap time (formatted as MM:SS.mmm)
- **Sector Times**: Individual sector times (S1, S2, S3)
- **Compound**: The tire compound used for the lap
- **Telemetry Status**: Whether high-frequency telemetry data is available for this lap
- **Track Status**: Any track condition flags (yellow flags, safety car, etc.)

```python
# Get a specific lap from a driver
fastest_lap = verstappen.get_fastest_lap()

# Display detailed lap information
fastest_lap
```

The lap display supports detailed analysis of specific laps, such as comparing qualifying laps or investigating race incidents.

```python
# Compare multiple laps
lap_10 = verstappen.get_lap(10)
lap_20 = verstappen.get_lap(20)
lap_30 = verstappen.get_lap(30)

# Display lap progression
display(lap_10, lap_20, lap_30)
```

## DataFrame Summaries

Beyond object displays, `tif1` provides a utility function that summarizes DataFrame contents. This function is useful with large datasets that contain thousands of laps or telemetry points.

### The `display_dataframe_summary()` Function

This function generates a concise summary showing:

- **Shape**: Number of rows and columns
- **Memory Usage**: Total memory consumed by the DataFrame
- **Backend**: Whether the DataFrame is Pandas or Polars
- **Column Names**: A preview of the available columns
- **Data Types**: The dtype of each column

```python
from tif1.jupyter import display_dataframe_summary

# Load session with lap data
session = tif1.get_session(2024, "Bahrain Grand Prix", "Race")
session.load(laps=True)

# Display a summary of the laps DataFrame
display_dataframe_summary(session.laps)
```

<Info>
  The `display_dataframe_summary()` function works identically with both **Pandas** and **Polars** backends. It detects the DataFrame type automatically and adjusts its output.
</Info>

### Comparing DataFrames

Use this function to compare the size and structure of different DataFrames:

```python
# Compare lap data vs telemetry data
display_dataframe_summary(session.laps)
display_dataframe_summary(verstappen.get_telemetry())
```

This comparison is useful for optimizing memory usage and for understanding the scale of the data.

## Advanced Usage

### Manual Display Control

`tif1` enables Jupyter displays automatically when it detects an IPython environment. Manual control of this behavior is available.

#### Enabling Displays

Automatic detection fails in rare cases, such as custom notebook environments and embedded IPython shells. Enable the display system manually in these cases:

```python
from tif1.jupyter import enable_jupyter_display

# Manually activate rich HTML displays
enable_jupyter_display()
```

This function registers the `_repr_html_()` methods for all `tif1` objects and ensures correct rendering in the environment.

#### Disabling Displays

Plain text representations are preferable for debugging or for terminal-based IPython sessions. Disable the HTML rendering in these cases:

```python
from tif1.jupyter import disable_jupyter_display

# Revert to plain text representations
disable_jupyter_display()
```

After a call to this function, `tif1` objects use their standard `__repr__()` methods instead of HTML rendering.

### Custom Display Functions

For custom visualizations, `tif1` exposes the underlying HTML generation functions:

```python
from tif1.jupyter import session_to_html, driver_to_html, lap_to_html

# Generate HTML strings for custom rendering
session_html = session_to_html(session)
driver_html = driver_to_html(verstappen)
lap_html = lap_to_html(fastest_lap)

# Use these in custom widgets or dashboards
from IPython.display import HTML
display(HTML(session_html))
```

## Visual Themes and Styling

The HTML components from `tif1` are theme-agnostic and visually consistent across notebook environments.

### Theme Adaptation

`tif1` uses CSS techniques to ensure displays are readable in both light and dark themes:

- **Semi-transparent backgrounds**: Backgrounds use `rgba()` colors that blend with the notebook theme
- **Adaptive borders**: Border colors adjust based on the surrounding theme
- **High contrast text**: Text colors are chosen to maintain readability in all themes
- **No hardcoded colors**: All colors are relative to the base theme of the notebook

- **Mobile devices**: Displays remain readable on tablets and phones

## Performance Considerations

The Jupyter integration is lightweight. Rich displays do not slow down the data analysis workflow.

### Lazy Rendering

HTML representations are generated on-demand only when an object is displayed. This means:

- **No overhead for non-displayed objects**: Creating thousands of `Lap` objects does not trigger HTML generation
- **Fast cell execution**: Displaying an object adds negligible time to cell execution
- **Memory efficient**: HTML strings are not stored; they are generated fresh each time

### Large DataFrames

When working with large DataFrames, `display_dataframe_summary()` only inspects metadata (shape, dtypes, memory usage) without loading the entire dataset into memory. This makes it safe to use even with multi-gigabyte DataFrames.

```python
# Safe even with millions of rows
huge_telemetry = session.get_telemetry()  # Could be 10+ million rows
display_dataframe_summary(huge_telemetry)  # Instant, no memory spike
```

### Optimization Tips

For maximum performance with large datasets:

1. **Load only the necessary data**: Use selective loading with `session.load(laps=True, telemetry=False)`
2. **Filter early**: Apply DataFrame filters before displaying to reduce rendering time
3. **Use Polars backend**: For very large datasets, Polars provides faster operations
4. **Batch displays**: When comparing many objects, use `display()` with multiple arguments rather than evaluating each separately

## Integration with Other Tools

### Pandas Styling

`tif1` DataFrames are standard Pandas or Polars objects, so they work with other visualization tools:

```python
# Use Pandas styling on tif1 DataFrames
session.laps.head(10).style.background_gradient(subset=['LapTime'])

# Highlight fastest laps
session.laps.style.highlight_min(subset=['LapTime'], color='lightgreen')

# Custom formatting for lap times
session.laps.style.format({'LapTime': lambda x: f"{x.total_seconds():.3f}s"})
```

### Plotly and Matplotlib

Rich displays work alongside plotting libraries and combine data inspection with visualization:

```python
import matplotlib.pyplot as plt

# Display session info
display(session)

# Then plot lap times
plt.figure(figsize=(12, 6))
plt.plot(verstappen.laps['LapNumber'], verstappen.laps['LapTime'])
plt.title('Verstappen Lap Times')
plt.xlabel('Lap Number')
plt.ylabel('Lap Time')
plt.show()
```

### IPyWidgets

Create interactive dashboards combining `tif1` displays with widgets:

```python
from ipywidgets import interact, Dropdown

def show_driver(driver_code):
    driver = session.get_driver(driver_code)
    display(driver)
    display_dataframe_summary(driver.laps)

    # Show fastest lap
    fastest = driver.get_fastest_lap()
    display(fastest)

# Get all driver codes from session
driver_codes = session.laps['Driver'].unique().tolist()
interact(show_driver, driver_code=Dropdown(options=driver_codes))
```

### Voilà Dashboards

The rich displays from `tif1` work in Voilà dashboards and support shareable F1 data applications:

```python
# In a notebook that will be converted to a Voilà dashboard
import tif1
from ipywidgets import interact, IntSlider, Dropdown

session = tif1.get_session(2024, "Monaco Grand Prix", "Race")
session.load(laps=True)

@interact(
    driver=Dropdown(options=session.laps['Driver'].unique().tolist()),
    lap_number=IntSlider(min=1, max=session.laps['LapNumber'].max(), value=1)
)
def explore_lap(driver, lap_number):
    driver_obj = session.get_driver(driver)
    lap = driver_obj.get_lap(lap_number)
    display(lap)
```

## Troubleshooting

### Displays Not Showing

If rich HTML displays do not appear:

1. **Verify IPython environment**: Run `get_ipython()` in a cell. If it raises an error, no IPython environment is active.

2. **Check for manual disable**: Check for an earlier call to `disable_jupyter_display()` in the same session.

3. **Restart kernel**: Sometimes a kernel restart resolves display issues. Go to Kernel → Restart.

4. **Manual enable**: Enable the displays explicitly:
   ```python
   from tif1.jupyter import enable_jupyter_display
   enable_jupyter_display()
   ```

### Plain Text Instead of HTML

If plain text representations appear instead of rich HTML:

- **Terminal IPython**: Rich displays require a browser-based environment. Terminal IPython shows plain text.
- **Output capture**: When output is captured with `%%capture`, HTML does not render. Remove the magic command.
- **Print statements**: Using `print(session)` bypasses HTML rendering. Evaluate `session` directly instead.

### Styling Issues

If displays look broken or poorly formatted:

- **Browser compatibility**: Use a modern browser (Chrome, Firefox, Safari, Edge)
- **Custom CSS**: Check whether custom notebook CSS interferes with the `tif1` styles
- **Theme conflicts**: Switch between light and dark themes, and use the theme that works better

### Performance Issues

If displays are slow to render:

- **Large DataFrames**: Use `display_dataframe_summary()` instead of displaying the entire DataFrame
- **Many objects**: Avoid displaying hundreds of objects in a single cell
- **Memory constraints**: Close unused notebooks to free up browser memory

## Best Practices

### Efficient Data Exploration

When exploring F1 data in Jupyter, follow these patterns:

```python
# 1. Load session and inspect metadata first
session = tif1.get_session(2024, "Monaco Grand Prix", "Race")
session  # Quick overview without loading data

# 2. Load only what you need
session.load(laps=True, telemetry=False)

# 3. Check data availability
display_dataframe_summary(session.laps)

# 4. Explore specific drivers
verstappen = session.get_driver("VER")
verstappen  # See driver info and lap count

# 5. Analyze specific laps
fastest = verstappen.get_fastest_lap()
fastest  # Detailed lap information
```

### Combining Displays with Analysis

Put displays between analysis steps to build a narrative:

```python
# Show session context
display(session)

# Analyze lap time distribution
import matplotlib.pyplot as plt
plt.hist(session.laps['LapTime'].dt.total_seconds(), bins=50)
plt.title('Lap Time Distribution')
plt.show()

# Focus on a specific driver
verstappen = session.get_driver("VER")
display(verstappen)

# Compare their fastest lap
fastest = verstappen.get_fastest_lap()
display(fastest)
```

### Documentation and Sharing

When creating notebooks to share with others:

1. **Use displays for context**: Rich displays help readers understand the data in the notebook
2. **Add markdown explanations**: Combine displays with markdown cells that explain the analysis
3. **Show data summaries**: Use `display_dataframe_summary()` to show readers the size of the data
4. **Include driver/lap displays**: Show the drivers and laps under analysis to help readers follow the notebook

## Real-World Examples

### Example 1: Race Strategy Analysis

```python
import tif1
from tif1.jupyter import display_dataframe_summary

# Load race session
session = tif1.get_session(2024, "Monaco Grand Prix", "Race")
session.load(laps=True)

# Show session overview
display(session)

# Analyze top 3 drivers
for driver_code in ['VER', 'LEC', 'HAM']:
    driver = session.get_driver(driver_code)
    display(driver)

    # Show their fastest lap
    fastest = driver.get_fastest_lap()
    display(fastest)

    # Analyze stint strategy
    stints = driver.laps.groupby('Stint')['LapNumber'].count()
    print(f"{driver_code} stint lengths: {stints.tolist()}")
```

### Example 2: Qualifying Comparison

```python
# Load qualifying session
quali = tif1.get_session(2024, "Silverstone Grand Prix", "Qualifying")
quali.load(laps=True)

# Compare Q3 performances
q3_drivers = ['VER', 'NOR', 'HAM', 'LEC']

for driver_code in q3_drivers:
    driver = quali.get_driver(driver_code)
    display(driver)

    # Get fastest Q3 lap
    q3_laps = driver.laps[driver.laps['Segment'] == 'Q3']
    if not q3_laps.empty:
        fastest_idx = q3_laps['LapTime'].idxmin()
        fastest_lap = driver.get_lap(q3_laps.loc[fastest_idx, 'LapNumber'])
        display(fastest_lap)
```

### Example 3: Detailed Telemetry Analysis

```python
# Load session with telemetry
session = tif1.get_session(2024, "Spa Grand Prix", "Race")
session.load(laps=True, telemetry=True)
```

### Example 4: Interactive Driver Comparison

```python
from ipywidgets import interact, Dropdown, IntSlider

# Load session
session = tif1.get_session(2024, "Monza Grand Prix", "Race")
session.load(laps=True)

# Get available drivers
drivers = session.laps['Driver'].unique().tolist()

@interact(
    driver1=Dropdown(options=drivers, description='Driver 1'),
    driver2=Dropdown(options=drivers, description='Driver 2'),
    lap_num=IntSlider(min=1, max=53, value=1, description='Lap')
)
def compare_laps(driver1, driver2, lap_num):
    # Show both drivers
    d1 = session.get_driver(driver1)
    d2 = session.get_driver(driver2)

    display(d1)
    display(d2)

    # Compare specific lap
    try:
        lap1 = d1.get_lap(lap_num)
        lap2 = d2.get_lap(lap_num)

        display(lap1)
        display(lap2)

        # Calculate time difference
        if lap1.lap_time and lap2.lap_time:
            diff = (lap1.lap_time - lap2.lap_time).total_seconds()
            print(f"\nTime difference: {abs(diff):.3f}s ({driver1 if diff < 0 else driver2} faster)")
    except Exception as e:
        print(f"Lap {lap_num} not available for one or both drivers")
```
