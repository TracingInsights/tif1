# E6. Polars telemetry reads without numpy, and a faster pyarrow-free IPC read

Branch `perf/elis-E6`, control `/tmp/tif1-elis-control` (b5b91ed). The box was
shared with the other Elis agents the whole time, so read ratios and pairs won.

## 1. Hypothesis

After Delphi D10 a polars process imports numpy on its first telemetry read
(~55 ms; `driver_tel` 44 -> 139 ms, `fastest_lap_tel` 12 -> 83, `quali_split`
2 -> 105). The numpy uses on those paths are masks, small gathers and
per-lap typed channels. polars' eager Series kernels (comparisons, `&`/`|`,
`not_`, `filter`, slices, `Series[Series]`) do not build a query plan. If they
are within 2x of the numpy masks, the common reads can skip numpy completely.
Separately, polars 2 reads the tier's IPC rows with `pl.read_ipc`, which is
`scan_ipc().collect()` (one plan per row) and copies the buffers. An eager
reader may be faster.

## 2. What changed

**(1) Numpy-free reads** (`models_polars.py`, `core.py`, `core_utils/helpers.py`,
`core_utils/json_utils.py`, `core_utils/session_state.py`, `cache.py`):

- `_filter_rows` takes a numpy mask or a Boolean Series. Nulls drop their
  rows. A Series mask is rechunked to one chunk, as the numpy-built masks
  were. Filtering the ~60-chunk joined-lap columns with a mask chunked
  differently was 10x slower (40 ms vs 4 ms for `driver_merged_x4`).
  `pick_driver` passes its comparison Series directly.
- `_join_lap_frames`: a new `_join_one_driver_laps` handles the common shape
  with Series kernels only: one driver, no null lap numbers or clocks, the
  clock already sorted. It finds the boundary duplicates by comparing two
  offset slices, so no shifted copy is built. Every other shape returns
  `None` and runs the numpy path unchanged. The `Time` rebasing moved into
  `_rebase_lap_time`/`_time_from_origin`, shared by both paths.
- `split_qualifying_sessions` builds its segment masks from Python lists
  (~300 laps; exact int/None comparisons). The `QualifyingSession`-column
  branch builds a Boolean Series.
- `core._fastest_laps_polars` works on the columns' `to_list()` values
  (~1,100 rows). The seconds are `float(ns) / 1e9`, the same IEEE result as
  the numpy cast. Rows are gathered column by column with `Series[Series]`.
  The old `DataFrame[ndarray]` gather also started polars' thread pool
  (~6 ms the first time in a process).
- `Session._lap_start_lookup` returns lists. On polars it uses a
  Series comparison and `filter`, plus a new `_polars_ns_list`. Without loaded
  laps it reads the laptime payload through the new
  `session_state._timedelta_ns_list` and `_datetime_ns_list` list twins, which
  return `None` for any value shape outside the payload's own, so the array
  helpers decide those. `_attach_session_clock` converts the lists back with
  `np.asarray` itself.
- Lone-lap payloads: the new `json_utils.decode_one_telemetry_payload` uses
  orjson while numpy is not in `sys.modules`. The native decoder returns
  numpy arrays, so its first call imports numpy for a ~0.5 ms decode. Only
  `Cache._get_telemetry` (one lap) uses it. Batch decodes keep the native
  decoder. pandas processes always have numpy loaded, so they keep the native
  path.
- `helpers._polars_list_telemetry_frame` and `_polars_list_channel` build the
  typed polars frame from orjson lists without numpy. They cover all-int,
  int/float, `"None"`-token and all-null numeric channels, Brake as bool/int,
  `DriverAhead` strings, `Time` as `round(seconds * 1e9)` (numpy's
  round-half-even), and `SessionTime`/`Date` from the clock. Anything else
  returns `_UNHANDLED`, and the existing numpy builder answers exactly as
  before. Inputs that return `_UNHANDLED`: bools or `None` in a numeric
  channel, ints beyond int64, float gears, non-finite or huge times, unknown
  channels, ragged lengths.
- `helpers._telemetry_channel_types()` returns `(list, DictionaryChannel)`
  without memoizing it until numpy is imported. No ndarray can exist before
  then. `_channel_list` follows.

**(2) IPC read** (`cache.py`): the new `_read_polars_ipc_row` calls the
extension's eager `PyDataFrame.read_ipc_stream` on the row bytes after the
8-byte `ARROW1` file magic. An IPC file written by pyarrow (every tier row,
`_write_polars_ipc`) is that magic, then a valid IPC stream, then the footer.
The result is the same frame: dtypes, categoricals, one chunk per column.
Any row the stream reader rejects goes through `pl.read_ipc`, which decides.
That covers polars' own file layout (polars-written files are *not* readable
this way), corrupt rows, non-files, and a polars build without the private
reader. The stream reader is used only for the serial tier read (1-3
drivers). In the pooled read it lost: it holds the GIL while decoding and
stalls the SQLite cursor loop that feeds the pool. The pyarrow reader is
still used when pyarrow is resident, as in D3.

Tests: `tests/unit/test_elis_e6_numpy_free_polars.py` (78 cases). It covers:

- the stream reader against `pl.read_ipc`, the fallback paths, and a
  truncated row
- the lone decode with numpy hidden
- the list builder against the numpy typed builder, on every branch and
  3 clock variants, plus 15 `_UNHANDLED` inputs
- the list builder against a native-decoded `_create_telemetry_df`
- the lap-clock list twins against the array helpers, and their deferrals
- `_filter_rows` Series masks (nulls, chunking)
- `_join_one_driver_laps` against the numpy path, with the fast path
  patched out
- `_fastest_laps_polars` against the pre-E6 numpy implementation (ties,
  null times, a null `Deleted`, driver filters)
- a session-status qualifying split with a red flag, a null start and an
  early out-lap

`tests/unit/test_polars_without_pandas.py` (numpy mode) now asserts that
`get_fastest_lap_tel()`, `pick_driver("VER").telemetry` and each lap's
`get_car_data()` leave numpy unloaded, and checks their heights, `Time`
values and schema. `AGENTS.md` describes the numpy-free paths and the reader
choice.

Probes (kept in `tools/perf/e6/`): `who_imports.py`/`who_imports_all.py`
(first importer, `--block` mode), `series_ops.py` (kernel costs),
`ipc_read.py`/`ipc_pool.py`/`all_tel_reader_ab.py` (readers),
`list_builder_parity.py`, `numpy_free_parity.py`, `merged_reps.py`,
`profile_step.py`.

## 5. CHANGELOG paragraph

- The common telemetry reads of a `lib="polars"` session no longer import
  numpy (~55 ms on a fresh process):
  - `pick_driver` filters with polars Series masks.
  - A driver's laps are joined into one telemetry slice with Series kernels.
  - `split_qualifying_sessions`, the fastest-lap selection and the lap
    start clock work on Python lists.
  - A lone lap read from the payload cache is decoded with orjson and typed
    from the lists while numpy is not loaded. The frames are the same as the
    numpy route's.

  The polars frame tier also reads the rows of one to three drivers with
  polars' eager IPC stream reader instead of `pl.read_ipc`: 9 ms instead of
  16 ms for a race driver row, and 15 ms instead of 31 ms for the first read
  of a process. The pooled read of a whole session keeps `pl.read_ipc`.

  Warm cache, fresh process, 2025 Bahrain race, whole-process wall:

  | call | before | after |
  | :--- | ---: | ---: |
  | `laps.pick_driver("VER").telemetry` | 373 ms | 264 ms |
  | `get_fastest_lap_tel()` | 284 ms | 236 ms |
  | per-lap `get_car_data()` over VER's laps | 380 ms | 252 ms |
  | `split_qualifying_sessions()` on qualifying | 300 ms | 231 ms |

## 6. Notes for the integrator

- Private polars API: `polars._plr.PyDataFrame.read_ipc_stream(source,
  columns, projection, n_rows, row_index, rechunk)` (polars 2.0.0). It is
  resolved once. A missing attribute, a changed signature (`TypeError`) or
  any `PolarsError` falls back to `pl.read_ipc`, so a polars upgrade can
  only make the read slower, never wrong. If polars 2.x grows a public eager
  in-memory IPC *file* reader, use it.
- Only pyarrow-written IPC files are guaranteed to have the "magic + stream"
  body. polars' own `write_ipc` files are not, and they take the fallback
  (tested). The tier writer `_write_polars_ipc` is pyarrow's. Keep it that
  way, or drop the stream path if the writer changes.
- The reader choice depends on process state, as in D3: pyarrow if
  resident, otherwise the stream reader for 1-3 drivers and `pl.read_ipc`
  for 4 or more. All three give equal frames.
- `decode_one_telemetry_payload` and `_polars_list_telemetry_frame` switch
  on `sys.modules.get("numpy") is None`. The same process can therefore build
  one lap from lists and the next from native arrays once numpy has loaded.
  Both routes give identical frames (2,810 payload frames checked). The
  parsed-payload LRU may hold either shape. Every consumer already accepts
  both (`_TELEMETRY_CHANNEL_TYPES` contract).
- `Session._lap_start_lookup` now returns `tuple[list[int], list[int]]`
  instead of numpy arrays. `_lap_clock` reads single entries, and
  `_attach_session_clock` converts with `np.asarray`. No other caller exists.
- Still on numpy for polars (left alone, not on the named workloads):
  - `pick_drivers` with more than 4 codes, `pick_quicklaps`, `pick_fastest`,
    `pick_track_status`, `pick_laps` lists, `pick_wo_box`/`pick_box_laps`
    (`_present_values`)
  - `iterlaps(require=...)`
  - every `PolarsTelemetry` method (`add_distance`, `resample_channels`,
    `fill_missing`, `merge_channels`, `slice_by_*`, `add_driver_ahead`)
  - the multi-driver and unsorted-clock joins
  - `get_weather_data`
  - the pooled payload decode

  These are why the notebook still loads numpy. Converting the
  `pick_*` family to Series masks is mechanical with the new `_filter_rows`
  (the mask helpers would need Series twins of `_present_values`: no native
  `is_not_null`. `x == x` gives null where `x` is null, and `filter` drops
  those rows, so `_filter_rows(frame, x == x)` keeps the present rows) and is
  a good follow-up. The telemetry methods rely on
  `searchsorted`/`cumsum`/`maximum.accumulate`, which have no plan-free
  polars kernel. Keep numpy there.
- Measuring trap: with `sys.modules["numpy"] = None`, `_create_telemetry_df`
  swallows the ImportError and returns `None`, which looks like a fast
  success. Check frame shapes (`who_imports.py` prints them) or use
  `numpy_free_parity.py`.
- Commits on the branch: three `perf(elis-E6): ...` commits; the report
  commit follows.
