# Elis E7: small certain wins on the warm pandas paths

## 1. Hypothesis

Several 1-5 ms items on the warm pandas paths are generic pandas machinery
doing more than the answer needs: `pick_driver` (a 1128-row categorical
compare plus a boolean take of every column), the `Time` rebase of
`_join_lap_telemetry`, the first `session.results` of a process (Ergast
merge plus module imports), the qualifying `split` (pyarrow string
kernels) and `laps.iloc[i]` (0.14 ms a row). I profiled each on the warm
cache (cProfile, plus manual timers over 20 in-process repetitions and
fresh-process first calls), kept the ones with a mechanism, and left the
rest with numbers. Every change had to keep values, dtypes, index, name
and class identical.

## 2. What changed

`src/tif1/models.py`
- `_interleaved_row` (`Laps.iloc[i]`, Pergamon Q7's row builder): a
  timedelta block with more than one column (12 columns in a laps frame) is
  boxed with one `ints_to_pytimedelta(values._ndarray[:, i], box=True)`
  call. Before, `TimedeltaArray.__getitem__` ran once per column at ~4 us
  each. The call gives the same `Timedelta` objects, in the array's own unit,
  and the `NaT` singleton (checked for s/ms/us/ns). Per row: 46 -> 5 us.
  The private function is probed at import with the other pandas
  internals, so a missing function sends `iloc` to pandas' own path.
- `Laps.pick_driver(code)` (`_driver_run`): when `Driver` is a category
  column (the session table), the index is a step-1 `RangeIndex`, and the
  driver's rows form one contiguous run, the result is `self.iloc[run]`
  instead of `self[self["Driver"] == code]`. The rows are found from the
  category codes. The slice has the same `RangeIndex(start, stop)`, blocks,
  class and `session` as the boolean take. Its blocks are shared under
  copy-on-write, so a write to the pick leaves the session table alone
  (tested). `Driver.laps` has done the same since Delphi. Anything else
  (no match, spread rows, other index or dtype, a duplicated `Driver`
  column) takes the boolean path unchanged.
- `split_qualifying_sessions` (`_qualifying_marks`): the Q1/Q2/Q3 digit of
  `QualifyingSession` is computed once per distinct label
  (`pd.factorize`), with `str.upper().strip()`. Before, the code ran
  `astype("string").str.upper().str.strip().str.extract(r"([123])$")`:
  three pyarrow kernels plus a per-row regex pass, ~4 ms on the first
  call of a process. Python's `upper`/`strip` equal pyarrow's
  `utf8_upper`/`utf8_trim_whitespace` on every ASCII character (checked
  over all 128, including `\x1c`-`\x1f`). The fast path runs only when
  every label is an ASCII `str` that ends in 1/2/3. Missing labels,
  unmarked labels, non-ASCII labels or non-strings take the pandas path, so
  behaviour such as the `TypeError` on a missing label is unchanged.
- `_timedelta_ns` / `_clock_ns_values`: a `timedelta64[ns]` (or naive
  `datetime64[ns]`) Series returns `values.to_numpy().view("i8")`. That is
  the same read-only view sharing the column's memory that the coerce +
  `astype` path returned (checked), at ~10 us instead of 82 / 109 us. These
  helpers run in the join (three calls per merged frame), `pick_fastest`,
  weather bounds, the lap starts and the split.

`src/tif1/core.py`
- `Session._lap_start_lookup` builds its driver mask with
  `models._driver_rows_mask` (the category codes compare) instead of
  `laps["Driver"].to_numpy(dtype=object) == driver`. The old line was a
  pyarrow take of the categories, and in a fresh process it imported
  `pyarrow.compute` (~4-5 ms) inside the per-lap telemetry loop.

`src/tif1/ergast/router.py`, `src/tif1/ergast/stats.py`
- `QueryPlan`, `ExecutedQuery` and `RoundInfo` are now plain `__slots__`
  classes instead of `@dataclass(slots=True)`. They keep the dataclass
  constructor (positional and keyword, the same defaults, a fresh
  `selectors` dict per plan), `__repr__` (same text, checked against the
  control classes), `__eq__` (same-class field tuple, else
  `NotImplemented`), `__hash__ = None` and `__match_args__`. The decorator
  cost ~0.55 ms per class at import, and the first `session.results` of a
  process imports both modules.

Tests: `tests/unit/test_elis_e7.py` (14 tests, offline). They cover:
- the `iloc` row equals pandas' own row element by element (types, units, NaT, negative position) for ns and ms frames;
- `pick_driver` equals the boolean take (index type and bounds, blocks, `session`) for runs, missing codes and wrong case, and the copy-on-write isolation of the pick;
- the fallbacks (spread rows, object column, relabelled index, sub-slice);
- the split equals the pandas expression path for plain, padded/lower-case, two-segment and category labels;
- `_qualifying_marks` defers for missing, unmarked, non-ASCII and non-string labels;
- the ns views equal the coercing path and are read-only;
- the Ergast classes' constructor defaults, repr text, equality, unhashability, slots and `match`.

Probes (in `tools/perf/`, run from the worktree root against the warm cache): `elis_e7_profile.py` (in-process timers and cProfile), `elis_e7_fresh.py` + `elis_e7_fresh_loop.py` (fresh-process first calls), `elis_e7_driver_tel.py`, `elis_e7_tel_diff.py`. I used the harness from the main repo unmodified.

### What was not done (numbers for the next round)

- `iloc` rest (~85 us a row): four category columns ~2.9 us each, five
  `str` columns ~1.3 us, the one datetime column 5.4 us (vectorized
  boxing costs more for one value), the block loop ~8 us, and the `Lap`
  wrap plus `__finalize__` ~18 us. No mechanism worth the risk was left.
- `results` (now ~10 ms fresh): ~2.5 ms is still the bodies of
  `ergast.router`/`stats`/`payloads`/`jolpica` (module constants and
  imports the cached path does not need), plus 0.5 ms of
  `ergast.structure` regexes it does use (time and ISO-date matchers). The
  rest is the frame build and the process's first `ArrowStringArray`.
  "Memoizing the results frame's column arrays" does not help the measured
  workload: `session.results` is already memoized per session, and the
  bench is one call per process.
- `_join_lap_telemetry` rest (~0.85 ms): the shallow copy plus the `Time`
  column set (0.19 ms), and the lap/clock comparisons over 43k rows. The
  rebased `Time` without the copy would change the frame's block layout,
  and the copy already costs only ~60 us.
- In-process repeated `pick + telemetry` timings are bimodal (10 vs 15
  ms) with allocator state, whichever pick path is used
  (`elis_e7_tel_diff.py`). Only fresh-process A/Bs decide that workload.

## 5. CHANGELOG paragraph

- **Small warm pandas paths (E7).** `laps.iloc[i]` boxes the laps frame's
  twelve timedelta columns with one call instead of one per column
  (200 rows 29 -> 20 ms). `pick_driver` slices the driver's run of rows
  when `Driver` is the session table's category column instead of taking
  every column through a boolean mask (0.8 -> 0.2 ms; ~5 -> ~1 ms as the
  first selection of a script). `split_qualifying_sessions` reads the
  `QualifyingSession` labels once per distinct value instead of through
  three pyarrow string kernels (fresh process 12 -> 7 ms). Nanosecond
  clock columns are read as their own int64 view (merged telemetry of four
  drivers 40 -> 35 ms). The Ergast query classes are plain slotted classes
  (the first `session.results` of a script 11.5 -> 9.7 ms). Values,
  dtypes, index and classes are unchanged.

## 6. Notes for the integrator

- `pick_driver` now returns a copy-on-write slice of the session table for
  the common case. Writes to it never reach the session table (pandas 3
  CoW, tested), and `to_numpy()` was already read-only in pandas 3 for
  both paths. Memory: the pick keeps the session table's blocks alive
  rather than owning ~80 rows of copies, which matters only if the pick
  outlives the session.
- `pick_driver` no longer triggers the process's first `take`, so the
  one-time `import pyarrow.compute` (~4-5 ms) lands wherever the next
  pyarrow kernel runs. I removed the one I found on the per-lap telemetry
  path (`_lap_start_lookup`). A workload whose first take is elsewhere will
  see it move, not grow.
- `_interleaved_row` depends on another pandas private
  (`pandas._libs.tslibs.timedeltas.ints_to_pytimedelta`). It sits in the
  same import probe as the other internals, so a removal disables the
  whole fast row path (it does not error).
- `QueryPlan(..., selectors=None)` now stores `{}`. The dataclass stored
  `None`, which every later use would have failed on. `dataclasses.fields()`
  / `asdict()` no longer apply to the three classes. Nothing in the
  package or tests used them.
- During the 8-pair A/B I added two `isinstance` guards (duplicated
  `Driver` / `QualifyingSession` columns). The notebook-only run, the
  suite and the parity digests ran on the final code.
- Commits were denied in the sandbox: everything is staged, and the
  intended message is in `.agents/perf-elis/E7_COMMITS.md`.
