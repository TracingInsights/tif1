# D1. `gc.freeze()` at interpreter exit

## Hypothesis

A fresh tif1 process ends with 40-80 ms of interpreter teardown that is
neither tif1's atexit hooks (0.3 ms) nor thread joins (1 ms): CPython's
finalization runs full garbage collections over the ~300k objects pandas,
numpy and pyarrow (or polars) built at import. Freezing the heap in an exit
hook makes those passes skip every object; memory is still released by
reference counting and, at the end, by the operating system.

## What changed

- `src/tif1/__init__.py`: `_exit_gc_freeze` registered with `atexit` when
  `tif1` is imported (not on Emscripten), so it runs after every hook
  registered later, tif1's SQLite cache flush (`cache._cleanup_cache`)
  included. It reads the `exit_gc_freeze` setting through the loaded config
  module; when tif1 was imported but never used, only the environment
  variable `TIF1_EXIT_GC_FREEZE` is consulted (no config file read at exit).
- `src/tif1/config.py`: `exit_gc_freeze` (default `True`), env
  `TIF1_EXIT_GC_FREEZE`.
- `docs/api-reference/config.mdx`: the setting and the two JSON examples.
- `tests/unit/test_exit_gc_freeze.py`: fresh-interpreter children check the
  heap is frozen at exit by default, that the env var and the setting turn it
  off, and that the cache is closed before the freeze.

## CHANGELOG paragraph

- Scripts exit sooner: `tif1` registers an exit hook that freezes the heap
  (`gc.freeze`) so CPython's final garbage collections skip the ~300k objects
  pandas, numpy and pyarrow (or polars) built at import, which cost 40-80 ms
  of every script's teardown. Memory is released as before; cyclic garbage
  alive at exit is not finalized (CPython never guaranteed it at shutdown).
  Fresh process, warm cache, 2025 Bahrain race: pandas `laps` 566 -> 493 ms,
  the notebook flow 984 -> 874 ms; polars `get_session` 383 -> 329 ms; a cold
  pandas `laps` 992 -> 876 ms. `exit_gc_freeze=False`
  (`TIF1_EXIT_GC_FREEZE=0`) turns it off.

## Notes for the integrator

The hook must stay registered at package import (atexit is LIFO): a hook
registered later than the cache cleanup would freeze before the SQLite
connection closes, which is harmless but would skip nothing of the cleanup's
own garbage. `gc.get_freeze_count()` reports the frozen objects. The hook
runs in any process that imported tif1, including pytest workers: the unit
suite is unaffected (fresh children in the tests verify the behaviour).
