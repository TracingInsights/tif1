# D6. `resample_channels` / `fill_missing` without per-column pandas ffill/bfill (pandas Telemetry)

Branch `perf/delphi-D6`, worktree `/tmp/tif1-delphi/D6`, control `255759b`.

## 1. Hypothesis

The notebook workload's 4-lap analysis step spent most of its ~60 ms in
`Telemetry.resample_channels(rule="0.1s")`: every non-continuous column
(`DriverAhead`, `nGear`, `Brake`, `DRS`, `Source`, `Status`, `Driver`,
`LapNumber`: 8 per lap) ran `self[col].iloc[positions].reset_index(drop=True).ffill()`
then `.iloc[held].reset_index(drop=True).bfill()`, four pandas ops at
~0.3-0.4 ms each, and `fill_missing` ran one `ffill().bfill()` /
`interpolate()` chain per column with gaps after a `Series` build plus
`hasnans` per column. The claim: compute one integer source-index map per
lap with numpy (forward fill as `np.maximum.accumulate` over the valid
positions, gathered at the bin positions, the leading gap back-filled) and
take every held column once with a dtype-preserving gather; reproduce the
pandas `interpolate(limit_direction="both")` with `np.interp` on the
positions; keep the pandas chain for the dtypes the numpy path does not
cover. Expected: ~19 ms per lap -> a few ms, identical values and dtypes.

## 2. What changed

`src/tif1/models.py` (pandas `Telemetry` only; the polars class is untouched,
it never shared the per-column pandas chains):

- New module helpers next to `_fill_rule`: `_column_array` (the stored
  column array through `DataFrame._get_column_array`, `_ixs(...)._values`
  as the fallback), `_na_mask` (the `isna` of a column array: `np.isnan`,
  `np.isnat`, `pd.isna` for object, a masked array's own `_mask`, else
  `.isna()`; None for bool/int ndarrays), `_ffill_bfill_source` (the
  source positions of `ffill()` then `bfill()`, optionally gathered at
  `held` before the backward fill exactly as `series.ffill().iloc[held].bfill()`
  reads them; None when every value is NA), `_take_column` (ndarray
  gather, `np.asarray(...)[idx]` for tz-naive `DatetimeArray`/`TimedeltaArray`,
  `EA.take` otherwise, so `Int64`, `str`, `boolean`, `Categorical` keep
  their dtype and NA), `_float64_column` (float64 view of numpy numeric
  and masked `Int64`/`Float64` columns with NaN for NA, the `to_numeric`
  parity; None otherwise), `_clock_ns_column` (`[ns]` datetime/timedelta
  arrays viewed as int64), `_filled_column` (the `fill_missing` verdict
  per column).
- `resample_channels` (rule path): reads every column as its stored array,
  takes the axis and clock columns from the `[ns]` arrays directly (no
  `pd.to_datetime`/`to_timedelta` round trip; other resolutions and kinds
  still go through `_clock_ns`), takes continuous channels as float64
  without `pd.to_numeric` when the stored dtype allows it, computes the bin
  means as plain `bincount` ratios when no sample is NaN and no bin is empty
  (bit-identical to the masked path: same divisions, and `np.interp` at its
  own knots returns the knots), holds every other column through one gather
  (`positions[held]` for gap-free columns, the `_ffill_bfill_source` map
  otherwise, an all-NA column stays all-NA), and assembles the result with
  `pandas_blocks._frame_from_columns(..., frame_class=Telemetry,
  column_index=self.columns)`: the dict constructor would infer `str` from
  an object ndarray, and the frame keeps this frame's column `Index` object
  as before. `_resampled_clock` takes the column array.
- `fill_missing`: finds the gaps on the stored arrays (no `Series` per
  column, bool/int ndarrays skipped outright), holds through
  `_ffill_bfill_source`, interpolates numpy float columns with
  `out[na] = np.interp(x[na], x[valid], values[valid])` on the positions
  (what pandas' linear `interpolate` runs; verified bit for bit), marks
  object `Source` gaps, and leaves all-NA held/interpolated columns alone
  (pandas would write back the same NA values). Masked floats, Arrow
  strings under the `Source` rule and any other dtype keep the pandas
  chain. The owned copy is made only when a column changes; object
  results are handed to `isetitem` as a `Series` over the frame's index
  (an object ndarray would be re-inferred as `str`).
- `_fill_rule` and `_is_continuous_column` decide on `np.dtype.kind` for
  numpy dtypes (same answer as the `pd.api.types` checks, ~1 us instead of
  ~8) and keep the pandas checks for extension dtypes.

`src/tif1/core_utils/pandas_blocks.py`: `_frame_from_arrays`,
`_frame_from_blocks`, `_direct_frame_from_columns` and `_frame_from_columns`
take keyword-only `column_index` (an Index to use as the column axis as is)
and `frame_class` (already on `_frame_from_blocks`); existing positional
calls are unchanged.

`tests/unit/test_delphi_d6_fill_resample.py` (71 tests): the previous
pandas chains are kept in the test as reference implementations and every
result is compared value for value and dtype for dtype (`check_exact`) on
gaps at the start, middle and end, all-NA columns, masked `Int64`/`Float64`/
`boolean`, object and `str` strings, bool, float32, a non-clock timedelta
column, a non-default and a non-uniform index, unsorted dates with NaT, the
`SessionTime` axis, non-`[ns]` clocks (general path), empty bins, random gap
patterns, plus unit tests of the source map and the plain-ratio shortcut.
No test was weakened.

## 4. Verdict: SHIP

The hypothesis holds: the two methods are 6.5x and 3x faster in process on
real laps, the notebook analysis phase is 60 -> 21 ms with every pair won,
no other phase regresses, and the digest is identical. The whole-process
wall of the notebook workload improves by the phase saving (~3.5-4% of a
~1 s process), which the harness resolves as 5/6 and 4/8 pairs; the
decision rests on the "clearly larger in-process phase win with the wall
not worse" clause of the brief.

## 5. CHANGELOG paragraph (Performance)

- `Telemetry.resample_channels` and `fill_missing` (pandas) no longer run a
  pandas `ffill`/`bfill`/`interpolate` chain per column: the value in force
  is found once per lap as a numpy source-index map and every held column
  (gear, DRS, brake, status, driver ahead, source, driver, lap number) is
  gathered once with its dtype kept; float gaps are closed with
  `np.interp` on the sample positions, which is the arithmetic pandas'
  linear `interpolate` runs; clocks and float channels are read from the
  stored arrays instead of through `to_datetime`/`to_numeric`; the
  resampled frame is assembled block by block with the frame's own column
  Index. Values, dtypes, column order and index are unchanged (digest of
  133 surfaces identical). 2025 Bahrain race, four fastest laps, in
  process: `resample_channels("0.1s")` 39.5 -> 6.1 ms, `fill_missing()`
  7.5 -> 2.5 ms; the notebook flow's 4-lap analysis step 60 -> 21 ms.
  Masked float columns, Arrow-backed strings under the `Source` rule and
  other unusual dtypes still take the pandas chain. The polars class is
  unchanged.

## 6. Notes for the integrator

- `resample_channels(new_date_ref=...)` (`_resample_onto_dates`) still runs
  the pandas chain for its held columns (with the extra "before the first
  sample" rule). `_ffill_bfill_source(na, np.maximum(held, 0))` plus a
  gather at the first valid position for `held < 0` would replicate it; not
  done here (not on the measured path, not in the parity digest).
- `fill_missing` no longer calls `isetitem` for an all-NA column under the
  hold/interpolate rules (pandas wrote back the same NA values); the
  values are identical, only the block layout of that column can differ
  (it stays in its consolidated block instead of becoming its own).
- The resampled frame is built from fresh arrays (gathers, bincount
  results, clock arithmetic), so nothing is shared with the source frame
  and copy-on-write references are not needed; `fill_missing` keeps
  `_owned_copy()` + `isetitem` (CoW-safe) for the same reason. A test
  checks the result does not alias the source.
- `_na_mask` returns a masked array's `_mask` itself (no copy); the helpers
  only read it. Keep it that way.
- `pd.DataFrame._get_column_array` is private pandas API (1.5-3.x); the
  helper falls back to `_ixs(i, axis=1)._values` if it is missing.
- The plain-ratio shortcut in the bin means is taken only when no sample is
  NaN and no bin is empty (`np.bincount(bins).all()`); an earlier draft
  checked only the samples and divided by zero on sparse laps. Covered by
  `test_empty_bins_are_interpolated_across` and the random-pattern tests.
- A/B runs and the parity digest are in this folder; the control-side
  micro benchmark was run with `PYTHONPATH=/tmp/tif1-delphi-control/src`
  against the D6 warm cache.
