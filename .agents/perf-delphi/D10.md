# D10. Polars sessions without numpy until needed

Branch `perf/delphi-D10`, control `255759b`. Box shared with the other
Delphi agents; every number is from the interleaved A/B harness (6 pairs,
fresh process per run, warm cache, offline, 2025 Bahrain Grand Prix).

## 1. Hypothesis

`import polars` costs ~180 ms and `import numpy` another ~55 ms on top of it
(numpy pulls `inspect`, `ast`, `dis`, `pickle`). A polars session paid for
numpy at `import tif1`: `tif1.core`, `core_utils/helpers.py`,
`core_utils/session_state.py`, `core_utils/ergast_results.py`,
`models_shared.py` and `models_polars.py` all imported it at module scope,
although reading `session.laps` back from the polars laps tier (a pickled
`PolarsLaps`), building the results frame and the state tables never needs an
array. Binding `np` through `core_utils/lazy_import.lazy_module` (the Olympia
OH3 mechanism that already keeps pandas out of polars sessions) and moving
the few module-level numpy constants and the per-value numpy casts of those
paths to plain Python should take ~55 ms off every polars script that stops
before telemetry, with the telemetry paths loading numpy at their first mask
or typed channel exactly as before.

## 2. What changed

Mechanism: `np = lazy_module("numpy", globals(), "np")` in the six modules
above (the `TYPE_CHECKING` branch keeps `import numpy as np` for ty), so the
first `np.X` of a process imports numpy and rebinds that module's global; a
pandas session pays one proxy call per module. Everything a polars
`laps`/`results`/`drivers`/`weather`/`race_control_messages`/`track_status`/
`session_status` read runs through was then made numpy-free:

- `src/tif1/core.py`: lazy `np`; `_native_isna` tests stdlib types first and
  numpy scalars only through `type(value).__module__ == "numpy"`; the native
  (polars) result-row scalars of `_best_lap_timedelta` and `_quali_row_fields`
  are `int` nanoseconds instead of `numpy.timedelta64` (the rows are private
  input of the results builder); the telemetry channel-type checks use
  `_telemetry_channel_types()`.
- `src/tif1/core_utils/helpers.py`: lazy `np`; `_NS_MIN`/`_NAT_INT64` are the
  literal `-(2**63)`; `_NULL_LIKE_TOKEN_ARRAY` and `_TELEMETRY_CHANNEL_TYPES`
  (`(list, numpy.ndarray, DictionaryChannel)`) are built on first use (the
  tuple through `_telemetry_channel_types()`, one call per payload).
- `src/tif1/core_utils/ergast_results.py`: lazy `np`; `_NAT_NS` literal;
  `_native_ns_list` (the int-nanosecond twin of `_native_ns_values`, which
  now wraps it; also accepts `int` ns) and `_native_result_columns`, the list
  twin of `_result_columns`: `finalize_results_frame_polars` builds every
  column as a typed `pl.Series` from Python lists (`Int64` then
  `.cast(Duration("ns"))`/`.cast(Datetime("ns"))`, a Series kernel, because
  polars misreads ints handed straight to `Duration`; `Float64` with `None`
  for NaN; `String` with `""`/`None` exactly as the array path), sorted by
  `Position` with unknown last, stable. A value only pandas can read (a
  numeric `Status`, a bool in a float column, a pandas scalar) returns `None`
  and the old array path runs unchanged.
- `src/tif1/core_utils/session_state.py`: lazy `np`; `_NS_MIN` literal;
  `status_frame` (polars) takes its `Time` list straight into `Int64`;
  `weather_frame` (polars) goes through `_weather_polars`: typed lists, with
  `_seconds_list_to_ns` replicating `helpers._seconds_to_td64ns` value by value
  (truncate, `round(x * 1e9) / 1e9` = numpy's round-half-even, scale,
  truncate; NaN -> null; inf or |x| >= 9e9 s -> `None`, the generic build, as
  `_td_cast_is_safe` refuses them); `_race_control_polars` parses the ISO
  timestamps with `_iso_timestamps_ns_list`/`_iso_timestamp_ns` (regex, keeps
  the nine fractional digits numpy keeps, raises on an impossible date like
  numpy); `file_t0_date_ns` uses the same parser and falls back to
  `numpy.datetime64` for any other spelling.
- `src/tif1/models_polars.py`: lazy `np` plus `from __future__ import
  annotations` (its `-> np.ndarray` annotations were evaluated at import;
  ruff dropped the quotes of eight forward references in the same pass).
- `src/tif1/models_shared.py`: lazy `np` (circuit geometry only).
- Tests: `tests/unit/test_polars_without_pandas.py` gets a `numpy` mode of
  its fresh-interpreter child (with an in-memory `session_info.json` so the
  state surfaces take the file path) asserting the nine laps/results/
  drivers/state surfaces leave numpy unloaded, that the first telemetry read
  then loads it and works, and the typed weather schema;
  `tests/unit/test_session_state.py::TestNumpyFreeTables` pins the scalar
  replicas to the numpy casts (`_seconds_list_to_ns` vs `_seconds_to_td64ns`,
  `_iso_timestamps_ns_list` vs `_iso_timestamps_ns`, the `file_t0_date_ns`
  fallback, the polars weather `Time`);
  `tests/unit/test_polars_session_wiring.py::TestPolarsResultsBuilder` builds
  the results frame on rows holding every value kind and asserts the list
  path equals the array path (schema and values, nulls equal), plus the
  three fallback triggers; `tests/unit/test_session_parity_fixes.py` covers
  the int-nanosecond native scalars.

Off-line check of the mechanism (fresh process, warm cache, my tree):
`import tif1` + `get_session(lib="polars")`: numpy not in `sys.modules`;
after `.laps`: no; after `.results`: no; after `weather_data`,
`race_control_messages`, `track_status`, `session_status`: no; after
`t0_date`: yes (it imports pandas, which imports numpy; D3's surface).

## 4. Verdict: SHIP

Every polars workload named by the section wins by far more than 3% on the
whole-process wall with 6/6 pairs (`import_get_session` -32%, `laps` -34%,
`results` -29%, `state` -7%), the telemetry workloads are not worse (4-6/6
pairs won, the numpy import only moves into their first array phase), pandas
is unchanged, and the user-visible surfaces are identical. `state` keeps
numpy because `t0_date` returns a `pd.Timestamp` on polars (D3 turns that
into `datetime`; with D3 the whole `state` workload stays numpy-free, since
its four tables already are).

## 5. CHANGELOG paragraph

- `lib="polars"` sessions import numpy only when something builds an array
  (~55 ms of their startup, ~110 ms on a loaded box): `core.py`, the shared
  helpers, the session-state tables, the results builder and the polars
  models bind `np` through the lazy module proxy that already keeps pandas
  out, the polars results frame is built from typed lists instead of numpy
  arrays, and the polars weather, race-control, track-status and
  session-status tables are typed lists too (the seconds and ISO timestamp
  casts replicate numpy's value for value). Warm polars, fresh process, 2025
  Bahrain race: import plus `get_session` 351 -> 240 ms, the script to `laps`
  378 -> 250 ms, to `results` 368 -> 260 ms, to the state tables 673 -> 627
  ms, `get_fastest_lap_tel()` end to end 390 -> 338 ms, a driver's
  `Laps.telemetry` 427 -> 400 ms, `fetch_all_laps_telemetry()` 578 -> 536 ms.
  The first telemetry read, `split_qualifying_sessions` and `t0_date` now
  carry the numpy import, so those alone are slower in isolation while every
  script that reaches them finishes sooner. pandas sessions are unchanged
  (pandas imports numpy).

## 6. Notes for the integrator

- Overlap with D3: D3 changes `t0_date`/`session_start_time` on polars to
  stdlib scalars and the pyarrow IPC read. This branch does not touch those
  lines; `session_state.file_t0_date_ns` is numpy-free here, so after both
  land `state` on polars never imports numpy. D3's `_arrow_strings_from_codes`
  replacement will meet the lazy `np` of `helpers.py` (fine: numpy is loaded
  by then, the global is already rebound).
- `_TELEMETRY_CHANNEL_TYPES` is no longer importable as a constant;
  `helpers._telemetry_channel_types()` replaces it (one call per payload,
  not per channel, in `core.py`; per channel in the two helpers' loops, where
  the frame build dominates). Other branches that import the constant will
  need the same one-line change.
- The polars results rows now carry `int` nanoseconds (`_best_lap_timedelta`,
  `_quali_row_fields` with `native=True`) and `_native_ns_list` accepts them;
  the frame values are unchanged (tests pin them).
- `models_polars.py` now has `from __future__ import annotations`; a
  `-> np.ndarray` annotation added without it would import numpy at module
  load again. The fresh-interpreter test catches that.
- Remaining numpy importers a polars session can reach: `pick_*`,
  `split_qualifying_sessions`, `get_fastest_laps`, every telemetry read
  (masks, typed channels, the pyarrow IPC reader), `t0_date`/
  `session_start_time` (pandas), `_summarize_laps_for_classification` (a
  session whose `drivers.json` is not a classification, or practice
  results), the circuit geometry of `models_shared.py`, `fuzzy.py` (an event
  name that needs fuzzy matching), `utils.py`. None is on the warm
  `laps`/`results`/state path of a 2018+ session with `session_info.json`.
- A weather payload whose `Time` holds a NaN is not possible from JSON; the
  list cast maps it to null as the array cast did, for symmetry.
- The parity tool's polars analysis selector is nondeterministic
  (`unique()` order); worth a `sorted()` in `tools/perf/delphi_parity.py`
  for the next round (not changed here: the tools are read-only for agents).
