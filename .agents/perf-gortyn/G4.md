# Gortyn G4: the rest of E6, polars `pick_*` and `iterlaps(require=...)` without numpy

## 1. Hypothesis

Elis E6 took `pick_driver`, the one-driver lap join, the qualifying split,
the fastest-lap selection and the lone-lap decode off numpy on polars
sessions. The other selections still built numpy masks, so the first of them
imported numpy (~55 ms on a quiet box, 50-145 ms under this round's load) in a
polars process: `pick_drivers`, `pick_quicklaps`, `pick_fastest`,
`pick_track_status`, `pick_laps`, `pick_wo_box`/`pick_box_laps`,
`pick_compounds`, `pick_team(s)`, `pick_tyre`, `pick_accurate`,
`pick_not_deleted`, `iterlaps(require=...)`, and the lookups behind
`get_driver` and `PolarsDriver.get_lap`. The polars notebook's `picks_x8`
phase was ~100 ms. Moving the selections to eager polars Series masks (no
query plans) should take that phase to a few ms, with every method at least
as fast as the numpy mask with numpy already loaded. The process wall gains
the numpy import whenever nothing later in the process needs numpy.

## 2. What changed

- `src/tif1/models_polars.py`: Boolean Series twins of the numpy mask helpers,
  using eager kernels only (comparisons, `&`/`|`/`~`, `zip_with`,
  `arg_min`/`arg_max`, `any`/`all`, `to_list`, `pl.Series(list)`):
  - `_filled`: `fill_null` through `zip_with`, because `fill_null` is a query plan.
  - `_present_series`: `x == x`, null exactly where `x` is null, then filled. It falls back to `is_not_null` for nested dtypes.
  - `_valid_series`: `x <= inf`, so NaN and null are both False.
  - `_isin_series`: `==` per value for up to 4 values, otherwise one set membership per row.
  - `_text_test_series`: the test runs once per distinct value.
  - `_first_true` and `_true_positions`.

  Methods converted:
  - `pick_drivers` / `_driver_number_values`, `pick_lap`, `pick_laps` (lists and ranges), `pick_team(s)`, `pick_tyre`, `pick_compounds`, `pick_quicklaps`, `pick_fastest` (all three rules, ties go to the first minimum), `pick_track_status` (equals/contains/excludes/any/none), `pick_wo_box`, `pick_box_laps`, `pick_not_deleted`, `pick_accurate`, `iterlaps(require=...)`.
  - `_distinct_present`.
  - `PolarsSessionResults._position_for`, which serves `get_driver`/`row_for`, now runs on Python lists over the ~20 result rows.
  - `PolarsDriver.get_lap`.

  `_filter_rows` already took a Boolean Series mask (nulls drop). The `PolarsTelemetry` arithmetic (`add_distance`, `resample_channels`, `slice_by_*`, `merge_channels`, `fill_missing`) stays on numpy, as the section asks. `_text_test_values` was removed (no callers left). The rare-input expression paths are unchanged.
- `tests/unit/test_gortyn_g4_series_masks.py` (new): each converted method is compared with the numpy implementation it replaced, on 120 random frames. The frames cover nulls, NaN, ties, empty results, the `strict`/threshold semantics of `pick_quicklaps`, the `IsPersonalBest`/`Deleted` rules of `pick_fastest`, and case handling of driver codes and compounds. Each helper also has unit cases.
- `tests/unit/test_polars_without_pandas.py` (numpy mode) now asserts that numpy stays unloaded through the whole pick family, `iterlaps(require=...)`, `get_driver(...)`, `get_lap`, `get_fastest_lap` and the fastest lap's `get_telemetry()`.
- `AGENTS.md`: the `models_polars.py` paragraph names the new rule and the helpers.
- `tools/perf/gortyn_g4/`: the probes.
  - `who_imports_notebook.py`: which notebook step imports numpy.
  - `method_bench(_ab).py`: per-method in-process timings, 20 repetitions on the 1128-row race laps, control with numpy loaded.
  - `real_parity(_ab).py`: 238 method surfaces on the real race, control vs candidate vs candidate with numpy import blocked.
  - `analysis_split(_ab).py` and `late_numpy_probe.py`: where the numpy import lands in the notebook.
  - A copy of the warm harness (`warm_bench.py`/`warm_ab.py`) with one new workload, `lap_analysis`: a lap-time notebook without telemetry arithmetic (laps, the notebook's eight picks, `iterlaps(require=...)`, every driver's fastest lap, four `get_driver(...).get_fastest_lap()`, results). The Delphi workloads in the copy are unchanged.

### Why the notebook wall does not move

The notebook's `telemetry_analysis_4` step (`add_distance`,
`resample_channels`, `merge_channels`) still needs numpy. On the candidate
that step is now where numpy is imported, and it grows by about the same
amount the picks lose (`analysis_split.py`: `numpy_import` 98-129 ms at that
point, every other sub-step unchanged).

The iterlaps telemetry loop also gets faster (56 -> 38 ms). While numpy is
unloaded, a lone lap's payload goes through E6's orjson decoder and list
builder (`decode_one_telemetry_payload`, `_polars_list_telemetry_frame`).

`late_numpy_probe.py` checked whether the late import costs more than an early
one because of gc. It does not: the import costs 50-145 ms under this box's
load whether it runs early or late, with gc on or off (gc on: 5 gen-0
collections and 1 gen-1 collection during the import, which is noise). So any
polars process that never runs telemetry arithmetic saves the whole import.
One that does just pays it later.

## 4. Verdict

**SHIP.** Every polars lap selection stops importing numpy, and every method
is at least as fast as before. Parity is exact on 131 + 133 digest surfaces
and 238 method surfaces.

The section's own bar is met on the phase: `picks_x8` 71-114 -> 3 ms, with
the notebook wall not worse (603 -> 600, 4/8; 585 -> 580, 6/10; one earlier
6-pair run read 627 -> 638, 2/6, within the box's noise). The notebook wall
cannot move because its telemetry arithmetic imports numpy later anyway.

The wall win is on laps-only analysis: `lap_analysis` 354 -> 269 ms (-24%),
won 24 of 24 pairs over three runs. `laps`, `fastest_lap_tel` and
`quali_split` are within noise.

## 5. CHANGELOG

- Lap selections on a polars session no longer import numpy. Every `pick_*`
  method of `PolarsLaps`, `iterlaps(require=...)`, `get_driver()` and
  `PolarsDriver.get_lap()` now filter with eager polars Boolean Series masks
  instead of numpy masks. They are 5-20% faster per call even with numpy
  already loaded (the eight picks of the benchmark notebook: 1.67 -> 1.47 ms).
  A polars process that analyses lap times without telemetry arithmetic skips
  the numpy import: a warm lap-time notebook (picks, `iterlaps`, fastest laps,
  results) runs in 269 ms instead of 354 ms (-24%). A notebook that later
  resamples or merges telemetry still imports numpy at that point, so its total
  time is unchanged.

## 6. Notes for the integrator

- **Broken control cache.** `/tmp/tif1-delphi-warm` (the shared control cache)
  no longer serves the race's `drivers.json` offline. Other agents' A/B runs
  against it will fail the same way. Re-prime it, or point the control arm at
  a private copy.
- **Polars null semantics are load-bearing.** `_filled` relies on `zip_with`
  reading a null mask entry as False. `_valid_series` relies on polars ordering
  NaN above `+inf` (`NaN <= inf` is False). `_present_series` relies on
  `x == x` being null exactly where `x` is (polars: NaN == NaN is True). The
  random-frame tests in `test_gortyn_g4_series_masks.py` pin all three against
  the numpy implementations, so a polars upgrade that changes one fails there
  first. G2's private-seam canary could list them.
- **`pick_quicklaps`** compares the Int64 nanosecond column against
  `best * threshold` (a float). polars upcasts to float64, as numpy did. The
  strict `<` and the threshold edge are covered by the tests.
- **`iterlaps` loop.** The notebook's `iterlaps` telemetry loop is ~18 ms
  faster on the candidate only because numpy is not loaded yet when it runs
  (E6's list decoder). That is a side effect, not a change to the loop.
- **Next step for the notebook wall.** Moving the remaining telemetry
  arithmetic off numpy is the only way to win the notebook wall. AGENTS.md
  calls `searchsorted`/`cumsum` query plans, so that needs a different
  mechanism (Python lists for the ~600-sample laps, or a native kernel). Not
  attempted here.
- **Harness copy.** `tools/perf/gortyn_g4/warm_*.py` differs from
  `delphi_warm_*.py` only by the `lap_analysis` workload. If the round keeps
  it, fold it into the main harness and the perf gate.
