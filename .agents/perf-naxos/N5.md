# Naxos N5: interpreter exit after a tif1 workload

Verdict: **REJECT** (no library change). The exit is already close to its
floor after Delphi D1. What remains is either CPython's module teardown,
which cannot be skipped without `os._exit`, or kernel work that scales with
the memory and pages the workload touched. Every knob tried either moved
that work to another part of the exit or made it slower.

## 1. Hypothesis

The brief put the interpreter's exit at ~20 ms after a pandas `laps` script
and ~50 ms after `fetch_all_laps_telemetry()`. Suspected causes were pool
joins, `munmap` of large buffers, allocator teardown, the SQLite close,
module teardown and gc passes. Part of that should be cuttable without
changing semantics: user `atexit` handlers still run, output is flushed, the
cache stays consistent and `os._exit` is not used.

## 2. What changed

Nothing in `src/` or `tests/`: `git diff d28ce70 -- src tests` is empty. The
prototypes below were measured and reverted. Added
`tools/perf/naxos_exit_probe.py`, an exit profiler:

- It runs a `delphi_warm_bench.py` workload in a fresh interpreter whose
  `atexit.register` and `threading._register_atexit` are wrapped before
  `tif1` is imported, so every exit hook is timed.
- Timestamps use `time.monotonic` (CLOCK_MONOTONIC, shared with the parent),
  so the parent splits the wall into: workload, threading shutdown and joins,
  each atexit hook, and the finalization tail (last atexit hook to process
  reaped).
- Several trees can be interleaved per rep.
- `--mem` reports RSS (anon/file), live threads by name, glibc `mallinfo2`
  and AnonHugePages. `--drop` and `--env` drive the experiments below.

`perf record` (`perf_event_paranoid`) and `strace` are not available in this
sandbox, so the tail was decomposed experimentally instead of sampled.

## 3. Measurements

Box at load 10-20 (other agents running). Warm cache `/tmp/naxos/warm-N5`,
offline, Python 3.13.

### Where the exit goes (control d28ce70; median of 5, quieter period; ms)

| workload | wall | thread shutdown | atexit hooks (`_cleanup_cache`) | finalization tail | exit total | exit share |
|---|---|---|---|---|---|---|
| pandas `laps` | 435 | 0.0 | 0.3 | 14.9 | 15.3 | 3.5% |
| pandas `all_tel` | 557 | 0.9 (decompress pool join) | 3.2 | 21.5 | 25.7 | 4.6% |
| pandas `notebook` | 703 | 1.1 | 3.1 | 24.3 | 28.6 | 4.1% |
| polars `laps` | 215 | 0.0 | 0.5 | 8.5 | 9.1 | 4.2% |
| polars `all_tel` | 341 | 0.0 | 3.9 | 26.3 | 30.3 | 8.9% |
| polars `notebook` | 551 | 0.0 | 3.7 | 30.5 | 34.3 | 6.2% |

A later 8-rep interleaved run (control vs this tree, identical sources, load
~20) gives the same minimums (pandas `all_tel` exit min 27-30 ms, polars
`notebook` 33-34 ms). Its medians differ by up to ±10 ms between identical
trees, which is the noise floor of an exit A/B at that load.

### What each part is

- **Finalization floor: CPython module teardown.** The tail after only
  importing, with the same `gc.freeze` tif1 uses:

  | imported | tail (ms) |
  |---|---|
  | bare interpreter | 1.7 |
  | `numpy` | 5.3 (4.0 with `OPENBLAS_NUM_THREADS=1`: OpenBLAS's thread-pool shutdown is ~1.3 ms) |
  | `pyarrow` | 7.8 |
  | `polars` | 5.3 |
  | `pandas` | 14.7 |
  | tif1 pandas `import_get_session` | 14.9 |
  | tif1 polars `import_get_session` | 7.1 |

  tif1's own modules add nothing measurable. Without the D1 freeze, the bare
  `import pandas` tail is 64 ms, so D1's hook works. CPython 3.13
  `finalize_modules` clears every live module's dict
  (`finalize_modules_clear_weaklist`), and that deallocates the ~300k import
  objects. This cannot be skipped without `os._exit`.
- **Resident memory, freed by the kernel at exit.** A scratch child holding N
  MB of touched 4 KB pages: tail 4.2 ms at 0 MB, 9.1 at 100, 26.3 at 300,
  50.2 at 600. That is ~0.08 ms/MB, the same whether the memory is freed by
  user `munmap` or by `exit_mmap`. Freeing it before the timestamp removes it
  from the tail (4.5 ms), but the work just moves earlier.
  - Pandas `all_tel`: anon RSS 267 MB (55 MB after `get_session`). 140 MB
    is already huge pages (G1/G6 decompression buffers), which free almost
    for free, so the tail grows only ~6-9 ms above the floor. glibc arenas
    keep 31 MB free (dynamic mmap threshold) and 48 MB are in use.
  - Polars `all_tel`: anon RSS 260 MB (28 MB after `get_session`) and no
    huge pages. The live frames are 129 MB (`estimated_size`), so ~100 MB is
    retained by polars' jemalloc or glibc (28 MB of it free in glibc). The
    tail grows ~19 ms above the floor.
- **Threads.** Idle threads cost ~0.03-0.05 ms each at exit (0 threads: 5.4
  ms tail, 64: 7.3, 100: 10.2). A pandas session carries 31 OpenBLAS threads
  plus the 8 `tif1-frame-decompress` workers, which
  `concurrent.futures._python_exit` joins in ~1 ms. A polars `all_tel` or
  `notebook` carries **102-133 threads**: 32 `polars-N`, 32
  `tokio-rt-worker` and 32 `async-executor`. The last 64 are started by
  `pl.read_ipc` (`scan_ipc().collect()`) on the pooled tier read, which costs
  ~3 ms at exit and some startup in the workload.
- **`_cleanup_cache` (3-4 ms) is page unmapping, not SQLite work.**
  - Pandas: closing the 4 idle D9 reader connections is 2.96 ms
    (0.75 ms each). The main connection's close, which runs the WAL
    checkpoint on an empty WAL and deletes the `-wal` file, is 0.15 ms.
  - Polars: the main connection's close is 3.5-4 ms. The pooled IPC rows are
    read through its cursor, so it holds the ~110 MB of touched pages in its
    2 GB mmap.

  Either way the cost is the `munmap` of the file pages each connection
  touched (~0.13 µs/page).

### Experiments (all rejected)

| experiment | result |
|---|---|
| Release tif1 state in the first atexit hook (`--drop`: `gc.collect()` + `clear_lap_cache()`) | The pandas session is cyclic garbage (55,041 objects) that the D1 freeze leaves unfreed at no cost. Collecting it costs 34 ms; collecting it on polars (1,444 objects, 12 ms) leaves the tail unchanged at 27 ms. Freeing buffers and memos ahead of exit is a net loss. |
| Park the idle reader connections in a cycle the freeze keeps, so their mmaps go with `exit_mmap` (prototype in `_cleanup_cache`, interleaved) | Exit probe, 12 reps: hooks 3.2 → 0.2 ms but tail 23.9 → 27.1, so exit 28.3 → 28.4 (`all_tel`, 5/12 pairs). On `notebook`, exit 29.1 → 34.4 (3/12). Warm A/B, 12 pairs: `all_tel` wall 609 → 619 (5/12), `notebook` 799 → 805 (5/12). The unmap moves into the kernel teardown instead of disappearing. It would also leave the `-wal`/`-shm` files on disk, because the main close is no longer the last. |
| Close the 4 idle readers concurrently on 4 threads (`sqlite3_close_v2` releases the GIL) | Hooks 4.2 → 5.6 ms, exit 31.2 → 34.3 (5/10). `munmap` takes `mmap_lock` for writing, so the unmaps serialize, and the threads add overhead. |
| THP for polars' jemalloc (`_RJEM_MALLOC_CONF=thp:always`, which the 169 MB `_polars_runtime` honours) | 270 MB of AnonHugePages, but RSS 260 → 410 MB and the workload 260 → 295 ms (huge-page zeroing). Tail 26 → 24 ms. Net loss, and it would change the user's polars allocator. |
| `OPENBLAS_NUM_THREADS=1` (exit side only) | numpy floor 5.3 → 4.0 ms. Start-up is N1's subject. |
| Close the SQLite connections on a daemon thread that overlaps CPython's finalization | Not built. In 3.13, `Py_FinalizeEx` frees the other threads' states (`_PyThreadState_DeleteList`) after `_PyRuntimeState_SetFinalizing`. A thread returning from `sqlite3_close_v2` into `PyEval_RestoreThread` would read its freed state. Waiting for it in an atexit hook overlaps nothing (the later hooks take ~0 ms). Not safe for 1-3 ms. |
| Skip the decompress-pool join | ≤1 ms, and only possible by removing the workers from the private `concurrent.futures.thread._threads_queues`. Not worth a private seam. |
| Avoid the final full gc | Already done by D1. With the freeze, the two `_PyGC_CollectNoFail` passes in `finalize_modules` cost ~0 (bare pandas tail 64 → 14.7 ms). |

## 4. Verdict

**REJECT.** The exit after a warm tif1 workload is 15-34 ms (3.5-9% of the
wall).

- The floor (15 ms pandas, 7 ms polars) is CPython's teardown of the modules
  pandas, pyarrow, numpy and polars build at import. tif1's own modules add
  nothing, and D1 already removed the gc passes.
- Most of the rest is the kernel freeing what the workload touched: ~0.08
  ms/MB of 4 KB anonymous pages, ~0.13 µs per mapped SQLite file page, and
  ~0.04 ms per thread. That cost is the same wherever it is paid, and
  overlapping it with finalization is unsafe on CPython 3.13.
- The one tif1-owned piece, the connection closes in `_cleanup_cache` (3-4
  ms), only moved into the tail when skipped, and got slower when
  parallelized.

No change reaches the 3% wall threshold, and none removes any work at all.

## 5. CHANGELOG paragraph

None: nothing ships. For the record in the round's results: "Naxos N5
measured the interpreter exit after a warm session at 15-34 ms. Of that,
15 ms (pandas) or 7 ms (polars) is CPython's module teardown, and the rest
is the kernel freeing what the session touched: ~0.08 ms per MB of resident
memory and ~0.04 ms per thread. Skipping or parallelizing the cache's
connection closes moved their 3-4 ms into the kernel's teardown or made it
slower, so tif1's exit path is unchanged."

## 6. Notes for the integrator

- **Do not retry:** releasing tif1's memos or buffers or running
  `gc.collect` before exit; leaving SQLite connections open for the kernel
  to unmap; closing connections concurrently or on a daemon thread during
  finalization; jemalloc THP for polars (`_RJEM_MALLOC_CONF=thp:always`);
  skipping the decompress-pool join.
- **Follow-up outside N5's scope:** a polars session that takes the pooled
  IPC tier read (≥4 drivers: `all_tel`, `load(telemetry=True)`, `notebook`)
  starts 64 extra threads (`tokio-rt-worker` ×32 and `async-executor` ×32)
  through `pl.read_ipc` → `scan_ipc().collect()`. They cost ~3 ms at exit,
  plus their start-up inside the workload. A pooled read that avoids that
  engine would save both. E6 found the eager stream reader GIL-bound in the
  pool, so this belongs with N2 (lazy polars load).
- The exit cost tracks resident 4 KB pages, so anything that cuts the pages a
  workload touches also shortens its exit: huge-page buffers (as G1/G6 did
  for pandas), fewer transient copies, or less glibc arena retention after
  the worker threads free big buffers. Polars `all_tel` keeps ~100 MB beyond
  its 129 MB of live frames.
- `tools/perf/naxos_exit_probe.py` is the reusable tool. Run it from the repo
  root with `TIF1_CACHE_DIR` set:

  ```bash
  python tools/perf/naxos_exit_probe.py --src A,B --workload pandas:all_tel --reps 8
  ```

  At load ≥15 the per-arm exit medians wander by ±10 ms between identical
  trees, so compare minimums or measure on a quiet box.
