# Q7: per-row Lap construction (`iterlaps`, `iloc[int]`)

**Verdict: KEPT.** Exact parity, and the candidate was faster in 6 of 6 interleaved fresh-process pairs on every per-row idiom.

## Hypothesis

On the warm laps frame, per-row lap access is dominated by pandas row materialization, not by tif1 work. The test frame was the 2026 Monaco race: 1455 laps, 46 columns and 17 blocks. A FastF1-style `lap.telemetry` lookup now costs about 1-6 us on a memo hit, so building the `Lap` row is what the user waits for.

## Mechanism (profiled)

- `iterlaps` (Argos A5 version, about 43 ms):
  - `to_numpy(dtype=object)`: 5 ms, unavoidable because the boxed values are the output.
  - `columns[keep]` per row: about 8 us x 1455. The str column Index filters through pyarrow compute on every row, yet the race has only 14 distinct null patterns.
  - Generic `Lap(values, index=..., name=...)` per row: about 8 us x 1455.
- `laps.iloc[i]` (about 0.115 ms):
  - `fast_xs` calls `interleaved_dtype` → `find_common_type` over 17 block dtypes on every call: 33 us. Most of that is `StringDtype`/`CategoricalDtype` hashing.
  - 46 `Block.iget` method calls.
  - The row is wrapped twice: `Series._from_mgr`, then `Lap(series)`, which goes through `Series.__init__` again.

## Change (`src/tif1/models.py` only)

- **Import-time probe.** A new module-level block probes the pandas internals Q7 needs: `sanitize_array`, `lib.maybe_convert_objects`, `SingleBlockManager`, `new_block`, `ExtensionBlock`, `interleaved_dtype` and `BlockPlacement`. The modules are bound through `Any` variables, following the TH2 pattern. If the probe fails, `_FAST_LAP_ROWS = False` and the public paths are used unchanged.
- **`_row_interleaved_dtype`** memoizes `interleaved_dtype` keyed by the tuple of dtype-object ids.
  - Each entry keeps the dtype objects alive, so an id cannot be reused while it is cached: a hit means the same objects, and the function is pure.
  - The cache holds at most 256 entries and is cleared when full.
- **`_lap_from_row`** runs the Series constructor's own steps for a freshly built 1-D object array:
  1. `lib.maybe_convert_objects` with `sanitize_array`'s exact arguments.
  2. If that call converted anything (a row of all timedeltas or all strings), the full `sanitize_array` runs instead.
  3. `SingleBlockManager.from_array`.
  4. `Lap._from_mgr`, then `_name` and `session` are set.

  For a 1-D object array of the index's length, `_sanitize_ndim` and `_sanitize_str_dtypes` do nothing, so skipping them is exact.
- **`Laps.iterlaps`** now:
  - computes the skip mask once, vectorized;
  - keeps one (kept positions, column Index) entry per distinct null pattern, keyed by `null_row.tobytes()`;
  - takes row values as `row_values[pos, keep_positions]`, or `.copy()` when the row has no nulls, so each row is a fresh owned array, as after the constructor's copy;
  - builds each lap through `_lap_from_row`.
- **New `Laps._ixs` override.** For `axis == 0` on a frame with at least 2 blocks whose interleaved dtype is object (every laps frame), it is `BlockManager.fast_xs` with:
  - the memoized dtype;
  - `Block.iget` inlined: `values[j, i]` for 2-D blocks (numpy and DatetimeLike) and `values[i]` for `ExtensionBlock`, which is exactly what the two `iget` implementations do;
  - `columns.view()` as the axis, as `fast_xs` does;
  - one `Lap._from_mgr`, then `_name`, `session=None`, and `__finalize__(self)` copies the session and attrs.

  Every other case (axis 1, single block, non-object interleaved dtype, probe failure) goes to `super()._ixs`.
- `iterrows` is untouched.

## Protocol

- Fresh process per run, interleaved control/candidate pairs (order alternated), 6 pairs.
  - Control: the frozen tree `/tmp/tif1-pergamon-control/src`, with cache copy c1.
  - Candidate: the worktree `src`, with cache copy c2.
  - Both copies come from the `/tmp/tif1-warm-q-base` snapshot.
- Harnesses are in `/tmp/tif1-q-Q7/scripts`: `bench.py` and `ab.py`. Raw results are in `Q7_ab.json`, next to this file.
- In-process numbers are best-of-N:
  - iterlaps and iloc: N=9;
  - telemetry loops: N=5, run after `fetch_all_laps_telemetry()`;
  - "first" means the first call in the process.
- The box was heavily loaded by the other agents during the A/B (control medians are about 2x those of a quiet single run), so ratios matter more than absolute values.

## Parity

- **Cross-process.** Control and candidate each dumped the following for every yielded or returned lap: class, name and name type, dtype, index labels and index dtype, `repr` of every value, type of every value, and `session is session`. Coverage:
  - full `iterlaps` (1445 laps);
  - LEC `iterlaps(["LapTime"])` (64 laps);
  - `iloc` for all 1455 rows plus `-1`;
  - LEC `iloc` for 10 rows;
  - `pick_fastest`.

  All identical.
- **In-process** (`/tmp/tif1-q-Q7/scripts/parity.py`). Compared against the inlined pre-Q7 algorithm and `pd.DataFrame._ixs` on the same object. The checks are the same per-element checks as above, plus:
  - `equals`;
  - `vars()` keys and `attrs`;
  - the block class;
  - whether the CoW references match (`has_reference`);
  - whether the values array is writeable.

  Frames checked:
  - the full laps frame with `require` set to the default and to `[LapTime, Sector1Time]`;
  - a driver subset, and `pick_quicklaps`;
  - a timedelta-only frame and a str-only frame (both inferred to non-object dtypes by the constructor);
  - a 2-column frame, a single-block float frame, and a frame with duplicate columns;
  - mutation after iloc: a `.loc` write, a new column, an astype;
  - lap mutation isolation.

  `require=[]` raises the same `ValueError` in both versions.
- **Contract tests.** `tests/unit/test_pergamon_q7_rows.py` (11 tests) covers the same matrix on a synthetic 15-column, many-block frame. It also covers the fallback with `_FAST_LAP_ROWS=False` and the bound on the dtype cache.

## Risks

- **Private pandas internals.** The change relies on `fast_xs` and constructor internals of pandas 3.0.6. A missing name disables the path at import time. A silent behaviour change in a future pandas would not, but the contract tests compare against `pd.DataFrame._ixs` and the public constructor, so they would catch it.
- **Shared Index objects.** Laps yielded by `iterlaps` with the same null pattern now share one column Index object. Index objects are immutable, and pandas itself shares `columns` across `iterrows` rows and across no-null rows in the old code.
- **Dtype cache scope.** The dtype cache is process-global, bounded at 256 entries, and keeps at most 256 tuples of dtype objects alive.
- **Conflicts.** `models.py` is the only source file touched. The edits sit around `Laps._constructor_sliced` (new `_ixs`), the `iterlaps` body, and a new block before `_IterLapResult`. Agents editing `Lap`/`Laps` in the same areas may conflict.
