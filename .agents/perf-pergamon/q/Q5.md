# Q5 — materialized tier (or cheaper builds) for the non-telemetry session tables

**Verdict: REJECTED (noise).** No source change. The whole-build ceiling (weather + rcm served
from a `session_frames` row, every build pass removed) is a deterministic 3.8 ms phase saving on
pandas that does not show on fresh-process `load()` wall (tier faster 3/8, median +2.5 ms
*slower*). Half of the polars "saving" is the polars lazy engine's one-time first-use init,
which the tier would only move to the user's first polars query. Rewriting the builders
directly (lever a) is bounded above by the tier, and the stage split caps it at ~2 ms.

## Hypothesis

A warm `session.load()` rebuilds weather / race-control messages (plus lazily `results`,
`drivers_df`, `get_circuit_info()`) from cached JSON on every fresh process. Either cheapen the
builders or materialize them like `laps_frames` (KR-1).

## What `load()` actually builds

`load()` touches `laps`, `weather`, `race_control_messages` and telemetry only. `results`,
`drivers_df` and `get_circuit_info()` are lazy and never run inside `load()`, so they cannot
contribute to a `load()` win. Their first-touch costs, fresh process, pandas: results 0.37-0.39 ms,
drivers_df 1.8-2.1 ms, circuit 0.8-1.1 ms. The ~9 ms in the brief was the sum of all five tables.
The `load()` share is weather + rcm only, about 4.1 ms on pandas.

## Profile (control tree `/tmp/tif1-pergamon-control/src`, warm 2026 Monaco Race)

Fresh-process first touch, pandas (3 runs each arm): weather 1.53-1.77 ms, rcm 2.23-2.71 ms.
Polars: weather 2.6-5.6 ms, rcm 1.3-3.1 ms.

Split, pandas (fresh process; best-of-200 warm in brackets):

| stage | ms |
|---|---:|
| SQLite read + orjson, weather.json / rcm.json | 0.06-0.07 / 0.10-0.11 |
| weather `_create_session_df` (`pd.DataFrame(dict)` + rename) | 0.54-0.61 (0.26) |
| weather dtype passes: null-like scan 0.26 (0.12), Time->td 0.16 (0.04), 5x `to_numeric` 0.27 (0.20), WindDirection Int64 0.09 (0.05), Rainfall boolean 0.06 (0.03) | ~0.8 |
| rcm `_create_session_df` | 0.71-0.76 (0.41) |
| rcm `Time` `to_datetime(format="ISO8601")` | 0.64 (0.13) |
| rcm 6 string columns `"None"` -> None loop | 0.94 (0.62) |
| rcm Sector / Lap | 0.37 (0.15) / 0.06 (0.05) |

orjson + SQLite are <0.2 ms of the 4.1 ms; the rest is pandas construction and per-column passes,
with first-call costs 2-5x the warm best. The datetime parse is 0.13-0.64 ms, not the driver.
The builders' cost is additive, not shared warm-up. They cost the same whether run before or
after telemetry: weather 1.65-1.78 vs 1.75-3.36 ms, rcm 2.23-2.44 vs 2.50-4.94 ms, 6 pairs.

Polars weather is two `PyLazyFrame.collect` calls (4 ms) plus lazy `rename` (1 ms). A trivial
`DataFrame.with_columns(...).rename(...)` run first costs 2.5-2.9 ms. After it, weather drops to
1.0-1.7 ms and rcm to 1.6-2.9 ms (4 pairs). So ~2.7 ms of polars "weather" is the lazy engine's
one-time init: the first polars expression in the process pays it, whoever runs it.

## Tier upper-bound probe (lever b ceiling)

`/tmp/tif1-q-Q5/harness/tier_probe.py` primes a `session_frames(year, gp, session, tbl, lib,
frame)` table with the control's built weather/rcm frames (pickle protocol 5 +
`_compress_frame_blob`, the KR-1 codec). The tier arm then does 2 point reads + decompress +
unpickle + assign inside the timed `load()` window; the built arm runs the control `load()`.
Same source tree, same cache copy, fresh process per run, ABAB-interleaved, 8 pairs
(`probe_ab.py`). Blobs: weather 14.1 kB -> 6.5 kB, rcm 30.5 kB -> 9.0 kB; decode 0.12 / 0.14 ms.

Pandas (`/tmp/tif1-q-Q5/probe_ab2.json`):

| phase | built median (min) | tier median (min) | tier faster |
|---|---:|---:|---|
| tier read + decode (both tables) | — | 0.41 ms | — |
| weather | 1.59 (1.48) ms | ~0 | 8/8 |
| rcm | 2.58 (2.45) ms | ~0 | 8/8 |
| telemetry | 59.9 (56.8) ms | 66.2 (50.3) ms | 2/8 (noise) |
| **load()** | **65.3 (61.8) ms** | **67.8 (51.7) ms** | **3/8** |
| get_session + load() | 295.0 ms | 306.2 ms | 4/8 |

Net deterministic phase saving: 4.17 - 0.41 = 3.8 ms. That is a ceiling: a real tier adds the
lock/codec checks, a miss probe on every first build, and a pickle + compress write. The
telemetry phase alone swings 48-89 ms between fresh processes on this shared box, so 3.8 ms is
not separable on `load()` wall at 8 pairs.

Caveat for other agents: a first run with *different* cache copies per arm
(`probe_ab.json`, control copy vs candidate copy) showed `load()` 69.6 -> 58.0 ms, 7/8. With
both arms on the same copy the effect vanished. Cache-copy state alone moved `load()` by
~7 ms, so A/B arms should share one cache copy whenever the change does not alter the format.

Polars (`/tmp/tif1-q-Q5/probe_ab_polars.json`, box heavily loaded during this run):

| phase | built median (min) | tier median (min) | tier faster |
|---|---:|---:|---|
| tier read + decode | — | 0.49 ms | — |
| weather | 8.09 (3.73) ms | ~0 | 8/8 |
| rcm | 3.02 (1.42) ms | ~0 | 8/8 |
| load() | 86.5 (59.1) ms | 63.0 (56.0) ms | 8/8 |
| get_session + load() | 476.7 ms | 452.8 ms | 5/8 |

Of the min-based 4.8 ms net polars saving, ~2.7 ms is the lazy engine's one-time init. A polars
user pays it again on the first `filter`/`with_columns`/`select` over `laps`, since nearly every
polars Series/DataFrame op dispatches through `lazy().collect()`. Real builder work is ~3.1 ms,
about 2.6 ms net of the tier read: below the 3 ms bar, and inflated by the loaded box.

## Lever (a), direct builder rewrites

Not implemented: the tier probe removes all build work, so it bounds any rewrite from above.
From the stage split, the cheapest realistic rewrite saves about 1.5-2 ms first-touch on pandas:

* **rcm:** build the six string columns as object arrays straight from the payload lists, and
  parse `Sector` from the list. This leaves `pd.DataFrame` construction and `to_datetime`.
* **weather:** skip `to_numeric` on columns that are already float64.

Below the 3 ms bar and undetectable on `load()`.

## Files changed

None in `src/` or `tests/`. Only this report. Harnesses (scratch, not committed) are in

`probe_ab.py`, `order_probe.py`, `polars_engine_probe.py`.

## Risks of the rejected change (for the record)

A `session_frames` tier would add a table, a schema-version dependency, invalidation hooks
(json scope), a polars variant and a write on first build. That buys ≤3.8 ms that cannot be
seen on fresh-process `load()`, with half the polars part being deferred rather than saved.
