# Q19 — Driver paths and per-Session classification on a warm cache

**Verdict: KEPT.** `Driver.laps` without loaded session laps: 41.3 → 7.5 ms on the first
call and 25.1 → 4.5 ms on later drivers. The chart idiom `get_session(...).get_driver(d).get_fastest_lap()`
drops 38.1 → 9.1 ms. `session.drivers` on a new Session drops 4.8 → 3.3 ms. The candidate
was faster in 8/8 interleaved fresh-process pairs for every one of these. Parity is exact on
2026 Monaco and on 2,434 drivers from 122 sessions (2018-2025).

## Findings

### 1. Why `Driver.laps` was slow

If `session.laps` has not been loaded, `Driver.laps` builds the frame as
`_process_lap_df(_create_lap_df(payload))`. For a 66-lap driver that takes 23-35 ms per
driver in steady state, and 41 ms on the first call. Almost all of it is per-column pandas
overhead: 46 columns go through `__getitem__`, `isin`, `mask` and `astype`, and
`_replace_null_like_strings` alone accounts for about 45 %.

Separately, `Driver._load_laps` → `_fetch_laptime_payloads` re-derived **all 22 drivers'**
payloads from the session table on every call, even when the driver's payload was already
in memory. When not in ultra-cold mode nothing uses that result. Cost: about 1-2 ms per call.

### 2. Why slicing the warm laps frame does not work

The hypothesis asked how a slice of the session laps frame differs from the per-driver build.
`laps.pick_driver(d)` / the session slice differs from it in four ways:

- **`index` column.** In the slice it holds session row positions (356, 357, …). The
  per-driver build has 0..n-1.
- **Categorical columns** (`Driver`, `Team`, `Compound`, `TrackStatus`). The slice keeps
  the categories of the whole session; the per-driver build has only the driver's own
  sorted values. `remove_unused_categories` reproduces this.
- **Columns whose dtype is inferred from the data.** These are `str`/`object` columns, the
  object `_STR_COLS`, `LapStartDate` (`pd.to_datetime` picks the resolution from the
  strings: `[ns]` for 9-digit fractions, `[us]`, `[s]` when all values are null) and columns
  outside the dtype contract. Inference over one driver's values can give a different dtype,
  or a different missing-value representation (None vs NaN), than inference over the whole
  session. The slice also carries all-null columns that only other drivers have, and the
  extra columns can come in a different order.
- **Stale frame tier.** This is what ruled the slice out. In the 2018-2025 corpus, 16 drivers
  in 3 sessions have a laps frame tier that disagrees with the cached laptime payload: the
  payload has `compound: "None"`, the tier frame has `"ULTRASOFT"`, `"SOFT"` or `"MEDIUM"`.
  The sessions are 2018 Monaco R, 2021 Dutch FP1 and 2025 Belgian R. A slice with all the
  fixes above still returned the tier's values, while the control `Driver.laps` returns the
  payload's. Only a check of every value against the payload could catch this, and that
  costs as much as building the frame from the payload.

A prototype of the slice approach reached about 4 ms and matched exactly on Monaco. It was
replaced because of the staleness problem.

### 3. The shipped mechanism

**`build_driver_laps_frame`** (new `src/tif1/core_utils/driver_laps.py`) builds the frame
straight from the payload, with one Python pass per column. Each column is converted
the way the pipeline would convert it:

- `_replace_null_like_strings` semantics, including the exact-token probe before the
  strip/lower match.
- The shared `_seconds_to_td64ns` / `_td_cast_is_safe` cast for timedeltas.
- float64, Int64, bool and boolean columns per the contract.
- pandas `str` inference for string columns (NaN for missing; an all-None column stays
  object/None).
- `astype(object)` for the object `_STR_COLS`.
- Categoricals with sorted string categories.

Two kinds of column still go through the real `_apply_laps_dtypes`, restricted to those
columns: `LapStartDate`, and non-string columns outside the contract. For `LapStartDate` the
null-like tokens are masked first, so the pipeline's strip/lower pass is skipped.

If a contract column holds a value the fast rules do not cover, the function returns None
and `Driver.laps` runs the pipeline exactly as before. Examples: bools in float columns,
numeric strings, non-null-like strings in bool columns, floats in `WindDirection`, inf/huge
timedeltas, non-strings in categoricals. Overflow/Type/Value errors raised inside the
builder also fall back. The frame is assembled with `DataFrame._from_arrays(verify_integrity=False)`
so object columns are not re-inferred as `str`, then consolidated. Column order comes from
running the real `_rename_columns` on an empty frame, cached per payload key layout, plus
the FastF1 order now factored out as `_fastf1_laps_column_order`.

**`Driver._load_laps` shortcut.** When not in ultra-cold mode, a memoized or derivable
payload is returned directly instead of going through `_fetch_laptime_payloads`. The result
is the same object. In ultra-cold mode the old path is kept, because its backfill consumes
the derived payloads.

**`_summarize_pandas_laps_vectorized`** (`core.py`) replaces the row loop that called
`_clean_scalar` four times per row:

- per-driver `np.maximum.at` / `np.minimum.at` give the highest truncated lap ≥ 0, the
  position of the last row that reaches it, and the best non-deleted lap;
- the first usable car number is found per group with the same `_clean_scalar` rules;
- driver keys are cleaned with `_clean_scalar`.

It falls back to the loop when `LapNumber`/`LapTimeSeconds` are not float64 or when two
driver values clean to the same key. In-process on the Monaco frame: 2.29 → 0.82 ms.
Polars is unchanged.

## Protocol

- **Driver paths.** `tools/q19_driver_paths.py --ab`, 8 interleaved pairs (ABBA...), a fresh
  `python -I` process per run, the same cache copy for both arms. Load average was 2.5-5.
  Each run:
  - times `get_session`, then the first `get_driver("LEC")`, `.laps`, `.get_fastest_lap()`,
    `.get_lap(30)` and `.get_fastest_lap_tel()`, then `get_driver("HAM").laps`;
  - times the chart idiom on a new Session: `get_driver(d).get_fastest_lap()`;
  - times `drivers`, `drivers_df` and `results` on another new Session.
- **Whole load.** `tools/warm_cache_benchmark.py` on both src trees, 6 pairs.
- **Parity, Monaco.** `--dump`/`--compare` pickles every returned frame from both trees and
  compares them on: columns, columns-Index dtype, dtypes, index (and its type), `equals`,
  sorted block signature (dtype + placements), element types in object columns (None vs
  NaN), categorical codes dtype, class and `session` binding. The frames compared are
  `laps`, `get_fastest_lap`, `get_fastest_lap_tel`, the second driver's laps, the chart
  idiom, all 22 drivers' `laps` and `get_fastest_lap` on a new Session, `get_lap` (a Series),
  `drivers`, `drivers_df` and `results`.
- **Parity, corpus.** `tools/q19_corpus_gate.py`, run offline on a copy of `~/.cache/tif1`.
  For every driver of every session with a laps frame it compares `build_driver_laps_frame`
  with the pipeline using the same checks, and compares the vectorized summary with the row
  loop (dict items and order).
- **Fuzz.** 3 × 3,000 mutated payloads (`/tmp/tif1-q-Q19/fuzz.py`): null-like variants,
  numeric strings, bools, huge ints, inf, short columns, removed keys, and team "" or "None".
  The build must either match exactly or return None, and must return None whenever the
  pipeline raises.

| step | control | Q19 | faster pairs |
|---|---:|---:|---:|
| `Driver.laps`, first call after `get_session` | 41.26 | 7.49 | 8/8 |
| `Driver.laps`, second driver | 25.12 | 4.52 | 8/8 |
| chart idiom `get_driver(d).get_fastest_lap()` (new Session) | 38.10 | 9.06 | 8/8 |
| `session.drivers` (new Session, includes the laps tier read) | 4.77 | 3.27 | 8/8 |
| `drivers_df` / `results` after `drivers` | 0.57 / 0.80 | 0.56 / 0.82 | noise |
| `get_fastest_lap` (on loaded driver laps) | 3.82 | 4.07 | 0/8 † |
| `get_lap(30)` | 0.89 | 0.90 | noise |
| `get_fastest_lap_tel` | 5.71 | 5.53 | noise |
| `get_driver` first / second | 7.76 / 0.39 | 4.57 / 0.39 | ‡ |
| `get_session` | 372.5 | 376.2 | ‡ |
| whole driver flow (get_driver … second laps) | 84.98 | 27.45 | 8/8 |

- † `get_fastest_lap` is about +0.25 ms because the new frame's column Index has no hash
  engine yet; the pipeline frame got one warmed during processing. This is a one-time cost
  moved to the first column lookup, not new work. The flow as a whole is 57 ms faster.
- ‡ `get_driver` runs the same code on both arms; identical profiles were checked in-process.
  The −3.2 ms on `get_driver` and +3.7 ms on `get_session` cancel out: the sum is
  380.2 → 380.8 ms. This looks like a GC/allocation timing shift, not a code effect.

In-process best-of measurements:

- per-driver build for LEC (66 laps): 33.8 ms with the pipeline, 4.0 ms with
  `build_driver_laps_frame`;
- classification summary: 2.29 ms with the row loop, 0.82 ms vectorized.

Whole warm load, 6 pairs (pandas): `get_session` 0.386 vs 0.382 s (3/6), laps
0.0026 vs 0.0023 s, telemetry 0.0743 vs 0.0742 s (3/6), total 0.463 vs 0.464 s (3/6).
Neutral, as expected.

Polars `Driver.laps` gains only from the `_load_laps` shortcut: about 5.5 → 4 ms on later
drivers. The polars build itself is unchanged.

## Parity

- 2026 Monaco: no issues across 22 drivers and every compared object (`drivers`,
  `drivers_df` and `results` identical).
- 2018-2025 corpus: 2,434 of 2,434 drivers exact, 0 fallbacks, 0 mismatches. The 122
  session summaries match the loop exactly. One session (2024 Japanese FP1) was skipped
  because its payload is not cached and the gate runs offline. See `Q19_gate.json`.
- Fuzz: 0 mismatches in about 3,900 fast builds. Whenever the pipeline raised, the builder
  returned None.

## Risks

- `build_driver_laps_frame` re-expresses pipeline semantics, so it must follow any change to
  `_process_lap_df`, `_apply_laps_dtypes`, `_replace_null_like_strings` or
  `CATEGORICAL_COLS`. The randomized contract test compares against the live pipeline and
  will fail on drift. The rules are deliberately conservative: anything unusual returns None.
- It uses pandas private API that tif1 already relies on elsewhere: `DataFrame._from_arrays`
  and `_consolidate_inplace`.
- `Driver.laps` still returns a different frame depending on whether `session.laps` was
  loaded first: the slice has session `index` values and session-wide categories. That
  behavior was already there and is kept for parity.
