# Q17: the sync telemetry path and the negative-result cache

**Verdict: KEPT, with narrowed scope.** The read side (the sync path checks
`is_known_missing` before the CDN walk) shipped as Q16 and is not
re-implemented here. Q17 adds the write side: when the sync CDN walk ends in
all-4xx, it records the verdict, and a sync fetch that succeeds drops any stale
verdict. Both mirror `fetch_json_async`.

## Hypothesis
`Lap.telemetry`, `lap.get_telemetry()`, `_LapInternal.telemetry` and the per-ref
fallback of `Laps.telemetry` (`_telemetry_merged`) all reach the network through
`Session._fetch_json(_unvalidated)` → `PayloadLoader.get`. The control tree's
`PayloadLoader.get` never reads the `missing_payloads` tier, so each fresh
process re-walks every CDN for laps that exist nowhere. In the 2026 Monaco race
those laps are LEC 66, STR 58 and SAI 72.

## Mechanism / entry-point audit
- Every sync entry point goes through `PayloadLoader.get`: `Lap.telemetry`,
  `Lap.get_telemetry`, `Driver.get_lap(...).telemetry`, `_LapInternal.telemetry`
  (via `_fetch_telemetry`), and `_telemetry_merged`'s per-ref chain (via
  `_get_telemetry_payload_for_ref(allow_prefetch=False)`). No sync path calls
  `fetch_from_cdn` directly. `get_telemetry_batch` and frame-tier callers only
  read the cache.
- The async paths (`fetch_multiple_async`, bulk prefetch, the
  `fetch_all_laps_telemetry` P5 skip) already honour verdicts whenever
  `use_cache` is on.
- Remaining bypass, by design: ultra-cold reads (`use_cache=False` on both the
  sync and async paths) skip every cache tier, verdicts included. On a warm
  cache ultra-cold mode is never auto-enabled, because
  `_resolve_telemetry_ultra_cold_mode` is False when `_session_cache_available()`.
  So it only affects an explicit `ultra_cold=True`. That matches the async
  contract, so I left it alone.
- `iterlaps()` never reaches the 3 missing laps: their `LapTime` is NaN, so the
  default `require=["LapTime", "Driver"]` skips them (1445 of 1455 rows are
  yielded). The loop that does hit them is any per-row loop over all rows
  (`laps.iterrows()`, `laps.iloc[i]`), `Laps.telemetry` for those drivers, or
  direct single-lap access.
- Only the async path wrote verdicts before Q17. A session whose missing laps
  were only touched through per-lap or per-driver access (no bulk telemetry
  load, or a cache older than Sestos L2) never got a verdict. Q16's read-side
  check therefore found nothing, and every fresh process walked again.

## Change (on top of Q16's `payload_loader.py`)
`src/tif1/payload_loader.py`:
- New `PayloadLoader._set_missing_verdict(cache_key, *, missing)`. It is gated
  like Q16's `_known_missing` (`enable_cache`, session-scoped loader) and calls
  `Cache.record_missing` or `Cache.discard_missing`.
- `PayloadLoader.get`:
  - A `DataNotFoundError` from the fetch step records the verdict when
    `use_cache or write_cache`. CI mode turns both off, so it leaves the cache
    untouched, same as async.
  - After a successful fetch with `write_cache`, the verdict is discarded. This
    is a dict-membership check once the verdict map is loaded; it is needed
    because cache-bypassing reads can fetch a payload that still has a verdict.
- The exception and log behaviour is unchanged: the same `DataNotFoundError` is
  re-raised.

The diff relative to Q16's file is in `.agents/perf-pergamon/q/Q17-on-Q16.patch`: 3 hunks,
+28 lines. Relative to the wave base (122f1dd), the diff also contains Q16's two
hunks verbatim.

Tests: `tests/unit/test_q17_known_missing_sync.py` (5 tests):
- A sync all-404 walk records the verdict. The next `get` then raises the same
  exception type, message and context with zero transport calls.
- An expired verdict is re-probed.
- `enable_cache=False` neither reads nor records verdicts.
- A cache-bypassing fetch drops a stale verdict.
- Session level: `Lap.telemetry` and `Laps.telemetry` on a known-missing lap
  never reach the transport, and the result is empty or correct.

Harness: `tools/q17_known_missing_probe.py`, plus
`/tmp/tif1-q-Q17/{ab.sh,record_check.sh,clear_verdicts.py,merged_parity.py}`.

## Protocol
Fresh process per run, and a fresh copy of `/tmp/tif1-warm-q-base/cache.sqlite`
per run (identical content for every arm). For the stubbed runs,
`CDNManager.try_sources` and `try_sources_async` are patched to count the walk
and raise the all-404 `DataNotFoundError`. "Walks" counts CDN walks. Arms:
control = `/tmp/tif1-pergamon-control/src`; q16 = this tree with Q16's
`payload_loader.py`; cand = Q16+Q17.

## Risks / notes for the integrator
- **Conflict:** this tree carries Q16's hunks verbatim, plus Q17's. If Q16 is
  already merged, apply `.agents/perf-pergamon/q/Q17-on-Q16.patch` (3 hunks:
  `_set_missing_verdict`, the record-on-`DataNotFoundError` wrapper around
  `self._fetch`, and the discard after `_cache_set`).
- A `DataNotFoundError` from the fetch step is treated as all-4xx.
  `CDNManager.try_sources` raises it only when every source refused with
  403/404, the same rule the async path uses. A `Session._fetch_from_cdn` test
  override that raises it records a verdict in that test's isolated cache
  (`tests/conftest.py` isolates the cache dir per test).
- **Finding, not changed (parity):** for a driver with a known-missing lap,
  `Laps.telemetry` cannot use the P10 driver-row slice or the U11 frame concat,
  because the missing lap is not in the row. It falls back to the payload-merge
  build: about 80 ms for LEC versus 19 ms for ANT, a driver with no missing
  lap. The frame it builds differs from the tier slice: `DriverAhead` is
  `str` (payload merge) versus `object` (tier), and the block count is 19
  versus 11. Values and index are equal. So drivers with a missing lap get a
  differently typed frame than drivers without one. Dropping known-missing refs
  before the P10 lookup would give about a 4x speedup for those drivers, but it
  changes the output versus control. It needs a separate decision on which
  dtype is canonical.
