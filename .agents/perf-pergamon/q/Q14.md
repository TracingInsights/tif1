# Q14 — charts drawn from a warm session spend most of their time outside the data path

**Verdict: KEPT.** Import plus first chart plus savefig for a non-seaborn chart:
1.84 → 1.05 s median (−43 %). The candidate was faster in 8/8 pairs on both
chart sequences tested. All 18 charts that render on the snapshot give
byte-identical PNGs.

## Hypothesis

On a warm session the data path (laps from the tier: ~1 ms, telemetry: a few
ms) is a small part of a chart. The wall time goes into imports, matplotlib
construction and rendering. Part of that cost can be avoided without
changing the rendered output.

## Probe: where the time goes (fresh process, warm 2026 Monaco R, Agg)

`tools/q14_chart_probe.py` times `import tif1` → `import tif1.charts` → the
first chart call (construction, including warm data access) → `savefig` to a
BytesIO (png, dpi 150, `bbox_inches="tight"`) → a second chart in the same
process.

Control (frozen tree), one run each:

| Phase | speed_traces | gear_shifts | position_changes | laptimes_distribution |
|---|---:|---:|---:|---:|
| `import tif1` | 0.013 | 0.013 | 0.013 | 0.013 |
| `import tif1.charts` | **1.43-1.52** | (same) | (same) | (same) |
| build, first chart | 0.12-0.27 | 0.09 | 0.15 | 0.50 |
| savefig, first chart | 0.16-0.24 | 0.10 | 0.17 | 0.37 |
| build + save, second chart | 0.23 | 0.14-0.25 | 0.27 | — |

`-X importtime` of `import tif1.charts`: 1.68 s in total. Of that, **seaborn
is 0.74 s**, almost all of it `scipy.stats` (0.65 s), pulled in by
`seaborn._statistics`. `tif1.charts.lap_times` imports seaborn at module
level, so every chart pays for it, even though only 3 of the 22 charts use
seaborn. **`scipy.spatial` is 0.13 s**, imported at module level by
`tif1.charts.telemetry` for `ConvexHull`, which only the G-G diagram uses.
The rest is needed by every chart: `matplotlib.pyplot` 0.32 s, and pandas
and numpy through tif1 0.24 s.

Inside a chart (cProfile, then re-timed without the profiler):

- **Data access:**
  - first `get_session` 23 ms (events and session setup), then 0.75 ms per later call
  - `session.laps` 0.01 ms
  - `finishing_order` 3.5 ms per new Session (`_summarize_laps_for_classification` in core.py)
  - fastest-lap telemetry a few ms
- **Avoidable pandas overhead in the chart helpers:**
  - `sess.laps[sess.laps["Driver"] == d]["Team"]` takes the whole 46-column, 17-block lap frame for one column: 1.6 ms per call. Called once per driver in the team-color helpers.
  - `apply_common_filters` copies the frame, then takes it once per filter: 6.7 ms.
  - `plot_position_changes` filters and sorts the full lap frame once per driver: 36 ms for 22 drivers, to draw two columns.
- **matplotlib:**
  - first-use font lookups (`_findfont_cached`, ~45 ms once per process)
  - axes and tick construction
  - Agg draw
  - PNG zlib encode, ~60 ms per chart at PIL's default compression level
- **Already cheap, no change needed:**
  - `setup_mpl`, including timple: 0.1 ms after the first call
  - the branding fonts, which use `FontProperties(fname=...)` and skip font lookup
  - `lib="polars"`, which loads the pandas view: no conversion

## Changes (all in `src/tif1/charts/`)

1. **seaborn imported lazily.** `lap_times.py`: the module-level `import
   seaborn as sns` moved into the three functions that use it:
   `plot_driver_laptimes`, `plot_laptimes_distribution` and
   `plot_laptime_heatmap`.
2. **ConvexHull imported lazily.** `telemetry.py`: `from scipy.spatial import
   ConvexHull` moved into `plot_gg_diagram`.
3. **seaborn colormap names still work.** Importing seaborn registers 12
   colormaps (`rocket`, `mako`, `flare`, `crest`, `vlag`, `icefire`, plus the
   `_r` variants). It changes no rcParams (checked). Before this change,
   `plot_track_*_map(cmap="rocket")` worked only because seaborn was always
   imported. The new `_common.ensure_colormap(cmap)` imports seaborn only when
   a string cmap is not registered with matplotlib. It is used by
   `track_maps._draw_segment_map` and `plot_gear_shifts`, the only two places
   that resolve a user cmap outside seaborn.
4. **`_common.apply_common_filters` takes the frame once.** Every row filter
   is evaluated on the input frame and ANDed into one numpy mask, then
   applied with a single take (`laps_df.copy()` only when no filter applies).
   Row filters commute, so rows, order, index, dtypes and block count are
   unchanged. Time drops from 6.7 to 1.6 ms.
5. **Team-color helpers select one column.** The `_driver_team_color`,
   `_team_color_for_driver` and `_driver_team` helpers in `telemetry.py`,
   `track_maps.py`, `lap_times.py` and `performance.py` now use
   `sess.laps["Team"][sess.laps["Driver"] == driver]`: 1.6 → 0.44 ms per call.
   The Series is identical (values, index, name, category dtype).
6. **`plot_position_changes` loops over three columns.** The per-driver
   filter-and-sort runs on `laps[["Driver", "LapNumber", "Position"]]`:
   36 → 9.5 ms for 22 drivers. The sort sees the same values in the same
   order, so it produces the same permutation.

## Parity

- **Charts.** `tools/q14_chart_parity.py` renders every chart on the 2026
  Monaco R in both trees and compares PNG bytes and `np.asarray(Image)`
  arrays. Two layouts were run:
  - all 22 charts in one process: seaborn is imported mid-run in the
    candidate and at import in control
  - 11 charts one per fresh process, so seaborn is never imported in the
    candidate

  Result: 18/18 and 11/11 charts are byte-identical (so pixel-identical).
- **Pre-existing failures.** Four charts fail identically in both trees on
  this session:
  - `top_speeds`: `idxmax` on an all-NA speed-trap row
  - `qualifying_grid` on a race: argmin of an empty sequence
  - `telemetry_comparison`: NaN → int
  - `gg_diagram`: "No driver could be processed"

  Because of the `gg_diagram` failure, the lazy `ConvexHull` path is covered
  by the `tests/unit/test_charts.py` fake-session tests, not by this session.
- **Frames.** `apply_common_filters` on the real session, 12 filter configs
  (defaults, deleted and pit toggles, drivers, teams, n_drivers, laps, both
  cutoff scopes, combos, an empty result): `equals`, index, dtypes, column
  order, block count (17, or 31 after the per-driver concat) and `Laps` type
  all match control.

## Risks and notes for the integrator

- Code that relied on `import tif1.charts` (or `tif1.plot_*`) as a side
  effect to register seaborn colormaps with matplotlib, for its own
  non-tif1 plots, now has to `import seaborn` itself. tif1's own `cmap=`
  arguments are covered by `ensure_colormap`.
- The first seaborn chart in a process now shows the seaborn import (~0.7 s)
  in its own call time instead of at import. The total is unchanged.
- No core.py or cache changes, so no conflicts are expected with the
  data-path agents.
- **Not done:**
  - PNG compression level: changing it trades file size for speed and is not
    pixel-relevant, so it is the user's choice.
  - Avoiding `matplotlib.pyplot`: users rely on `plt.show()` and pyplot
    figures.
  - `_summarize_laps_for_classification` (3.5 ms per new Session; each chart
    call builds a fresh Session via `get_session`): it lives in core.py, which
    other agents are editing.
- The four chart failures listed under Parity are pre-existing bugs on 2026
  Monaco R and are out of scope here.
