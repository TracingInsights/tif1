# Q1 — lazy lap-frame materialization for `Session.load()`

**Verdict: KEPT.** Warm pandas `load()` 58.0 → 38.6 ms median (−33 %, 8/8
pairs); `fetch_all_laps_telemetry()` unchanged (eager, 1452 real frames);
first touch of a driver 4.3 → 3.4 ms (6/6). Trade-off: a lap touched after a
lazy `load()` pays its ~12 us build on first access (the fifty-laps idiom
measures +0.6 ms of building plus wherever the gen-1 GC lands).

## Hypothesis

After Pergamon, a warm `load()` spends ~30 ms of its telemetry phase in
`decode_driver_frames` building 1452 per-lap pandas frames from the 22
decoded driver rows (block slices, `BlockManager`, `Telemetry` object,
~11 us each), and most users then touch a handful of laps. Keep the decoded
group arrays per driver and build each lap's frame on first access.

## Mechanism

- `frame_codec.DriverFrameSource(blob, frame_class)`: parses the driver
  blob header, takes the writable body, runs `_group_parts` for every
  layout group (one `np.frombuffer` per block, whole-driver dictionary
  decode for object/str columns) and keeps `(columns, laps, row offsets,
  parts)` per group plus `lap -> (group, position)`. `frame(lap)` builds
  one frame as views of those arrays; `frames(wanted)` is the eager loop
  (`decode_driver_frames` now delegates to it; same views, same blocks).
- `Cache.get_telemetry_frame_sources(year, gp, session, drivers,
  frame_class)`: reads + decompresses the driver rows exactly like
  `_get_driver_frames` and returns `{driver: DriverFrameSource}`.
- `SessionMemo`: a second `"telemetry_df"` store, `_telemetry_sources`
  (`(driver, lap) -> source`). `get()` materializes a pending frame on
  first access (through `frame_adopter`, which `Session.__init__` binds to
  `_adopt_telemetry_frame` so the built `Telemetry` carries `session` and
  `driver` like an eager one), moves it into `_telemetry_dfs` and drops the
  pending entry; `contains`/`kind_size` count pending frames; `set()`
  replaces a pending entry; `items()` and `materialize_telemetry()` force
  the rest; `clear()` drops them.
- `Session.load(telemetry=True)` calls `_load_all_laps_telemetry()`: on a
  pandas session with the cache available it reads the lap refs, loads the
  sources for every driver with a ref not yet memoized, registers them,
  and only falls through to the eager `fetch_all_laps_telemetry()` when
  refs remain that the tier does not hold and the negative cache does not
  know as missing (legacy per-frame rows, payload tier, network — cold
  loads are unchanged). Polars sessions keep the eager call.
- `fetch_all_laps_telemetry()` is untouched as a contract: when called
  first it reads the tier eagerly as before; after a lazy `load()`
  `_memoized_telemetry` calls `materialize_telemetry()` once and returns
  the real frames.
- `_get_telemetry_df_for_ref` (single lap, no prior load): the driver's row
  is held as a source instead of being built in full (P6 built all 76 frames
  of the driver); a lap the row lacks falls through to the per-frame tier
  with `whole_driver=False` so the row is not decoded twice.

## Protocol

Fresh process per run, interleaved control/candidate pairs, control tree
`/tmp/tif1-pergamon-control/src`, private copies of the warm snapshot
(`/tmp/tif1-q-Q1/{control,candidate}/cache.sqlite`), 32-core box shared
with other agents' benchmarks (medians + per-pair wins).

1. Probe (`probe_split.py`, 3 fresh processes, best-of-5 in process on the
   22 Monaco driver rows): decompress only 7.2-9.0 ms, decompress +
   `_group_parts` 12.3-13.6 ms, full eager decode 28.7-29.8 ms — ~16 ms of
   per-lap construction deferrable per warm load.
2. `load()` A/B (`load_run.py`/`load_ab.py`: `get_session` + `load()` +
   one lap + `fetch_all`), 8 pairs.
3. `tools/pergamon_warm_ab.py` (fetch_all as the first telemetry call),
   2 x 8 pairs.
4. `tools/pergamon_idioms_bench.py` via `idioms_ab.py`, 6 pairs.
5. In-process codec micro (`codec_micro.py`: control module vs candidate
   module on the same decompressed blobs, best-of-5 x 3 rounds) for the
   eager refactor.
6. Parity (`parity.py`): control `fetch_all` frames vs (a) candidate
   `load()` then every lap touched one by one through `Lap.telemetry` in
   reverse laps order, (b) candidate `load()` then `fetch_all`. Class name,
   columns, dtypes, block classes, index, `DataFrame.equals`.

| idiom | control | candidate | faster |
|---|---:|---:|---|
| first lap of a driver (no prior load) | 4.275 | **3.385** | 6/6 |

The fifty-laps row: the 50 laps are all ANT (rows 200-250), whose row was
already held after the first idioms. Instrumented (`gc_probe.py`,
telemetry access only, rows pre-sliced): control 0.13 ms (memo hits),
candidate 2.37 ms = 50 x ~12 us builds + a gen-1 collection (1.6 ms) that
lands inside the loop — the control runs the same collection during the
preceding `iloc` slicing (P6 built the 76 frames under `_suspend_gc`). So
the real cost is ~12 us per touched lap; the bench's +3 ms is that plus GC
placement, on a loop dominated by pandas row access (7.3 ms of `iloc`).

Parity: 1452/1452 frames equal for both candidate paths (type `Telemetry`
with the session attached, columns, dtypes, block classes, index, values);
`lazy pending at load: 1452`, no pending source left after the sweep.

## Risks / notes for the integrator

- Behavioural: after `load()`, `session._memo._telemetry_dfs` is empty
  until laps are touched; code that inspects the memo store directly must
  use `memo.get`/`contains`/`kind_size` (tests in the tree do not touch the
  dict). Every public path (`Lap.telemetry`, `Laps.telemetry`,
  `fetch_all_laps_telemetry`, `get_fastest_lap_tel`) goes through
  `SessionMemo.get`.
- Frames built lazily are views of the same body the eager path uses, so
  mutation semantics are unchanged (the body is shared per driver either
  way).
- A lazy `load()` followed by `fetch_all_laps_telemetry()` costs ~2 ms more
  than before in total (per-ref memo work on 1452 refs); a user who only
  calls `fetch_all` is unaffected.
- The per-lap first-access cost (+12 us) is the mechanism; the GC
  placement effect on a tight loop over one driver's laps is
  measurement-visible (fifty-laps idiom) but not a real cost increase.
- Functions changed: `core.py` `Session.__init__` (one line binding
  `frame_adopter`), `Session.load` (calls the new
  `Session._load_all_laps_telemetry`), `Session._get_telemetry_df_for_ref`
  (lazy driver source before the tier read), `Session._memoized_telemetry`
  (one `materialize_telemetry()` call); `cache.py` `SessionMemo.__init__`,
  `get`, `contains`, `items`, `kind_size`, `set`, `clear`, new
  `add_telemetry_source`, `_materialize_telemetry`, `materialize_telemetry`,
  new `Cache.get_telemetry_frame_sources` (placed just before
  `get_driver_merged_frame`); `frame_codec.py` new `DriverFrameSource`,
  `decode_driver_frames` body. `Cache._get_driver_frames` and
  `_decompress_frame_rows` are NOT modified (Q11 rewrote them);
  `get_telemetry_frame_sources` only calls `_decompress_frame_rows(rows,
  min_parallel=2)` and copies the SQL of `_get_driver_frames` — after
  merging Q11 it should adopt Q11's read path (streamed cursor / shared
  pool) the same way `_get_driver_frames` does.
