# Q4 — laps frame tier consolidation / `Laps.pick_*` cost

**Verdict: KEPT (re-scoped).** The hypothesis as stated, that the frame served
from the laps frame tier is poorly consolidated, is **falsified**. The cost
was elsewhere: the pandas subclass constructor path re-wrapped every
selection through `Laps.__init__` / `Lap.__init__`, and that made a shallow
manager copy each time. Removing it makes every `pick_*` 15-28 % faster
(8/8 fresh-process pairs), the tier read is unchanged, and parity is exact.

## Probe (falsifies the consolidation lever)

Warm 2026 Monaco GP Race laps from `laps_frames` (`Cache.get_laps_frame`),
1455 rows x 46 columns:

- `laps._mgr.nblocks` = **17**, `laps._mgr.is_consolidated()` = **True**,
  which is the same layout the Argos A4 build produces. The tier pickles the
  consolidated frame and unpickling keeps it. Block dtypes: 1 per kind
  (float64 x14 cols, timedelta64 x12, bool x5, object x2, int64, datetime64,
  Int64, boolean) plus 4 categorical and 5 `str` (Arrow) extension blocks,
  which cannot be merged.
- Nothing to consolidate or canonicalise before the tier write. The polars
  tier has no block layout.

Split of one `laps[mask]` (0.27-0.28 ms, best-of-300, in-process):

| step | ms |
|---|---:|
| `isin` mask on the categorical `Driver` | 0.10 |
| `mgr.take` (17 blocks; the 5 Arrow `str` blocks are ~8 us each) | 0.16 |
| `Laps(df)` re-wrap (`_constructor_from_mgr` -> `__init__` -> `mgr.copy(deep=False)`) | **0.065** |
| plain `DataFrame[mask]` on the same frame, for reference | 0.175 |

## Mechanism

pandas 3 builds every result of a DataFrame/Series operation (take, column
get, row xs, isna, ...) from a fresh manager. For a plain DataFrame,
`_constructor_from_mgr` wraps it with `_from_mgr`. For a subclass it calls
`self._constructor(df)`, and `DataFrame.__init__(df)` / `Series.__init__(ser)`
then shallow-copies that just-built manager (~65 us per frame result on 17
blocks). `Laps` results and every `Lap` column Series paid this. `Lap` is
`_constructor_sliced`, so each `self["Driver"]`/`self["LapTime"]` inside a
pick and each `.notna()` on it paid too.

Change (`src/tif1/models.py`):

- `Laps._constructor_from_mgr(mgr, axes)`: `Laps._from_mgr(...)` and
  `session = None` (what `__init__` sets).
- `Laps._constructor_sliced_from_mgr(mgr, axes)`: `Lap._from_mgr(...)`,
  `_name = None` (pandas contract: the caller sets the name),
  `session = None`.
- `Lap._constructor_from_mgr(mgr, axes)`: the same for `Lap`.

`__finalize__` still propagates `session` (and `_name`) from the source,
exactly as before. The `pick_*` bodies are unchanged. A categorical-code
mask was measured (0.03 vs 0.10 ms for `isin`), but it was not adopted:
the gain is smaller and it adds a second code path for hand-built frames.

## Parity

Cross-tree dump (control vs candidate, fresh processes, compared as plain
pandas): **0 mismatches over 50 entries**. Each entry compares the value
(`equals`), type, index, column order, dtypes, Series name and dtype, the
result's class (`Laps`/`Lap`), `session is <the session>` and `nblocks`.

- Covered: the full laps frame and every `pick_*` variant (driver by code,
  number and dict; quicklaps; fastest with and without `only_by_time`; a
  driver's fastest; lap, laps by list/int/slice/open slice; team(s); tyre;
  compounds; track status `equals`/`contains`; wo_box; box_laps
  both/in/out; not_deleted; accurate; a chained pick).
- Also covered: `iloc`/`loc` rows, column get, `notna`/`isin`/arithmetic on a
  column, row label slice, column subset, `copy` (deep and shallow),
  `sort_values`, `head`, `reset_index`, `groupby().min()`/`.first()`,
  `pd.concat`, `assign`, `dropna`, row-wise `apply`, `iterrows`, `describe`.
- Mutation isolation: writing to a pick result or a column Series does not
  reach the session frame. Both trees agree.

## Risks

- The hooks are private pandas API (`_constructor_from_mgr` and
  `_from_mgr`, both since pandas 2.1; the floor is 3.0.6). If pandas ever
  stopped calling them, the code would fall back to the default path,
  which is slower but correct. The new test pins the behaviour.
- The result no longer gets the defensive shallow copy that `__init__` gave.
  That is the same isolation a plain DataFrame gets, because pandas passes a
  manager built for the result. The mutation-isolation checks cover it.
- `Driver`, `Telemetry` and `SessionResults` keep the default path
  (out of scope).
