# Q3 — trim tif1's own share of the `import tif1.core` chain

**Verdict: REJECTED (below threshold).** The whole tif1-attributable part of
the chain is ~9 ms; the only deferrable piece that the warm path does not
need at import is ~3 ms, and half of that comes back in the first telemetry
build. Measured paired win on import: +2.7 ms median (22/25 pairs), under
the 5 ms bar. The working change is kept as `Q3.patch` next to this file
(3 files, 38 insertions, lint/ty/tests green) in case the integrator wants
the 2.7 ms for import-only / laps-only processes; it is not committed to
`src/`.

## Hypothesis

`python -X importtime -c "import tif1.core"` is ~250-290 ms of which pandas
and numpy are untouchable; the remainder attributable to tif1 was estimated
at 15-25 ms and should be deferrable (lazy imports, probes on first use).

`tif1/__init__.py` holds nothing heavy (the 7 ms cumulative quoted in the
task is `exceptions` + `logging`/`typing`/`urllib.parse`, which pandas
imports anyway and are simply attributed to whichever module is first).

What is left is pyc loading + class-body execution of the three big modules
(`core`, `cache`, `helpers` ~4 ms together) and codecs the warm path needs
(sqlite3, orjson, zstd ~1 ms). Neither is deferrable without restructuring
the modules or moving work into `get_session`.

## Mechanism tried

1. `helpers._probe_direct_blocks` (the pandas-internals round-trip guard)
   runs on first use via `_direct_blocks_ok()`; every direct-block entry
   point (`_frame_from_columns`, and `encode_frame`/`decode_frame`/driver
   codec in `frame_codec.py`) calls it, so the guard still runs before the
   first direct block build. `_DIRECT_BLOCKS_OK` stays a module global
   (`None` = not probed; tests pin it to `False` as before).
2. `cdn.get_cdn_manager()` builds the `CDNManager` singleton on first call
   (double-checked lock) instead of at import; a warm load never calls it.

Not touched (warm path needs them): sqlite3, orjson, zstd, lz4 (0.2 ms,
compression side only, not worth the seam), pandas/numpy, asyncio.

## Protocol and numbers

Control = `/tmp/tif1-pergamon-control/src` (HEAD except the three files);
candidate = this worktree. Fresh process per run, interleaved A/B.

**tif1-attributable import** (numpy+pandas imported first, then
`import tif1.core` timed; 25 pairs):

| arm | min | median |
|---|---:|---:|
| control | 8.55 ms | 9.11 ms |
| candidate | 6.23 ms | 6.47 ms |
| paired delta | | **+2.69 ms median**, 10-90 pct [0.0, +6.8], candidate faster 22/25 |

Min-of-5 importtime self sum of the same modules: 9153 -> 6170 us (−3.0 ms:
helpers 2200 -> 507, pyarrow.pandas_compat/vendored.version 945 -> 0,
cdn 417 -> 381).

**Whole `import tif1.core`** (25 pairs, box shared with other agents):
control min 232.7 / median 287.5 ms, candidate min 223.4 / median 275.1 ms,
candidate faster 16/25 (p≈0.11 on a sign test). A second 25-pair batch run
while the unit suite was executing gave 9/25 and min delta −1.3 ms; the
between-batch spread of the control min alone (206 vs 232 ms) is far above
the 5 ms resolution the verdict needs, which is why the isolated measurement
above is the one that counts.

**Warm phases** (`tools/pergamon_warm_ab.py`, pandas, 8 pairs, each arm on
its own copy of `/tmp/tif1-warm-q-base/cache.sqlite`):

| phase | control median / min | candidate median / min | candidate faster |
|---|---:|---:|---|
| get_session | 0.2750 / 0.2140 s | 0.2712 / 0.2487 s | 6/8 |
| laps | 0.0016 / 0.0014 s | 0.0015 / 0.0015 s | 3/8 |

The telemetry phase picks up ~1.5 ms: the probe (~1 ms) and the
`pyarrow.pandas_compat` import (its `pa.array(..., from_pandas=True)` for
str columns in `frame_codec` is the same lazy trigger) now run there. For a
full warm load the change is neutral; the win exists only for processes that
never build a telemetry frame.
