# Q8: Telemetry analysis methods on cached laps

**Verdict: KEPT.** All 22 measured methods and idioms are faster; 20 of them win at least 5 of 6 interleaved pairs in both runs. The one exception is `add_driver_ahead` without existing columns: −1 to −3 %, which is noise. It was not touched; it only benefits from the class-wide change.
Parity: 32 120 / 32 120 method outputs on the full 1452-frame session (plus fastest laps and driver-merged frames) and 414 / 414 synthetic edge cases match the control tree.

## Hypothesis

The `Telemetry` methods that users call per lap do pandas work that can be avoided. The candidates were:

- re-wrapping the frame on every pandas op;
- deep copies before assignment;
- `pd.to_timedelta` on columns that are already `timedelta64`;
- interpolating columns that have no NaN;
- Series chains for arithmetic that numpy can do directly.

## Mechanism (what the profile showed, what changed)

1. **Every pandas op on a `Telemetry` paid two wraps.**
   - pandas 3 builds each result as `DataFrame._from_mgr` and then calls `Telemetry(df)`. Its `__init__` shallow-copies the manager again, which costs 40–90 µs under copy-on-write.
   - Column access did the same through `Series(ser)`.
   - So `copy()`, `iloc`, boolean masks, `sort_values` and `drop` all paid the extra wrap, and so did every method built on them. `_wrap` then added one more `Telemetry(frame)` copy.
   - Fix:
     - `Telemetry._constructor_from_mgr` now adopts the fresh manager with `Telemetry._from_mgr`. Metadata starts as None, exactly as `__init__` leaves it, and pandas' `__finalize__` fills it in.
     - `_constructor_sliced_from_mgr` returns the plain Series.
     - `_wrap` re-tags a fresh `Telemetry` result in place. It also resets attrs and flags, as `Telemetry(frame)` did. When the frame is `self` or not a `Telemetry`, it uses the old path.
     - Subclasses of `Telemetry` keep pandas' default route.
2. **`integrate_distance` / `calculate_differential_distance`** built about 10 intermediate Series (`to_numeric`, `fillna`, `/3.6`, `to_timedelta`, `total_seconds`, `diff`, `clip`, `*`, `cumsum`).
   - They now do the same arithmetic in numpy: `asi8 / pps` seconds, NaN and NaT become 0, `diff` is clipped at 0 with the same `>= 0` rule, then `np.cumsum`.
   - This fast path runs only for float64 `Speed` with a numpy timedelta `Time` in s/ms/us/ns and unique columns.
   - If the step array contains a NaN (for example inf × 0), `integrate_distance` falls back to pandas, because pandas' skipna `cumsum` behaves differently in that case.
3. **`fill_missing`**
   - Removed: a deep copy, two column lookups per column, and `interpolate` on columns that have no NaN.
   - It now reads dtypes once and interpolates only non-float64 columns or float64 columns that contain NaN.
   - It still assigns every numeric column, so the block layout of the result is unchanged. Int64 columns are still interpolated, because that turns them into Float64.
4. **`merge_channels` / `resample_channels`**
   - Both made deep copies and re-assigned `Time` through `pd.to_timedelta`.
   - That step is now skipped when `Time` is a numpy timedelta column alone in its block. `to_timedelta` is the identity for every m8 unit, and the reassignment only moved the block, so the block count stays the same.
   - `resample_channels` takes `Time` plus the numeric channels before the NaT filter, `set_index` and `sort_index`, so the text and object columns are no longer carried through them.
   - `dropna` runs only when there is a NaT.
5. **`add_differential_distance`, `add_relative_distance`, `add_track_status`, `merge_channels`** now use `_owned_copy()`.
   - This is a shallow copy, which copy-on-write makes safe to modify.
   - For unconsolidated frames it stays a deep copy, because `copy(deep=True)` consolidates and the layout has to match.
   - `calculate_driver_ahead` skips `to_numeric` on float64.

Not changed:

- **`merge_asof` internals.** About 70 % of what remains in `merge_channels` is pandas' column-index work, mostly engines over the `str` column Index. Replacing `merge_asof` with a hand-rolled searchsorted could not guarantee exact parity.
- **Building the `fill_missing` manager directly.** About 0.7 ms of `setitem` remains. Removing it would mean more pandas-internals coupling for a method that is rarely called.
- **`slice_by_time` arithmetic.** Timedelta unit semantics make an exact numpy rewrite risky.
- **`add_distance` / `add_driver_ahead` without existing columns.** These frames are rare: tif1 telemetry always carries both columns.

## Protocol

- **Corpus:** a copy of `/tmp/tif1-warm-q-base/cache.sqlite` (2026 Monaco GP Race) and frames from `session.fetch_all_laps_telemetry()`.
- **Reference frame:** HAD lap 3, 580 rows, 19 columns, 8 blocks.
- **Per-method timing:** best-of-200, in-process, in a fresh process per arm, with 6 interleaved control/candidate pairs, run twice. The control is the frozen tree `/tmp/tif1-pergamon-control/src`.
- **Machine conditions:** load average 8–17 from other agents, and the CPU governor was `powersave`. Absolute numbers are therefore about 1.5–2× the brief's, but the ratios are stable across both runs.
- **"Comparison notebook" (fresh process):**
  1. Pick the fastest laps of 4 drivers and call `get_telemetry()`.
  2. For each lap: `add_distance()`, `merge_channels(ref)`, `resample_channels("0.1s")`, `fill_missing()`, `slice_by_time(10, 30)`, `add_differential_distance()`, and a boolean selection.
  3. Run a distance-indexed delta.
  4. Time the analysis block.
- **Parity:**
  - **Full corpus:** every method in the bench (plus `copy`/`iloc`/mask/column access) was run on all 1452 frames, the 4 fastest laps and 4 driver-merged frames (about 33 k rows each). The comparison digest covers:
    - type, `driver`, `session` identity, attrs, flags, block count, columns and column-index dtype, the index (pickled), and per-column dtype + value bytes;
    - for Series: name, dtype and index;
    - for exceptions: type and message.
    - The digest ignores block order and view-vs-owning buffers. Neither is observable through `equals` or the dtypes.
  - **Edge cases:** 19 synthetic frames covering:
    - NaN `Speed`, NaT `Time`, float-seconds `Time`, `m8[ms]` `Time`, int and Float64 `Speed`, inf `Speed`, `Time` running backwards;
    - unconsolidated frames, `SessionTime`+`Time`, attrs and `allows_duplicate_labels=False`, duplicate columns;
    - reversed and unsorted rows, empty frames, no `Time`.
  - Each edge case was run through 22 calls including `join`, `base_class_view`, a pickle round-trip and a mutation-isolation check. The results match the control exactly, including the same 9 exceptions.

## Risks

- **Private pandas hooks.** `_constructor_from_mgr`, `_constructor_sliced_from_mgr`, `_from_mgr`, `_mgr.blknos` and `_mgr.is_consolidated()` are private. Pergamon P1 and P6 already rely on `_from_mgr` and `BlockManager`. A pandas upgrade that changes these hooks would surface in the new contract tests.
- **Fresh results are re-tagged in place.** `_wrap` mutates fresh `Telemetry` results instead of copying them. Every internal caller passes a result it owns. `frame is self` and non-`Telemetry` inputs keep the copying path.
- **Buffer ownership differs.** Results now own their extension-array buffers instead of holding shallow views, and blocks can be in a different order. This is not observable through `equals`, the dtypes or values, and the block count is unchanged. It does change the bytes of `pickle.dumps(frame)` for an identical frame: the pickle size differs by about 13 bytes per extension column.
- **Q7 also edits `models.py`.** Q7 works on `Laps.iterlaps` and row access; every Q8 edit is inside `class Telemetry`, so a textual conflict is unlikely.
