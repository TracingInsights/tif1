# Corinth C2: a pre-2018 (Ergast-only) session, cold

## 1. Hypothesis

A cold Ergast-only session (`get_session(1998, "Monaco", "R").laps`) took
1.3-6.5 s against ~25 ms warm. The hypothesis was that most of this is
request structure rather than data: sequential round trips, redundant
requests, and lookups for data that cannot exist. Tracing first and then
removing what the trace shows should cut the cold time several-fold, with
identical frames.

## 2. What changed

A request trace (`tools/perf/corinth_c2_trace.py`, every `get_json` with
start/end/thread/status) of cold 1998 Monaco, 2010 Monza, 1975 British and
1955 Monaco on the control showed three costs:

1. **Lookups for tables Ergast does not have.** Ergast has lap timings from
   1996 and pit stops from 2011 (Ergast's documented coverage; checked on
   Jolpica: `1995/17/laps` and `2010/19/pitstops` give `total: 0`, `1996/1/laps`
   and `2011/1/pitstops` have rows). The control still asked for
   `pitstops.json` on every 1996-2010 race and `laptimes.json` on every
   pre-1996 race. Each lookup was a jsDelivr 404 or 403 (a 404 over the stdlib
   bridge first, then the niquests import and the same request again), a
   StaticDelivr 404, and finally an empty Jolpica page. That is 1.2-3.6 s per
   cold session, 60-90% of the cold `laps`. jsDelivr answers 403 "Package size
   exceeded the configured limit of 50 MB" for a missing file of the Stats
   repository. A 403 is treated as transient, so the walk also slept 1 s and
   retried, and the miss was never persisted. Warm-cache sessions online
   repeated the walk, and offline they raised `NetworkError` on `laps` (1975
   British, polars). Now `_ergast_table_covers(endpoint, year)` (`core.py`,
   with `ERGAST_FIRST_LAPS_SEASON = 1996` and `ERGAST_FIRST_PIT_STOPS_SEASON =
   2011` in `core_utils/constants.py`) makes `_ergast_table_race` return
   `None` for those tables without a request. `None` is exactly what the
   empty Jolpica answer produced, so the frames are unchanged.
2. **A first wave of files that do not exist.** `get_session` starts the
   stdlib first wave (Elis E2) on `drivers.json`/`session_laptimes.json` of the
   per-year repository, which has no pre-2018 folders: 404s while pandas
   imports. Now `_preconnect_cdn` gives an uncached Ergast-only session the
   Stats files it will read (`_ergast_first_wave_urls`): `{year}/events.json`,
   the classification (`results`/`quali_results`/`sprint_results`), and for a
   race, `laptimes.json` and `pitstops.json` when the season can have them.
   The folder is the event name's slug, the rule `_ergast_session_cached`
   already uses; a renamed folder only leaves bodies untaken. These files come
   from cold jsDelivr edges (0.2-2 s each), so this wave's `take` waits up to
   the request timeout (`first_wave.start(..., wait_limit=)`; the default
   stays `WAIT_LIMIT` = 3 s for the timing wave, and the argument is only
   passed for the Ergast wave).
3. **Sequential files.** `_ergast_laps` read the classification, then the lap
   timings, then the pit stops, one round trip each. Now
   `Session._prefetch_ergast_tables` fetches the files the session still
   needs in one parallel wave (`ErgastPayloadLoader.stats_payloads`, the
   existing thread-pool fan-out) before the readers run. It only fills the
   payload memo; the readers keep the same Stats-then-Jolpica routing and
   error behaviour. It skips offline mode, a memoized classification, fresh
   cache entries, and waves of one file. This matters when (2) did not run
   (a second session in the process, `cdn_preconnect` off).

While measuring the 1975 British race (asked for as "British"), a warm
polars `get_session` turned out to spend ~120 ms importing numpy for the
fuzzy event-name matcher (`fuzzy.py`, `np.zeros`/`flatnonzero`/`argmax` on a
few dozen ratios). A polars session never imports numpy otherwise (Elis E6,
Naxos N3). The matcher now uses lists. It returns the same results with the
same types: 12,030 random query/reference cases compared with the control's
numpy version gave 0 mismatches (`.scratch/fuzzy_eq.py`, not committed). A
polars Ergast-only session (`get_session` + `laps` + `results`) now never
imports numpy (new fresh-interpreter test). This overlaps C9's
schedule/resolution path; see the notes.

Files: `src/tif1/core.py`, `src/tif1/core_utils/constants.py`,
`src/tif1/first_wave.py`, `src/tif1/fuzzy.py`;
tests `tests/unit/test_corinth_c2_ergast_cold.py` (new, 13 tests),
`tests/unit/test_preconnect.py` (the `first_wave.start` double accepts
`wait_limit`); tools `tools/perf/corinth_c2_trace.py` (request trace),

## 3. Measurements

`get_session` + `laps` + `results` + `drivers`; control `/tmp/corinth/control/src`
(552c357) vs this tree; arms alternate ABAB/BABA per rep. Cold runs get an
empty cache per run and use the live CDN. Warm runs use a cache each arm
primed itself, because the candidate stores fewer entries. Warm runs are
online, because the control cannot answer 1975 British offline (see 2.1).
The box had a load average of 25-30 from other agents throughout, which
shared the network too (C1/C3/C4 fetch Stats/Jolpica/CDN files). Times are

## 4. Verdict

**SHIP.** Cold Ergast-only sessions are 2.2-5.4x faster on the whole
process (pandas 1.6-2.2 s -> 0.72-0.78 s, polars 2.1-2.8 s -> 0.51-0.64 s,
every pair won). Cold `laps` drops from 0.9-1.5 s to 3-38 ms. The
fuzzy-matcher change is an independent 28% warm win for polars sessions
whose event name is resolved fuzzily. Frames are identical and no warm path
regresses.

## 5. CHANGELOG

- Cold pre-2018 (Ergast-only) sessions load 2-5x faster: 1998 Monaco
  `get_session` + `laps` + `results` 2.06 s -> 0.72 s on pandas, 2.81 s ->
  0.52 s on polars, and the same on 2010 Monza, 1975 British and 1955
  Monaco. A session no longer asks for lap timings before 1996 or pit stops
  before 2011, which Ergast does not have. Each such lookup was a jsDelivr
  404/403, a StaticDelivr 404 and an empty Jolpica page, 1.2-3.6 s, and a
  warm cache could not answer it offline. `get_session` now starts the
  round's Stats files (season index, classification, lap timings, pit stops)
  while pandas or polars imports, in place of the timing files that do not
  exist before 2018. The lap timings and pit stops of a round are fetched in
  one parallel wave instead of one after another. Fuzzy event-name matching
  no longer imports numpy: a polars `get_session(1975, "British", "R")` is
  394 -> 282 ms warm.

## 6. Notes for the integrator

- **Coverage constants.** `ERGAST_FIRST_LAPS_SEASON`/`ERGAST_FIRST_PIT_STOPS_SEASON`
  hard-code Ergast's coverage. If Jolpica ever back-fills older lap timings
  or pit stops, tif1 will not ask for them until the constants move. The gate
  covers the `Session` paths only (`_ergast_table_race`, `laps`, `pit_stops`);
  `tif1.ergast` interface queries (`Ergast().get_lap_times(1975, 10)`) still
  walk the mirrors to Jolpica. C3 owns the router; the same gate in
  `router._stats_laps`/`_stats_pitstops` would save it there too.
- **jsDelivr 403 on missing Stats files.** jsDelivr answers 403 ("Package size
  exceeded the configured limit of 50 MB") for a Stats file it does not hold,
  not a 404. `payloads._fetch_stats` treats any 403 as transient: a 1 s sleep,
  a second walk, and no persisted verdict. So a genuinely missing file (for
  example `quali_results.json` of seasons without qualifying data, or a
  sprint file) re-walks with the sleep in every process, and offline it
  raises. The year gate removes the two common cases; a general fix (persist
  a miss when StaticDelivr says 404 and jsDelivr says 403) is a C3/router-level
  change that I did not make.
- **First-wave slug.** The wave guesses the folder from the event name (the
  `_ergast_session_cached` rule). When the Stats folder differs, the bodies
  are fetched for nothing (bounded, daemon threads) and the session fetches
  the right ones as before. The prefetched lap timings are speculative for a
  user who reads only `results`; `load()` builds the laps of an Ergast-only
  session anyway.
- **Error paths.** On a failed file, `_prefetch_ergast_tables` returns the
  error to nobody and the reader fetches again, so a total outage pays the
  mirror walk twice. Offline with an empty cache, `laps` and `pit_stops`
  still raise `NetworkError` as before, because both read the classification
  first.
- **Polars `laps` warm.** The remaining warm cost of a polars Ergast-only
  `laps` (~37 ms vs ~25 ms on pandas) is the process's first polars query
  plan in `_process_polars_laps` (~35-55 ms the first time, 3-5 ms after). It
  is shared with cold modern polars laps; a plan-free version is a follow-up.
- **Overlap with C9.** `fuzzy.py` is on the event-resolution path C9 may also
  touch.
- **Measurement scripts.** `tools/perf/corinth_c2_bench.py` and
  `corinth_c2_trace.py` are new; nothing in the main harness was copied or
  modified.
