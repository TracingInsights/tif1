# C10: one bundle file per session (`session.v1.bin`)

## 1. Hypothesis

A cold session pays one request per small file it reads: `drivers.json` and
the session laptimes (the first wave, during the pandas/polars import), then,
one after the other, the weather and race-control tables, the Stats season
index and the session's classification (another repository), and
`session_info.json`. A season loop pays the laps wave and the classification
per race. Putting those files, byte for byte, in one compressed file next to
the session's files (the N7/G3 pattern: a new data-repository file, an encoder
in `tools/data/`, a reader that asks for it first and falls back to the
per-file JSON, off by default until published) should take every round trip
after the first off the cold critical path, with frames and payloads
unchanged.

Live trace first (this box, jsDelivr ~15 ms per request; `get_session` + `load()`
+ `results` + `t0_date`, pandas): first wave (2 files, 65-120 ms incl. TLS,
inside the import), then `rcm`+`weather` (15 ms, parallel), `events.json`
(16 ms) -> `results.json` (15 ms), `session_info.json` (15 ms), sequential. A
live 4-race loop (`get_session(2025, r, "R")`, `laps`, `results`) took 60-70 ms
per race here: the laps wave (22-32 ms) plus the classification (16 ms) in
sequence (I could not reproduce the survey's ~650 ms per race; the link was
quick at the time).

## 2. What changed

Format (`design/SESSION_BUNDLE_FORMAT.md`): `{year}/{gp}/{session}/session.v1.bin`
= magic `TIF1SES\x01` + u64 body size + one zstd frame (content checksum) of
`u32 head size | head JSON | bodies`. Head: `format`, `built_at` (epoch s),
`entries` (`[name, size]`), `absent`. Entries: `drivers.json`,
`session_laptimes.json`, `session_info.json`, `weather.json`, `rcm.json`, plus
the Stats files under their cache keys (`stats/{year}/events.json`, the season
index, and `stats/{year}/{slug}/{results|quali_results|sprint_results}.json`,
the file tif1 reads for the session). Bytes are the files' bytes after content
decoding: every parser downstream is unchanged.

Files:

- `src/tif1/core_utils/session_bundle.py` (new): codec (`encode_bundle`,
  `decode_bundle`, `SessionBundleError`); orjson + zstd (`zstandard` below 3.14,
  `compression.zstd` from 3.14); no numpy/pandas.
- `src/tif1/session_bundle.py` (new): the reader. `start()` downloads a
  session's bundle once per process (a future in the fetch pool, shared by
  every caller); `_load` takes it from the stdlib first wave when the wave
  carried it (`first_wave.take_status`), else `transport.get_bytes` per mirror;
  a primary-CDN 404 is remembered in the missing tier (and the process);
  transport failures and unreadable bundles fall back to the files without a
  verdict. `member()`/`member_async()` hand out a member's bytes, `ABSENT`, or
  None (fetch the file). On decode the Stats entries are held for the Ergast
  tier and a background writer (`register_frame_writer`, joined at close/exit)
  fills the payload tier with every member the cache lacks, as a fetch stores
  it (bytes; the validated object when a validator is on and changed it),
  records `absent` members as missing, and writes the Stats entries as
  `{"fetched_at": built_at, ...}` unless the tier holds a newer one.
- `src/tif1/async_fetch.py`: `fetch_json_async` asks the bundle for a member
  after the cache/offline checks and before the CDN walk (`_bundle_member`:
  parse off-loop, validate as a fetched file; absent -> missing verdict +
  `DataNotFoundError`).
- `src/tif1/payload_loader.py`: `PayloadLoader.fetch_from_cdn` does the same
  for the sync loader (`session_info.json`, the ultra-cold drivers path); `get()`
  then validates, memoizes and caches as before.
- `src/tif1/ergast/payloads.py`: `_read_entry` takes a Stats entry from a
  decoded bundle when memo/SQLite hold nothing newer, aged from `built_at`
  (so `cache_only()`/`is_fresh` see it and the current-season TTL applies
  unchanged); `sys.modules` check, so a warm process never imports the reader.
- `src/tif1/core.py`: `_preconnect_cdn` puts the bundle URL in the first wave
  instead of the two first-wave files (2018+, bundles on);
  `_start_ergast_prefetch` starts the session's bundle when the classification
  needs a fetch, and `_load_ergast_payload` waits for a bundle in flight
  (outside `cache_only`).
- `src/tif1/first_wave.py`: slots keep the HTTP status; `take_status(url)`
  (`take` unchanged).
- `src/tif1/config.py`: `session_bundle` (default False), `TIF1_SESSION_BUNDLE`.
- `tools/data/encode_session_bundle.py` (new): encoder from a `{year}` checkout
  (`--session-dir`, `--repo-dir`) + Stats checkout (`--stats-dir`), or from a
  tif1 cache (`--cache`); `--verify` decodes and compares every entry's bytes
  and parse.
- `tests/unit/test_session_bundle.py` (new, 28 tests): codec round trip and
  damage (magic, truncation, checksum, size, format), the async and sync
  readers (one request for every member, bundle off, 404 + verdict across
  processes, unusable bundles, absent members, members the bundle lacks,
  non-members), the payload-tier fill and `write_cache=False`, the Ergast tier
  reading Stats entries under `cache_only()` and the current-season ageing, the
  first-wave handover (200 and 404), `take_status`, the pre-connect URL, the
  env switch, and a fresh interpreter importing the reader without
  pandas/numpy/polars.
- `tools/perf/corinth_c10_cold_local.py` (new harness, adapted from
  `naxos_n7_cold_local.py`): a local **HTTPS** CDN (throwaway openssl
  certificate; the child replaces `wassima.generate_ca_bundle`, which both the
  stdlib first wave and niquests read, so the production cold path runs
  unchanged: first wave during the import, the bridge, niquests) serving the
  per-year files and the Stats repository from the primed caches, and the
  bundles encoded from them. Token buckets (link 8 MB/s, 6 MB/s per
  connection), a first-byte delay per request (`--rtt-ms`, 40 by default;
  connection set-up is not delayed), HTTP/1.1. Records phases, start-up and
  exit-hook time, traffic, `pandas` imported; `--verify` digests the frames;
  `--keep-caches` keeps each arm's cache.
- `AGENTS.md`: a "Session bundles" bullet.

## 3. Measurements

Cold, local HTTPS CDN, fresh process and empty cache per run, control =
`/tmp/corinth/control` (per-file requests), candidate = this tree with
`TIF1_SESSION_BUNDLE=true`, ABAB interleaved, same interpreter. Workloads:
`laps` (get_session + laps), `laps_results` (+ results), `load` (get_session +
`load()` + results + `t0_date`, then weather/messages read), `quali_load`
(same on the qualifying), `loop6` (rounds 1-6 of 2025, get_session + laps +
results each, one process). ms; wall = process wall median (p90); "after
import" = in-process time after `get_session` (the part the bundle can move;
`get_session` is the pandas/polars import, 400-2300 ms on this loaded box).

## 4. Verdict: SHIP (format, encoder, reader, off by default until the data repositories publish bundles)

With bundles published, every cold flow that reads more than the first wave
gets faster, on both backends and at both latencies: a six-race loop −22% /
−24% (8/8, 7/8) at 40 ms and −15% (8/8) at 15 ms; `load()` + results +
`t0_date` −15% pandas (13/16), −40% polars (8/8), −12% at 15 ms (8/8); the
qualifying −17% (13/16); `laps` + `results` −6% pandas (15/20; a 16-pair run
tied), −13% polars (6/8), −4% at 15 ms (6/8). After the import the saving is
the round trips: 80-200 ms per session at 40 ms, ~40-70 ms at 15 ms, and
~50 ms per race in a loop. Payloads, the payload tier, the cold frames and
the warm surfaces are unchanged. `laps` alone gains nothing (no round trip to
save) and pays ~3-6 ms of CPU; the walls there are within noise. Off (the
default) the tree makes exactly the control's requests.

## 5. CHANGELOG

- Session bundles (off by default until the data repositories publish them):
  `{year}/{gp}/{session}/session.v1.bin` holds a session's small files byte
  for byte in one zstd file: `drivers.json`, the session laptimes,
  `session_info.json`, weather, race control, and the Ergast classification
  with its season index from the Stats repository. With `session_bundle=True`
  (`TIF1_SESSION_BUNDLE`), a cold session asks for it in the first wave instead
  of `drivers.json` and the laptimes, and every later read of those files is
  answered from it: no request for the weather and race-control tables,
  `session_info.json` or the classification. On a local HTTPS CDN with a 40 ms
  first-byte delay and an 8 MB/s link, `load()` + `results` + `t0_date` takes
  981 ms instead of 1148 ms (pandas) and 470 ms instead of 787 ms (polars),
  and a six-race `laps` + `results` loop 1393 ms instead of 1778 ms (polars
  889 instead of 1172); with a 15 ms delay, 598 instead of 678 ms and 859
  instead of 1007 ms. The 2025 Bahrain race's bundle is 48.9 KB against
  66.1 KB for the same files gzipped one by one. A session without a bundle
  costs one request (the 404 is remembered in the missing-payload tier) and
  then reads its files as before. Members are validated and cached exactly as
  fetched files; the classification ages from the bundle's build time, so the
  current season's `ergast_ttl_hours` still applies.
  `tools/data/encode_session_bundle.py --verify` writes and checks the files.

## 6. Notes for the integrator

- **Release order.** No new dependency (zstd is already used by the cache;
  `compression.zstd` from 3.14). Ship the reader off, publish bundles, then
  flip `session_bundle` to True (and document it in the config docs page and
  `docs/` where `telemetry_columnar` is listed; `docs/` is not in this sparse
  checkout, so no doc page was touched). CHANGELOG.md was not edited; the
  paragraph is above.
- **Publishing contract (the main risk).** The reader trusts `absent` and
  treats members as current as of `built_at`. The pipeline must rebuild a
  session's bundle whenever a member changes: a file published later (else a
  7-day missing verdict for it), a corrected file, the Stats classification
  amended (penalties), the season index updated. Practice bundles carry the
  race results only once the race has run: rebuild an event's practice bundles
  after its race. The bundle couples the `{year}` repository to the Stats
  repository at build time (the Stats files keep their own paths and tif1
  still reads them alone when a bundle lacks them). jsDelivr caches `@main`
  files like the per-file JSON: purge bundles together with their files.
- **Current season.** A Stats entry from a bundle is used only within
  `ergast_ttl_hours` of `built_at` (current season); an older bundle's
  classification is ignored and the file is fetched, so bundles never make
  results staler than today. The session files themselves have no TTL (as
  today).
- **Where it does not help.** A first session's `laps` (the first wave already
  overlaps the import; the bundle saves no round trip and costs ~3-6 ms of
  CPU: decode ~1 ms, the payload-tier writer ~1.5 ms in a background thread).
  If that matters, persist the served members on the foreground path (as the
  control does) and delay the writer for the rest; I measured it not worth
  the complexity. Telemetry is out of scope (N7's tel.v2 files).
- **Season loops / C1.** Complementary to C1's code-side work: a loop now pays
  one request per session (the laps wave carries the classification too). A
  next-round lookahead (C1) would prefetch one bundle instead of 2-3 files.
- **Harness.** HTTPS so the production first wave and bridge run (both trust
  stores come from `wassima.generate_ca_bundle`, replaced in the child); no
  OCSP for the throwaway certificate, HTTP/1.1 only, connection set-up not
  delayed. The 40 ms delay is the hypothesis's; at this box's real jsDelivr
  latency (~15 ms) the savings are about 40% of the 40 ms ones. Ergast merge
  on (the control's default), hedging off (one source).
- **Bundles carry the season index per session** (~2.5 KB each, ~60 KB per
  season of races): the price of answering `results` without a second request.
- **Result files** (`.agents/perf-corinth/`): `C10_cold_local_pandas.json`
  (8 pairs), `C10_cold_local_pandas_16.json` (16), `C10_cold_local_pandas_exit.json`
  (20, start-up/exit split), `C10_cold_local_polars.json`,
  `C10_cold_local_pandas_rtt15.json`, `C10_cold_local_pandas_off.json`,
  `C10_cold_local_verify_{pandas,polars}.json`, `C10_ab_pandas.json` (warm),
  `C10_parity_{pandas,polars}.json`.
- **Commits** were denied by the sandbox: everything is staged; the intended
  messages are in `C10_COMMITS.md`.
