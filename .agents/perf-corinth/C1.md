# C1: a season loop, cold (Corinth)

## 1. Hypothesis

A cold season loop (`for r in rounds: s = get_session(2025, r, "R"); s.laps; s.results`)
pays each round's requests on its critical path, one round after the other.
That costs ~650 ms per race in the survey, against ~120 ms for the whole loop warm.
Fetching a session's independent files together, keeping connections warm across
sessions, and fetching the next round's files in the background (at most one
session ahead) should cut the loop without touching single-session loads.

## 2. What changed

Trace first (`.scratch` tracer patching `first_wave._StdlibClient._request`,
`async_fetch._get_resolved` and `NiquestsTransport.get_json/get_bytes`, control tree):

- The first cold session starts the stdlib first wave (`drivers.json` and
  `session_laptimes.json` in parallel). Every later session's wave already rode
  the kept-alive stdlib connections through the bridge (no re-handshake, no
  niquests import), so step (2)'s "keep connections warm" was already true.
- After the laps build, `.results` fetched the Stats `results.json` on the main
  thread: a second round trip in series per race. Round 1 also fetches `events.json` (the season index).
- Per race on a hot jsDelivr edge: wave ~20-30 ms, laps build ~20 ms, Stats
  file ~15-22 ms, results build ~5 ms, about 70 ms in all. On an edge miss
  (jsDelivr fetching from GitHub) each file takes 150-800 ms, and `weather.json`
  after `load()` takes up to 1.5 s with the hedge to Hugging Face. The hot-edge
  laptimes TTFB is ~45 ms against ~20 ms for `drivers.json`: the edge gzips the
  340 KB file on the fly. Identity encoding comes to the same total (TTFB 22 +
  body 26 ms), so I did not change it.

Change:

- `src/tif1/session_lookahead.py` (new). `on_get_session` (called by
  `get_session` after `_preconnect_cdn`) records the session (year, session
  name, schedule backend, round, encoded coordinates). `note_fetch` is called at
  the top of `CDNManager.try_sources`/`try_sources_async`, so it sees every
  network fetch. It records the session-level paths (no `/`, so never telemetry)
  of the current session. `note_classification` (from `Session._load_ergast_payload`)
  records the Ergast endpoint the session read. When round r follows round r-1 of
  the same season, session and backend, and round r-1 fetched something over the
  network, it:
  - probes the cache for round r (the probe is handed to the session, which
    would run it anyway) and stops if round r is cached;
  - fetches round r's Stats classification file if no earlier lookahead slotted it;
  - fetches round r+1's files: the same paths round r-1 fetched (laps-only
    loop: drivers + laptimes; `load()` loop: + weather + rcm), plus the Stats
    file when round r-1 read the classification. It skips this when round r+1
    is cached, when the schedule dates its session in the future, or when there
    is no next round. The Stats URL is only built when the season index is
    cached, so nothing is requested just to find the file.
  - Slots of a passed round are dropped (`first_wave.discard`), and so is every
    slot when the sequence breaks. At most one round ahead.
- `src/tif1/first_wave.py`: `prefetch(urls, timeout)` registers slots and fetches
  them over the wave's `_StdlibClient` (one thread start on the caller, which
  starts one daemon thread per further URL). If the wave's client is still being
  built it waits on `_client_settled`, bounded by the slot deadline. It does
  nothing if no wave ran in the process. `discard(urls)`. The next load takes the
  bodies through the existing `pending`/`take` hand-over (async `_stdlib_served`,
  sync `NiquestsTransport.get_json`). Anything but a `200` with a JSON object goes
  to niquests as before, so the CDN fallback, 403/404 handling and hedging are
  unchanged. The background threads only do socket I/O and zlib (both release
  the GIL): no parse, no cache write.
- `config.py`: `session_lookahead` (default True, `TIF1_SESSION_LOOKAHEAD`).
  It is also off in offline/CI mode, without `cdn_preconnect`, without threads
  (Pyodide), and before 2018.
- `tests/unit/test_corinth_c1_session_lookahead.py`: 34 tests covering sequence
  detection, the switches, cached/future/last-round cases, classification URLs,
  slot hand-over over fake `http.client` connections (sync transport takes the
  slot, one request), `get_session` wiring and the probe hand-over.
  `tests/conftest.py` resets the module between tests.
- `tools/perf/corinth_c1_cold_bench.py`: my copy of `delphi_cold_bench.py` with
  the season workloads (`season`, `season_load`, `season_laps`, `season_tel`),
  `--rounds`, p90, per-run records, and a per-race digest of laps/results (row
  hashes) that the parent compares across arms.
- `AGENTS.md`: one architecture paragraph.

Main-thread cost: 9.5 µs per `get_session` outside a sequence, 0.1 µs per
`note_fetch`, ~1-2 ms per `get_session` inside a sequence (two cache probes,
schedule lookups, one thread start).

## 4. Verdict

**SHIP.** The season loop, the workload the hypothesis names, is 41% faster on
the whole-process wall in pandas (4236 → 2519 ms, 5/5) and 35% faster in polars
(4679 → 3034 ms, 5/5), with the loop phase about halved. The `load()` loop is
27% faster (4/4) and the telemetry loop 18% faster (4/4). Frames are identical,
parity is 0/133 and 0/131, and single-session cold loads and every warm path are
unchanged within noise: the lookahead only acts on round r after round r-1, and
is off in offline mode.

## 5. CHANGELOG

- A script that walks a season (`get_session(year, r, ...)` for r = 1, 2, 3, ...)
  now fetches the next round's files while it works on the current one. When
  `get_session` is asked for round r right after round r-1 (same season, session
  and schedule backend), it fetches in the background, over the first wave's
  kept-alive connections, the session files round r-1 fetched (laptimes and
  drivers, plus weather and race control after `load()`) and the Ergast
  classification for round r+1. The next round's load takes the bodies instead
  of requesting them. One round ahead, nothing for cached or future sessions,
  never telemetry. A cold 24-race loop of `.laps` and `.results` went from 4.2 s
  to 2.5 s (pandas) and 4.7 s to 3.0 s (polars). The loop alone went from 3.4 s
  to 1.7 s. A fastf1-style `load()` loop over 8 races went from 3.2 s to 2.3 s.
  Single sessions and warm loads are unchanged. `session_lookahead=False`
  (`TIF1_SESSION_LOOKAHEAD`) turns it off.

## 6. Notes for the integrator

- Wasted requests: a script that stops after round r leaves round r+1's files
  unused: ~0.4 MB uncompressed (~60 KB on the wire) for laps+results loops,
  plus weather/rcm after `load()`. A loop over rounds that have not run yet
  requests nothing (schedule dates), and neither does a loop over cached rounds
  (cache probe). The slots of an unconsumed round are dropped when the sequence
  moves on or breaks. The last lookahead's bytes stay in memory until the
  process ends (bounded: one round).
- No OCSP check on the prefetched requests: they ride the first wave's stdlib
  connections, so the same security note as the first wave applies. They are
  only possible once a first wave ran (`cdn_first_wave` on, no proxy,
  `wassima` present); otherwise there is no lookahead.
- `on_get_session` runs before the pandas import on the first call and costs
  9.5 µs outside a sequence. It never raises (best effort, debug log).
- Round 2 pays a one-time cost: its own wave runs beside the first lookahead,
  which opens 3-4 more TLS connections (r2 `laps` 108-139 ms against ~50 in the
  control). The rounds after it gain far more.
- The remaining floor at one round ahead is the laptimes fetch latency (~50-70
  ms per race, mostly the edge's on-the-fly gzip). Two rounds ahead would bring
  a hot-edge loop near the ~25-30 ms per race of main-thread CPU (an estimate
  from the trace, not measured). The hypothesis caps the lookahead at one round
  because of wasted requests, so I did not build it.
- Per-race main-thread CPU left: the laps frame-tier write (`set_laps_frame`,
  pickle ~2 ms + lz4 ~2 ms + insert, synchronous), the laps build (~10-15 ms),
  and the payload-tier writes. Moving the frame write off-thread would contend
  for the GIL (pickle holds it); not tried.
- Not done, by design: starting the Stats classification beside a single cold
  session's first wave (DO_NOT_RETRY: "a speculative Ergast thread on cold
  loads"). The lookahead only fetches it when the previous round of the
  sequence read it, so it is never speculative in that sense.
- Docs: `session_lookahead` / `TIF1_SESSION_LOOKAHEAD` should be added to the
  configuration page (`docs/` is not in this sparse tree).
- A wrinkle seen in the traces, not mine to fix: jsDelivr answered 403 for the
  2025 Miami race laptimes on an edge miss, and the niquests path then took
  1-2 s through Hugging Face and StaticDelivr. A later run got a 200.
