# Corinth C7: the CLI

## 1. Hypothesis

`python -m tif1.cli --help`/`version` take 200-230 ms and the CLI uses typer
+ rich. Deferring imports a command does not need should cut its startup
while keeping stdout, stderr and the exit codes identical.

The profile changed the picture. The light commands (`version`, `--help`,
`events`, `sessions`, `cache-info`) already ran at 120-175 ms on this box,
and most of that is not tif1's: the interpreter plus `site` (~35 ms), typer
(~33 ms with its vendored click) and `rich.console` (~20 ms, mostly regex
compiles). The one tif1 cost there was `tif1.__version__`, which went
through `importlib.metadata` (~20-25 ms).

The session commands were the real cost. `results`, `drivers`, `fastest`
and `standings` take 490-620 ms warm, and ~300 ms of that is
`import pandas` (with numpy, pyarrow and OpenBLAS's thread start; ~3 s of
CPU across 32 cores). None of those tables needs pandas:

- A polars session never imports pandas, numpy or pyarrow (AGENTS.md).
  `results`/`drivers`/`fastest` can load polars sessions and print the same
  text.
- `standings` can print the Ergast standings rows without building any
  frame.

## 2. What changed

- `src/tif1/cli.py`
  - `results`, `drivers` and `fastest` load `lib=_session_lib()`: polars
    when `importlib.util.find_spec("polars")` finds it, else pandas. Only
    `find_spec` runs here. polars itself is imported inside `get_session`,
    so a cold session still starts its first-wave fetches before the import.
  - The tables read row dicts from either backend. `_polars_rows` uses
    Series conversions only, with no query plan. Durations come back as int
    nanoseconds, the value a `pd.Timedelta` holds; `datetime.timedelta`
    would truncate below a microsecond.
  - `_seconds` and `_fmt_td` read an int as nanoseconds, as
    `pd.Timedelta(int)` does. They sum it the way `Timedelta.total_seconds`
    does: the whole seconds plus `(ns % 1e9) / 1e9`. A plain `ns / 1e9`
    differs in the last bit for ~25% of values, so `225.92675525800001`
    becomes `225.926755258`. A unit test found this, and 300k random values
    confirmed the formula.
  - `fastest` without `-d` sorts as pandas' `sort_values` does (quicksort,
    missing last). With no tie, a Python sort gives the same order. numpy's
    quicksort does not keep tied rows in order, even on sorted input (n > 16
    partitions). So when two drivers tie, `_sort_order` makes the same numpy
    `argsort(kind="quicksort")` call on the same `timedelta64[ns]` values,
    and imports numpy only then. The old polars branch called
    `DataFrame.sort`, which is a query plan.
  - `_fmt_num` checks for missing values without pandas (`None`/NaN, or
    `pd.isna` when pandas is already loaded).
  - `standings` prints `tif1.ergast.standings.standings_rows(...)`, so it
    imports neither pandas nor polars.
  - Fixed: on the control, `tif1 fastest Y E S` crashed with
    `TypeError: unsupported format string passed to datetime.timedelta.__format__`
    when the configured `lib` was polars (`TIF1_LIB=polars`). The old polars
    branch formatted a `timedelta` with `:.3f`. It now prints the pandas
    table.
- `src/tif1/core_utils/ergast_results.py`: `build_standings_frame` is split
  into `standings_records(payload, kind, native=False)` (the row dicts) and
  the frame build. The pandas rows are unchanged. With `native=True`,
  `DateOfBirth` is the `datetime` or `None`.
- `src/tif1/ergast/standings.py`: adds `standings_rows(kind, year, round)`,
  the same rows without a frame (not in `__all__`).
- `src/tif1/core_utils/dist_version.py` (new): `tif1_version()` reads the
  `Version` header of the first `tif1-*.dist-info` on `sys.path`. It finds
  it the way importlib.metadata's `FastPath` lookup does (`os.listdir` per
  entry, name normalization, first match wins), so `email`, `zipfile` and
  `csv` are never imported. It hands over to `importlib.metadata.version`
  for anything it does not cover:
  - an `*.egg-info` or an `.egg` path entry
  - a zip on `sys.path`
  - a `sys.meta_path` finder other than `PathFinder` with
    `find_distributions`
  - a missing `Version` header

  The lookup takes ~1 ms; `importlib.metadata` took ~20-25 ms in a fresh
  process. `tif1.__getattr__("__version__")` and `http_session.user_agent()`
  use it. The User-Agent is built by the cold first-wave threads and at
  `tif1.ergast.interface` import, so those paths also skip the
  `importlib.metadata` import. I measured only the CLI.
- Tests:
  - `tests/unit/test_corinth_c7_cli.py` (new, 64 cases):
    - The `fastest`/`fastest -d`/`drivers`/`results --no-ergast` tables are
      equal across backends on a 22-driver cached session with three-way
      ties.
    - `_sort_order` equals `DataFrame.sort_values` on 40 random
      tie-heavy/null-bearing inputs, for both timedelta and float.
    - The ns formatting equals `pd.Timedelta` on 10k random values.
    - `standings_rows` equals the standings frame.
    - The dist-info lookup follows `sys.path` order, defers on egg/zip/custom
      finder/missing header, and agrees with `importlib.metadata`.
    - In a fresh interpreter, `tif1.__version__` and `standings_records`
      import none of pandas, polars, numpy or `importlib.metadata`.
  - `tests/unit/test_cli_ergast.py`: the missing-standings test patches the
    new seam (`standings_rows`) instead of `tif1.get_driver_standings`, which
    the command no longer calls. It also asserts the message now.
- Harness:
  - `tools/perf/corinth_c7_cli_parity.py` runs the control and candidate
    trees' CLI per command line and compares stdout, stderr and the exit
    code byte for byte. A traceback counts as equal when both arms raise the
    same exception line; only the frames' source lines differ.
  - `tools/perf/corinth_c7_cli_ab.py` is the interleaved A/B of CLI
    commands: ABAB/BABA, one unmeasured run per arm, wall plus child CPU
    from `os.wait4`, `--cold` for an empty cache per run.
  - A first version used `subprocess.run(timeout=...)`. That polls
    `waitpid` with up to 50 ms back-off and quantized every wall to ~50 ms
    steps (165/216/316/567 ms). Those numbers were discarded
    (`C7_ab_warm_quantized_discarded.json`); the tables below use `wait4`.
  - The session parity digests are in `/tmp/corinth/C7_parity_pandas.json`
    and `/tmp/corinth/C7_parity_polars.json`, outside the tree (2 MB each).
- `AGENTS.md`: one paragraph on the CLI's backend choice and parity rules.

## 3. Measurements

Box: 32 cores, load average 23-64 during the runs (up to ten agents). Cold
runs shared the ~10 MB/s link with the other agents' cold benchmarks.
Python 3.13, the main venv. The cache is `/tmp/corinth/warm-C7` (2025
Bahrain race and qualifying), with `TIF1_OFFLINE_MODE=true` for the warm
runs. Each run is a fresh process, `python -m tif1.cli ...`. The wall is
the whole process, in ms.

### What the commands import now

Checked with an `atexit` probe in each command's process (both trees):

- Control: pandas, numpy and pyarrow for every session command and
  `standings`; `importlib.metadata` for `version`.
- Candidate: polars only for `results`/`drivers`/`fastest`. polars itself
  imports `importlib.metadata`. `standings` and `version` import none of
  these.

## 4. Verdict

**SHIP.**

- Every session command, warm and cold, wins by far more than the 3% bar,
  with ≥9/10 pairs warm and ≥4/5 cold:
  - warm `drivers`, `results Q`, `fastest`, `fastest -d`: 0.45-0.50x
  - warm `standings`: 0.31x
  - warm `results R`: 0.80x in the noisiest pass, ~0.56x in the quieter one
  - cold: 0.56-0.70x
- `version` wins 15% (26/30 pairs).
- Parity is complete across 209 CLI command lines and both session digests.
- It also fixes the `fastest` crash on polars-configured installs.
- The other light commands are unchanged. Their remaining cost is typer +
  click (~33 ms), rich (~20 ms) and the interpreter (~35 ms).
  - typer's `--help` renderer imports `rich.markdown`, markdown-it and
    pygments (~38 ms) at module level.
  - Deferring those would need stubbing a third-party module or replacing
    typer, which would change output or patch someone else's library. Not
    done.

## 5. CHANGELOG

- The CLI's session tables no longer import pandas. `tif1 results`,
  `drivers` and `fastest` load polars sessions when polars is installed and
  print the same tables. Polars durations are read as int nanoseconds and
  summed as `Timedelta.total_seconds` sums them, and tied fastest laps keep
  pandas' quicksort order. `tif1 standings` prints the standings rows
  without building a frame. On a warm 2025 Bahrain cache:
  - `drivers`, `results`, `fastest` and `fastest -d`: 567-618 → ~316 ms
    (0.45-0.56x)
  - `standings`: 518 → 165 ms

  Cold, `results` goes from 705 → 453 ms and `fastest` from 770 → 448 ms.
  The process CPU falls from ~3 s to ~0.3 s: no numpy import, so no
  OpenBLAS thread start. `tif1.__version__` and the User-Agent read the
  dist-info `Version` header directly instead of importing
  `importlib.metadata` (~1 ms instead of ~20-25 ms), and `tif1 version`
  goes from 132 → 112 ms. Fixed: `tif1 fastest` raised a `TypeError` when
  the configured backend was polars.

## 6. Notes for the integrator

- The backend choice is `find_spec("polars")`. A polars 1.x install
  (Pyodide only; the CLI does not run there) makes `get_session` log its
  usual "Polars not available, falling back to pandas" warning. The tables
  are then the pandas ones.
- One case of `Status` printing is unproven. The pandas `Status` column can
  read `NaN` when the column mixes strings and missing values; the CLI
  printed `nan`, while polars has `null` and prints `""`. No session in
  the 209 checked lines shows it: practice results and the lap-derived
  `--no-ergast` classification both printed identically. If a data case
  appears where they differ, the fix is in `results` (map a polars `None`
  Status in a column that has strings to `"nan"`) or, better, in pandas'
  finalize.
- `_sort_order` reproduces numpy's quicksort by calling it. If numpy
  changes its timedelta argsort, pandas changes with it, and so does the
  CLI.
- `dist_version` mirrors importlib.metadata's lookup for the plain
  dist-info layout only and defers on everything else. Editable installs by
  uv/pip/hatch write a `*.dist-info` into site-packages, which is the
  covered case.
- `tif1.ergast.standings.standings_rows` and
  `ergast_results.standings_records` are new non-`__all__` helpers. They
  could back a pandas-free `get_driver_standings(lib="polars")` later; today
  that converts a pandas frame.
- Every warm walls table on this box was taken at high load. Read the
  ratios and pairs won; the CPU column is the steadier number for the
  session commands.
- Not done: trimming typer/rich startup (third-party), and the `--help`
  rich-markdown import (typer's `rich_utils` module level).
