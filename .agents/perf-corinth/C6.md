# C6. Plotting (Corinth)

## 1. Hypothesis

Plotting is how many users end a script, and its cost is mostly imports.
`import tif1.plotting` took ~500 ms (matplotlib + pyplot + legend, numpy
included) although the color, name and style lookups need no matplotlib.
The native charts were thought to be dominated by data preparation. The idea
was to defer what the common helpers do not need, then profile the chart
functions on a warm session and cut what is tif1's. Rendering inside
matplotlib was out of scope.

## 2. What changed

Profiling (`tools/perf/corinth_plot_phases.py`, warm 2025 Bahrain, fresh
process) showed that tif1's own data preparation is small, about 50 ms per
chart: rapidfuzz import 16 ms, the `iterrows` session mapping ~5 ms,
`setup_theme`, ~10 ms of telemetry. The large costs were imports. The
biggest was `import seaborn`, which `plot_driver_laptimes` paid for one
`sns.scatterplot` and one `sns.despine`: 860 ms, 773 of it scipy.stats, out
of a 1.8 s process.

- **`src/tif1/plotting.py`**
  - Matplotlib is no longer imported at module import.
    - `setup_mpl`, the color schemes, `apply_plot_style` and
      `_reset_theme_rcparams` write `matplotlib.rcParams` (the object
      `pyplot.rcParams` is) after a local `import matplotlib`. pyplot is not
      imported.
    - `add_sorted_driver_legend` imports `matplotlib.legend` itself.
    - The former module attributes `mpl`, `plt` and `cycler` resolve on
      first access through a module `__getattr__`, for backward
      compatibility.
  - `fuzzy_matcher`, and with it rapidfuzz and numpy, is imported only on
    the fuzzy fallback of `_match_driver`/`_match_team`. An exact feature
    hit (`"VER"`, `"Red Bull Racing"`) never needs it.
  - `_iter_session_rows` reads the results columns whole (`_column_values`,
    `tolist()`) instead of `results.iterrows()`. These are the same values,
    so `str()` gives the same strings.
  - fastf1 check: `fastf1/plotting/_plotting.py` imports `pyplot` and
    `cycler` at module level, inside `try` blocks
    (https://github.com/theOehrly/Fast-F1/blob/master/fastf1/plotting/_plotting.py).
    tif1 now differs only in what is in `sys.modules` after
    `import tif1.plotting`. Every function that touches matplotlib imports
    it before use, so no figure, rcParams value or return value changes. A
    script that draws imports pyplot itself.
- **`src/tif1/charts/lap_times.py`**
  - `plot_driver_laptimes` no longer imports seaborn. `_scatter_by_compound`
    makes the matplotlib calls that seaborn 0.13.2's `_ScatterPlotter`
    makes for `scatterplot(data=laps, x="LapNumber", y="LapTime",
    hue="Compound", palette=..., s=80, linewidth=0, legend="auto")`, in the
    same order:
    - `_attach`: `update_units` seeded with seaborn's `categorical_order`,
      then `set_inverted(True)`, because seaborn types a Timedelta y as
      categorical.
    - `comp_data`: unit conversion plus transform and the same `dropna`.
    - The scatter with `color=None, edgecolor="w"`, which consumes one
      property-cycle colour exactly as seaborn does, then `set_facecolor`.
    - `_add_axis_labels`.
    - The legend: one `Line2D` per hue level, built as seaborn's
      `_scatter_legend_artist` builds it, added with `add_artist`, then
      `ax.legend(title="Compound")`.
    - The "missing palette keys" `ValueError` and the "Ignoring `palette`"
      `UserWarning`, as seaborn raises and warns them.
  - `_despine_all_sides` replaces `sns.despine(left=True, bottom=True)`.
  - `_seaborn_variable_type` and `_seaborn_categorical_order` port the two
    seaborn helpers involved.
  - `plot_laptimes_distribution` (violin + swarm) and
    `plot_laptime_heatmap` still use seaborn: reproducing those is a much
    larger surface.
- **Tests**
  - New `tests/unit/test_chart_scatter_parity.py` draws seaborn's figure and
    the new one on the same frame and compares every artist (lines, markers,
    collections with offsets, colours, sizes and linewidths), labels and
    their visibility, limits, `dataLim`, inversion, the axis converter,
    locator and formatter, spines, the legend title, texts and handles, the
    next cycle colour, tick labels, and the Agg pixel buffer.
    - Frames: plain, gaps (NaT/NaN/None), categorical Compound with an
      unused category, one compound, no compound, empty, all-NaT. Each runs
      with timple's converter and with no timedelta converter registered,
      and once more under the fastf1 theme.
    - Also covered: the missing-key error, the warning, and the
      `variable_type`/`categorical_order` ports against seaborn's on 9
      vectors.
  - `test_charts.py`: `plot_driver_laptimes` works with `sys.modules["seaborn"]
    = None`.
  - `test_chart_import_contracts.py`:
    - `import tif1.plotting` plus several lookups imports no
      matplotlib/pyplot/rapidfuzz/seaborn.
    - The lazy `mpl`/`plt`/`cycler` attributes are the real objects.
    - `setup_mpl` writes rcParams without importing pyplot.
- **Harness (my copies, run from this tree)**
  - `tools/perf/corinth_plot_bench.py`: fresh-process plotting workloads. A
    figure digest (artists, axis state, Agg pixel SHA-1) is written with
    `C6_DIGEST=`.
  - `tools/perf/corinth_plot_ab.py`: a copy of `delphi_warm_ab.py` that runs
    it, interleaved ABAB with the order flipped every pair, and compares
    both arms' digests on the first pair.
  - `tools/perf/corinth_plot_phases.py`: a phase-split and cProfile probe.

## 3. Measurements

The control is `/tmp/corinth/control/src` (552c357) and the candidate this
tree. Both arms ran on `/tmp/corinth/warm-C6`, offline, `MPLBACKEND=Agg`,
Python 3.13, with `HOME=/tmp/corinth/home-C6` (matplotlib font cache warm).
Every workload is a fresh interpreter ending in `savefig` to PNG (dpi 60).
Workloads:

- `import_plotting`: `import tif1.plotting`.
- `team_color`: a script that only wants colors. `get_session` race, then
  `get_team_color`, `get_driver_color`, `get_driver_color_mapping`,
  `get_compound_color` and `get_driver_style`.
- `speed_trace`, `laptime_scatter`, `strategy`: the fastf1 gallery scripts.
  - `speed_trace`: quali, VER/LEC fastest laps, `get_car_data().add_distance()`,

  - `laptime_scatter`: race, 3 drivers' quick laps, compound colors.
  - `strategy`: race stints, `barh` per stint, `get_compound_color`.

## 4. Verdict: SHIP

Both changes are wins on their named workloads, 8/8 pairs in every run,
with identical figures:

- Lazy matplotlib in `tif1.plotting`: `import tif1.plotting` 0.5-0.8 s →
  0.02 s. A script that only needs colors runs 33-39% faster.
- seaborn-free `plot_driver_laptimes`: a fresh process's first chart goes
  from 2.4 s to 1.3 s (-44%).

Everything else is neutral, and nothing measured got worse.

## 5. CHANGELOG

- **Plotting imports (Corinth C6).**
  - `tif1.plotting` no longer imports matplotlib when it is imported. The
    color, name and style lookups need none, and `setup_mpl` and the
    legend/style helpers import it when called. rapidfuzz loads only for a
    fuzzy driver or team lookup.
  - `import tif1.plotting` 0.5 → 0.02 s; a script that only reads team
    colors 0.90 → 0.55 s.
  - `plot_driver_laptimes` draws its compound scatter with matplotlib
    directly: the same calls seaborn's `scatterplot` made, and the same
    figure down to the pixels. It no longer imports seaborn and
    scipy.stats: first chart in a process 2.4 → 1.3 s.
  - `tif1.plotting.mpl`/`plt`/`cycler` still resolve, on first access.

## 6. Notes for the integrator

- **seaborn coupling.** `_scatter_by_compound` mirrors seaborn 0.13.2
  (pinned `>=0.13.2,<1`). `test_chart_scatter_parity.py` compares it with
  the installed seaborn, so a seaborn release that changes `scatterplot`'s
  artists fails that test. Then decide whether the chart should follow (port
  the change) or keep its look (pin the expectation). The chart's look is
  tif1's; seaborn was only the drawing tool.
- **Import-time difference from fastf1.** fastf1 imports pyplot with
  `fastf1.plotting`; tif1 now does not. It is observable only via
  `sys.modules`, or via `from tif1.plotting import *`, which no longer
  exports `mpl`/`plt`/`cycler`/`fuzzy_matcher`; that module has no
  `__all__`.
  - `setup_mpl` imports `matplotlib` but not pyplot. rcParams written
    before pyplot is imported stay in force: same object.
- **Still on seaborn:** `plot_laptimes_distribution` (violinplot +
  swarmplot) and `plot_laptime_heatmap`. Each still pays ~0.85 s of
  seaborn/scipy.stats import in a fresh process. The heatmap is the next
  candidate: `sns.heatmap` is a `pcolormesh` plus ticks and a colorbar,
  smaller than violin/swarm. It needs the same artist and pixel parity test.
- **What is left in a typical chart script** is the imports a user cannot
  avoid (matplotlib ~250 ms, pyplot ~250 ms, pandas ~220 ms), matplotlib
  text layout, and `savefig`. tif1's own data preparation is ~30-50 ms per
  chart, mostly first-touch `results` and telemetry reads.
- The `team_color` A/B shows the pandas import moving into `get_session`
  (+170-230 ms on that phase). It was previously hidden inside matplotlib's
  numpy import; the wall is what moved.
- Scratch: digests and profiles in `/tmp/corinth/home-C6` (small); PNGs at
  `/tmp/corinth/C6_plot.png`. No cache copy was made.
