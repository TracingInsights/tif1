Architecture:
- Library source in `src/tif1/`; public API via lazy `__getattr__` exports in `__init__.py`.
- `core.py` is the monolith (~4200 lines): Session class, data loading, lap/telemetry/weather/race-control parsing; re-exports the model family for backward compatibility (`tif1.core.Laps` etc. are aliases of the `tif1.models` classes, resolved by a module `__getattr__`). A polars session never imports pandas: `core.py`, `core_utils/helpers.py` and `core_utils/ergast_results.py` bind `pd` (and core binds `tif1.models`) through `core_utils/lazy_import.lazy_module`, which rebinds the global to the real module on first use; pandas sessions import pandas, `tif1.models` and `core_utils/pandas_blocks.py` up front (`_load_pandas_models`). On the polars path use `is_pandas_frame`/`is_pandas_series` instead of `isinstance(x, pd.DataFrame)`, quote `cast("pd.DataFrame", ...)`, read the schedule row with `Session._event_row()` instead of the pandas `Session.event`, and build results rows with `native=True` scalars; `tests/unit/test_polars_without_pandas.py` guards it in a fresh interpreter. `session.drivers`/`drivers_df`/`results` are in classification order: `Session._driver_rows_info` keeps the upstream `drivers.json` order when it already is a classification and otherwise rebuilds it from the laps table (`_summarize_laps_for_classification`, one pass over the few needed columns, either backend); missing car numbers are backfilled from the same summary. `gp`/`session` attributes stay URL-encoded (CDN paths); `event_name`/`session_name` are the decoded forms for messages and error context. Its fetch seams `Session._fetch_from_cdn(_fast)`/`_fetch_json(_unvalidated)` are thin delegates into `payload_loader.py`, kept as one override seam for older tests. `t0_date`, `session_start_time`, `track_status`, `session_status`, `session_info` and `total_laps` read the session's `session_info.json` (fastf1's live-timing TrackStatus/SessionStatus/SessionInfo/LapCount values, published per session from 2018; `Session._session_info_file`, fetched once on first use and memoised in `_session_state`, parsed pandas-free by the `file_*` helpers of `core_utils/session_state.py`); without the file they fall back to the derivations from the race-control messages, the laps and the schedule (and a null `t0_date` in the file to the laps). On a polars session `t0_date`/`session_start_time` are stdlib `datetime`/`timedelta` (`None` when unknown) and the derived `session_info` is built from `_event_row()` (`_derived_session_info_native`), so none of them imports pandas; pandas sessions keep `pd.Timestamp`/`pd.Timedelta`/`NaT`. Tests that build an in-memory `Session` and read these properties stub `_fetch_json` (missing file -> `DataNotFoundError`) so nothing reaches the network.
- `models.py` is the canonical model module: `Laps`, `Lap`, `Telemetry`, `Driver`, `SessionResults`, `DriverResult`, plus the `TelemetryProvider` protocol (the backend-neutral `CircuitInfo` and `LazyTelemetryDict` live in the pandas-free `models_shared.py` and are re-exported) — the narrow (mostly private) session seam the models consume. `Session` satisfies it structurally; tests can use in-memory fakes. `models.py` must never import `core.py` at runtime (import cycle).
- `models_polars.py` holds the polars-native classes (`PolarsLaps`, `PolarsLap`, `PolarsTelemetry`, `PolarsSessionResults`, `PolarsDriverResult`, `PolarsDriver`, the `.f1` namespace). Its hot paths (every `pick_*`, the slices, `Laps.telemetry`, `merge_channels`, `add_distance`, `fill_missing`, `get_weather_data`, `split_qualifying_sessions`, the results frame) run on numpy masks and column gathers on a cloned `_df` instead of query plans (a plan costs ~0.5 ms, the first of a process ~7 ms); only rare inputs (non-ASCII qualifying labels, fractional lap numbers, tied status times) take the expression path. Keep new methods off the query engine. The selections never import numpy (Gortyn G4): every `PolarsLaps.pick_*`, `iterlaps(require=...)`, the results lookup behind `get_driver` and `PolarsDriver.get_lap` filter with Boolean Series masks (`_filled` is `fill_null` through `zip_with`, `_present_series`/`_valid_series`/`_isin_series`/`_text_test_series`/`_first_true`, ~20-row results on Python lists), each as fast as the numpy mask with numpy loaded. The common `PolarsTelemetry` arithmetic does not import numpy either (`add_track_status` and unsorted or null clocks in `merge_channels`/`slice_by_time(interpolate_edges=True)` still do; Naxos N3: numpy plus the `numpy.ma` that polars' ndarray conversion imports were ~120 ms of the polars notebook's analysis): `add_distance`/`add_differential_distance`/`add_relative_distance` divide by full-length Series (a division by a scalar is a multiplication by its reciprocal in polars, 1 ulp off numpy) and sum with `itertools.accumulate` (numpy's `cumsum` is sequential); `slice_by_*`, `merge_channels` (`_nearest_rows`) and `fill_missing` use Boolean Series masks, `bisect` and list kernels, numpy only above `_LIST_KERNEL_MAX_ROWS` rows or above 4096 once `numpy.ma` is loaded (`_numpy_kernels`; both give the same values); `fill_missing`'s interpolation and `resample_channels(rule=)` run without query plans on frames up to `_EAGER_RESAMPLE_MAX_ROWS` (`_resample_eager`, `_linear_fill`: polars' `interpolate` is `low + step * ((high - low) / steps)`, a bin's mean a Kahan sum in row order, the plan's `join_asof` takes the last of equal timestamps). The resampler's query plan is not deterministic at the ulp level (on some frame sizes its grouped mean adds a bin's rows plainly in a thread-dependent order), so the eager resampler matches it on every bin of at most two rows and is within an ulp or so of it elsewhere, as the plan is of itself. The common telemetry reads of a polars process never import numpy either (Elis E6: ~55 ms): `pick_driver`, the one-driver lap join (`_join_one_driver_laps`), `split_qualifying_sessions`, `core._fastest_laps_polars` and the lap clock (`Session._lap_start_lookup`, lists) run on eager Series kernels (comparisons, `&`/`|`, `not_`, `filter`, slices, `Series[Series]`, never `fill_null`/`is_null`/`arg_true`/`cum_*`/`search_sorted`, which are query plans) or Python lists; `_filter_rows` takes a numpy or a Boolean Series mask (nulls drop, used as one chunk); a lone lap's payload is decoded with orjson while numpy is not imported (`json_utils.decode_one_telemetry_payload`) and built by `helpers._polars_list_telemetry_frame`, which returns `_UNHANDLED` for anything outside its clean cases so the numpy builder answers exactly as before. A pandas session never imports this module.
- `session.py` is a thin re-export shim pointing into `core.py`.
- `io_pipeline.py` and `lap_ops.py` were removed (pass-through shims); internal helpers live in `core.py`/`core_utils/`.
- `payload_loader.py` is the single payload-loading pipeline: `PayloadLoader.get` (session memo -> SQLite cache -> fetch -> validate -> memo/cache write-back), `fetch_from_cdn(path, fast=)` (retry/backoff unless `fast`), async `get_many` (delegates to `fetch_multiple_async`), and `get_url` + thread-safe `get_url_loader()` for absolute-URL payloads (used by `events.py`). HTTP goes through injectable `HttpTransport` implementations (`NiquestsTransport` in production, `InMemoryTransport` in tests). Validation failures always raise — no patched-callable escape hatch (the old `__code__`-sniffing test-compat machinery was removed).
- `ergast/` is the Ergast tier (fastf1 `fastf1.ergast` parity): `structure.py` (fastf1's flattening tables plus `totalRaceTimeGap` and the sprint-qualifying schedule keys), `interface.py` (`Ergast`, the response classes, `source` attribution, `result_type="polars"`: `ErgastPolarsResponse`, a polars frame with the paging mixin built on first use so the module never imports polars), `router.py` (the routing matrix: anything season-scoped that the Stats files answer exactly comes from `TracingInsights-Archive/Stats` via `stats.py`, season-wide answers assembled from per-round files; seasons/drivers/status lists, `status=` filters, no-season queries and `current`/`last` go to Jolpica via `jolpica.py`, which allows at most 4 requests in any second and 200 in any hour (sliding windows; Jolpica's limit is 500/h, fastf1 caps itself at 200/h) and honours `Retry-After`; a missing/empty Stats file falls through to Jolpica for that round), `payloads.py` (memo -> SQLite `json` tier `{"fetched_at", "payload"}` wrapper -> `CDNManager.try_sources_repo`; past seasons cached permanently, current season and Jolpica answers for `ergast_ttl_hours`; a "missing" verdict needs a 404 from every mirror, a 403 is retried once and never persisted, and a miss that involved a 403 is remembered in-process for 60 s so repeated lookups do not re-walk the mirrors), `standings.py` (`get_driver_standings`/`get_constructor_standings`), `legacy.py`. The merged Stats `laptimes.json` repeats a lap split across Jolpica pages: `jolpica.merge_split_laps` joins the timings. Past-season Stats files are snapshots: Jolpica later edits metadata (URLs, localities, circuit names, current permanent numbers, status vocabulary), so `tif1.ergast` frames can differ from fastf1's live answers in those columns while results, times, points and positions match.
- `core_utils/ergast_results.py` merges the Ergast classification into `Session`: `Session.results`/`drivers`/`drivers_df` follow the official classification for Race/Sprint/Qualifying (practice borrows the race results for `DriverId`/`TeamId` only), did-not-start drivers are synthesized, `Time` is the true total race time (`TimeGap` the gap), fastf1's 22 columns come first (`FASTF1_RESULTS_COLUMNS`) then `TIF1_RESULTS_EXTRA_COLUMNS`, the index is `DriverNumber`. The Stats file rides alongside `drivers.json` (a daemon thread started by `_start_ergast_prefetch`, never a pool: pool workers are joined at interpreter exit); the thread starts only when a fetch is needed: a warm cache is resolved inline by `_resolve_cached_ergast_payload` under `ergast.payloads.cache_only()`, where a lookup that would fetch raises `ErgastFetchNeeded` instead; `_load_ergast_payload` memoizes the outcome, including a failure (re-raised in Ergast-only seasons, degraded to the lap-derived classification otherwise). A car two drivers shared (pre-1960s classifications) keeps the plain number as the label of its first driver and labels the others `number/Abbreviation` (`unique_driver_labels`) so `results.index` and `session.drivers` stay unique; `get_driver` accepts those labels, numbers and codes. `get_session(..., ergast=False)` / `ergast_results` turn it off. Seasons before `F1_API_FIRST_YEAR` (2018) are Ergast-only (`Session._ergast_only`): drivers and results from the classification, laps synthesized from the Ergast lap timings through the normal laps pipeline (per-driver laps are filtered from that table; `_driver_has_timing_data` is not consulted there), every timing payload raises `DataNotFoundError`. Their schedules list all five sessions as fastf1's Ergast backend does (`Session{i}` is always session `i`); `get_session` raises `DataNotFoundError` for any session outside `ERGAST_LOADABLE_SESSIONS` (Qualifying, Sprint, Race). `MIN_YEAR` is 1950.
- `events.py` has two schedule backends: f1schedule (2018+, vendored + live) and Ergast (`data/schedules/ergast/schedule_{year}.json`, compact `events.json` copies vendored by `tools/vendor_ergast_schedules.py`; the current season is fetched live from Stats with a TTL). `backend=None` picks f1schedule from 2018 and Ergast before; `"fastf1"`/`"f1timing"` mean f1schedule, `"ergast"` the Ergast table. Every schedule carries `CircuitId`/`CircuitName`/`CircuitLatitude`/`CircuitLongitude`/`EventUrl`/`CircuitUrl` (joined by round from the packaged Ergast file, never a request). `Event`/`EventSchedule` carry their `backend`; `get_events_remaining`, `get_testing_event`, `get_testing_session` and `is_testing()` exist.
- Unit tests keep `ergast_results` off (conftest) because the merge reaches a CDN; the `ergast_offline` fixture routes the loader and Jolpica client through `tests/fixtures/ergast/` (real Stats and Jolpica payloads) and turns the merge on. `tests/unit/test_ergast_fastf1_compliance.py` compares the flattening with fastf1's and needs `fastf1` installed by hand (`uv pip install fastf1 --no-deps`; it pins pandas below 3).
- HTTP via `http_session.py` (niquests session) + `async_fetch.py` (async parallel fetching with niquests); sync and async payload entry points share the CDN fallback loops owned by `cdn.py` (`CDNManager.try_sources` / `try_sources_async`). niquests' OCSP revocation check stays on; `http_revocation_check=False` skips it (120-240 ms per cold process; a security trade-off, so not the default). `ocsp_cache.py` (Elis E3) makes the kept check cheaper: `_create_session` loads `qh3._hazmat` without the `qh3` package `__init__` (the QUIC stack, ~30 ms) and restores the GOOD verdicts earlier processes persisted (SQLite `json` row `tif1/ocsp_verdicts`, at most 8, re-validated, honouring `nextUpdate` and a 7-day cap) into niquests' `InMemoryRevocationStatus` through its pickling contract; new GOOD verdicts are re-authenticated against their issuer and written after each connection warm-up and at `close_session` (`http_revocation_cache=False` turns the persistence off). `get_session` probes the cache (`_preconnect_cdn`; an Ergast-only season counts as cached when the Stats tier holds its classification, `Cache.has_json_entry`) before the session imports pandas/polars; an uncached session starts `first_wave.py` there (Elis E2/E9): daemon threads fetch the first-wave files (`_FIRST_WAVE_PATHS`) over `http.client` + `ssl` (trust store `wassima.generate_ca_bundle()`, niquests' User-Agent and gzip, ALPN http/1.1) while pandas/polars imports, and the fetch pipeline takes each body once (`take`, bounded). Single sync requests (`NiquestsTransport.get_json`) and the first telemetry wave (`async_fetch._stdlib_served`, `first_wave.bridge_open`; bridge requests bounded by `cdn_hedge_max_delay`, never hedged) ride the kept-alive stdlib connections until niquests has a session whose warm-up connected; the bridged request past `first_wave.BRIDGE_WARM_AFTER` (80, more than one driver's laps) starts the niquests import + `warm_connections` in a daemon thread (`warm_niquests`), so a one-driver wave runs on the stdlib alone (Naxos N8: the warm-up never finished before such a wave did, and its ~120-145 ms of import CPU under the GIL slowed the wave's receive threads) and a longer wave moves to niquests as before (starting it earlier, at the first-wave handover, measured slower). Anything but a `200` with a JSON object goes to niquests (CDN fallback, 403/404, retries and hedging unchanged). The stdlib requests skip niquests' OCSP check (documented); `cdn_first_wave=False` (`TIF1_CDN_FIRST_WAVE`) restores the Olympia pre-connect (niquests imported on the calling thread, `warm_connections` per first-wave path, every request through niquests); a proxy or a missing `wassima` makes the wave's thread warm niquests instead. `close_session` never waits for a session a warm-up thread is still building (exit). A cached session never imports niquests or starts a thread.
- Cache in `cache.py` (all tiers: `LRUCache` (the single LRU impl), SQLite `Cache` with kind-based `get_entry`/`set_entry`/`invalidate`, process-global backend lap caches `get_backend_lap_cache`/`clear_lap_cache`, and the per-session `SessionMemo` tier held as `Session._memo`). The materialized telemetry-frame tables are versioned through SQLite `PRAGMA user_version` (`_FRAME_TIER_SCHEMA_VERSION`): bump it whenever the dtype/column contract of a built telemetry frame changes, so stale frames are dropped once and rebuilt from the payload tier. The pandas driver rows of that tier are stored narrowed (`core_utils/frame_narrow.py`, row magic `TF1\x03`: the nanosecond clocks as `int32` milliseconds or deltas from `SessionTime`, `Int64` channels and the `DriverAhead` codes as `int8`, every encoding verified by a round trip before it is stored) and widened in place in the decompression worker, so every reader of driver blobs is unchanged and un-narrowed rows still read; The polars tier's per-driver Arrow IPC rows (`telemetry_frames_pl_ipc`, written by pyarrow's writer in the background frame writer) are read by pyarrow when it is already imported (`_ipc_reader_prefers_arrow`, faster in-process) and otherwise by polars: one to three drivers through the extension's eager IPC stream reader on the bytes past the file magic (`_read_polars_ipc_row`, ~2x `pl.read_ipc`; it holds the GIL, so the pooled read of four or more drivers keeps `pl.read_ipc`, which is also the fallback for any row the stream reader rejects), so a warm polars session never imports pyarrow (its `DriverAhead` codes become a `String` column through a polars gather, `helpers._polars_strings_from_codes`). CDN fallback in `cdn.py` (jsDelivr primary, Hugging Face buckets fallback, StaticDelivr as last-resort backup, never raw.githubusercontent.com); `CDNSource.format_repo_url`/`serves` and `CDNManager.try_sources_repo` serve repositories outside the per-year layout (the Stats repository; Hugging Face is skipped for it; the Ergast tier is sync-only, fanned out through a thread pool in `payloads.stats_payloads`).
- Config in `config.py` (singleton Config class, env vars + `.tif1rc` file support).
- Retry/circuit-breaker in `retry.py`; event schedule in `events.py` + `schedule_schema.py` (the pandas `Event`/`EventSchedule` classes live in `event_frames.py`, imported lazily so schedule lookups never import pandas; their public path stays `tif1.events`). Event-name resolution order: exact name (case-insensitive) → per-season alias table `EVENT_NAME_ALIASES` in `core_utils/constants.py` (circuit/city/country names; an alias whose event is not on that season's calendar raises instead of falling through) → fuzzy matching (`fuzzy.py`), which must score at least `_FUZZY_MIN_SCORE` (70) in `events.py`; below that `FuzzyMatchError` (an `EventNotFoundError`) is raised instead of loading the closest event. Testing events match by their exact name only (never through an alias or fuzzy match). Testing events of one season that share a name (2026's two "Pre-Season Testing" weeks) are numbered in date order by `_convert_f1schedule_year` (`Pre-Season Testing 1`/`2`, the data repositories' folder names; the event name is the CDN folder and the key of every schedule lookup, so a shared name made the second test overwrite the first); the shared name resolves to the first through the payload's `name_aliases`, as fastf1's first-match search does. A non-string `gp` (int, numpy int, whole float) is a round number; a session identifier that `float()` accepts is session N (1-5), and 2021/22 "SQ" means the Sprint. Resolution is pandas-free (`_resolve_event_name` / `_resolve_event_round` on the schedule payload, one vendored season loaded per year) and memoized per (query, exact_match) on the season's schedule record, so `get_session` resolves once (`Session(..., _event_resolved=True)`). Add an alias rather than tuning the fuzzy scorer when a name resolves wrongly.
- Validation (pydantic) in `validation.py`; errors in `exceptions.py` (hierarchy rooted at `TIF1Error`).
- Types in `types.py`: TypedDicts (LapDataDict, TelemetryDataDict, etc.), Literals (SessionType, BackendType, CompoundType).
- Shared helpers in `core_utils/`: `constants.py` (column names, rename maps), `gc_control.py` (stdlib-only `suspend_gc`: cyclic GC off for an allocation burst; `promote=True` ends it with `gc.freeze(); gc.unfreeze()`, an O(1) move of the burst's survivors into the oldest generation on GIL builds of CPython 3.11-3.13, used by the read-side frame builds and by the first import of pandas/numpy/polars/`tif1.core` through `lazy_import.import_promoted`; skipped when the process froze objects itself), `helpers.py` (DataFrame utils, validation; pandas-free at import), `pandas_blocks.py` (the pandas block assembly and its import-time probes, pandas sessions only), `json_utils.py` (JSON parsing), `backend_conversion.py` (pandas↔polars), `resource_manager.py`, `session_state.py` (weather, race-control, track-status and session-status tables built from whole columns via `to_numpy()` on either backend, never per-value casts or a polars query plan), `driver_laps.py` (exact column-by-column laps frame builds for one driver and for a whole first session load, `build_laps_frame`, falling back to the generic pipeline when a column is not reproducible; it imports pandas, so `core.py` imports it lazily inside `_pandas_laps_from_merged`: `tests/unit/test_polars_without_pandas.py` guards that), `frame_codec.py`/`frame_narrow.py` (frame tier rows), `telemetry_stream.py` (`PriorityFetchStream`: the cold `load(telemetry="lazy")` waves run on one event loop in a daemon thread, the laps a caller waits for first, each key fetched once; once the waves follow laps-row order (`Session._lazy_lookahead_next`), the next `lazy_telemetry_lookahead` drivers fill the free slots; `fetch_all_laps_telemetry` closes it and memoizes its payloads; interpreter exit cancels its requests in flight through a `threading._register_atexit` hook).
- Columnar telemetry files (Gortyn G3, Naxos N7, `design/TELEMETRY_COLUMNAR_FORMAT.md`): `core_utils/columnar_telemetry.py` encodes/decodes `{driver}/tel.v2.{first}.bin` (ten laps per file, `first` = 1, 11, 21...; typed columns in one zstd frame; the channels fastf1 and the data pipeline derive from others are stored as the ULP distance to a prediction computed with IEEE `+ - * /` only (no libm, no FMA): fastf1's merge interpolates over float64 nanosecond dates of millisecond timestamps, so with a per-lap start date (`dates`, searched mod 512 ns) `numpy.interp` (car channels at the position rows) and a quadratic interpolating spline (`x`/`y`/`z` at the car rows, `distance` at the position rows) reproduce them, plus `distance`'s integration, `rel_distance`, and the pipeline's `acc_x/y/z` (fdlibm `atan2` spelled out); ~85% fewer bytes than the gzipped lap JSON; decoded laps equal the native decoder's mapping bit for bit). The predictions run in `tif1_native.tel_integ`/`tel_accx`/`tel_lateral`/`tel_spline`/`tel_interp`/`tel_apply` (`native/src/telcols.rs`, GIL released) when the installed build has them (`json_utils.NATIVE_TEL_*`), else in their numpy twins; both must stay bit-identical (`tests/unit/test_columnar_telemetry.py`), and changing a prediction is a format version bump. The reader asks for the files only when every kernel is installed (`json_utils.native_columnar_decoder_available()`; the numpy decoder is ~6x slower per file). `async_fetch` asks for them on cold waves only (a batch with two or more laps of a driver, or the lazy stream's requests with `driver_files=True`; a lone lap keeps its JSON): one download per file per process in the fetch pool (`_driver_file_future`), shared by the wave's lap requests on any event loop, through `HttpTransport.get_bytes` (`NiquestsTransport`, `InMemoryTransport`). Missing (a 404 on the primary CDN, remembered in `missing_payloads` and ending probes for that session in-process), unreadable, failing or lap-less files fall back to the lap JSON. Path helpers live in the numpy-free `constants.py` (`columnar_chunk_first_lap`, `columnar_file_path`). Off with `telemetry_columnar=False` (`TIF1_TELEMETRY_COLUMNAR`), validated telemetry, offline and Pyodide. The data pipeline runs `tools/data/encode_driver_telemetry.py` (`--verify`, needs `tif1-native`).
- Rust decoder `tif1-native` (`native/`, pyo3 abi3; from 0.11.1 a dependency on CPython Linux/macOS/Windows x86_64/arm64 through the `pyproject.toml` marker, pure-Python fallback elsewhere; `tests/unit/test_pyproject_markers.py` pins the marker to the wheel matrix of `native.yml`): `json_utils.decode_telemetry_payload` uses it when importable (`TIF1_DISABLE_NATIVE=1` turns it off). Key patterns:
- Session.load() accepts `laps`, `telemetry`, `messages`, `weather` to control what data gets fetched. Telemetry is lazy by default (`load_telemetry_lazy=True`, unlike fastf1): `load()`/`telemetry=True` register the laps and fetch nothing; the first read of a driver fetches that driver's laps in one wave (`_ensure_lazy_telemetry`, through `core_utils/telemetry_stream.py` on a cold session), except that on a cold session a driver's first read that asks for one lap fetches that lap's file alone (`_lazy_lone_lap`/`_fetch_lazy_lone_lap`, Naxos N11: payload tier only, its frame is memoized but not written to the frame tier; a failure falls to the per-lap path) and the next read brings the rest; an `iterlaps()` loop marks its drivers with two or more laps as walked (`_note_lazy_telemetry_walk`) so the loop starts with the wave; cached sessions never go lone. On a cached polars session (lazy, or eager when the frame tier holds every lap: `_polars_telemetry_load_pending`, Naxos N2) `load()` reads no driver row; the first `_LAZY_CACHED_LONE_WAVES` (2) waves read their drivers alone, the next reads every pending row, and an `iterlaps()` walk reads all its drivers at once (`_ensure_lazy_telemetry_walk`). `telemetry="eager"` (or `load_telemetry_lazy=False`) is fastf1's eager load, `telemetry=False` registers nothing (per-lap fetches). A telemetry failure is a log warning plus an empty frame at the lap's first access, never an exception; `load()` writes no telemetry to the cache. Tests about the eager pipeline pass `telemetry="eager"`; this behaviour is user-facing and documented in `COMPATIBILITY.md` ("Lazy telemetry in `load()`"), `docs/migration-from-fastf1.mdx` and `docs/concepts/sessions.mdx` (Lazy telemetry): keep them in step with any change to it.
- Data flows: CDN URL → async HTTP fetch → JSON parse → DataFrame construction → column rename/reorder → cache.
- The CDN system fetches from TracingInsights GitHub data repos (per-year repos like `{year}`), served via jsDelivr (primary) with Hugging Face buckets (`huggingface.co/buckets/tracinginsights/{year}`, same repo layout via `/resolve/`) as fallback and StaticDelivr as last-resort backup. A 404 from one CDN falls through to the next; `DataNotFoundError` is raised only when every CDN returns 404.
- Exception hierarchy: TIF1Error → DataNotFoundError → {DriverNotFoundError, LapNotFoundError}; TIF1Error → {NetworkError, InvalidDataError, CacheError, SessionNotLoadedError, AsyncRequiredError}. Event-name failures are `ValueError`s outside that tree: ValueError → EventNotFoundError → {FuzzyMatchError → EventNotInSeasonError, ExactEventNotFoundError (also a `KeyError`, an `exact_match` miss)}. `DriverNotFoundError` is also a `ValueError` (fastf1's `get_driver` raises one).
- All exceptions accept `**context` kwargs for structured error info.

Constraints:
- Never use `https://raw.githubusercontent.com` as a CDN for the data repositories (rate limits). Use jsDelivr (primary), Hugging Face buckets (fallback), or StaticDelivr (last resort) only. The one sanctioned raw GitHub URL is the live event schedule: `events.py` fetches `theOehrly/f1schedule/master/schedule_{year}.json` (the file FastF1 reads, 5-minute edge cache) for the current/future season, caches the raw file in the SQLite `json` tier under `f1schedule/schedule_{year}.json` for `schedule_ttl_hours` (default 6, `TIF1_SCHEDULE_TTL_HOURS`), and falls back to the vendored `data/schedules/f1schedule/` files; past seasons are served from the vendored files only.
- Python >=3.11 (CI tests 3.11 through 3.15); use type hints everywhere; Google-style docstrings for public APIs.
- Ruff ruleset (see pyproject.toml for full select/ignore); line length 100, double quotes, space indent.
- Keep imports sorted (ruff/format), avoid unused imports, prefer explicit names.
- Handle errors via custom exceptions in `exceptions.py`; never swallow network/data errors.
- orjson for JSON parsing (not stdlib json).
- pandas >=3.0.6 as primary backend; polars (`>=2.0.0,<3`) is a declared dependency but lazy-loaded (`_ensure_polars_available()` falls back to pandas if it is missing). pyarrow is a runtime dependency too (polars↔pandas conversion goes through Arrow). Charts always draw from a pandas session; `lib="polars"` on a chart loads the pandas view of the same session.
- Windows is a supported platform even though CI's blocking jobs run on Ubuntu (two advisory `windows-latest` legs run the unit suite): read and write text with an explicit `encoding="utf-8"` (ruff `PLW1514` enforces it), never turn a filesystem path into a URL or cache key with `str()` (use `.as_posix()`; `InMemoryTransport.key_for` builds fixture keys), resolve the home directory through `config._home_dir()`, and keep the unit-suite socket blocker's loopback exception (asyncio's `socketpair()` self-pipe needs it on Windows). Two conftest guards fail a test that leaks config state (`_config_leak_guard`) or writes the developer's real `~/.tif1rc` (`_real_config_file_guard`): patch `HOME` and `Path.home` with a temporary directory instead.
- Always optimize for performance. Entire existence of this library is to focus on optimization, speed and performance. Performance is critical
