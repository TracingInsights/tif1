Build/lint/test:
- Install deps: `uv sync --all-extras`
- Tests: `uv run pytest tests/ -v`
- Single test file: `uv run pytest tests/unit/test_core.py -v`
- Single test by name: `uv run pytest tests/ -v -k "test_name"`
- Unit only: `uv run pytest tests/unit/ -v` (real sockets are blocked by an autouse fixture in `tests/conftest.py`; a test that must reach the network needs the `integration`, `compliance_online` or `benchmark` marker)
- Integration only: `uv run pytest tests/integration/ -v`
- Property-based: `uv run pytest tests/property/ -v`
- Benchmarks: `uv run pytest tests/benchmarks/ -v -m benchmark`
- Lint: `uv run ruff check src/ tests/`
- Format: `uv run ruff format src/ tests/`
- Types: `uv run ty check src/tif1`
- Coverage: pytest runs with `--cov` by default; fail threshold is 80%.

Architecture:
- Library source in `src/tif1/`; public API via lazy `__getattr__` exports in `__init__.py`.
- `core.py` is the monolith (~4200 lines): Session class, data loading, lap/telemetry/weather/race-control parsing; re-exports the model family for backward compatibility (`tif1.core.Laps` etc. are aliases of the `tif1.models` classes, resolved by a module `__getattr__`). A polars session never imports pandas: `core.py`, `core_utils/helpers.py` and `core_utils/ergast_results.py` bind `pd` (and core binds `tif1.models`) through `core_utils/lazy_import.lazy_module`, which rebinds the global to the real module on first use; pandas sessions import pandas, `tif1.models` and `core_utils/pandas_blocks.py` up front (`_load_pandas_models`). On the polars path use `is_pandas_frame`/`is_pandas_series` instead of `isinstance(x, pd.DataFrame)`, quote `cast("pd.DataFrame", ...)`, read the schedule row with `Session._event_row()` instead of the pandas `Session.event`, and build results rows with `native=True` scalars; `tests/unit/test_polars_without_pandas.py` guards it in a fresh interpreter. `session.drivers`/`drivers_df`/`results` are in classification order: `Session._driver_rows_info` keeps the upstream `drivers.json` order when it already is a classification and otherwise rebuilds it from the laps table (`_summarize_laps_for_classification`, one pass over the few needed columns, either backend); missing car numbers are backfilled from the same summary. `gp`/`session` attributes stay URL-encoded (CDN paths); `event_name`/`session_name` are the decoded forms for messages and error context. Its fetch seams `Session._fetch_from_cdn(_fast)`/`_fetch_json(_unvalidated)` are thin delegates into `payload_loader.py`, kept as one override seam for older tests.
- `models.py` is the canonical model module: `Laps`, `Lap`, `Telemetry`, `Driver`, `SessionResults`, `DriverResult`, plus the `TelemetryProvider` protocol (the backend-neutral `CircuitInfo` and `LazyTelemetryDict` live in the pandas-free `models_shared.py` and are re-exported) — the narrow (mostly private) session seam the models consume. `Session` satisfies it structurally; tests can use in-memory fakes. `models.py` must never import `core.py` at runtime (import cycle).
- `models_polars.py` holds the polars-native classes (`PolarsLaps`, `PolarsLap`, `PolarsTelemetry`, `PolarsSessionResults`, `PolarsDriverResult`, `PolarsDriver`, the `.f1` namespace). Its hot paths (every `pick_*`, the slices, `Laps.telemetry`, `merge_channels`, `add_distance`, `fill_missing`, `get_weather_data`, `split_qualifying_sessions`, the results frame) run on numpy masks and column gathers on a cloned `_df` instead of query plans (a plan costs ~0.5 ms, the first of a process ~7 ms); only rare inputs (non-ASCII qualifying labels, fractional lap numbers, tied status times) take the expression path. Keep new methods off the query engine. A pandas session never imports this module.
- `session.py` is a thin re-export shim pointing into `core.py`.
- `io_pipeline.py` and `lap_ops.py` were removed (pass-through shims); internal helpers live in `core.py`/`core_utils/`.
- `payload_loader.py` is the single payload-loading pipeline: `PayloadLoader.get` (session memo -> SQLite cache -> fetch -> validate -> memo/cache write-back), `fetch_from_cdn(path, fast=)` (retry/backoff unless `fast`), async `get_many` (delegates to `fetch_multiple_async`), and `get_url` + thread-safe `get_url_loader()` for absolute-URL payloads (used by `events.py`). HTTP goes through injectable `HttpTransport` implementations (`NiquestsTransport` in production, `InMemoryTransport` in tests). Validation failures always raise — no patched-callable escape hatch (the old `__code__`-sniffing test-compat machinery was removed).
- `ergast/` is the Ergast tier (fastf1 `fastf1.ergast` parity): `structure.py` (fastf1's flattening tables plus `totalRaceTimeGap` and the sprint-qualifying schedule keys), `interface.py` (`Ergast`, the response classes, `source` attribution, `result_type="polars"`: `ErgastPolarsResponse`, a polars frame with the paging mixin built on first use so the module never imports polars), `router.py` (the routing matrix: anything season-scoped that the Stats files answer exactly comes from `TracingInsights-Archive/Stats` via `stats.py`, season-wide answers assembled from per-round files; seasons/drivers/status lists, `status=` filters, no-season queries and `current`/`last` go to Jolpica via `jolpica.py`, which paces 4 req/s and 500 req/h and honours `Retry-After`; a missing/empty Stats file falls through to Jolpica for that round), `payloads.py` (memo -> SQLite `json` tier `{"fetched_at", "payload"}` wrapper -> `CDNManager.try_sources_repo`; past seasons cached permanently, current season and Jolpica answers for `ergast_ttl_hours`; a "missing" verdict needs a 404 from every mirror, a 403 is retried once and never persisted, and a miss that involved a 403 is remembered in-process for 60 s so repeated lookups do not re-walk the mirrors), `standings.py` (`get_driver_standings`/`get_constructor_standings`), `legacy.py`. The merged Stats `laptimes.json` repeats a lap split across Jolpica pages: `jolpica.merge_split_laps` joins the timings. Past-season Stats files are snapshots: Jolpica later edits metadata (URLs, localities, circuit names, current permanent numbers, status vocabulary), so `tif1.ergast` frames can differ from fastf1's live answers in those columns while results, times, points and positions match.
- `core_utils/ergast_results.py` merges the Ergast classification into `Session`: `Session.results`/`drivers`/`drivers_df` follow the official classification for Race/Sprint/Qualifying (practice borrows the race results for `DriverId`/`TeamId` only), did-not-start drivers are synthesized, `Time` is the true total race time (`TimeGap` the gap), fastf1's 22 columns come first (`FASTF1_RESULTS_COLUMNS`) then `TIF1_RESULTS_EXTRA_COLUMNS`, the index is `DriverNumber`. The Stats file rides alongside `drivers.json` (a daemon thread started by `_start_ergast_prefetch`, never a pool: pool workers are joined at interpreter exit); the thread starts only when a fetch is needed: a warm cache is resolved inline by `_resolve_cached_ergast_payload` under `ergast.payloads.cache_only()`, where a lookup that would fetch raises `ErgastFetchNeeded` instead; `_load_ergast_payload` memoizes the outcome, including a failure (re-raised in Ergast-only seasons, degraded to the lap-derived classification otherwise). A car two drivers shared (pre-1960s classifications) keeps the plain number as the label of its first driver and labels the others `number/Abbreviation` (`unique_driver_labels`) so `results.index` and `session.drivers` stay unique; `get_driver` accepts those labels, numbers and codes. `get_session(..., ergast=False)` / `ergast_results` turn it off. Seasons before `F1_API_FIRST_YEAR` (2018) are Ergast-only (`Session._ergast_only`): drivers and results from the classification, laps synthesized from the Ergast lap timings through the normal laps pipeline (per-driver laps are filtered from that table; `_driver_has_timing_data` is not consulted there), every timing payload raises `DataNotFoundError`. Their schedules list all five sessions as fastf1's Ergast backend does (`Session{i}` is always session `i`); `get_session` raises `DataNotFoundError` for any session outside `ERGAST_LOADABLE_SESSIONS` (Qualifying, Sprint, Race). `MIN_YEAR` is 1950.
- `events.py` has two schedule backends: f1schedule (2018+, vendored + live) and Ergast (`data/schedules/ergast/schedule_{year}.json`, compact `events.json` copies vendored by `tools/vendor_ergast_schedules.py`; the current season is fetched live from Stats with a TTL). `backend=None` picks f1schedule from 2018 and Ergast before; `"fastf1"`/`"f1timing"` mean f1schedule, `"ergast"` the Ergast table. Every schedule carries `CircuitId`/`CircuitName`/`CircuitLatitude`/`CircuitLongitude`/`EventUrl`/`CircuitUrl` (joined by round from the packaged Ergast file, never a request). `Event`/`EventSchedule` carry their `backend`; `get_events_remaining`, `get_testing_event`, `get_testing_session` and `is_testing()` exist.
- Unit tests keep `ergast_results` off (conftest) because the merge reaches a CDN; the `ergast_offline` fixture routes the loader and Jolpica client through `tests/fixtures/ergast/` (real Stats and Jolpica payloads) and turns the merge on. `tests/unit/test_ergast_fastf1_compliance.py` compares the flattening with fastf1's and needs `fastf1` installed by hand (`uv pip install fastf1 --no-deps`; it pins pandas below 3).
- HTTP via `http_session.py` (niquests session) + `async_fetch.py` (async parallel fetching with niquests); sync and async payload entry points share the CDN fallback loops owned by `cdn.py` (`CDNManager.try_sources` / `try_sources_async`). niquests' OCSP revocation check stays on; `http_revocation_check=False` skips it (120-240 ms per cold process; a security trade-off, so not the default). `get_session` probes the cache (`_preconnect_cdn`; an Ergast-only season counts as cached when the Stats tier holds its classification, `Cache.has_json_entry`) before the session imports pandas/polars; an uncached session imports niquests there and `warm_connections` opens one connection per first-wave request (`_FIRST_WAVE_PATHS`) in daemon threads, which the first fetches wait for (`wait_for_warm_connections`, bounded); a cached session never imports niquests or starts a thread.
- Cache in `cache.py` (all tiers: `LRUCache` (the single LRU impl), SQLite `Cache` with kind-based `get_entry`/`set_entry`/`invalidate`, process-global backend lap caches `get_backend_lap_cache`/`clear_lap_cache`, and the per-session `SessionMemo` tier held as `Session._memo`). The materialized telemetry-frame tables are versioned through SQLite `PRAGMA user_version` (`_FRAME_TIER_SCHEMA_VERSION`): bump it whenever the dtype/column contract of a built telemetry frame changes, so stale frames are dropped once and rebuilt from the payload tier. The pandas driver rows of that tier are stored narrowed (`core_utils/frame_narrow.py`, row magic `TF1\x03`: the nanosecond clocks as `int32` milliseconds or deltas from `SessionTime`, `Int64` channels and the `DriverAhead` codes as `int8`, every encoding verified by a round trip before it is stored) and widened in place in the decompression worker, so every reader of driver blobs is unchanged and un-narrowed rows still read; CDN fallback in `cdn.py` (jsDelivr primary, Hugging Face buckets fallback, StaticDelivr as last-resort backup, never raw.githubusercontent.com); `CDNSource.format_repo_url`/`serves` and `CDNManager.try_sources_repo` serve repositories outside the per-year layout (the Stats repository; Hugging Face is skipped for it; the Ergast tier is sync-only, fanned out through a thread pool in `payloads.stats_payloads`).
- Config in `config.py` (singleton Config class, env vars + `.tif1rc` file support).
- Retry/circuit-breaker in `retry.py`; event schedule in `events.py` + `schedule_schema.py` (the pandas `Event`/`EventSchedule` classes live in `event_frames.py`, imported lazily so schedule lookups never import pandas; their public path stays `tif1.events`). Event-name resolution order: exact name (case-insensitive) → per-season alias table `EVENT_NAME_ALIASES` in `core_utils/constants.py` (circuit/city/country names; an alias whose event is not on that season's calendar raises instead of falling through) → fuzzy matching (`fuzzy.py`), which must score at least `_FUZZY_MIN_SCORE` (70) in `events.py`; below that `FuzzyMatchError` (an `EventNotFoundError`) is raised instead of loading the closest event. Testing events match by their exact name only (never through an alias or fuzzy match). A non-string `gp` (int, numpy int, whole float) is a round number; a session identifier that `float()` accepts is session N (1-5), and 2021/22 "SQ" means the Sprint. Resolution is pandas-free (`_resolve_event_name` / `_resolve_event_round` on the schedule payload, one vendored season loaded per year) and memoized per (query, exact_match) on the season's schedule record, so `get_session` resolves once (`Session(..., _event_resolved=True)`). Add an alias rather than tuning the fuzzy scorer when a name resolves wrongly.
- Validation (pydantic) in `validation.py`; errors in `exceptions.py` (hierarchy rooted at `TIF1Error`).
- Types in `types.py`: TypedDicts (LapDataDict, TelemetryDataDict, etc.), Literals (SessionType, BackendType, CompoundType).
- Shared helpers in `core_utils/`: `constants.py` (column names, rename maps), `helpers.py` (DataFrame utils, validation; pandas-free at import), `pandas_blocks.py` (the pandas block assembly and its import-time probes, pandas sessions only), `json_utils.py` (JSON parsing), `backend_conversion.py` (pandas↔polars), `resource_manager.py`, `session_state.py` (weather, race-control, track-status and session-status tables built from whole columns via `to_numpy()` on either backend, never per-value casts or a polars query plan), `driver_laps.py` (exact column-by-column laps frame builds for one driver and for a whole first session load, `build_laps_frame`, falling back to the generic pipeline when a column is not reproducible; it imports pandas, so `core.py` imports it lazily inside `_pandas_laps_from_merged`: `tests/unit/test_polars_without_pandas.py` guards that), `frame_codec.py`/`frame_narrow.py` (frame tier rows).
- Optional Rust decoder `tif1-native` (`native/`, pyo3 abi3, distribution not on PyPI yet and not a dependency): `json_utils.decode_telemetry_payload` uses it when importable (`TIF1_DISABLE_NATIVE=1` turns it off). Numeric channels come back as numpy arrays and `DriverAhead` as a `json_utils.DictionaryChannel` (int32 codes into a category list, `tolist()` gives the orjson list); every consumer of a telemetry payload accepts list, ndarray and DictionaryChannel channels (`helpers._TELEMETRY_CHANNEL_TYPES`, `_channel_list`) and must build frames identical to the orjson lists (`tests/unit/test_native_decoder.py`). `.github/workflows/native.yml` builds and tests the wheels (abi3 only, no free-threaded wheels; Linux glibc/musl, macOS universal2, Windows x64/arm64; sdist) and uploads only from a manual dispatch; the CI `native` job reruns the unit suite with the extension built from the commit.
- Optional polars backend: lazy-loaded, gate behind `_ensure_polars_available()` in `core.py`.
- CLI (typer + rich) in `cli.py`; Jupyter support in `jupyter.py`; plotting in `plotting.py`.
- `fastf1_compat.py` provides fastf1 compatibility shims (e.g. `set_log_level`).
- Pyodide (browser) support: `core_utils/runtime.py` owns the runtime facts (`IS_EMSCRIPTEN`, `THREADS_AVAILABLE`, `can_block_on_awaitables()`, `run_sync_in_browser()`, `import_supported_polars()`); every thread/pool start is gated on `THREADS_AVAILABLE` (inline fallback) and the five sync entry points bridge to their coroutine through one helper, `core._run_coroutine_sync` (native: nest_asyncio2 shim + `asyncio.run`; Pyodide: `pyodide.ffi.run_sync` under JSPI, else `AsyncRequiredError`). `browser.py` is the Pyodide transport (`urllib3` for the sync `HttpTransport` seam, `pyodide.http.pyfetch` for the async fan-out via `AsyncHttpTransport`) plus IndexedDB persistence; `payload_loader.default_transport()` picks it on emscripten. `Session.load_async()` is the async twin of `load()`. `pyproject.toml` carries `sys_platform == 'emscripten'` dependency twins (major-only floors) checked against `tools/pyodide_target.json` by `tests/unit/test_pyproject_markers.py`; `tools/pyodide_smoke.mjs` installs the wheel in Node's Pyodide and `tools/pyodide_browser_check.mjs` drives Chrome/Firefox through Playwright (main thread, Web Worker, XMLHttpRequest path, IndexedDB persistence); both run `tools/pyodide_checks.py` (CI job `pyodide-smoke`).
- Tests in `tests/` split into `unit/`, `integration/`, `property/`, `benchmarks/`.

Key patterns:
- Session.load() accepts `laps`, `telemetry`, `messages`, `weather` booleans to control what data gets fetched.
- Data flows: CDN URL → async HTTP fetch → JSON parse → DataFrame construction → column rename/reorder → cache.
- The CDN system fetches from TracingInsights GitHub data repos (per-year repos like `{year}`), served via jsDelivr (primary) with Hugging Face buckets (`huggingface.co/buckets/tracinginsights/{year}`, same repo layout via `/resolve/`) as fallback and StaticDelivr as last-resort backup. A 404 from one CDN falls through to the next; `DataNotFoundError` is raised only when every CDN returns 404.
- Exception hierarchy: TIF1Error → DataNotFoundError → {DriverNotFoundError, LapNotFoundError}; TIF1Error → {NetworkError, InvalidDataError, CacheError, SessionNotLoadedError, AsyncRequiredError}. Event-name failures are `ValueError`s outside that tree: ValueError → EventNotFoundError → {FuzzyMatchError → EventNotInSeasonError, ExactEventNotFoundError (also a `KeyError`, an `exact_match` miss)}. `DriverNotFoundError` is also a `ValueError` (fastf1's `get_driver` raises one).
- All exceptions accept `**context` kwargs for structured error info.

Constraints:
- Never use `https://raw.githubusercontent.com` as a CDN for the data repositories (rate limits). Use jsDelivr (primary), Hugging Face buckets (fallback), or StaticDelivr (last resort) only. The one sanctioned raw GitHub URL is the live event schedule: `events.py` fetches `theOehrly/f1schedule/master/schedule_{year}.json` (the file FastF1 reads, 5-minute edge cache) for the current/future season, caches the raw file in the SQLite `json` tier under `f1schedule/schedule_{year}.json` for `schedule_ttl_hours` (default 6, `TIF1_SCHEDULE_TTL_HOURS`), and falls back to the vendored `data/schedules/f1schedule/` files; past seasons are served from the vendored files only.
- Python >=3.11 (CI tests 3.11 through 3.15); use type hints everywhere; Google-style docstrings for public APIs.
- Ruff ruleset (see pyproject.toml for full select/ignore); line length 100, double quotes, space indent.
- Keep imports sorted (ruff/format), avoid unused imports, prefer explicit names.
- Handle errors via custom exceptions in `exceptions.py`; never swallow network/data errors.
- orjson for JSON parsing (not stdlib json).
- pandas >=3.0.6 as primary backend; polars (`>=2.0.0,<3`) is a declared dependency but lazy-loaded (`_ensure_polars_available()` falls back to pandas if it is missing). pyarrow is a runtime dependency too (polars↔pandas conversion goes through Arrow). Charts always draw from a pandas session; `lib="polars"` on a chart loads the pandas view of the same session.
- Windows is a supported platform even though CI's blocking jobs run on Ubuntu (two advisory `windows-latest` legs run the unit suite): read and write text with an explicit `encoding="utf-8"` (ruff `PLW1514` enforces it), never turn a filesystem path into a URL or cache key with `str()` (use `.as_posix()`; `InMemoryTransport.key_for` builds fixture keys), resolve the home directory through `config._home_dir()`, and keep the unit-suite socket blocker's loopback exception (asyncio's `socketpair()` self-pipe needs it on Windows). Two conftest guards fail a test that leaks config state (`_config_leak_guard`) or writes the developer's real `~/.tif1rc` (`_real_config_file_guard`): patch `HOME` and `Path.home` with a temporary directory instead.
- Always optimize for performance. Entire existence of this library is to focus on optimization, speed and performance. Performance is critical
